# 文档维护原则

让读者找到现行规则、当前交付状态和对应证据，并让每类信息有明确的维护位置。

## 信息归属

| 信息 | 主要维护位置 | 维护内容 |
| --- | --- | --- |
| 当前交付状态 | [MVP 实施基线](../../../docs/handovers/MVP_IMPLEMENTATION_BASELINE.md) | 核对日期、代码基准、已提交／工作区／未实现能力、实现缺口与证据入口 |
| 产品行为与未决决定 | [PRD](../../../docs/PRD.md)、[GLOSSARY](../../../docs/GLOSSARY.md) | 产品范围、行为、领域定义、已确认决定与 TBD |
| 技术实现与选型 | [ARCHITECTURE](../../../docs/ARCHITECTURE.md)、[TECH_STACK](../../../docs/TECH_STACK.md) | 实际模型与接口、不变式、采用技术和预留选型 |
| 页面职责与导航 | [INFORMATION_ARCHITECTURE](../../../docs/INFORMATION_ARCHITECTURE.md) | 页面、路由、返回路径和 UI 状态契约 |
| 阶段执行安排 | 对应阶段 README／PLAN | 后续顺序、准备条件、实施起点、范围和方法 |
| 验收证据 | 对应 ACCEPTANCE／执行记录 | 日期与版本、环境、检查结果、浏览器观察和未验证项 |
| 使用、开发与数据维护操作 | USAGE／DEVELOPMENT／UPGRADING | 可执行的操作步骤、配置和兼容边界；环境特有的历史处理放验收记录 |
| 研究与隔离原型 | references／prototypes 的索引与原记录 | 输入版本、证据范围、提案状态和复现入口；不替代现行产品契约 |

README 保留产品简介与使用入口；AGENTS 保留工程约定和 skill 入口；文档索引按问题和职责导航。它们通过链接指向交付状态与证据。

## 判断该保留什么

- 当前实现、提交、工程验收和用户使用验收分别核对，结论绑定相应证据。
- 删除重复的 HEAD、提交状态、检查通过结论和完整能力清单；保留理解契约所需的现行／未来边界、技术采用状态和必要范围限定。
- 原书 ruby 与自动注音、手动片段学习与 EPUB 学习衔接分别表达；工作区能力的适用说明链接实施基线。
- 历史验收保留当时的日期、起点、环境、数字与限制。后续验证追加自己的记录，明确对象与范围。
- 基线的历史部分提供证据索引，测试数量与包体积由原记录维护。
- 文档版本和撰写日期照常维护；基线中的代码基准记录核对时的版本。

## 活动资料与归档

- 以是否仍承担现行契约、执行安排或运行依赖判断归档，不能只看文件日期。已完成验收即使保留设备实测等未验证项，也可以归档；仍影响当前交付的限制由基线承接。
- 混合旧方案与未完成设计的文件，先将独有待办、候选参数与未决问题承接到活动阶段入口，再归档原方案。现行规则引用负责规范，避免重新复制一份完整方案。
- 迁移前搜索代码、测试、fixtures、脚本和文档中的路径引用；历史与研究目录须显式纳入搜索。测试仍读取的固定样例不随整个阶段机械归档。
- 历史记录保留当时的事实与用语，只调整迁移所需的链接并补充现行入口。活动验收矩阵中的旧预期则更新或移出，避免其与现行规范竞争。

## 按变化维护

先读 [AGENTS](../../../AGENTS.md)，核对分支、工作区改动和本次范围，保留已有修改。定位信息的主要维护位置，结合代码、生成接口和已有记录判断现状；将需要删除的重复内容对应到承接位置。

按段落核对现行行为、未来方案和历史事实；同一文件的演进表、活动验收矩阵、指南操作步骤与接手提示词也可能残留旧状态，开头的效力声明不能代替修正。入口变化时沿完整操作路径核对后续步骤。文档与实现不一致时，先确认是文档过时、未落实契约还是未定产品决定，不据代码现状擅自改写已确认要求。

按变化更新：新验证结果写入验收记录，交付状态变化更新基线，行为或实现变化更新负责规范，后续顺序变化更新阶段入口。接手提示词引用基线与顺序，保留职责、准备动作和执行约束。

优先局部精简与引用调整；已完成资料按归档边界迁移，更新入站链接和迁移后的相对链接。索引说明资料的用途与效力，接手提示词明确已完成起点和下一步准备条件。基线使用核对时的确切提交或工作区描述，避免用会随时间漂移的“本次提交”表示当前状态。

指南优先回答用户如何完成操作。补齐必要步骤与恢复检查，兼容边界区分“未验证”和代码已确定不支持；会话、缓存等机制只保留影响操作的说明。备份恢复示例用临时合成数据验证，不对用户数据库执行演示。

## 完成检查

- 删除项仍可从主要维护位置查到，读者能从入口到达基线、后续安排与原始验收。
- 产品行为、TBD、工程硬约束及历史事实保持准确。
- 链接与标题锚点有效，代码基准和工作区状态可核实；归档后的待办和原始证据仍可从活动入口到达。
- 运行 `just check-docs` 和 `git diff --check`，并遵循 AGENTS 的其他检查要求。当前链接脚本只校验本地路径，标题锚点和本轮涉及的 skill／非 README 研究文档需另行核对，不能将路径通过描述为全部引用通过。
- 更新 skill 时校验其结构、引用与既有 UI 元数据的一致性。只增加会改变后续判断的经验，避免把本轮文件清单和问题实例堆成长期规则。
