# 领域术语与讨论记录

> 更新：2026-09-26。按门类逐步对齐，未讨论的概念不在这里预先定型。
> 「已对齐」记录已确认的含义；「提案」保留待讨论的定义。术语不等于数据库表，也不自动增加 MVP 功能。

## 1. 来源、片段与语境（已对齐）

当前方向：**创建来源记录 → 添加片段 → 围绕片段讨论、保存讲解并积累学习点。** Segment 是共同的学习起点；工作台只是承载操作的界面，不决定讲解或讨论内容的归属。

首页称为「来源目录」，以 Source 组织片段。首轮由用户手动录入，不要求系统保存 EPUB、字幕或视频等素材。

| 术语 | 定义 | 边界与例子 |
|---|---|---|
| Source／来源记录（界面简称「来源」） | 系统中表达用户声明的来源范围的记录，不与单个文件或素材一一对应。 | 如一部作品及其多卷内容，或动画某一集。可以只有标题和备注，不要求系统持有完整内容，也不要求自动核实归属。 |
| Segment／学习片段 | 本次学习、讲解或讨论所针对的目标文本。 | 可以是半句、一句或多句；首轮由用户手动录入，归属于来源记录。无需先有完整解析才可讨论。 |
| Context／语境内容 | 帮助理解目标片段、但不属于本次解析范围的附带内容。 | 如前文、后文；提供理解线索不代表它们也成为本次逐项解析或提取的对象。使用「语境内容」以免与下文待定义的「材料」混淆。 |
| SourceRef／出处信息 | 当前为片段上的可选自由文本，记录用户声明的具体出处。 | 如页码、集数与时间戳；不等于未来素材的外键或自动定位。它与描述来源范围的 Source 不同。 |
| Collection／学习集合 | 用户按学习目的组织的一组学习内容。 | 如「容易听错的日常表达」。保留概念，当前 MVP 不引入；不作为 Source 的同义词。 |

补充边界：

- 手动录入与未来从素材选取是不同入口，汇合到 Segment 的学习流程；手动录入不需要虚构 TXT 素材实体。
- 同一 Source 可容纳不同入口取得的片段；具体卷次、版本与位置可由各片段的出处信息描述。首轮不建立素材库或文件层级系统。
- 手动提供的目标原文与前后文是学习输入，须区分目标范围与用户疑问、听写等附带信息；不把整份提交内容当作系统保存的素材实体。
- 系统无须自动核实出处，仍可记录用户声明的来源关系。
- 同一来源下的片段不一定在原作中相邻；录入顺序不等于原作顺序。不能仅凭「此前添加的两条」就把它们当成原文前文。
- 作品、卷、集、文件之间的层级尚未确定；这里不预设素材库模型。

Segment 的目标原文在尚未被 AI 任务使用时可编辑；首次引用它的 AI 任务被系统接受后固定。来源与管理信息的维护不回写历史调用输入。编辑与级联删除的产品行为以 PRD 的 F2 节为准。

## 2. 素材（已对齐）与材料（提案，待确认）

素材指系统保存、供选取或处理时作为输入依据的内容，可来自 EPUB、TXT、字幕，以及与音视频配套的资源；不限定一个文件对应一份素材。Source 表达来源范围，Segment 表达选定的学习目标，素材保存可供选取的输入内容。当前没有真实素材接入计划，不建立素材库。将来从素材选取目标文本后，仍进入同一 Segment 学习流程。

材料仍是待讨论的提案：以素材为依据，将原内容或其引用与分句、词项标注、位置映射等派生结果组织起来，供后续使用。派生结果可以独立存储，不要求改写素材；此处不构成导入、加工或打包功能要求。

素材与材料的英文名、存储形式、定位方式、组合粒度、版本及删除关系仍未确定；材料包含哪些处理结果、解析文档是否属于材料，也留待讨论。`source_ref` 目前只是自由文本出处，不能据此预建素材或材料表，也不能推断素材与 Source、Segment 的外键关系。仅复制或封装文件不自动形成新的材料身份。

## 3. 解析文档（已对齐）

| 术语 | 定义 | 边界 |
|---|---|---|
| Analysis／解析文档 | 围绕一个目标片段形成的一份自足讲解，具有独立的文档身份。 | 可以是完整解析、专题讲解或讨论成果整理；不等同于一次模型调用或聊天记录。同一 Segment 可以有多份独立 Analysis，无须为这些讲解另造实体。 |
| AnalysisRevision／解析修订版 | 一份 Analysis 在一个确定时刻的完整内容。 | 生成后保留不变；对已有文档的修改产生同一 Analysis 下的新修订版。 |
| Section／讲解块 | 文档中可以单独定位、引用和编辑的部分。 | 当前主要按 Markdown 二级标题切分，不要求与知识点一一对应。 |
| Learning Object（LO）／学习对象 | 当前对二级标题讲解块使用的展示称呼。 | 不承诺是最小知识单元，不直接等于 Occurrence 或复习卡片；Section 是对应的文档结构术语。 |
| Preamble／前置内容 | 第一个二级标题之前的内容。 | 按位置定义；不强制承担翻译、总览等固定教学功能。 |
| Normalization／解析文档规范化 | 按规则识别块边界，建立结构与定位信息的过程。 | 保留原文；不负责纠错、补讲或提取知识点。 |

### 3.1 重新解析与修订

- 新建讲解：为目标 Segment 创建一份 Analysis 及其初始修订版；完整解析、专题讲解和讨论整理均可采用此身份。
- 重新解析：为同一 Segment 创建另一份独立 Analysis 及其初始修订版，原文档保留。对已有讲解再次整理条目的行为见 PRD F5，不因新建讲解而自动清理旧候选或迁移其出处。
- 修改已有讲解：在明确选定的 Analysis 内产生新修订版，历史修订不被覆盖。
- 纯问答不保存讲解时，不产生 Analysis 或文档修订。

判断依据是操作作用于「新文档」还是「已有文档」，不是改动字数。对已有文档的全量替换，在概念上也可以形成修订。工作台 Agent 在同一对话中应能新建讲解、修改已有讲解及生成、修改待整理候选；用户在界面中决定是否收录。这不是按对话长短或新建／修订二选一的能力分配。首轮提供创建／删除 Analysis 的业务接口及 Agent 创建工具；整份 Analysis 删除只经用户界面执行，暂不开放 Agent 工具。块级编辑工具是首轮基本能力，快捷入口的呈现待闭环打磨。

```text
同一 Segment
├── Analysis A（首次解析）
│   ├── Revision A1
│   └── Revision A2（修改 A1）
└── Analysis B（重新解析）
    └── Revision B1
```

### 3.2 块身份与历史引用

- 讲解块的持久身份与展示编号分开；编号可随排列变化。
- 块级修改可以延续同一块的身份，但其在不同修订版中的内容分别保留。
- Occurrence 引用具体修订版及其中的块，不能因文档更新而静默转向最新内容。
- Analysis 的默认展示选择，以及选定文档与修订的交互，尚未在此决定。

块级更新可改标题、正文或同时替换该块；未提供的字段保持原值。插入可指定某块之后，也可插入正文开头；删除块只从新修订中移除。三类修改成功后都生成新的完整修订版，历史修订和指向它们的引用保持不变。Preamble 可修改或清空，不强行赋予普通标题。多份 Analysis 并存时，写入必须明确定位文档、基础修订和目标块，并校验它们与当前 Segment 的归属及基础修订是否仍为当前版本；具体工具签名由架构契约确定。

已确认的引用规则：全量替换若没有显式的块身份映射，为新块分配新身份，旧引用继续指向旧修订；不按标题或位置自动假定新旧块相同。重新解析产生的独立文档也不自动继承另一份文档的块身份。是否提供全量替换工具及其具体实现仍留待编辑功能阶段决定。

### 3.3 讨论与讲解保存

- 可以直接围绕 Segment 开始短问答或持续讨论，无需先生成完整解析。同一线程可继续打磨讲解和生成、修改待整理候选，不永久绑定唯一一份文档。首轮 Agent 读取当前 Segment 内已有的持久讲解和条目、必要的 Source 元信息、本线程历史及用户背景偏好；其他线程留下的持久讲解可共享，但不检索其聊天历史，也不跨 Segment 检索。用户界面的跨片段积累库不受此限制。
- 聊天记录保留讨论过程。需要重读的讨论成果应整理成独立、自足的 Analysis 讲解，再按具体 Revision／Section 关联 Occurrence；不要求用户重读低密度聊天来学习。
- 保存讲解、生成待整理候选与用户收录学习点是不同能力。首轮提供 Agent 读取已有条目、创建单条或多条 `pending` 候选、按审核规则修改 `pending` 的基本工具；暂缓手动创建 Occurrence。快捷完整解析和独立批量提取按钮保留为候选入口，待基本闭环打磨后决定呈现方式，不作为开工前提；以后按高频组合补充快捷工具，不预建通用组合框架。
- 若提供「生成完整解析」快捷入口，其意图包含生成和保存自足讲解，结果应是可独立打开的 Analysis，不能仅留下长聊天回复；用户可在同一线程继续讨论、修改讲解及待整理候选，并在界面中收录。
- 自然语言指令可表达保存或修改讲解、生成或修改待整理候选的任务意图；是否还需逐次审核由该线程的权限模式与具体操作决定。普通问答不自动产生讲解或候选。组合操作保留已独立保存的成果并逐项反馈，见 PRD F8，继续执行的幂等与预算协调仍待细化。

### 3.4 参考对象、修改目标与工具审核

- **参考对象**是回答或拟定方案时读取的原文、讲解或条目；**修改目标**是本次写入实际作用的已有对象。选中或引用某对象可帮助理解指代，本身不自动授权修改它。
- 明确指名的修改目标优先；上下文中唯一选中的对象可帮助解释「这一节」等指代；持续打磨同一讲解的任务可以沿用已确定目标。出现多个合理目标而无法判断时再澄清。线程可在不同任务间更换目标。
- 每个对话有清楚可见、可选择的**审核模式**或 **Full access**，并可为新对话设置默认模式。产品初始默认为审核模式；改变新线程默认值不自动改变已有线程。仅在线程空闲时可切换该线程模式，运行中或待审核时不可切换，也不会自动放行挂起方案。
- 审核模式下，读取和检索可直接进行；明确要求新建讲解时可直接保存。Agent 创建条目一律为 `pending`，单条与批量创建候选默认无需审核。修改已有讲解、修改已有待整理候选内容，以及使用已开放的删除工具时，应先展示确定目标、基础版本及具体变更或影响范围供审核；混合工具不能以生成候选为由绕过修改审核。普通候选工具不能暗中修改讲解或已有收录条目。
- 首轮不提供 Agent 收录、设为仅参考或退回待整理的状态工具，也不能直接创建 `learning`／`reference` 条目，或通过先创建候选再改变状态来代替用户整理。用户从界面收录后为 `learning`，无需再次结算；Full access 仅省去已开放工具的逐次审批，不扩大工具范围。
- 审核方案只应用展示并获同意的版本；拒绝不写入。同意或拒绝时都可附加新指令：同意后须先成功保存获批方案，再处理新指令；拒绝保留原内容，并按新指令重新准备。批准本身不等于保存成功，新指令不能静默改变已批准内容。
- 待审核方案可持久等待，离开页面不代表同意或拒绝；依赖该写入的操作等待实际保存成功。若基础版本已被其他操作改变，旧方案不能照旧获批并覆盖新内容，应基于当前版本重新准备审核。候选内容编辑工具仅作用于当前仍为 `pending` 的条目；若待审期间用户已将其收录、设为仅参考或删除，执行时须重新核对，旧方案不能继续应用，也不能自动改回 `pending`。获批的候选内容修改成功后仍为 `pending`，批准不表示收录。
- Full access 省去已开放工具的逐次审批，但不扩大工具集或任务意图，不跳过定位与引用校验、不可变修订、历史出处及目标冲突检查。普通问答在两种模式下都不自动修改内容。
- 用户界面删除整份 Analysis 前，展示关联的全部 Revision／Section 及引用条目（含 `learning`／`reference`），并由用户确认；该 Segment 下的对话仍保留，旧指向显示已删除。首轮不开放 Agent 删除整份 Analysis 工具。Source／Segment 的界面删除仍按已确认范围展示影响并确认；线程权限模式仅管理已开放的 Agent 工具。
- 用户可停止正在运行的一轮；停止不撤销已保存成果，不再启动后续生成、修复或工具，未执行的待审方案取消。已提交操作按实际保存结果反馈，残缺消息标为中断，不能冒充成功讲解。同线程运行或待审期间不可发起新轮，输入可保留为草稿但不排队；审核反馈中的附加指令属于当前轮，待审须经同意、拒绝或停止才能继续。其他线程不因此阻塞。首轮暂缓编辑历史消息和任意分支。

## 4. 知识表示与提取边界（已对齐）

| 术语 | 定义 | 边界 |
|---|---|---|
| KnowledgePoint／知识点 | 可以单独识别、讨论和积累的语言知识对象，如某个词的用法、语法结构或固定表达。 | 不要求是语言学上的最小单位，不等于复习卡片；不预先规定必须以视图或独立实体实现。 |
| Occurrence／知识点出现记录 | 对某个知识点在目标片段中一次具体体现的记录，包含原文定位、语境解释和具体 AnalysisRevision／Section 出处。 | 承载可能出错的提取判断；收录不表示掌握，也不等于复习卡片。MVP 可保存实例记录而暂不确定跨片段的知识点归属。 |
| Surface／原文形式 | 实例在目标原文中实际呈现的文字。 | 与抽象句型或词典形式不同；可以由不连续的原文部分组成。 |
| Span／原文位置 | 原文形式在目标片段中的具体位置。 | 可以是一段或多段；相同文字在不同位置可以有不同定位。 |
| Anchor／检索锚点 | 为检索、召回和分组提供的简短表示。 | 允许多个；相同 anchor 不证明知识点相同。具体书写规则仍待确定。 |
| Gloss／语境简释 | 对当前 Occurrence 的意义或作用的简短说明。 | 服务于列表浏览，不替代完整解析，不自动成为通用定义。 |
| Tag／标签 | 从受控维度描述条目的分类标记。 | AI 只能从预先确定的枚举中多选或不选，不能自由创造标签；当前词表见下文。 |

已确认的边界：

1. 收录学习点以已有的自足讲解为依据，原文用于定位和核对；不从未整理的聊天话语直接拼出低密度学习内容，也不自行补充来源讲解未涉及的新知识。讲解可以来自完整解析、专题讲解或讨论整理，不要求固定的独立 AI 提取阶段。
2. 一条 Occurrence 表达一个用户能够单独作出收录决定的学习点。不追求机械地切到最小；Span 相同不足以判定记录重复。
3. Occurrence 同时回到目标原文和具体解析修订中的讲解块；与 Section 不要求一一对应。
4. MVP 暂缓管理跨片段的 KnowledgePoint 归属，但保留该概念。按 anchor 分组只是浏览方式，不是同一性裁决。
5. 不同讲解对同一原文位置的 Occurrence 分别保留各自来源，不自动合并。这类记录的数量不能直接当成原文中的出现次数。
6. 再次整理已有讲解时，先读取相关已有条目，再补充遗漏的待整理候选，或对已有待整理候选提出明确的内容及出处修改；修改仍按线程权限审核。已有 `learning`／`reference` 条目仅供参考，Agent 不修改。旧候选不会自动失效，不整批替换、自动合并、迁移整理状态或让出处跟随新修订漂移。不能仅凭相同 anchor 或原文位置合并，也不承诺完美识别语义重复。用户明确要求重做时，可按既有删除规则清理选定候选后再生成；普通再次整理不包含清理。具体行为见 PRD F5；用户合并与跨片段实例归属管理仍待后续讨论。
7. 若由 AI 批量提取，采用明确、可校验、带版本的契约。受控枚举、字段结构和语义填写规则须事先定义；允许以后升级，但不能由模型在单次输出中自行扩展。首轮 Agent 创建候选须满足相同的出处与定位约束；手动创建 Occurrence 暂缓。

具体 Occurrence schema、类型判定边界、重复文字定位方式及按类型区分的 anchor 规则仍待细化。

### 4.1 当前类型与标签词表（已对齐）

`kind` 单选以下类型，不允许自由添加：

| 值 | 含义 |
|---|---|
| `lexis` | 词汇及其当前用法 |
| `grammar` | 语法形式、组合关系或句法功能 |
| `expression` | 作为整体学习的表达 |
| `other` | 当前类型未覆盖的学习点 |

当前不单列语音类型。类型之间的具体判定规则仍需通过实例细化。

`tags` 从以下词表多选或不选，不重复，不接受词表外值：

| 值 | 选择依据 |
|---|---|
| `conjugation` | 被引用的解析明确讲解活用或形式变化 |
| `omission` | 被引用的解析明确讲解省略及其理解 |
| `contrast` | 被引用的解析明确比较不同表达、形式或用法 |
| `register` | 被引用的解析明确讲解正式程度、礼貌程度或使用场合 |
| `pronunciation` | 被引用的解析明确讲解读音、音变或听辨现象 |

标签描述当前学习点的讲解关注点，不依据素材来源、词性等信息自动推断。词表可随提取契约版本迭代。

### 4.2 Surface 范围与 anchor 方向（已对齐）

- Surface 选择「足以呈现本条用法的尽量短的原文」，不一律取单词或整句。具体形式化规则与正反例留待实践完善。
- Anchor 按 Occurrence 类型制定不同的形式化规则；具体规则仍为后续讨论内容。

### 4.3 条目整理与删除（已对齐）

| 整理状态 | 用户意图 |
|---|---|
| 待整理（`pending`） | 已留下候选，尚未决定如何处理；不要求清空 |
| 已收录（`learning`） | 留下作为后续学习内容；不表示掌握，不自动启动排期或练习 |
| 仅参考（`reference`） | 留下供用户主动查找和阅读，默认不参与后续学习活动 |

三种整理状态可相互调整。当前尚未实现学习活动，已收录与仅参考仍保留不同意图，不仅是暂时的筛选条件；具体活动如何使用状态在设计该活动时确定。

删除表达不再需要保留该记录，例如错误、重复或试验产物；它不是另一种可逆整理状态。首轮不提供独立忽略、归档、回收站或恢复入口；删除 Occurrence 不删除原文和讲解，已删除内容不进入日常浏览。以状态变更软删除是存储约束，不等于向用户提供一个可找回的隐藏选项。

用户通过界面直接收录、设为仅参考或退回待整理，无须 Agent 审批；首轮 Agent 不改变这三种整理状态。界面优先使用具体整理动作，不要求用户完成不可逆的「结算」。删除不隐含对某知识点永久拒绝再次建议；再次整理不能恢复已删除记录。新修订若纠正旧解释，Agent 可提示受影响条目，但旧条目出处不自动漂移；用户须自行将 `learning`／`reference` 条目退回 `pending`，Agent 才可按权限提出修改。再次整理无新学习点可以正常完成，不要求用户管理提取批次。部分失败时保留已独立保存的成果，并区分已保存、未保存和需核实的结果，见 PRD F8。

## 5. 阅读、再理解与主动学习（阅读基线已确认）

依据：用户亲自体验 [reading-experiment](../references/occurrence_anchor_pilot/reading-experiment/README.md) 后，确认直接渲染原 Section 的 Markdown 已能作为「阅读与再理解」的基线；已知体验问题是部分内容略长。

### 5.1 阅读基线

- Occurrence 的标题、简释、anchor 和标签用于索引、定位与浏览提示，不以这些短字段替代学习内容。
- 阅读条目时，展示目标原文、对应的 Surface，以及具体 AnalysisRevision 中被引用的 Section 的 Markdown 讲解。讲解在当前页面可见，并保留返回完整解析的入口。
- 多个来源 Section 保留各自身份和原有顺序；其推导、对比、例子与限定条件继续作为学习内容的一部分。
- 先前的提取与 anchor 实验保留，可供今后的检索、归属和聚类研究复用；阅读方向调整不否定这些索引工作的价值。
- 内容偏长是后续呈现体验问题，目前不据此要求自动摘要、删除内容或重新生成已有讲解。

### 5.2 JSON 与主动学习的边界

- 当前阅读基线不依赖独立持久化的 JSON 文档树，也不要求新增一次 LLM 语义转写。实验保留，但尚未确定其生产用途。
- Markdown 结构解析与为主动学习提取「问题、答案、例句、对比」等语义内容是不同任务；前者的成功不证明后者已解决。
- 无论后续使用固定规则还是 LLM，都应从具体主动学习／复习交互的需要出发，再设计字段与提取契约；不预先把 JSON 树或 Occurrence 当成复习卡片。
- 本次验收确认的是小样本阅读体验可用，不是长期记忆效果、SRS 效果或掌握度的验证。主动学习方式及其数据需求仍待讨论，当前不扩大 MVP 范围。

## 6. 产品演进与第一轮实现

用户希望未来向可定制学习形式、提供原生学习组件的 ITS 演进，以兼容不适合卡片的内容。卡片式 SRS 是可能采用的形式之一，不作为所有主动学习的统一模型。

已确认以 Segment 为共同起点，支持讨论、保存自足讲解、收录可追溯学习点的产品方向。首轮基本能力已确认，快捷按钮的呈现待基本闭环打磨，交付顺序仍待编排；后续教学形式不要求在首轮之前定完，也不提前把 Occurrence、JSON 文档树或 ReviewItem 当成通用学习活动的既定载体。阶段性实施基线见 [MVP_IMPLEMENTATION_BASELINE.md](handovers/MVP_IMPLEMENTATION_BASELINE.md)。
