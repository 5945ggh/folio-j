# 领域术语与讨论记录

> 更新：2026-10-03，补充素材与材料的已对齐含义。本表维护定义、身份、归属与引用边界，操作流程引用 PRD；未讨论的概念不在这里预先定型。
> 「已对齐」记录已确认的含义；「提案」保留待讨论的定义。术语不等于数据库表，也不自动增加 MVP 功能。

## 1. 来源、片段与语境（已对齐）

片段学习的既有方向：**创建来源记录 → 添加片段 → 围绕片段讨论、保存讲解并积累学习点。** Segment 是这类活动的共同起点；工作台只是承载操作的界面，不决定讲解或讨论内容的归属。新增的阅读对话与原文引用方向见[原生阅读方向讨论稿](handovers/epub-reading/DIRECTION.md)，不要求每次阅读提问先创建 Segment。

「来源目录」是以 Source 组织片段的功能区域，不等同于应用首页；当前根入口暂时跳转至来源目录。已实现入口由用户手动录入；当前 EPUB 阶段增加托管素材与阅读入口，按 [PRD 4.7](PRD.md#47-当前-epub-阶段安排)分切片实施。

| 术语 | 定义 | 边界与例子 |
|---|---|---|
| Source／来源记录（界面简称「来源」） | 系统中表达用户声明的来源范围的记录，不与单个文件或素材一一对应。 | 如一部作品及其多卷内容，或动画某一集。可以只有标题和备注，不要求系统持有完整内容，也不要求自动核实归属。 |
| Segment／学习片段 | 本次学习、讲解或讨论所针对的目标文本。 | 可以是半句、一句或多句；首轮由用户手动录入，归属于来源记录。无需先有完整解析才可讨论。 |
| Context／语境内容 | 帮助理解目标片段、但不属于本次解析范围的附带内容。 | 如前文、后文；提供理解线索不代表它们也成为本次逐项解析或提取的对象。使用「语境内容」以免与下文的「材料」混淆。 |
| SourceRef／出处信息 | 当前为片段上的可选自由文本，记录用户声明的具体出处。 | 如页码、集数与时间戳；不等于未来素材的外键或自动定位。它与描述来源范围的 Source 不同。 |
| Collection／学习集合 | 用户按学习目的组织的一组学习内容。 | 如「容易听错的日常表达」。保留概念，当前 MVP 不引入；不作为 Source 的同义词。 |

补充边界：

- 手动录入与未来从素材选取是不同入口，汇合到 Segment 的学习流程；手动录入不需要虚构 TXT 素材实体。
- 同一 Source 可容纳不同入口取得的片段；具体卷次、版本与位置可由各片段的出处信息描述。EPUB 材料归属 Source，不据此建立通用素材库或文件层级系统。
- 手动提供的目标原文与前后文是学习输入，须区分目标范围与用户疑问、听写等附带信息；不把整份提交内容当作系统保存的素材实体。
- 系统无须自动核实出处，仍可记录用户声明的来源关系。
- 同一来源下的片段不一定在原作中相邻；录入顺序不等于原作顺序。不能仅凭「此前添加的两条」就把它们当成原文前文。
- 作品、卷、集、文件之间的层级尚未确定；这里不预设素材库模型。

Segment 的目标原文在尚未被 AI 任务使用时可编辑；首次引用它的 AI 任务被系统接受后固定。来源与管理信息的维护不回写历史调用输入。编辑与级联删除的产品行为以 PRD 的 F2 节为准。

## 2. 素材与材料

**含义与主要方向已对齐，实施契约按切片收口。** 素材是用户提供的原始输入，可来自 EPUB、TXT、字幕及音视频配套资源。素材本身保持不可变。本阶段按[主要设计方案](handovers/epub-reading/MATERIAL_BASELINE.md)托管 EPUB 副本；当前具体实现采用数据库内原始字节，其他素材类型仍未接入。不限定长期一个文件对应一份素材。

材料是素材经过应用处理后，可由应用利用的形态。它可以保留原始内容及呈现资源，并组织阅读、选取、语境获取和定位所需的处理结果；不要求改写素材或统一变为纯文本。Source 继续表达来源范围，Segment 继续表达选定的学习目标。

素材到材料的可逆映射已明确不作为要求。原始输入身份、应用可利用的处理结果，以及受支持引用到阅读位置的可靠定位分别确定；不要求材料能够逆向还原原始文件。具体保证见主要设计方案，不据此引入完整 Unicode 自实现或通用恢复机制。

材料在当前代码中称 `Material`，属于一个 Source；原始字节、材料身份、不可变处理版本、版本内原始 spine 资源分别表达。引用绑定版本与资源的码点范围和原文快照，显示布局与分词不决定位置身份。阅读章按目录组织有序资源范围，原目录章名不承担位置身份。`source_ref` 当前仍是自由文本出处，不等同于可执行位置引用。材料随 Source 删除不可见，托管字节暂不物理清理，首轮无独立材料移除；具体存储见[切片 1 契约](handovers/epub-reading/SLICE_1_DRAFT.md)。原文引用与阅读对话继续按 [PRD 4.7](PRD.md#47-当前-epub-阶段安排)后续切片实施。

## 3. 解析文档（已对齐）

| 术语 | 定义 | 边界 |
|---|---|---|
| Analysis／解析文档 | 围绕一个目标片段形成的一份自足讲解，具有独立的文档身份。 | 可以是完整解析、专题讲解或讨论成果整理；不等同于一次模型调用或聊天记录。同一 Segment 可以有多份独立 Analysis，无须为这些讲解另造实体。 |
| AnalysisRevision／解析修订版 | 一份 Analysis 在一个确定时刻的完整内容。 | 生成后保留不变；对已有文档的修改产生同一 Analysis 下的新修订版。 |
| Section／讲解块 | 文档中可以单独定位、引用和编辑的部分。 | 当前主要按 Markdown 二级标题切分，不要求与知识点一一对应。 |
| Learning Object（LO）／学习对象 | 当前对二级标题讲解块使用的展示称呼。 | 不承诺是最小知识单元，不直接等于 Occurrence 或复习卡片；Section 是对应的文档结构术语。 |
| Preamble／前置内容 | 第一个二级标题之前的内容。 | 按位置定义；不强制承担翻译、总览等固定教学功能。 |
| Normalization／解析文档规范化 | 按规则识别块边界，建立结构与定位信息的过程。 | 保留原文；不负责纠错、补讲或提取知识点。 |

### 3.1 重新解析与修订

- 新建讲解：为目标 Segment 创建一份 Analysis 及其初始修订版；完整解析、专题讲解和讨论整理均可采用此身份。
- 重新解析：为同一 Segment 创建另一份独立 Analysis 及其初始修订版，原文档保留。对已有讲解再次整理条目的行为见 PRD F5，不因新建讲解而自动清理旧候选或迁移其出处。
- 修改已有讲解：在明确选定的 Analysis 内产生新修订版，历史修订不被覆盖。
- 纯问答不保存讲解时，不产生 Analysis 或文档修订。

判断依据是操作作用于「新文档」还是「已有文档」，不是改动字数。对已有文档的全量替换，在概念上也可以形成修订。生成与编辑行为见 [PRD F3](PRD.md#f3-解析)，同线程的能力边界见 [PRD F7](PRD.md#f7-片段讨论与成果整理)。

```text
同一 Segment
├── Analysis A（首次解析）
│   ├── Revision A1
│   └── Revision A2（修改 A1）
└── Analysis B（重新解析）
    └── Revision B1
```

### 3.2 块身份与历史引用

- 讲解块的持久身份与展示编号分开；编号可随排列变化。
- 块级修改可以延续同一块的身份，但其在不同修订版中的内容分别保留。
- Occurrence 引用具体修订版及其中的块，不能因文档更新而静默转向最新内容。
- Analysis 的阅读选择与文档／修订定位见[阅读与导航](INFORMATION_ARCHITECTURE.md)，不由本表规定交互。

块级编辑和 Preamble 编辑的产品行为、文档／基础修订／块的归属与版本校验见 [PRD F3](PRD.md#f3-解析)，具体工具签名由架构契约确定。

已确认的引用规则：全量替换若没有显式的块身份映射，为新块分配新身份，旧引用继续指向旧修订；不按标题或位置自动假定新旧块相同。重新解析产生的独立文档也不自动继承另一份文档的块身份。是否提供全量替换工具及其具体实现仍留待编辑功能阶段决定。

### 3.3 讨论与讲解保存

- ChatThread／讨论线程保留围绕 Segment 的讨论过程；同一线程不永久绑定唯一 Analysis。
- Analysis 保存可脱离聊天独立阅读的自足讲解；Occurrence 再关联其具体 Revision／Section。短专题也可具有独立讲解身份，不要求扩写为完整报告。
- 保存讲解、生成待整理候选与用户收录学习点是不同能力；普通问答本身不产生讲解或候选。

讨论入口、共享资料范围与目标判定见 [PRD 4.5](PRD.md#45-讨论共享资料与成果保存) 和 [F7](PRD.md#f7-片段讨论与成果整理)；明确生成并自动保存的行为见 [PRD 6.3](PRD.md#63-形成并阅读讲解) 和 [F3](PRD.md#f3-解析)。候选创建与整理见 [F5](PRD.md#f5-学习条目创建与整理)，部分成功与反馈修复见 [F8](PRD.md#f8-状态与诊断)。

### 3.4 参考对象、修改目标与工具审核

- **参考对象**是回答或拟定方案时读取的原文、讲解或条目；**修改目标**是本次写入实际作用的已有对象。选中或引用某对象可帮助理解指代，本身不自动授权修改它。
- **审核模式**要求适用的已有内容修改先展示具体方案，获批后执行；**Full access**省去已开放工具的逐次审批，不扩大工具集合或任务意图。批准不等于实际保存成功。
- **待审核方案**是尚未应用的拟议变更，不是正式讲解或条目；**停止**结束本轮后续执行，不撤销已经保存的成果。

参考对象与修改目标的判定见 [PRD F7](PRD.md#f7-片段讨论与成果整理)；模式默认值、切换、操作分类、具体方案、用户反馈与过时目标处理见 [F9](PRD.md#f9-agent-工具权限与审核)。主动停止、同线程串行与离开页面后的处理见 [PRD 6.6](PRD.md#66-异步操作与离开页面) 和 [F7](PRD.md#f7-片段讨论与成果整理)；保存结果与修复见 [F8](PRD.md#f8-状态与诊断)。整份 Analysis 及 Source／Segment 的删除范围与确认行为见 [F2](PRD.md#f2-source-与片段)。

## 4. 知识表示与提取边界（已对齐）

| 术语 | 定义 | 边界 |
|---|---|---|
| KnowledgePoint／知识点 | 可以单独识别、讨论和积累的语言知识对象，如某个词的用法、语法结构或固定表达。 | 不要求是语言学上的最小单位，不等于复习卡片；不预先规定必须以视图或独立实体实现。 |
| Occurrence／知识点出现记录 | 对某个知识点在目标片段中一次具体体现的记录，包含原文定位、语境解释和具体 AnalysisRevision／Section 出处。 | 承载可能出错的提取判断；收录不表示掌握，也不等于复习卡片。MVP 可保存实例记录而暂不确定跨片段的知识点归属。 |
| Surface／原文形式 | 实例在目标原文中实际呈现的文字。 | 与抽象句型或词典形式不同；可以由不连续的原文部分组成。 |
| Span／原文位置 | 原文形式在目标片段中的具体位置。 | 可以是一段或多段；相同文字在不同位置可以有不同定位。 |
| Anchor／检索锚点 | 为检索、召回和分组提供的简短表示。 | 允许多个；相同 anchor 不证明知识点相同。具体书写规则仍待确定。 |
| Gloss／语境简释 | 对当前 Occurrence 的意义或作用的简短说明。 | 服务于列表浏览，不替代完整解析，不自动成为通用定义。 |
| Tag／标签 | 从受控维度描述条目的分类标记。 | AI 只能从预先确定的枚举中多选或不选，不能自由创造标签；当前词表见下文。 |

已确认的边界：

1. 收录学习点以已有的自足讲解为依据，原文用于定位和核对；不从未整理的聊天话语直接拼出低密度学习内容，也不自行补充来源讲解未涉及的新知识。讲解可以来自完整解析、专题讲解或讨论整理，不要求固定的独立 AI 提取阶段。
2. 一条 Occurrence 表达一个用户能够单独作出收录决定的学习点。不追求机械地切到最小；Span 相同不足以判定记录重复。
3. Occurrence 同时回到目标原文和具体解析修订中的讲解块；与 Section 不要求一一对应。
4. MVP 暂缓管理跨片段的 KnowledgePoint 归属，但保留该概念。按 anchor 分组只是浏览方式，不是同一性裁决。
5. 不同讲解对同一原文位置的 Occurrence 分别保留各自来源，不自动合并。这类记录的数量不能直接当成原文中的出现次数。
6. 再次整理不改变已有记录身份或用户整理决定，旧条目出处不随新修订漂移；相同 anchor 或原文位置不足以判定重复。具体读取、补充、修改与明确重做行为见 [PRD F5「再次整理已有讲解」](PRD.md#再次整理已有讲解)；用户合并与跨片段实例归属管理仍待后续讨论。
7. 若由 AI 批量提取，采用明确、可校验、带版本的契约。受控枚举、字段结构和语义填写规则须事先定义；允许以后升级，但不能由模型在单次输出中自行扩展。首轮 Agent 创建候选须满足相同的出处与定位约束；手动创建 Occurrence 暂缓。

具体 Occurrence schema、类型判定边界、重复文字定位方式及按类型区分的 anchor 规则仍待细化。

### 4.1 当前类型与标签词表（已对齐）

`kind` 单选以下类型，不允许自由添加：

| 值 | 含义 |
|---|---|
| `lexis` | 词汇及其当前用法 |
| `grammar` | 语法形式、组合关系或句法功能 |
| `expression` | 作为整体学习的表达 |
| `other` | 当前类型未覆盖的学习点 |

当前不单列语音类型。类型之间的具体判定规则仍需通过实例细化。

`tags` 从以下词表多选或不选，不重复，不接受词表外值：

| 值 | 选择依据 |
|---|---|
| `conjugation` | 被引用的解析明确讲解活用或形式变化 |
| `omission` | 被引用的解析明确讲解省略及其理解 |
| `contrast` | 被引用的解析明确比较不同表达、形式或用法 |
| `register` | 被引用的解析明确讲解正式程度、礼貌程度或使用场合 |
| `pronunciation` | 被引用的解析明确讲解读音、音变或听辨现象 |

标签描述当前学习点的讲解关注点，不依据素材来源、词性等信息自动推断。词表可随提取契约版本迭代。

### 4.2 Surface 范围与 anchor 方向（已对齐）

- Surface 选择「足以呈现本条用法的尽量短的原文」，不一律取单词或整句。具体形式化规则与正反例留待实践完善。
- Anchor 按 Occurrence 类型制定不同的形式化规则；具体规则仍为后续讨论内容。

### 4.3 条目整理与删除（已对齐）

| 整理状态 | 用户意图 |
|---|---|
| 待整理（`pending`） | 已留下候选，尚未决定如何处理；不要求清空 |
| 已收录（`learning`） | 留下作为后续学习内容；不表示掌握，不自动启动排期或练习 |
| 仅参考（`reference`） | 留下供用户主动查找和阅读，默认不参与后续学习活动 |

三种整理状态可相互调整。当前尚未实现学习活动，已收录与仅参考仍保留不同意图，不仅是暂时的筛选条件；具体活动如何使用状态在设计该活动时确定。

删除表达不再需要保留该记录，例如错误、重复或试验产物；它不是另一种可逆整理状态。首轮不提供独立忽略、归档、回收站或恢复入口；删除 Occurrence 不删除原文和讲解，已删除内容不进入日常浏览。以状态变更软删除是存储约束，不等于向用户提供一个可找回的隐藏选项。

删除不隐含对某知识点永久拒绝再次建议，也不由再次整理恢复已删除记录。用户整理、候选修改和再次整理的行为见 [PRD F5](PRD.md#f5-学习条目创建与整理)，部分成功与反馈修复见 [F8](PRD.md#f8-状态与诊断)。

## 5. 阅读、再理解与主动学习（阅读基线已确认）

依据：用户亲自体验 [reading-experiment](../references/occurrence_anchor_pilot/reading-experiment/README.md) 后，确认直接渲染原 Section 的 Markdown 已能作为「阅读与再理解」的基线；已知体验问题是部分内容略长。

### 5.1 阅读基线

- Occurrence 的标题、简释、anchor 和标签用于索引、定位与浏览提示，不以这些短字段替代学习内容。
- 阅读条目时，展示目标原文、对应的 Surface，以及具体 AnalysisRevision 中被引用的 Section 的 Markdown 讲解。讲解在当前页面可见，并保留返回完整解析的入口。
- 多个来源 Section 保留各自身份和原有顺序；其推导、对比、例子与限定条件继续作为学习内容的一部分。
- 先前的提取与 anchor 实验保留，可供今后的检索、归属和聚类研究复用；阅读方向调整不否定这些索引工作的价值。
- 内容偏长是后续呈现体验问题，目前不据此要求自动摘要、删除内容或重新生成已有讲解。

### 5.2 JSON 与主动学习的边界

- 当前阅读基线不依赖独立持久化的 JSON 文档树，也不要求新增一次 LLM 语义转写。实验保留，但尚未确定其生产用途。
- Markdown 结构解析与为主动学习提取「问题、答案、例句、对比」等语义内容是不同任务；前者的成功不证明后者已解决。
- 无论后续使用固定规则还是 LLM，都应从具体主动学习／复习交互的需要出发，再设计字段与提取契约；不预先把 JSON 树或 Occurrence 当成复习卡片。
- 本次验收确认的是小样本阅读体验可用，不是长期记忆效果、SRS 效果或掌握度的验证。主动学习方式及其数据需求仍待讨论，当前不扩大 MVP 范围。
