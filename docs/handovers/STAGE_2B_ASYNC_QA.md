# 第二阶段 2B：片段后台异步问答

状态：开发准备；本文件确定验收边界与开工前必须落地的技术契约，不表示功能已经实现。长期行为以 [PRD](../PRD.md) F1、F2、F7–F9 为准，领域身份见 [GLOSSARY](../GLOSSARY.md)。

## 目标与范围

用户从已保存的 Segment 发起问答，后台接受并执行，离开、刷新和重开后仍能查看任务与持久历史；支持主动停止，并阻止旧任务迟到结果恢复执行或覆盖新轮。没有 Analysis 也能提问。普通问答只保存讨论与 Run，不自动创建讲解或 Occurrence。

2B 包含输入快照、接受任务时原子锁定原文、线程与消息的持久身份、后台任务与调用记录的关系、停止及迟到结果保护。不能继续按旧交接中的“2B 只有上下文、2C 才有历史”拆走本轮所需的持久历史。完整成果写入、Section 编辑、候选工具及混合审核界面留到后续切片，不把文本验证成功当作工具能力已验证。

## 开工前必须落实的契约

以下技术细节须先写入架构和正式 API schema，再实现依赖它们的代码；不能仅靠前端禁用或 prompt 约定。

1. **任务接受事务。** 在同一原子边界内核对 Source／Segment 未删除、线程空闲、模型可用，确定实际输入与模型配置，保存本轮任务／消息并设置 `text_locked_at`。与编辑原文、删除来源／片段并发时必须有确定赢家；失败或停止不解除已接受任务带来的锁定。保存片段、模型预选不锁原文。
2. **输入快照。** 明确保存目标原文、用户提供的前后文、实际使用的 Source 信息、问题、本轮补充要求、学习背景、讲解预设、所需本线程历史，以及实际选入的当前片段持久资料内容与版本／出处（或接受时已确定的不可变版本引用），不要求全量加载全部资料。管理备注是否输入须显式规定。模型按本次选择与线程当前选择解析，接受后固定 Provider／模型身份、协议、参数及凭据引用；修改默认值或凭据不反写已接受输入。不读取其他线程历史或跨片段资料。
3. **线程、轮次、Job 与 Run。** 固定主外键、状态迁移、接受响应和查询端点；区分已接受任务、实际模型调用、持久消息和成功结果。同线程运行中不可重复接受或排队，其他线程独立。定义客户端重试接受请求的幂等键及冲突响应，避免响应丢失或重复点击产生两次调用。新线程复制默认权限，已有线程只在空闲时可切换。
4. **后台执行与观察。** worker 从持久记录领取任务，领取须原子且有执行身份，调用仍经 `llm/`。页面刷新、关闭或多观察者不会重新发起生成。固定轮询或 SSE 的重连／补读协议；若采用 SSE，每个订阅者独立接收，不能用单个消费队列分走事件。持久文本与终态是重新打开时的依据。
5. **停止、删除与迟到结果。** 固定停止意图持久化、执行取消、终态写入、线程释放的顺序及竞争判定。每次进度／最终写入核对任务执行身份、当前状态和对象存在性；旧任务不能覆盖新轮或恢复已删除内容。停止完成才允许新轮，不再启动后续调用；残缺消息明确标为中断，已提交结果按实际保存情况反馈。
6. **失败、重启与预算。** 明确 queued／running 在重启时的处理、不自动重放真实请求、用户重试如何形成新的可追溯尝试。继承 2A 的单次调用、无 SDK 自动重试和凭据脱敏基础；为问答显式确定超时、并发、调用预算和用量语义，不将未来修复循环与底层重试叠加。未知 token 用量保持未知。
7. **迁移与删除。** 从空库可建，增量升级保留来源、片段、设置和历史验证；不改写旧 Run 的文本验证含义。固定 Source／Segment 级联删除与线程、消息、Job、Run 的处置，防止后台恢复已删除学习内容。凭据仍为本机私有文件，不复制进快照或浏览器持久存储。

## 必须取得的验收证据

- 离线验证接受与编辑／删除竞争、同线程双提交、输入与模型快照、凭据更新、旧任务迟到、停止与完成竞争、重启中断、不重复调用、跨线程隔离及两协议普通／流式失败与不完整输出。
- 浏览器验证提交后离开／刷新／重开、持久历史、运行与中断反馈、停止后继续发送、切换模型不改写历史，以及窄屏。夹具与真实接入证据分别记录。
- `just gen-api`、`just check`；生成类型不可手改。测试禁止真实网络和模型。
