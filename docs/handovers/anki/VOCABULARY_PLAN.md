# 手动词汇制卡与 Anki 复习回流（前一轮备选方案）

2026-11-24 · 当前优先评审[阅读器单向导出提案](READER_EXPORT.md)。下文保留前一轮关于本地学习笔记、来源卡组、片段入口和复习回流的整体方案，供将来讨论持久学习记录时参考。下文中的“首期”及验收步骤均属于该备选方案。当前交付状态见[实施基线](../MVP_IMPLEMENTATION_BASELINE.md)。

## 一次制卡和复习

读者读到「水を入れて煮込みながら、ぼんやりと灰汁を取る」，选中「取る」，填入自己这次要记的词义「撇去、除去浮沫」。正面显示词条和带有目标表达的原句，背面首先给出这个义项。即使已有一张用「いい点を取る」记“取得”的笔记，本次仍可单独保存。每份笔记只派生一张词义回忆卡。

读者在 Anki 翻面后自评能否想起所填词义。返回 Folio-J，刷新后可以看到“上次复习 11 月 25 日 · Good”（示例），并找回当时导出的题面和出处。这条结果属于该卡的词义回忆。如正面有原句，原句就是当次设计提供的提示。这个模板的学习目标由产品统一定义，制卡时无需再填“能力”或“任务类型”。本阶段的完成条件到查看这条自评为止。造句、语法辨析、Agent 制卡和自建调度留待有具体练习需求时设计。

## 如何从两个页面制卡

| 入口 | 自动带入 | 读者操作与返回 |
|---|---|---|
| EPUB 阅读器的选区工具栏「制卡」 | 捕获选中的基字原文及其精确材料出处。选中文字预填词条，从同章已校验正文提取所在句，保留词在句中的实际写法。选区覆盖多句时直接使用选区，无法可靠取整句时允许手填例句。 | 在原处打开轻量表单，填写本句义，可改词条和例句。保存后留在原阅读位置，成功反馈提供「查看卡片」。单纯划选或制卡均无需创建 Segment。 |
| 片段详情的原文区「制卡」 | 带入当前 Segment、所属 Source 和片段原文。已划选时预填目标词，否则将词条留给读者。已有确切书籍出处的片段可沿用该出处。 | 使用同一表单。长片段允许摘取其中一句。保存后回到原片段。手动录入的片段即使只有来源和原文也能制卡。 |

两个入口都只要求填写**词条、本句义**。读音、例句、译文和备注按需补充。读者可从即时查词词卡复制或选取单个义项，查询本身仍是临时操作。保存的释义以读者最终确认的文字为准。把「煮込み」改成词典形「煮込む」时，例句仍保留「煮込み」。高亮使用当次可核实的选区。用户改写例句后，无法确认范围就按普通文本展示。原文定位继续指向最初取材的位置。

## 笔记字段、题面与卡背出处

建议新建 Folio-J 自有的 Anki 笔记类型，以本机 Kaishi 的布局为参照。它仅有一个卡片模板。首次发送时按需创建。若 Anki 中同名类型的字段或模板不兼容，保留原类型，提示选择新的 Folio-J 类型名称。

| 字段 | 首期填充和展示 |
|---|---|
| `Word`、`Word Meaning`、`Sentence` | 正面大字显示词条，其下为可选原句。背面首先显示本句义。只有词条和本句义时也能复习。 |
| `Word Reading`、`Sentence Meaning`、`Notes`、`Pos` | 背面按有值的字段显示读音、例句译文、备注和词性。 |
| Kaishi 的其他辅助字段 | 可在 Anki 类型中保留 `Word Furigana`、`Sentence Furigana`、`Katsuyou`、`Word Audio`、`Sentence Audio`、`Picture`、`Pitch Accent`、`Pitch Accent Notes`、`Frequency`。无注音时用普通文本。音高及频率沿用默认隐藏。首期表单以文字为主，音视频采集、上传和生成另行设计。 |
| **`SourceMetadata`** | 一个只读的展示字段。模板把它放在卡背最底部，使用可读的小字号和次要文字色，与答案分开。Anki 离线复习时也能读到。 |
| `FolioId` | Folio-J 自动写入的唯一笔记标识，放在 Anki 类型的第一字段，正反面均不渲染。这样相同词条可保存不同义项，同一笔记重试仍受 Anki 首字段判重保护。 |

**卡背只显示到章节。** 本地出处快照包含 `source_title`（来源标题）、可空的 `material_title`（应用内书名）和 `chapter_title`（确切出处核验所得章名）。Source 就是读者声明的作品或来源范围，一部作品下可有多卷。导出的 `SourceMetadata` 按“来源 · 书名 · 章节”连接已有值，相邻同名去重。百分比、位置码、内部 ID、文件路径和片段的自由文本出处均不拼进卡背。写入 Anki 时转义文字，仅模板负责排版。

| 取材情况 | 卡背底部示例 |
|---|---|
| 来源「桜町日記」，材料「桜町日記 第一卷」，章名「夕食」 | 桜町日記 · 桜町日記 第一卷 · 夕食 |
| 来源和书名同为「桜町日記」，章名「夕食」 | 桜町日記 · 夕食 |
| 手动片段，仅有来源「日语料理随笔」 | 日语料理随笔 |

书名或来源改名后，本地列表仍按身份找到旧卡。卡背保留当时导出的叫法。应用内要回到原处，另用已有的材料版本、资源码点范围和原文快照校验。片段只有整段出处时，返回的是原片段范围。只有能够映射并校验所选词时才定位到词。自由填写的页码或书名不能建立材料关联。[来源与精确出处](../../GLOSSARY.md#21-精确材料出处) · [定位与章名的读取契约](../../ARCHITECTURE.md#精确出处与相邻语境)

## 从哪里看已保存的卡片

建议以**来源空间的「Anki 卡片」**作为主入口，与现有的素材、片段、讲解视图并列。这里列出该来源在 Folio-J 保存的笔记，包括待发送项。可按材料筛选，也可查看没有材料关联的笔记。两个来源碰巧使用同一个 Anki 卡组时，两份来源列表仍各自准确。列表每行显示词条、本句义、简短出处、发送状态和最近自评。点开才看完整内容、历史和可用的原文／片段入口。

**书籍详情增加「本书的 Anki 卡片」**，打开同一个列表并预选该材料，返回时恢复书籍详情。材料目录按真实的 `material_id` 查询，包含阅读器直接制作及从本书片段制作的卡。同来源的其他卷、缺少确切出处的手动片段留在来源视图。阅读器和片段的成功反馈可以直达刚保存的条目。这个安排只需维护一套列表，也保留了现有书籍详情里的「查看词汇」作为全书词频统计入口。[现有目录与详情](../../INFORMATION_ARCHITECTURE.md#素材库与来源空间)

## 来源怎样绑定 Anki 卡组

1. **首次导出。** 表单显示目标配置及默认卡组名，默认值取当前 Source 标题。读者点击「保存并发送」后，在目标 Anki 配置中查找同名普通卡组，已有则连接，缺少则创建并连接。也可在发送前选择另一个已有普通卡组，或输入新卡组名。仅打开表单不修改 Anki。同名来源可共用卡组。名称包含 Anki 分隔符 `::` 时展示将创建的层级。名称非法或命中筛选卡组时，请读者改名或选择普通卡组。
2. **后续导出。** 按“本地 Anki 连接＋Source ID”记住卡组 ID 和最近确认的名称。Source 改名仍使用原绑定。Anki 内改名按卡组 ID 找回新名称。卡组被删除或替换时显示失效，读者重新选择。只有尚未绑定的来源使用首次自动创建规则。
3. **更改目标。** 在来源的卡片列表提供「更改默认卡组」，作用于此后新发起的导出。已发送卡片留在实际卡组，待核对的发送继续对照原目标。在 Anki 中手动移过的卡按实际卡组显示。历史卡片的批量搬迁作为后续独立功能。

AnkiConnect 由同机 Folio-J 后端连接，缺省为回环地址。设置中可检查连接、看到当前 Anki 配置名称，并按需设置 API key，凭据沿用应用现有的私有存储方式。首期一次使用一个明确选择的 Anki 配置。外部 ID 均属于对应集合，Folio-J 为连接建本地身份，记录端点和所选 profile 名。v1 写入可携带当前 session 来识别中途切换。v6 读写前核对活动 profile。端点、同名 profile 和会话重连均不能证明离线期间集合未被替换。用户恢复或更换集合时重新确认绑定。发现已知卡组／笔记标记不符、无法确认写入目标时暂停写入。对同名集合的替换，首期不能保证自动发现。[上游连接与集合语义](https://github.com/FooSoft/anki-connect/blob/d9165b4c563ee01ceb3f7c4daaa034eefaabffc6/API_V1.md#working-with-collections)

## Folio-J 保存什么

以下是拟议的逻辑记录及约束，可据此编写 ORM 和迁移。手动笔记以 Source 为归属，材料和片段负责说明它从哪里来。一条来源、一次原文选区或一个片段都可以产生多份笔记。

| 记录 | 关键字段与用途 |
|---|---|
| 词汇笔记 | 本地 ID（也是 `FolioId`）、`source_id`、可空的 `segment_id` 和 `material_id`、可用的材料版本与精确出处、原选文字、三个标题快照、用户确认的词条／本句义／例句及可选字段、模板标识与版本、保存时间。按来源和材料分页检索。核心内容可独立于 Anki 回看。 |
| Anki 连接和来源卡组绑定 | 连接身份、端点、profile、凭据引用。每个“连接＋来源”最多一个默认普通卡组。保存 deck ID 及最近确认的名称。 |
| 导出记录 | 关联本地笔记和目标连接，冻结此次目标卡组、发出的字段与模板版本。保存发送状态、Note ID、实际派生的 Card ID、最近核实的实际卡组及核对时间。本期每份笔记向一个目标导出一次。一张卡可对应多次复习。 |
| 复习记录 | 连接、外部 review ID、Card ID、回答时间、原始记录类型与评分。以“连接＋review ID”去重，通过已绑定的 Card 找回笔记。列表的最近自评从有效作答派生。Anki 保存自己的到期日和调度状态。 |

阅读器直接取材时 `segment_id` 为空。从片段取材时按真实归属填 `source_id`，有可核实的材料身份才填 `material_id`。复用现有出处值与服务端校验，材料范围和可编辑例句分别存放。手动片段日后改文，已确认的卡片内容仍是当时快照，制卡不增加锁定 Segment 原文的触发条件。这些记录可以回答“针对哪个词义、用什么提示、在哪张卡上怎样自评”，本阶段无需建立知识点、能力评分或 SRS 表。

**实现位置。** 后端 `services/` 集中受理笔记、校验取材归属、选择目标、处理发送结果和读回复习。AnkiConnect 通信集中在独立模块，负责协议、鉴权、会话和错误转换。路由只接收请求和返回结果。两个前端入口共用草稿表单与保存调用，来源／材料入口共用分页查询。建议开放保存并发送、按来源列出（可选材料筛选）、读取详情、重试／核对、刷新复习、设置来源目标这几类操作。手动操作不调用模型，也不产生 LLM Run。实施时附增量数据库迁移，运行 `just gen-api` 更新客户端。[现行技术栈](../../TECH_STACK.md) · [工程约定](../../../AGENTS.md)

## 外部写入、核对与复习回流

**保存和发送分开记账。** 用户提交时先在 SQLite 短事务内用同一请求标识保存笔记和发送意图，提交成功后才调用 Anki。相同请求和内容返回原记录，同键异文提示冲突，有意制作另一条同词笔记才分配新 ID。同一笔记只允许一个在途发送，首次确定来源绑定也按连接和来源串行处理。网络调用不占用数据库写事务。

**离线仍可保存。** 已选目标时冻结连接、预期 profile 和卡组 ID。首次按名称建组则冻结待解析的名称。恢复连接后按这份记录查找或创建。此时该来源尚无绑定才补记默认目标，旧请求不会覆盖读者后来选定的卡组。既有 ID 失效时需重选，不能按旧名自动重建。首次使用且尚未配置连接时只保存本地笔记并标“待选择目标”。两种情况均由读者从列表继续发送，后来的来源改名或默认卡组变更不改写已选目标。只有核实实际生成的卡片后才显示“已发送”。

| 情形 | 处理与界面反馈 |
|---|---|
| 创建成功、回执丢失，或 Anki 成功后 Folio-J 重启 | 发送前已落库的意图保留为待核对。按原连接和 `FolioId` 查找，核验字段与类型，找回 Note ID 和实际 Card ID 后补记。明确尚未创建才用原 ID 再发送。多条命中、字段不符或生成卡数并非一张时提示核对，保留现有外部内容。已建卡组或笔记类型在重试时复用。 |
| Anki 未启动、鉴权失败、配置不符 | 显示具体原因和上次成功核对时间。已缓存的笔记和自评仍可读。连接失败不能推断卡片已删除，也不能据此更换协议重发。 |
| 用户在 Anki 改字段、改模板、移牌组或删卡 | 刷新时按连接、Note ID、`FolioId` 和实际 Card ID 核对。内容／题型变化时标示“与导出时不同”，保留导出快照和可确认的评分。明确找不到目标时标示“Anki 中已缺失”。外部编辑留在 Anki，移动更新最近所见卡组。删除不触发自动重建。历史只能证明导出时的内容，无法还原的复习时题面保持未知。 |
| 更新复习结果 | 详情可刷新此卡，列表可分批刷新当前页已绑定卡片，并展示上次成功读取时间。按 Card ID 读取有效作答，保留 Again／Hard／Good／Easy。手工重排、无评分记录不计入自评。明确存在的卡完整读毕后，才按该卡核对撤销或更正。离线、卡片缺失、分页未完均保留上次成功结果。首次未读取显示“尚未读取”，成功读取为空才显示“暂无复习记录”。 |

本地删除按现有菜单语义扩展，以下为草案建议。删除片段后，独立保存的词汇笔记留在来源下，保留当时原文并关闭片段入口。普通删书保留笔记和历史书名，返回原书时说明材料已删除。重新导入同一 EPUB 不换绑。勾选“同时删除学习积累”时，将该材料精确关联的本地词汇笔记及回流记录计入影响和清理范围。删除来源则清理所属的本地笔记、导出记录、复习记录和卡组绑定。清理沿用现有删除事务，停止后续发送并隔离迟到回执。Anki 已接受的外部写入可能已生效。删除确认明确说明 Anki 中已有的笔记、卡组与历史由读者在 Anki 管理。[现行删除范围](../../PRD.md#删除与清理)

## 手板、实机与验收

| 切片 | 验收动作 |
|---|---|
| **交互手板** | 用模拟 Anki 连接演练两个入口、手填本句义、卡背出处、选择或创建卡组、待发送及回流列表。界面明确标注模拟数据。覆盖同一来源多卷、手动片段只有来源、同词两义、书名与来源同名。让读者检查操作是否打断阅读、能否从来源和书籍详情找回同一张卡。 |
| **真实制卡** | 用独立测试 profile、样本 EPUB 和手动片段贯通真实 Anki Desktop。验证默认创建或复用同名普通卡组、手选目标、一份笔记派生且仅派生一张卡、元信息实际只到章、两种「取る」都能保存。切换 profile、改名／删除目标卡组、模拟丢失回执后重试，核实无错投和重复卡。 |
| **真实回流** | 在测试 profile 对已导出的卡完成正常 Anki 复习。回 Folio-J 刷新，核对 Card、时间及评分。重复刷新不重复计数。验证撤销一次作答、手工重排、移动及删除外部卡、离线时查看上次结果。另验普通删书、含学习积累的删书、删片段／来源的本地效果。 |

首个真机切片先核实该安装提供的能力。上游推荐新集成使用 v1，可用 `api.describe` 探测。只提供 v6 的目标安装用 legacy 动作验证所需子集。v1 创建笔记返回实际生成的卡，v6 `addNote` 后可通过 `notesInfo` 查询。回流对应 v1 `reviews.list` 或 v6 `getReviewsOfCards`。会话发生变化时重新核对集合。自动化测试使用本地替身，实机验收单独记录 Anki 与插件版本、协议和实际结果。手板可以先交付，阶段完成须经过真实制卡和回流两项验收。[固定版本接口参考与本地取用方法](../../../references/anki-connect/README.md)
