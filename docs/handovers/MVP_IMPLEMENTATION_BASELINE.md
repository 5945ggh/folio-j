# 第一轮 MVP 实施基线

> 状态：首轮基本能力已确认；首个切片[来源与片段管理](archived/STAGE_1_SOURCE_SEGMENT.md)已完成，2A／2B均已完成，下一阶段见[2C开工准备](STAGE_2C_ANALYSIS_TOOLS.md)；总体讲解快捷入口随Analysis切片提供。
> 产品范围以 [PRD.md](../PRD.md) 为准，领域含义以 [GLOSSARY.md](../GLOSSARY.md) 为准，技术方案以 [TECH_STACK.md](../TECH_STACK.md) 为准。
> 本文件区分已确认的基本能力与待打磨的呈现方式，不把旧流水线、实验 schema 或架构占位自动升级成定案。

## 1. 目标体验与能力关系

**创建来源记录 → 手动录入目标片段及附带信息 → 围绕 Segment 讨论、保存自足讲解与收录学习点 → 查找并重读原文和具体来源讲解。** 这是能力关系，不规定用户必须走完固定步骤。

Segment 是共同学习起点；工作台是承载这些操作的界面，不决定内容归属。没有完整解析也可以直接讨论。工作台 Agent 支持短问答与持续讨论，并在同一线程中新建讲解、修改已有讲解和生成、修改待整理候选；用户通过界面收录或调整整理状态。不按对话长短划分 Agent 能力，也不把线程永久绑定一份文档。同一 Segment 可保存多份 Analysis，内容可以是完整解析、专题讲解或讨论成果整理；已有讲解的修改产生不可变的新 Revision。学习背景与讲解偏好按 PRD F1 自动带入适用的请求，新入口的具体调用方式随入口契约确定。

保存讲解、生成候选与用户收录学习点是不同能力。首轮 Agent 可读取已有条目、创建单条或多条 `pending` 候选并按审核规则修改 `pending`；用户从界面整理状态，手动创建 Occurrence 暂缓。提供总体讲解快捷入口，复用对话内生成并自动保存Analysis的能力；独立批量提取按钮保留为候选入口。讨论成果整理为自足讲解后再作为 Occurrence 的出处，避免以低密度聊天记录代替可重读内容。标题、gloss、anchor 和标签服务索引，详细推导、对比与例子由被引用的讲解承载。

## 2. 当前范围与后续方向

| 范围 | 已确认边界与首轮取舍 |
|---|---|
| 来源与片段 | Source 来源记录、手动输入 Segment、可选译文／备注／听写／出处等；无须上传或保存素材 |
| 讲解与追溯 | 可保存自足 Markdown 讲解；每次模型调用产生 Run；独立 Analysis、不可变 Revision、可定位 Section；规范化保留原文 |
| 讨论 | 可围绕 Segment 进行短问答或持续讨论，不以前置完整解析为条件；首轮 Agent 读取当前 Segment 的持久讲解与条目、必要的 Source 元信息、本线程历史及用户背景偏好；不检索其他线程聊天历史或跨 Segment 内容，用户界面的跨片段积累库仍可使用 |
| 积累与阅读 | Occurrence 精确关联原文位置与具体 Revision／Section；待整理、已收录、仅参考可相互调整。仅参考默认不参与学习活动，收录不表示掌握；支持查找并在页面内阅读目标原文与来源 Section |
| 设置与诊断 | 单用户画像、解析偏好、本地 provider 配置、必要的调用与失败诊断 |
| 讲解保存、候选生成与用户收录入口 | 提供创建／删除 Analysis 的业务接口，Agent 可创建但首轮不开放整份 Analysis 删除工具；Agent 可读取已有条目、创建单条或多条 `pending`、按审核规则修改 `pending`，用户在界面中整理状态。手动创建 Occurrence 暂缓；总体讲解快捷入口纳入Analysis切片，独立批量提取按钮待闭环打磨 |
| 讨论整理与编辑 | 同一线程支持新建独立讲解、修改指定的已有讲解及生成、修改已有待整理候选。Section 更新、插入、删除成功时生成新 Revision，旧引用不漂移；Preamble 可修改或清空。是否提供全量替换工具待编辑阶段决定，暂缓历史消息编辑与任意分支 |
| Agent 工具权限 | 产品初始默认审核模式，可设置新线程默认模式；线程只在空闲时切换审核模式或 Full access，运行及待审期间不可切换或自动放行。Agent 单条或批量创建待整理候选默认无需审核，修改已有候选需按模式审核，批准后仍待整理。首轮不提供 Agent 整理状态工具；Full access 仅省去已开放工具的逐次审批。混合方案展示待细化 |
| SRS／ReviewItem／ITS／原生学习组件 | 后续范围；先从具体主动学习交互定义需求，不提前建立通用教学引擎或强制采用卡片 payload |
| EPUB／字幕／音视频导入、自动语境选择 | 后续范围；不得恢复已删除的「前两条录入片段就是原文前文」占位 |
| KnowledgePoint 归属、自动聚类与合并 | 后续范围；现有 anchor 实验保留，不宣称已解决知识点同一性 |
| JSON 文档树 | 实验保留，不是当前阅读功能或后续主动学习的既定数据契约 |

自然语言指令可表达保存或修改讲解、生成或修改待整理候选的任务意图；具体写入遵守线程权限模式。普通问答不自动产生讲解或候选。明确要求新建讲解在审核模式下可直接保存，修改已有讲解或待整理候选须先审核具体方案；Full access 省去逐次审批，但不扩大工具集或任务意图，也不能直接创建已收录／仅参考条目或通过候选状态变更实现自动收录。组合操作保留已独立保存的成果，逐项反馈与修复见 PRD F8。快捷工具以后按实际高频组合增加，不预建通用组合框架。

ITS 是产品演进方向，卡片式 SRS 只是可能的学习形式之一。首轮实现须保留可追溯内容与清晰模块边界，不为未来每种活动预建字段、表或插件系统。

## 3. 交付顺序

旧版按「解析 → 独立提取 → 结算 → 阅读 → 追问」排列切片，已经不能表达直接讨论、讨论成果保存、候选生成和用户整理。以下仅保留交付原则与无冲突的验收约束；**不把旧顺序视为已定方案，总体讲解快捷入口已纳入2C，其余快捷入口不预先固定。**

每个实际选定的切片应连通前端、API、持久化与必要检查，交付可体验的行为。依据已确认的 Segment、Analysis、Revision、Section、Occurrence 关系编排切片；具体分批计划尚未确定。讨论不依赖已有解析，保存讲解不依赖先收录学习点，收录也不要求独立 AI 批量提取。

| 能力或约束 | 关键验收方向 |
|---|---|
| 工程入口与片段录入 | 本地启动，Source 与 Segment 重启后仍在；OpenAPI 生成客户端；空库能建立当前 schema，需保留数据或正式发布后维护增量迁移；不含真实密钥 |
| 讲解保存与原文阅读 | Run 可追溯；Revision 不变；Section 可复原；来源讲解可在页面内重读；刷新与失败不把未完成输出冒充成功文档 |
| 讨论与整理 | 可围绕 Segment 开始独立线程，进行短问答或持续打磨；读取范围符合首轮边界并追溯实际来源；新建与修改在同一线程可用；快捷总体讲解与对话内生成均自动保存为Analysis；普通问答无隐式写入 |
| Agent 工具审核 | 审核模式能查看具体目标、版本和变更，同意或拒绝并附加指令；待审核可返回处理，过时方案不覆盖新版本；Full access 对已开放且符合任务的工具省去逐次审批，仍校验引用和修订规则 |
| 停止与轮次 | 可停止一轮且保留实际已保存成果；停止后不再启动生成、修复或工具，未执行待审方案取消，残缺消息标中断；同线程运行或待审时只可保留输入草稿，不能发起或排队新轮，其他线程可继续 |
| 学习点整理与阅读 | 对原文位置及明确 Revision／Section 精确定位；旧出处不漂移；Agent 创建和修改的候选保持 pending，用户从界面收录后为 learning，无需重复结算；阅读保留来源讲解，收录不代表掌握 |
| 再次整理与部分失败 | 先读已有条目，补遗漏或提出待整理候选的明确修改；已收录、仅参考只供参考。以实际保存的独立结果为单位保留成功部分，反馈未保存与需核实项；修复不重复创建成功项、不绕过审核，预算耗尽后明确报告未完成原因 |
| 使用反馈与打磨 | 以实际学习流程试用，修复阻碍学习的缺口，根据具体反馈同步文档和测试 |

若离线样本用于开发和浏览器验证，应明确标为 fixture／模拟结果，保留来源，不冒充真实 API 录制或已验证的线上模型质量。真实模型效果由用户正常使用验证；测试继续禁止真实网络与模型调用。

## 4. 切片开始前要固定的局部契约

这些问题不需要挡住全部实施，但必须在依赖它们的切片开工前形成明确决定，并回写相应规范。下面不再沿用旧切片字母：

- **历史原文定位。** 首次引用目标原文的 AI 任务被系统接受前允许编辑，接受后固定；失败或中断不自动解除。实现须保证编辑与任务接受的边界一致，不得让调用实际输入和历史偏移指向另一份文本。
- **文档身份与目标。** 用 `Segment → Analysis → AnalysisRevision → Section` 表达关系；完整解析、专题讲解和讨论整理共享此模型。当前修订属于某份 Analysis，不能只有一个含义不明的片段级修订指针。参考对象与修改目标分别表达：明确对象优先，唯一选中对象可帮助解释指代，持续打磨任务可沿用目标；有歧义时再澄清。选中对象不自动授权修改。Section 写入须显式定位 Analysis、基础 Revision 和目标块或插入位置，校验它们与当前 Segment 的归属及当前版本；建议工具签名见架构，仍是待实现契约。工具写入细节见 PRD `[TBD-16]`。
- **块级编辑。** 更新 Section 可改标题、正文或同时替换该块，省略字段保持原值；插入多个 Section 可在指定块后或正文开头；删除 Section 只在新修订中移除。三者成功都生成新的完整 Revision，历史引用保持原指向。Preamble 可修改或清空，不强制套用普通 Section 标题。是否提供全量替换工具留待编辑功能阶段决定。
- **规范化与 ID。** 纯函数只做确定性切分和派生结构；持久 ULID 的首次分配由编排／持久化层完成，或通过显式输入提供。不能一边在纯函数内部生成随机身份，一边声称完整结果确定。
- **上下文与公共资料。** 用户手动决定是否提供前后文及其范围；明确目标和语境。首轮 Agent 只读取当前 Segment 的持久讲解和已有条目、必要的 Source 元信息、本线程历史及用户背景偏好；其他线程的持久讲解共享，但不检索其他线程的聊天历史或跨 Segment 内容。用户界面的跨片段积累库不因此受限。实际使用的来源须可追溯；具体读取契约在架构中落实。
- **候选契约。** Agent 的基本工具包括读取已有条目、创建单条或多条 `pending` 候选、按审核规则修改 `pending`。无论有无独立批量提取按钮，都需明确带版本的字段与语义契约；A0 可作参考，但试验通过不代表它已是生产定案。所有候选创建须维持原文和具体 Revision／Section 的定位约束；手动创建 Occurrence 暂缓。
- **写入与审核。** 产品初始默认审核模式；每线程显示并可选择审核模式或 Full access，可配置新对话的默认模式，改变默认值不自动影响已有线程。线程只在空闲时切换模式，运行中或待审期间不能切换，挂起方案不会自动放行。审核模式可直接读／检索，明确要求新建讲解可直接保存；Agent 单条或批量创建条目一律为 `pending`，默认无需审核。修改已有讲解、修改已有 `pending` 候选内容或使用已开放的删除工具，先审核确定目标、基础版本、具体变更或影响范围。同意只应用展示版本，拒绝不写；附加指令在同意且实际保存成功后继续处理，或在拒绝后重新准备，不得静默改变获批内容。批准不等于保存成功，也不表示候选已收录；修改候选成功后仍为 `pending`。待审核可持久等待，离开不代为决定；依赖操作等保存成功，基础版本变化则重新准备审核。候选内容编辑工具只作用于当前仍为 `pending` 的条目；待审期间用户已收录、设为仅参考或删除时，执行前重新核对，旧方案不能照旧应用或自动将状态改回 `pending`。Full access 跳过逐次审批，仍受任务意图、工具范围、定位校验、不可变修订、历史引用和目标冲突检查约束。普通问答无隐式写入。首轮不提供 Agent 收录、设为仅参考或退回待整理的状态工具，也不能创建 `learning`／`reference` 条目或通过先创建候选再改变状态收录。普通候选工具不能暗中修改讲解或已有收录条目，混合操作按全部实际效果检查权限。混合方案的审批展示见 PRD `[TBD-17]`。
- **停止与轮次。** 用户可停止正在运行的一轮，不回滚已保存成果；停止后不得再启动生成、修复或工具，未执行的待审方案取消，已提交操作按真实保存结果反馈，残缺消息标为中断。同线程运行或待审期间不可发起新轮、不可排队，但可保留输入草稿；审核附加指令属当前轮，待审须经同意、拒绝或停止后才能继续。其他线程独立运行；暂缓编辑历史消息及任意分支。
- **成功、部分失败与恢复。** 操作成功须通过适用的字段、类型、原文定位、讲解引用、权限和当前目标状态校验，且实际保存；这不证明教学解释正确或提取完整。以实际保存的独立条目／修改为单位保留成功部分：如 10 条候选中 8 条保存、2 条定位失败，保留 8 条，另 2 条只留诊断，不作为正常 Occurrence；整个输出不可解析时不猜测部分成功。已保存讲解不因后续候选失败撤销，中断也不回滚成果。工具反馈区分已保存、未保存、保存结果需核实，给出成功记录身份和具体原因；修复失败项，不重建成功项。未创建成功的候选修复走创建，已保存候选修改仍按审核；目标变化先重读，不修改 `learning`／`reference` 或绕过状态。可修复校验失败回传 Agent 修正，临时故障有限重试，保存情况不明先核实；待审核不是失败，拒绝或权限不允不作为错误反复重试。自动修复采用统一的有限次数／时间／调用预算，参数及底层重试与 Agent 循环的协调见 PRD `[TBD-16]`，不得叠加旧的固定「2 次」独立预算。用尽预算则停止、保留成功部分并说明未完成原因，用户可之后继续。无新学习点可正常完成。产品行为见 PRD F8；恢复、幂等及预算参数仍需技术细化。
- **整理状态与再次整理。** 待整理、已收录、仅参考可相互调整，候选不要求清空；仅参考可主动查找与阅读，默认不参与后续学习活动，已收录不自动启动排期。用户从界面直接收录、设为仅参考或退回待整理，首轮 Agent 不改变整理状态。再次整理已有讲解先读取相关已有条目，以补遗漏候选、提出已有 `pending` 的明确内容及出处修改为主；修改按线程权限执行。`learning`／`reference` 只供参考，旧候选不自动失效；不整批替换、自动合并、迁移状态或漂移出处。仅凭 anchor 或原文位置不能合并，也不保证语义判重完美。新修订纠正旧解释时可提示受影响条目；用户自行退回 `pending` 后，Agent 才可修改。用户明确重做时可按既有删除规则清理选定候选后再生成，普通再次整理不隐含清理；不要求管理提取批次，各调用仍留痕。不同 Analysis 的条目各自保留来源；不因删除记录而自动建立永久拒绝建议的规则。具体行为见 PRD F5。
- **删除。** 首轮提供创建／删除 Analysis 的业务接口；Agent 可创建 Analysis，但不开放整份 Analysis 删除工具。用户界面删除整份 Analysis 前展示关联的全部 Revision／Section 与引用条目（包括 `learning`／`reference`）并确认；该 Segment 下对话不随之删除，旧指向显示已删除。首轮不提供独立忽略状态；删除不需要的 Occurrence 是独立操作，已删除内容不进入日常浏览且不提供恢复入口，删除 Occurrence 不删除原文与讲解。产品界面手动删除 Source／Segment 的级联范围沿用 PRD F2，包含已收录条目，删除前展示范围并确认。保留 Occurrence 软删除、不让迟到结果复现、不提供归档或回收站的已确认边界。关联调用记录及物理清理策略在架构中落实。

## 5. 文档与实现如何共同迭代

- 每个切片先写清当前行为、局部未决项的处理方式和验收用例，然后实现并体验；同一交付内更新对应文档。
- Glossary 记录概念与已确认边界；PRD 记录当前产品行为与范围；Architecture 记录实际模型、约束与接口；实验报告保留观察及其局限。
- 只在行为或契约确实变化时更新相关文档，不把开发流水账复制进所有文件。
- 版本号、模型／prompt／提取规则与原始产物留存，使之后调整规则时仍能解释历史结果。
- 不因未来 ITS 的未决设计暂停当前内容保存与阅读能力，也不因可以开工就跳过当下的历史引用、数据完整性和失败处理。

## 6. 完成标准

- 首轮基本能力可从用户输入走到可重读的自足讲解与有出处的学习点；数据可持久化，结果可追溯。按阶段细化对应验收用例，总体讲解快捷入口验证生成并保存同一闭环，其他快捷按钮不作为验收基本能力的前提。
- `just lint`、`just test` 及必要的构建检查通过；schema 变更运行 `just gen-api`。仓库没有对应命令时，应由工程初始化建立入口，不能长期将其缺失作为已完成开发的豁免。
- 规范化性质测试、Occurrence 定位与引用测试、独立 Analysis 的来源隔离和核心失败路径有适当覆盖。
- 实际浏览器验证，并明确区分模拟数据验证、真实模型可用性和用户学习体验。
- 未实施项、工程占位与尚未验证的模型表现如实列出，不以机械通过率代替教学内容质量。
