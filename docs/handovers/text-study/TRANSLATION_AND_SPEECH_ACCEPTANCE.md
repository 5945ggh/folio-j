## 浏览器观察与 UI 调整

使用 `/private/tmp/folio-j-translation-qa/` 内的独立 SQLite 数据库和合成 EPUB。后端生成函数替换为固定模拟译文，并禁止进程向外建立连接；不使用用户模型凭据、真实原书或日常数据库。截图证明布局与交互，模拟译文不用于评价翻译质量。

1. 原生双击选词出现“翻译／朗读／保存为学习片段”动作条。翻译在历史与语境就绪后直接受理，去掉了重复的“开始翻译”确认。
2. 成功卡先显示短原文引用和译文；朗读、保存、返回原处放在同组，配置与重新翻译折叠。关闭后正文不重新排版，最近翻译可找回结果。无用分页按钮已移除。
3. 从译文保存片段成功后仍停留在阅读器，显示已保存去向和明确另存入口。片段原文与出处一致，关联结果可展开查看；辅助动作放在原文卡之后，保持原文优先。

5. 设备朗读设置实际列出了当前浏览器提供的日语声音及本地／远端来源，语速、检测和试听入口可见；未实际播放，不能据此评价读音或声线质量。

## 2026-10-23：翻译语境范围修复

用户提供的 v1 实测截图显示，前文中的一句被附加到选区译文。检查发现，v1 虽已要求只翻译目标，但规则、前文、目标和后文被合为单条 user 消息。

新增 `translation-v2` 系统模板，明确只翻译 `target`，禁止补译参考语境中的句子或事件，并加入范围示例。目标语言、前后文和选区通过 JSON 分字段传入 user 消息；原文中的引号、换行及类似分隔符仍作为数据保留。实际 messages 在受理时固定，执行时保存到 Run，Chat Completions 与 Responses 均使用该快照。v1 模板、已受理任务及历史成功结果保持原样；新译文需明确重新翻译取得。

回归覆盖截图中的输入分离、两种协议实际 HTTP 请求与 Run 消息一致、排队后模板变更不改变请求，以及有／无版本字段的 v1 历史任务兼容。翻译专项 15 项、`just lint` 与全量 `just test` 通过（后端 585 项、前端 413 项）。本次未修改前端或数据库 schema，未调用真实模型；离线测试验证输入契约，v2 的实际翻译范围仍待同模型重译确认。未触及 TBD。
