# C2 精确验收样例与实施门禁

2026-10-22。本轮先验收 C1，再独立审查本文件与对应固定数据，审查问题收口后才实现 C2。规则依据为 [PRD 4.7](../../PRD.md#47-当前-epub-阶段安排)，完整交互矩阵见 [TEST_MATRIX](TEST_MATRIX.md)。这里固定工程句界，不增加 Sentence 实体，也不改变出处身份。

## 句界规则 `context-sentences-v1`

输入为章内按 part 顺序拼接的 NFC 定位正文。分句保留所有空白和标点；part、DOM 节点、iframe、视觉换行和分词技术块均不构成句界。自动摘录随后整理副本，出处范围与原文不变。

- 句末字符集合为 `。！？!?`，连续句末字符作为一组；紧随其后的闭合符号 `」』）)]】〉》”’` 并入该句。句末组与闭合符号可交替连续出现，不产生空句。
- 紧随句末组／闭合符号的空白并入前句，例如 `本当！？　` 为一句。没有终止标点时，正文中的 LF 构成段落结束，连续空白／LF 并入前段。CRLF 整组保留。纯空白不单独计句；章首空白并入第一句。
- 不对引语内部做语法推断：`「行く。」と答えた。次だ。` 固定为 `「行く。」`、`と答えた。`、`次だ。` 三句。ASCII 句点 `.`、省略号 `…` 不属于终止集合，避免小数或缩写产生隐含规则。
- 先对整章建立句界，再裁出目标两侧。与目标相交句的未选残部计该侧一句；空残部不计句，目标文字不出现在语境里。若残部只有空白，接入该侧最近的外侧非空句，不新增句数；没有外侧非空句时，摘录为空且不截断。
- 每侧从最近的残部／句向外取，保留原句界与残句计数。两侧副本按 Unicode White_Space 集合整理：CRLF 转 LF，纯空白行内容清空，内部连续空行最多保留一行，去除副本两端空白。正文行内空格、全角空格、标点、组合字符、变体选择符和零宽字符保留；FEFF 不属于 White_Space，不能用 JavaScript `trim()` 替代。标题按普通正文处理。
- 句数和字符数各自受限；任何预算为零时为空。每次加入远侧候选后按合并整理副本的 NFC 码点长度计字符预算。字符不足时取贴近目标的部分并停止，再去除裁切边缘空白。前侧取后缀，后侧取前缀，保持原阅读顺序；不跳过长句拿远处短句。内部保留的空格、LF 和标点各计一码点。
- `truncated` 仅表示字符限额保留了某句／残部的部分非空白内容，同时省略其余内容。只裁到句间空白而未纳入新句正文、句数限制、纯空白侧、零预算及恰好完整候选均为 false。关闭自动预装时两侧为空且 false。用户编辑、已存 Segment 语境及历史输入快照沿用原值。

## 固定数据

[c2-context-cases.json](fixtures/c2-context-cases.json) 为纯逻辑验收输入，不由待测实现生成预期。`start`／`end` 是整章 NFC 码点半开区间，`before`／`after` 是精确字符串。句界样例另给完整句列表；测试须逐字比较，不仅比较长度。每次调用前后深度比较章节、预算与出处，锁定 exact、摘要、spine 和坐标不变；原分句固定数据沿用原空白，不随摘录整理改写。

## Unicode 原生选区与回读

以下 DOM 的文字节点分别列出，不含 `rt`／`rp`。`node:offset` 中 offset 为浏览器 UTF-16 单元；输出 start／end 为资源 NFC 码点。正向和反向选择预期相同。

| 编号 | DOM／原始投影与选区端点 | 精确预期 |
| --- | --- | --- |
| U1 | 节点 `甲𠮷`、`カ`、`\u3099乙😀。`；从 `0:1` 到 `2:4` | 整体 NFC 正文 `甲𠮷ガ乙😀。`；范围 `[1,5)`，exact=`𠮷ガ乙😀`，4 个码点；反向拖选不改变顺序 |
| U2 | 同上，从 `1:0` 到 `2:1` | `[2,3)`，exact=`ガ`，跨节点 NFC 不漂移 |
| U3 | 同上，从 `0:2` 开始，或在 `2:3` 结束 | 拒绝：端点切开非 BMP 的 surrogate pair；不移动端点凑合法范围 |
| U4 | 同上，在 `1:1`／`2:0` 处分界 | 拒绝：端点切开 `カ`＋结合浊点；不扩大成整字后冒充原选区 |
| U5 | `<ruby><span data-locator-leaf="0">漢</span><rt>かん</rt><rp>）</rp></ruby><span data-locator-leaf="1">字😀</span>`；从 base `0:0` 到后节点 `1:3` | 正文 `漢字😀`，范围 `[0,3)`，exact=`漢字😀`；读音、括号不进入 exact 或预算。只选 rt／rp 拒绝；端点落在 rt／rp 拒绝 |
| U6 | U1 的 part 资源起点为 10，spine_index=4 | 输出范围 `[11,15)`，保留 spine=4；相同资源在 spine=1 的出现不得替换此身份 |
| U7 | U1 加自动 ruby、切换注音显示、横竖排／字号／行距后重新划选 | 仍为 `[1,5)`；回读高亮覆盖同样四个码点，读音不参与定位 |
| U8 | U5 的 ruby 和 span 为 root 的两个直接子节点（无间隔空白）；`(root,0)→(root,2)` 与 `(ruby,0)→(ruby,1)`，offset 是 childNodes 索引 | 分别为 `[0,3)`／`漢字😀`、`[0,1)`／`漢`；正反方向相同。`(rt,0)` 或 rt 文字节点内部作为端点均拒绝；不把 childNodes 索引当作 UTF-16 索引 |
| U9 | 空选择、多 Range、已销毁或上一代 iframe、跨 iframe 选择 | 明确拒绝，不截取部分有效选择提交 |

结构化章范围与回读 fixture 已列在固定数据的 `chapter_cases` 中，使用同章多资源 API fixture 验证全部范围高亮。任一 frame 投影失败时报告不完整，保留重试目标；不得提交未成功呈现位置、提前消费返回点或回退到普通位置掩盖失败。

## 独立审查与验证记录

样例作者为主代理。独立审查须核对句界、混合长短句的两侧方向、NFC 与 UTF-16 端点、截断标记、章界和草稿竞态，并记录发现与结论。C2 实现前在此追加审查证据；实施后的运行证据记入 C2 验收记录。

### 2026-10-22 独立审查结论

独立审查代理 `c2_case_review` 首轮发现两项实施门禁缺口：纯空白残部的归属／截断标记、元素 childNodes 端点缺少精确输入。作者补齐规则及 6 个空白样例，并补上含 ruby 的元素端点和 2 个结构化章范围 fixture。

复审通过。审查者用独立只读计算核验 9 个分句、25 个语境、2 个章范围样例的 NFC、码点范围、近端切片、双预算、资源／part 组装、全部高亮及首段导航位置；没有未解决阻塞项。该结论允许在 C1 验收后开始 C2，实现和浏览器验收仍须另行完成。
