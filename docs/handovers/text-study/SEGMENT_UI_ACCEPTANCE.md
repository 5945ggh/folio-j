先用真实组件回归保护字段提交、草稿保活、停止、审核和成果入口，再分别调整资料与讨论展示，最后统一验收。讨论受理、提交核实与成果通知继续使用原协调逻辑；父页面继续维护讨论显隐和窄屏焦点。没有新增依赖、后端接口、数据库变更或 TBD 决策。

单条回复直接保存为讲解、讨论主视图、自动概括标题与提示词响应风格留在后续设计范围。

## 同日交互修正

用户复核后取消合并的大配置折叠区，拆成模型、审核模式、本轮要求三个独立按钮，各自打开对应的原生浮层。浮层互斥，打开不增加输入区高度或挤压消息区；关闭后保留补充草稿并恢复按钮焦点。删除资料表单的五句常驻规则／用途说明与无引用样式。新建对话改为带悬停提示的加号，两处收起讨论图标只保留外框和分栏线。

新增浏览器回归先在旧界面产生红灯，再验证独立按钮、浮层互斥、输入区和历史区几何不变、关闭后草稿与焦点、320px 宽度，以及加号按钮名称和说明文字移除。实际页面验证三个入口、Escape 先关浮层、外部点击关闭和两处无箭头图标。

模型与审核模式进一步改为直接列出原生单选项，当前项显示勾选，单击一次就按既有版本化接口更新并收起；重复选择当前项只收起，不发起更新。运行中禁改、失效模型门禁与 Provider 区分保留。本轮要求继续使用独立输入浮层。新增回归覆盖无内嵌下拉框、直接可见选项、单次更新及自动关闭；实际页面检查模型列表和两项权限，选择当前权限后直接收起。

## 删除本轮要求入口

删除讨论中的本轮要求按钮、独立补充框和临时预设覆盖。新请求直接发送可见聊天文字，省略预设覆盖字段以采用服务端默认值；设置中的长期预设、后端历史字段、审核补充要求和已受理请求的同请求核实保留。旧失败任务及遗留草稿的补充文字合并到可见聊天框，避免隐藏输入或丢失文字。

本轮新增纯函数回归覆盖旧补充全文恢复和幂等转换，讨论浏览器回归检查只有两个设置入口、新提交无预设覆盖／隐藏补充、旧失败恢复、草稿往返及原有停止／审核／权限行为。浏览器可通过现有开发服务器的 `browser-tests/?suite=workbench` 单独运行讨论回归。

## 提交前并发编辑修复

提交前审查复现：编辑器打开后另一窗口保存新备注，首次保存返回 409；旧冲突区只显示译文和语境，确认后却把全部旧字段写回，覆盖了新备注。

修复后以打开时快照计算字段差异，每次只提交实际改动和预期版本。冲突单独读取完整的当前七字段，读取失败保留草稿并提供重试；用户核对成功读取的内容后才允许再次保存。确认只更新版本依据，未改字段继续省略。服务端在提供 expected_revision 时对原文、听写、备注、出处等字段同样执行版本检查。

验证先在旧实现产生全字段回写失败，再通过真实 SegmentDetail／SegmentForm 与模拟 API 验证并发字段保留、七字段分别修改与清空、读取失败重试和确认后再次冲突；新增字段差异纯逻辑 10 项通过。四类后端局部更新回归也先复现陈旧版本被接受，修复后全部通过。

内置浏览器打开隔离冲突样例，观察到最新听写、出处和备注均出现在核对区；向下滚动后用户修改的译文草稿仍保留，核对前“保存更改”禁用。见[冲突核对截图](evidence/translation/segment-conflict.png)。联合工程检查与独立复审汇总至[阅读辅助验收](TRANSLATION_AND_SPEECH_ACCEPTANCE.md#2026-10-23提交前审查修复与联合验收)。
