# 查词分词粒度对照实验

实验日期：2026-11-14，提交收口日期：2026-11-15。比较基准为 `main 653a4d60` 的查词实现。本记录与[基础词卡验收](DICTIONARY_BASELINE_ACCEPTANCE.md)分别保存功能交付和独立实验的证据。

## 方法与结果

实验独立于生产查词。比较 A、C-only 和一次 C 分析后拆分 B/A 的联合候选，使用合成词典和固定日文样本；不读取私人词典，不访问真实网络或模型。实验脚本：[benchmark_dictionary_granularity.py](../../../scripts/benchmark_dictionary_granularity.py)。脚本读取固定的 `653a4d60` 查词源码，在隔离模块供给各粒度词元，复用原有召回、排序、聚合规则。复跑命令：

```sh
backend/.venv/bin/python scripts/benchmark_dictionary_granularity.py --repetitions 40 --output /tmp/dictionary-granularity.json
```

环境：macOS 27.2 arm64、Python 3.11.14、SudachiPy 0.6.11、SudachiDict-core 20260723。32 个落点、31 个独立窗口、40 条合成词条，每侧最多 96 码点，窗口长度中位 12.5、P95 102、最大 192。每格 1280 次计时；冷表示分析缓存未命中，但已加载分词词典；热表示分析缓存命中，候选仍重新生成。耗时单位 ms，表内为中位／P95。

| 测量（无 hints） | A | C | C+B/A |
| --- | --- | --- | --- |
| 冷分词 | 0.016 / 0.111 | 0.014 / 0.107 | 0.021 / 0.182 |
| 冷候选生成 | 0.237 / 1.507 | 0.174 / 1.022 | 0.284 / 2.892 |
| 冷查询计算 | 0.421 / 1.906 | 0.359 / 1.188 | 0.465 / 3.282 |
| 热查询计算 | 0.406 / 1.814 | 0.344 / 1.114 | 0.446 / 3.094 |

分别调用三次 tokenize 的分词耗时为 0.042 / 0.303 ms。联合模式的调用计数为 32 次 C tokenize 和 780 次逐词 split；32 例派生 A/B 与分别分析所得的范围、表层、读音、原形、规范形、词性、OOV 均一致。已有完整 A hints 时，A 候选生成不调用 tokenize，联合模式复用 A hints、增加一次 C 及 B 拆分；冷查询计算从 0.440 / 1.353 ms 增为 0.538 / 2.779 ms。个别查询还会执行已有规范形活用校验的附加分析，不能把所有路径概括为总共一次调用。

A 与联合模式的候选数中位／P95／最大为 39.5／171／513 与 45／184／556，唯一查询 key 为 31／150／475 与 31.5／150／480。31 个窗口的 Python 分析缓存保留约 687／875 KiB；冷查询 Python 分配峰值的中位／P95 约 64／230 与 65／278 KiB。内存测量不包含原生分词器内部内存。

效果样例：

- `申し込んだ` 点击内部 `込`：C-only 丢失 `込む` 的还原，联合模式保留；整体 `申し込む` 的原有还原继续可用。
- `外国人参政権`：C 保留整体、B 保留 `外国人`，B 的完整读音能改善合成同形异读条目的排序。
- `想い出しました`：C／联合模式增加 `思い出す` 的规范表记召回，实际接续仍为 `想い出し／まし／た`。
- 词典仅收录 `連合`、C 切出 `国際連合` 时，三种查询都只返回真实命中的 `連合`，不会把未命中的长 C 词元变成词典条目。

结论：一次 C 加 split 不需要三次独立分词，额外分词耗时很小；候选生成与处理才是长窗口及热查询的主要增量。当前结果不包含 SQLite、HTTP、首次初始化、真实大词典或并发，只支持继续局部评测，尚不足以默认切换生产策略。


## 检查与限制

实验脚本通过 Ruff、格式检查和 strict Pyright，离线复跑命令已执行。合成样本的命中与耗时不能替代真实词典大规模评测；本轮不将 C 分析接入正式查词，未改全书分词、注音、词频统计或 TBD。
