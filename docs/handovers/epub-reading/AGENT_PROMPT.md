## 接手动作

从 [MVP 实施基线](../MVP_IMPLEMENTATION_BASELINE.md)核对代码基准、已提交能力、工作区改动与验收范围，再按[阶段入口的接力顺序](README.md#下一阶段接力顺序)选择当前切片。复用已有片段讨论、Analysis 生成保存和块级编辑审核，将本切片连通到真实阅读与学习路径。

实施前用具体交互收口阶段入口列出的未决行为。涉及从讨论形成讲解时，至少推演“一问引用两处，最后只整理其中一句”，明确目标与相关问答的选取、新建或复用 Segment、成果入口和部分成功反馈。

## 沿用已确认的契约

- 原 EPUB 字节与已发布处理版本保持不变。引用绑定材料版本、原始 spine 资源、码点范围及原文快照；显示布局和分词结果保持原文坐标稳定。
- 原书 ruby 优先，自动注音补充未覆盖的范围。分词结果作为可重建派生数据保存，重算保持材料核心版本与已有引用不变。
- 独立材料删除清空托管原书与派生阅读数据，保留材料身份、Source、片段及其学习积累和其他材料；材料自身或 Source 删除后均不可读，Source 级删除暂保留托管字节与编译产物。重导已删材料创建新身份与版本，历史出处不换绑；移动及一并删除积累继续后置，规则见 PRD F2。
- 手动 Segment 入口继续使用。消息原文引用与 Segment 分别保存，Analysis 归属 Segment；普通划选不创建学习片段或调用模型。
- 材料 Agent 的上下文和权限在切片 3 收口，模型读取范围须由明确操作确定。成果保存沿用现有审核、不可变修订、幂等与部分成功保留规则。

## 推进与验收

普通工程决定自主推进。对尚未确定、会影响阅读体验、数据保留、权限或费用的行为，带具体示例、推荐方案和取舍与用户收口；继续推进不依赖该决定的工作。

每个切片连通前端、API 和持久化，完成仓库规定的检查与浏览器验收，再接下一条路径。使用独立验收库验证数据与删除行为，保护用户日常数据。测试使用离线样例和模拟模型；需要真实模型响应时由人类录制。

将已确定的规则写回负责规范，将结果和验证限制写入阶段验收记录，并同步 MVP 实施基线。Occurrence、积累库、SRS／ITS、视频／asbplayer 和 MCP 留待后续阶段。
