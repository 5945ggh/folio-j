# 图片查看器加载与定位测量

> 2026-10-27；对象为 `db50943` 之上的工作区改动。测量使用隔离浏览器与本机只读样本，不代表真实网络或并发负载下的延迟。

## 浏览器交互

使用 `BROWSER_TEST_SUITE=reader-image-performance pnpm --dir frontend test:browser`，在 1280×900 隔离 Chrome 中运行完整 Reader 和 50 项离线图片夹具。每次图库清单／定位响应人为延迟 150 ms；图片内容为本地夹具，不访问真实网络。时间从操作到目标图片完成加载、有布局并经过两次动画帧；轮询间隔为 20 ms。图库切图从已加载图库页的第 1 张切到第 2 张，两图使用不同 URL，缩略图可以预加载。重复打开在首次后台定位完成后进行。

| 场景 | 优化前，单次 | 优化后，三次中位数（范围） | 本次操作内的清单／定位请求数，前 → 后 |
| --- | ---: | ---: | ---: |
| 正文首次打开 | 366 ms | 39 ms（37–40 ms） | 2 → 1（后台） |
| 同一会话重复打开 | 46 ms | 50 ms（50–53 ms） | 2 → 0 |
| 图库切到下一张 | 215 ms | 47 ms（43–50 ms） | 1 → 0 |

优化前只有一次基线观测，不能据此推断统计显著性；优化后重复打开的显示时间没有可确认的改善，但消除了该场景的后台元数据请求。上述 0 次图库切图请求依赖当前页元数据及缩略图已加载；跨页或尚未加载的图片仍需读取。优化前原生 `<img>` 请求未由夹具的 `fetch` 计数器记录，不能据此比较前后图片字节请求总数。优化后这三个计时区间内均未新发图片字节请求。

## 本机只读服务函数样本

从当前本地库只读取得两个较大编译包，在同一进程各执行三次并取中位数；不输出书名、材料 ID、正文或图片内容。计时仅含函数执行，不含 SQLite 查询、HTTP、浏览器解码或并发等待。

| 压缩编译包 | 图片出现项 | 原清单扫描 | 原单项清单扫描 | 原末图读取 | 新精确定位 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 14.7 MiB | 20 | 184 ms | 186 ms | 188 ms | 195 ms |
| 11.0 MiB | 20 | 168 ms | 178 ms | 175 ms | 175 ms |

新定位仍需解包并扫描完整编译包，单次成本与原清单扫描相近。正文已显示图片不再等待这一步；定位一次返回条目及总数，省去原有第二次清单扫描和正文首图内容请求。后端尚无图片派生索引缓存，未缓存的图库页和图片内容仍会解包扫描。

## 回归范围

图片浏览器回归覆盖桌面、窄屏、竖排、减少动态效果及 StrictMode；验证定位延迟时先显示正文图、关闭隔离迟到请求、DOM 图片属性被改写时仍使用可信源、正文与图库共享图片、正确的出现项与返回位置。缓存单元测试覆盖复用、容量淘汰、共享请求取消和会话释放；服务端测试覆盖定位、重复出现、版本失效与 Source 删除。真实触屏、真实系统剪贴板、不同设备及大图峰值内存未在本轮测量。

初次优化测量时，`just test` 通过（后端 743 项、前端 616 项），前端构建、类型检查、变更文件 Biome 检查及 `just check-docs` 通过。`just lint` 在后端 Ruff 和 Pyright 通过后，因同一工作区 `ReaderControls.tsx` 的 Biome 无障碍及格式错误未通过。
