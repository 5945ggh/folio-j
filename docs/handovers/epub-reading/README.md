# EPUB 原生阅读阶段安排

> 本文维护 EPUB 阶段的执行顺序、准备条件与切片安排。当前交付状态及验收入口见 [MVP 实施基线](../MVP_IMPLEMENTATION_BASELINE.md)。

本阶段从 EPUB 导入与阅读继续接通片段学习和材料范围内的随手问答。选区与出处由文本与资料计划 C1／C2 交付；材料对话及从讨论形成讲解保留为后续切片。Occurrence、主动复习、视频及外部 AI 接入不作为这些切片的前置条件。

## 开发切片

下文记录各切片的范围与完成标准，交付状态见[实施基线](../MVP_IMPLEMENTATION_BASELINE.md#1-当前实现差额与验收依据)。

### 切片 0 样书与定位契约验证

本切片的样书、正文投影、选区往返、渲染取舍及扩展验证边界见[历史验收](../archived/epub-reading/SLICE_0_ACCEPTANCE.md)。后续扩大支持范围时补充对应样例与浏览器验证。

### 切片 1 导入材料与基础阅读

本切片的导入、托管、目录组章与基础恢复见[历史验收](../archived/epub-reading/SLICE_1_ACCEPTANCE.md)。后续阅读器、注音与章节记忆的当前规则由架构维护，原始证据从[实施基线](../MVP_IMPLEMENTATION_BASELINE.md)查找。

### 切片 2 从原文接入现有学习能力

本切片由 [C1／C2 历史计划](../archived/text-study/PLAN.md)承接，从原生选区建立或显式选用 Segment，接入独立讲解、按需讨论及返回原文的路径。语境预装、片段复用、只读出处、原处预览和草稿保护的现行规则由 [PRD 4.7](../../PRD.md#47-当前-epub-阶段安排)维护，接口及定位实现见[架构](../../ARCHITECTURE.md#资料写入与材料出处契约)，验收入口见实施基线。

完成标准：从阅读到学习再返回阅读的路径连通；目标原文与历史输入稳定；手动 Segment、原有讨论与讲解编辑不回归。这一切片先验证既有能力的实际价值，不依赖材料对话全部完成。

### 切片 3 材料对话与消息引用

扩展线程归属与输入快照，支持材料范围内的随手提问、消息原文引用、历史消息定位，以及从引用派生的阅读标记。已有后台执行、停止、恢复与记录能力复用，但逐项核对新的作用域。

实施前用具体交互定下：加入引用是否展开侧栏、无活跃线程时何时新建线程、同一问题多处引用、手动粘贴、上下文默认范围与费用控制。默认行为不能导致选中文字就调用模型，也不能因阅读器知道全文而默认向模型发送全文。

完成标准：发送时固定本轮目标；翻页不改变已受理请求；点击标记打开确切消息；重复或重合引用不丢失身份；无定位消息正常使用；刷新、失败、停止和线程隔离均有证据。

### 切片 4 从讨论形成持久讲解

从已有阅读讨论明确选择学习目标与相关问答，建立或选用 Segment，再整理为 Analysis；原阅读线程保留，并提供成果及出处入口。

完成标准：多处引用不会自动拼成一个目标；用户不必重新复制讨论；Analysis 继续归属 Segment；部分成功可找回，重试不重复创建已成功成果；材料对话不能借组合动作绕过现有编辑审核。

## 分词接入时机

全量注音使用绑定正文版本的持久分词资产；完整准备成功后才进入阅读，重建不改变材料核心版本、引用与阅读位置。不引入 Lexeme 或独立 Sentence 实体。现行机制见[架构](../../ARCHITECTURE.md#313-全量注音与分词资产)，定位边界见[材料基线第 8 节](MATERIAL_BASELINE.md#8-分词与派生数据的后续接入)，历史证据见[全量注音验收](../archived/full-ruby/ACCEPTANCE.md)。

## 协作与验收

以切片为单位交付可使用的前后端路径，不将全部后端完成后才接 UI。每个切片使用短期 `codex/*` 分支；开始前确认当前其他修改的归属，不覆盖并行工作。

- 主代理负责范围、契约、任务派遣和集成验收；schema、迁移、API 与生成客户端由同一责任方协调。
- 契约确定后，后端实现、前端阅读交互和测试样例可在互不重叠的文件范围并行；前端不手写服务端接口类型。
- 测试代理优先准备有意义的正文与定位样例，独立核对边界；不要将同一份未确定契约分别交给多个实现代理自由设计。
- 按 [AGENTS](../../../AGENTS.md)执行 `just lint`、`just test`；schema 变化运行 `just gen-api` 并检查迁移；UI 在浏览器实际验收。文档变化运行 `just check-docs`。
- 测试继续禁止真实模型与网络调用。模拟模型证明的是交互和数据链路，不冒充真实教学质量；需要新录制时按仓库规则由人类执行。

阅读与扩展的实际验证范围见[切片 1 验收](../archived/epub-reading/SLICE_1_ACCEPTANCE.md)和[R1.1 工程验收](../archived/reader-r1/ACCEPTANCE.md)。

## 下一阶段接力顺序

C1／C2 已交付，当前能力与验收限制见[实施基线](../MVP_IMPLEMENTATION_BASELINE.md)。查询既有切片的实施依赖与取舍时，按需读[历史计划](../archived/text-study/PLAN.md)。切片 3／4 尚未启动，接手时先按以下顺序收口：

1. 材料对话与消息引用仍属后续切片 3，启动前先收口具体交互、上下文、权限和费用。
2. 从讨论整理讲解的切片 4 接续材料对话，先明确目标选取、相关问答范围、保存反馈与部分成功恢复。

各切片独立实施和验收，新计划中的产品规则按其 S0 同步，不从计划状态推定已经交付。

## 阅读辅助后续安排

阅读翻译与设备朗读的当前能力、验收入口和设备限制见[实施基线](../MVP_IMPLEMENTATION_BASELINE.md#1-当前实现差额与验收依据)。[原方案](../archived/text-study/TRANSLATION_AND_SPEECH_PLAN.md)保留获批范围与历史取舍；现行保存、采用与找回入口由 [PRD 4.8](../../PRD.md#48-阅读翻译与设备朗读)及[阅读与导航](../../INFORMATION_ARCHITECTURE.md#选区与资料往返)维护。以下事项按具体需求另开切片，不作为材料对话的前置条件。

| 未完成事项 | 启动或验证条件 |
| --- | --- |
| 真实翻译质量与资源预算 | 用真实长短样句检查目标、语境、超时和输出触顶；需要新的模型响应时由人类按 `RECORD=1` 录制，自动测试继续离线 |
| 设备声音与语速 | 在用户实际设备试听，核实 Chrome 语速参数传递与实际变速差异；设备声音来源、网络依赖及跨设备差异分别记录 |
| Segment 直接生成译文 | 作为独立小切片确认目标归属、原文保护、已有译文和材料出处的关系；当前不以阅读器选区任务替代任意片段任务 |
| 专用翻译 adapter | 选定服务后核实独立语境、语言、术语表及参数能力；不满足请求时明确提示，不静默丢弃语境或把语境当额外待译文本 |
| 远端 TTS 与保留音频 | 用户选型后细化接入、声音发现、费用、存储与删除；明确保留的音频与普通缓存分开，设备 fallback 由用户显式启用 |
| 其他翻译与维护范围 | 无材料出处的任意文本、批量／整章翻译、端侧模型安装管理、独立译文清理及内容缓存按具体需求设计；清理明确采用关系，缓存不合并出处身份 |

目标与语境字符上限、总时限、执行及等待数量、缺省输出预算的试验初值见[原方案第 11 节](../archived/text-study/TRANSLATION_AND_SPEECH_PLAN.md#11-已确认决定与资源候选)，当前值由[集中配置](../../../backend/src/app/config.py)中的 `TranslationLimits` 维护，并受全局模型并发约束。实测时记录实际配置与所选模型支持的输出预算，检查长样句是否触顶，不把字符数换算成 token 或费用。离线边界验证不替代真实质量、性能或设备结论。

未来非 LLM 翻译保留真实调用记录，不伪造 prompt、模型名或 token 用量；第二种 adapter 落实时确定记录形态。接入身份、凭据与功能默认值的复用继续遵循现有设置契约，不提前增加空表单或改造全部 Provider 配置。
