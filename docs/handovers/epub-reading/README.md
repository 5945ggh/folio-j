### 切片 3 材料对话与消息引用

扩展线程归属与输入快照，支持材料范围内的随手提问、消息原文引用、历史消息定位，以及从引用派生的阅读标记。已有后台执行、停止、恢复与记录能力复用，但逐项核对新的作用域。

实施前逐项收口下列问题；这些是原方向稿与定位方案承接的设计条件，尚不构成完整的材料对话接口。

| 主题 | 需要确定的行为与边界 |
| --- | --- |
| 线程与消息归属 | 阅读线程以材料为目标，不能借任意 `segment_id` 容纳；与已有片段线程复用哪些基础、API、权限和 Job 快照如何扩展。消息可有零个或多个引用，无定位提问正常使用 |
| 选择、草稿与发送 | 加入引用是否展开侧栏、无活跃线程时何时创建、如何选择多线程，以及单纯选区、草稿引用与已发送引用的生效时点。普通划选不创建片段或调用模型；手动粘贴没有可靠定位时不生成精确标记 |
| 定位值与阅读标记 | 候选沿用版本、原始 spine 资源、有序码点半开范围及 `exact` 快照；限长 `prefix`／`suffix` 仅供识别或未来恢复，不替代学习语境。引用与 Segment 分别保存关系，标记由消息引用派生；同范围可聚合呈现但保留消息与引用身份，重叠引用不自动合并 |
| 请求冻结与失配 | 发送时固定引用、实际语境和版本，翻页及迟到选择不改变已受理请求。严格核对版本、资源、范围与快照；不可用时保留历史文字并说明无法定位，不按相同文字静默换绑，不先做模糊恢复 |
| 上下文、权限与费用 | 明确默认语境窗口、旧问题引用、未读内容与剧透边界、工具读取范围、历史复用及预算。评估由应用直接处理可确定的选区、出处与已有内容查询的方案；侧栏显示连续历史不意味着每轮发送全部历史，知道全文不意味着默认发送全文 |
| 阅读交互与执行方式 | 是否需要独立阅读 Agent、具体工具集合、按钮与工具的分工及执行方式均待决定；结合桌面与窄屏明确侧栏尺寸、展开及恢复行为，不由现有聊天基础反推已选方案 |

完成标准：点击标记打开确切消息；重复或重合引用不丢失身份；无定位消息、刷新、失败、停止和线程隔离均有证据。定位继续验证 ruby、跨节点 NFC、UTF-16／码点转换、重复 spine、同章多资源、重排与快照失配；跨 iframe 拖选、不连续或跨章目标不伪装成完整选区。准备失败或迟到结果不消费回读目标，不保存未成功呈现位置。

### 切片 4 从讨论形成持久讲解

从已有阅读讨论明确选择学习目标与相关问答，建立或选用 Segment，再整理为 Analysis；原阅读线程保留，并提供成果及出处入口。

实施前推演“一问引用 A、B 两处，最后只整理 A”：由用户确定 A 的目标范围，B 可作语境或比较依据，不将所有引用拼成目标，不迁移整条阅读线程。明确相关问答选择、范围调整、新建或显式复用 Segment、整理依据、成果发现与返回入口，以及成功事实和幂等关系；问题焦点、讨论语境与最终学习目标可以不同。

完成标准：多处引用不会自动拼成一个目标；用户不必重新复制讨论；Analysis 继续归属 Segment；部分成功可找回，重试不重复创建已成功成果；材料对话不能借组合动作绕过现有编辑审核。

## 协作与验收

以切片为单位交付可使用的前后端路径，不将全部后端完成后才接 UI。每个切片使用短期 `codex/*` 分支；开始前确认当前其他修改的归属，不覆盖并行工作。

- 主代理负责范围、契约、任务派遣和集成验收；schema、迁移、API 与生成客户端由同一责任方协调。
- 契约确定后，后端实现、前端阅读交互和测试样例可在互不重叠的文件范围并行；前端不手写服务端接口类型。
- 测试代理优先准备有意义的正文与定位样例，独立核对边界；不要将同一份未确定契约分别交给多个实现代理自由设计。
- 工程检查、迁移、API 生成和 UI 浏览器验收按 [AGENTS](../../../AGENTS.md)执行。
- 测试继续禁止真实模型与网络调用。模拟模型证明的是交互和数据链路，不冒充真实教学质量；需要新录制时按仓库规则由人类执行。

阅读与扩展的实际验证范围见[切片 1 验收](../archived/epub-reading/SLICE_1_ACCEPTANCE.md)和[R1.1 工程验收](../archived/reader-r1/ACCEPTANCE.md)。

阅读翻译与设备朗读的当前能力、验收入口和设备限制见[实施基线](../MVP_IMPLEMENTATION_BASELINE.md#1-当前实现差额与验收依据)。[原方案](../archived/text-study/TRANSLATION_AND_SPEECH_PLAN.md)保留获批范围与历史取舍；现行保存、采用与找回入口由 [PRD 4.8](../../PRD.md#48-阅读翻译与设备朗读)及[阅读与导航](../../INFORMATION_ARCHITECTURE.md#选区与资料往返)维护。以下事项按具体需求另开切片，不作为材料对话的前置条件。

| 未完成事项 | 启动或验证条件 |
| --- | --- |
| 真实翻译质量与资源预算 | 用真实长短样句检查目标、语境、超时和输出触顶；需要新的模型响应时由人类按 `RECORD=1` 录制，自动测试继续离线 |
| 设备声音与语速 | 在用户实际设备试听，核实 Chrome 语速参数传递与实际变速差异；设备声音来源、网络依赖及跨设备差异分别记录 |
| Segment 直接生成译文 | 作为独立小切片确认目标归属、原文保护、已有译文和材料出处的关系；当前不以阅读器选区任务替代任意片段任务 |
| 专用翻译 adapter | 选定服务后核实独立语境、语言、术语表及参数能力；不满足请求时明确提示，不静默丢弃语境或把语境当额外待译文本 |
| 远端 TTS 与保留音频 | 用户选型后细化接入、声音发现、费用、存储与删除；明确保留的音频与普通缓存分开，设备 fallback 由用户显式启用 |
| 其他翻译与维护范围 | 无材料出处的任意文本、批量／整章翻译、端侧模型安装管理、独立译文清理及内容缓存按具体需求设计；清理明确采用关系，缓存不合并出处身份 |

目标与语境字符上限、总时限、执行及等待数量、缺省输出预算的试验初值见[原方案第 11 节](../archived/text-study/TRANSLATION_AND_SPEECH_PLAN.md#11-已确认决定与资源候选)，当前值由[集中配置](../../../backend/src/app/config.py)中的 `TranslationLimits` 维护，并受全局模型并发约束。实测时记录实际配置与所选模型支持的输出预算，检查长样句是否触顶，不把字符数换算成 token 或费用。离线边界验证不替代真实质量、性能或设备结论。

未来非 LLM 翻译保留真实调用记录，不伪造 prompt、模型名或 token 用量；第二种 adapter 落实时确定记录形态。接入身份、凭据与功能默认值的复用继续遵循现有设置契约，不提前增加空表单或改造全部 Provider 配置。
