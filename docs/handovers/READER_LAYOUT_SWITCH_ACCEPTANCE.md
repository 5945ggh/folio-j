# 阅读方向切换修复

2026-10-29，基于 `19815f0` 完成并提交阅读方向切换修复。修复横排切到竖排时正文移出视口的问题；本记录中的导航协调重构为后续建议。

## 原因与修复

页边标记使用正文滚动容器内的绝对坐标。方向切换时，正文已完成竖排测量，旧标记的纵向坐标却要等 React 提交后才移除；它们暂时撑开纵向滚动范围，使旧 `scrollTop` 得以保留。原恢复流程仅更新阅读轴，正文因残留纵向偏移而全部离开视口。

离线 Chrome 用例在 400 段、3 个 iframe、3 处学习标记、章节中部位置稳定复现：iframe 的 `writingMode` 已是 `vertical-rl`，高度正确，容器却保留 `scrollTop=16708`，可见原文为空。

`MaterialReader` 的 DOM 恢复适配在计算目标矩形前清零非阅读轴：竖排清 `scrollTop`，横排清 `scrollLeft`。阅读轴仍按原锚点恢复；资源就绪、布局票据、位置保存与 iframe 身份规则保持原有契约。

## 结构建议与范围

建议分步推进：先让导航结果携带此次已加载并校验的 Chapter／part，删除页面二次查缓存及回退到旧章 part 的逻辑；再集中正文替换、重排、暂离的顺序约束。Navigation、Layout、Frames 保留为内部实现，新的协调 interface 应拥有 generation、呈现回执、资源就绪和稳定采样时机。

本次切换路径不经过导航的缓存重查；导航结果优化不能直接修复此故障。先交付小范围故障修复，再单独实施结构调整。不新增依赖、接口、迁移或 TBD；未验证 Safari、Firefox、实体触屏或浏览器扩展组合。
