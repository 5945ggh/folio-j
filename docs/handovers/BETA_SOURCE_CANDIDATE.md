# 首个源码包评审与恢复演练

2026-11-01 在 macOS 27.2 arm64、Chrome 156、Python 3.11.14、Node.js 24.22.1 上验证本地候选包。待审版本为 `0.1.0+candidate.2`，源码提交为 `7ebf9a60821be79a111c029c64c6d9bca3b7a99e`。ZIP 共 404 个文件，SHA-256 为 `3a3b588a09fdce6a04d58301da00ab913011a7111927a7eee9bd2c456e43a8a2`。

## 从源码包恢复

1. 将 ZIP 解压到两个独立目录，各自使用临时用户主目录。在两处都照包内 README 安装锁定依赖，使用本机已有的下载缓存，在解压目录新建虚拟环境和前端依赖目录。两处都没有 Git 元数据。
2. 从第一份启动应用，通过本机 API 导入原创合成 EPUB。在第一章保存书签「重读第一章」与阅读位置，在第二章保存目标原文「引用の文章。」、人工译文和一份人工讲解及其后续修订。导入一部单词条合成词典，登记禁用的模型服务与虚构凭据。
3. 服务运行时备份被拒绝。停服后执行包内 `just backup`，在第二个目录中用 `just restore` 恢复到全新位置。再次指向该目标时拒绝覆盖。启动恢复库前核对数据库与备份的 SHA-256，相同。原库在整次操作前后摘要相同。
4. 在恢复库读取片段译文、当前与旧版讲解、第一章书签和阅读位置，核对材料版本、当前词典及查词结果。用隔离 Chrome 打开讲解，点击「在原文中定位」回到第二章，页面中的标记范围是完整的「引用の文章。」。点击书签跳回第一章。恢复后 Run 表为零。
5. 同一待审包也成功恢复上一份候选包生成的真实合成备份。针对未来数据库升级，回归测试在临时迁移链加入一项新字段，验证旧包先按原数据版本恢复，再经 Alembic 升级并保留数据。旧程序拒绝新版库，清单与实际数据库版本不符时也拒绝。

本机的 `dist/releases/candidate-02/` 保存待审 ZIP、SHA256SUMS 和解压出的用户文档。`rehearsal/` 保存合成备份、两张浏览器截图和带原文、材料身份及版本的验证结果。源码包内三份用户文档的 13 个本地路径及标题锚点均已核对。打包命令见[开发指南](../DEVELOPMENT.md#构建供试用的源码包)，数据支持范围见[升级与备份](../UPGRADING.md#当前迁移基线)。

候选提交的 `just lint` 和 `just test` 通过。后端 1230 项通过，因私有样书未随仓库分发跳过 1 项，前端 809 项通过。实际解压包在两处均完成生产构建。Linux 与原生 Windows 未在本次演练中运行。

## 首个公开 beta

首个公开测试版定为 `v0.1.0-beta.1`。用户文档审阅已完成，发布仍采用源码包；Git 标签与包内 `RELEASE.json` 标识该次发行，前后端包元数据中的 `0.1.0` 表示当前基础版本。

上述候选包只保留为历史演练证据，不能改名后用于发布。正式包从发布标签重新生成，核对包内文档、安装启动及两份独立解压目录之间的备份恢复后，再推送标签并发布。首份公开 beta 的合成备份随本机发布证据保留，供后续版本验证。

公开附件、SHA-256 校验和及该包实际验证范围由 [GitHub Release](https://github.com/5945ggh/folio-j/releases/tag/v0.1.0-beta.1) 维护。本机对应产物目录为 `dist/releases/0.1.0-beta.1/`。
