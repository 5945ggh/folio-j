# 第二阶段 2C：Analysis 与成果工具开工准备

> 2026-09-27。状态：本轮讨论后的产品边界与开发准备；尚未实现。具体API、执行状态与预算须由开发负责人在对应实现前补齐，不将本记录或提示词草案当作已完成能力。

长期依据：[PRD](../PRD.md)、[术语表](../GLOSSARY.md)、[架构](../ARCHITECTURE.md)。前置实现及验收见[2B记录](archived/STAGE_2B_ASYNC_QA.md)，提示词审阅见[全链路聚合草案](PROMPT_CHAIN_REVIEW.md)。

## 1. 本轮已确认的行为

- 直接讨论不要求先有讲解。用户要求生成总体讲解、专题讲解或整理讨论成果，意图是生成并保存一份独立Analysis；不增加生成后再次要求“保存”的步骤。
- 提供片段的“生成总体讲解”快捷入口，教学组织参考[既有总体讲解模板](../../references/first_step_analysis_examples/v0.1/prompt-template.md)。快捷入口与聊天中的生成意图复用同一服务，前者没有既有线程历史时，以本次片段材料和生成要求建立任务上下文。
- 对话内生成采用当前主对话上下文快照的内部生成分支。继承截至触发点的完整对话语义、材料、用户要求和已读取资料，不先用摘要替代全文，也不让主模型在工具参数中重复复述已经明确的范围与重点。
- 分支追加适用的教学与Markdown写作要求，模型直接输出Markdown，不把完整新文档正文塞进工具调用JSON参数。新文档完成、校验并保存后，主对话得到成果身份、具体修订和真实保存结果。
- 上下文继承不等于机械复制所有system或协议消息：普通聊天专用的“当前没有成果工具”等指令不能成为生成分支的任务规则；触发分支的未完成tool call不得作为悬空协议消息重放。实际传入的上下文、转换规则和提示词版本须可追溯，不伪造工具成功或静默省略资料。
- 分支是本轮内部执行过程，不新增用户可管理的聊天分支树。写作指令、中间输出和调用记录保留在本地，不全部回灌主对话；主对话保留成果引用与执行结果，正文通过读取工具按需取得。
- Analysis列表和读取范围为当前Segment；工作台是活动界面，不是文档归属。列表提供身份、标题及简短说明，指定读取提供确切Revision和Section内容。未额外生成AI摘要时，用标明为摘录的正文片段，不为每份文档自动增加摘要调用。
- Analysis局部编辑在主对话通过Section工具完成，更新、插入、删除均形成新修订；不要求每次编辑都进入生成分支。沿用现有审核模式与Full access规则。
- 不推断Section语义依赖，不预建交叉引用维护或“移动解释”工具。若以后提供多操作提交，其分组依据是具体变更方案，不是自动推断的依赖图。
- Occurrence是结构化学习条目，不以Markdown为本体；引用明确Revision中的一个或多个Section。已收录／仅参考条目对Agent只读，创建只写pending，条目状态由用户管理。旧引用不随新Revision漂移。
- 整份Analysis删除继续仅由用户管理界面确认；Section删除属于文档修订。自然语言请求和快捷入口不扩大既有工具权限。

## 2. 开发顺序

### 2C.1 生成、保存与读取闭环

落地Analysis／不可变Revision／派生Section、规范化与只读展示；片段快捷生成及对话触发生成共用执行服务；Agent可列出当前片段文档并读取明确文档／修订／块。提供用户删除Analysis的影响预览及确认，保持迟到结果和历史入口的删除边界。

未涉及修改既有文档时，不要求用户再次审核明确请求的新建讲解。缺少二级标题等既有软格式问题只记录警告并展示，不将警告自行升级为生成失败。未完成、失败或停止的输出不冒充成功文档。

### 2C.2 局部编辑与审核

接入Section更新、插入、删除，以及Preamble更新或清空；每次操作显式定位Analysis、基础Revision和Section。审核绑定确切方案，应用前重新检查目标版本。成功操作返回新Revision，后续操作使用该版本。首批按操作展示／审核，不以隐含的“整轮原子事务”覆盖已有部分成功规则；批量变更集不作为首批前置条件。

主对话可讨论并编辑刚生成的Analysis，不重复全文生成。文档正文与模板参数分离；编辑工具中的局部正文仍可使用结构化参数传输，不建立“Markdown绝不能出现在工具参数中”的全局规则。

### 后续Occurrence切片

接入当前Segment条目列表／详细读取、pending创建与修改、用户整理及出处阅读。先固定版本化的字段与anchor规则，再实施创建校验；不用旧A0实验规则替代生产契约。Analysis开工不等待Occurrence的全部规则。

## 3. 需要用户意见与可采用默认值的事项

### Analysis分支模型选择

已向用户询问：分支默认使用设置中的“解析生成”模型，或沿用本轮主对话模型。建议采用解析模型设置，并在发起前明确显示、允许本次改选。继承上下文不意味着必须继承模型。

在用户明确答复前，此项是建议默认而非已确认产品决定。模型选择及其不可用时的提示必须在实现前固定；禁止执行时静默回退其他模型。后台接受任务时固定真实配置，不因排队期间全局默认改变而换用模型。

### 无须阻挡开工的界面默认

- 用户已明确选中的Analysis保持选中；新建成功后打开新文档；无选择时列出可选文档并使用最近更新项作为初始阅读项，始终提供切换入口。界面选择不自动授权修改。
- 生成时在讲解区域展示明确标注“生成中／尚未保存”的进度或草稿，保留停止入口；只有实际保存成功才显示正式文档身份。不要把临时输出说成已创建Analysis。
- 审核按具体操作展示目标、基础版本与正文差异；用户拒绝不作为可自动重试的错误。更复杂组合审核的TBD-17暂不扩大。

这些是可逆的首轮实现默认，可随实际浏览器体验调整，不要求逐项等待用户批准。

## 4. 由开发负责人在实现前落实的工程契约

- **数据与迁移：** 持久文档身份、当前修订指针、不可变正文与来源、Section派生及稳定身份映射。使用增量迁移，保留已有学习数据；从空库和现有库升级均验证。
- **规范化：** source Markdown为真相；纯函数切分，不改写，不随机生成身份；初始身份由持久化层分配。R1可复原、R2幂等、R3不改写，格式警告与硬错误分开。
- **工具契约：** 明确列表分页、读取默认版本及返回的确切版本、当前Segment归属、生成触发和错误结果。工具能力是模型／协议相关的，不能把2A文本调用成功等同于工具调用已经验证；两种协议的请求和事件均需离线契约测试。
- **输入与调用：** 区分本轮接受时的不可变资料／模型配置与分支触发时累计的已完成对话／工具结果；记录完整消息与出处。现有2B每Job一次生成的执行方式不能原样宣称支持多调用。每次实际模型调用仍经LLM层并记录Run。
- **任务与停止：** 分支归属于当前轮；停止撤销后续生成和保存权限，提交时校验执行标识与对象未删除。已保存成果不回滚；主对话收尾失败不能抹去成功文档或触发重复创建。
- **统一预算：** 主对话工具循环、分支生成与有限修复共享有界调用次数／时间／输出预算和现有全局并发名额，不能由子调用重新获得无限预算。初值集中定义并测试耗尽行为，由工程侧给出依据；不静默把2B原有60秒总量当作新的长文多步骤任务契约。
- **保存与恢复：** 每次创建／编辑有可核实的幂等身份；模型输出完成且通过适用检查后提交Revision和成功状态；写入结果不明先查询实际成果，不重新生成或重复创建。重启后的未完成分支、审核和已提交成果分别处理。
- **上下文与界面：** 成果卡片展示与模型下一轮输入分开，避免把模板及整篇报告重复拼进每轮；确切正文保存在Revision，读取时带身份与版本。对话历史和Run保留真实过程，不为节约上下文篡改既有记录。

以上待补齐正式schema、状态迁移与测试用例后才能交给实现代理；不把“产品无阻塞”写成“技术契约已全部完成”。原则性工程决定由负责人落实，涉及新产品含义或不可逆数据处理时再询问用户。

## 5. 提示词委托与审阅

提示词措辞由原生子代理起草，主代理按已确认产品范围审核；不逐句等待用户决定。当前[聚合草案](PROMPT_CHAIN_REVIEW.md)明确区分已运行模板和未来候选。

开发完成后，须从实际版本化模板及工具说明重新生成一份聚合视图：标明调用阶段、加载条件、上下文来源、模板版本及一组示例渲染。不能以本草案代替真实全链路，也不能用示例渲染证明模型质量。所有生产prompt仍保存在backend/prompts中，修改递增版本。

## 6. 验收与未决边界

- 快捷入口和聊天请求均生成可独立打开的Analysis；无需再次要求保存，刷新不重复调用或创建。
- 普通问答不自动生成文档；专题不自动扩整段；上下文分叉保留已讨论要求，并按记录的模型／资料快照执行。
- 当前片段列表与确切版本读取、Section修改的归属／版本／审核、旧引用不漂移均有离线回归。
- 停止、重启、删除、并发与迟到结果、保存成功后回复失败、预算耗尽均验证实际持久结果。
- 规范化性质测试、空库与增量迁移、schema变更后API类型重生成、完整仓库检查和实际浏览器验收通过。模型质量与实际工具兼容性另记真实验证证据，不让测试访问真实网络。
- TBD-07沿用现有软格式占位，不扩大为强制模板；TBD-16需在本阶段落实生成／保存／编辑执行契约；TBD-17首批按具体操作审核，不声称复杂组合已定案。TBD-03在Occurrence创建切片前用具体例子收口，不阻塞Analysis。

本轮准备验证：主代理同步长期规范和实施基线，子代理起草聚合提示词并独立复核契约；`UV_NO_SYNC=1 just check-docs` 检查22份文档、88个本地链接通过，`git diff --check`通过。仅修改文档，未修改运行时、生产提示词或用户配置；没有执行真实模型调用。此证据不表示2C功能已经开发或验收完成。
