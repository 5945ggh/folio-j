# 即时查词活用拆分与布局验收

2026-11-02，基于 `ccfbd2a8` 的 `codex/dictionary-inflection` 工作区，复核即时查词的活用说明并修复长接续布局。当前能力见[实施基线](../../MVP_IMPLEMENTATION_BASELINE.md)，行为与展示分别由 [PRD](../../../PRD.md#epub-即时查词)和[页面契约](../../../INFORMATION_ARCHITECTURE.md#即时查词)维护。

## 范围与修复

后端为命中候选保留实际消费的原文成分、词典形、六形和音便，前端按各词条自己的证据展示。规范表记承接须验证本地读音和活用类型；可能形逆推等派生不直接套用六形。查询响应增加可选说明，经 OpenAPI 生成前端类型，不新增数据库表或学习记录。

审查时使用真实词卡组件和应用样式，复现「食べさせられていなかった」的七段说明：1280×900 窗口中向下拖动卡头，再缩短为 1280×320，卡片只剩 120px 高，原固定卡头约 139px，释义滚动区变成 0px。移除活用说明后，同样操作仍可显示释义，确认长说明引入了回归。

修复后，单词条和同范围并列词条的活用说明统一放在各自词头下方，与释义共用滚动区。固定卡头保留词头与操作按钮；窄屏父卡收起时继续隐藏正文与活用，保留词头及出处片段。沿用既有浮窗定位与拖动规则，无新增高度状态、依赖或产品 TBD。

## 浏览器验证

新增 [dictionary-inflection-layout 回归](../../../../frontend/browser-tests/dictionary-inflection-layout.tsx)使用真实 Chrome、生产组件和应用样式，接口与词条使用合成数据。测试运行器新增本机视口调整绑定，向浏览器发送实际 resize，而非改写尺寸属性。

- 单词条卡片真实向下拖动 350px 后缩短至 1280×320，释义滚动区保持可见，活用说明每行和长释义末行均能滚入可见区域。
- 同一原文范围的三个词条分别展示各自证据；无证据的词条不占说明行。
- 390px 窄屏展开子卡后，父卡隐藏活用，保留词头和出处片段，前景卡继续显示说明。

在临时副本中把单词条说明放回原固定卡头，并恢复原间距，新回归明确因释义区为 0px 失败；恢复修复后通过。另运行既有 `reader-dictionary` 的 1280、900、740、390、320px 五场，检查父子卡、关闭、翻页、拖动、设置与图库共存，以及迟到响应保护。
