# 数据库迁移基线整理验收

## 范围

2026-10-25，延续开发数据可丢弃的授权，原 `0001_initial` 至 `0006_translations` 收敛为单一静态 `0001_schema_baseline`。直接建立当前 28 张应用表，保留字段顺序、类型、空值、服务器默认值、外键、主键、CHECK、唯一约束和部分索引；ORM、前端接口及产品行为不变。

删除旧原文保护回填、材料批量重建、逐步升级／降级及专用历史测试。Alembic、版本生成模板、后续增量迁移入口保留；版本脚本不导入运行时 ORM 或调用 create_all。迁移连接始终启用外键，保留显式 `BEGIN IMMEDIATE`、整笔 DDL／DML 回滚及提交前全库外键检查。初始基线的完整 downgrade 删除全部应用表，须显式执行。

## 回归与独立核验

先新增唯一新基线断言，原六版本链产生 RED，再合并 DDL 并清理旧测试。迁移与数据库业务约束共 16 项定向测试通过，覆盖：

- 空库建立、28 表与 ORM 的列／类型／主键／外键／索引一致性，六个历史 SQL 默认值、两个部分唯一索引和六个语境 CHECK。
- 多次 upgrade 保持全部已有数据和结构，含父子自引用修订的 downgrade／重新建立。
- 修改运行时 metadata 不影响固定初始 DDL，临时目录生成 revision 后仍可升级。
- 外键保持开启，失败 DDL／DML 和最终外键检查失败都回滚；旧开发 revision 明确拒绝且原数据不变。

作者与独立审查分开。另用修改前本机库结构快照与新空库比较列顺序、默认值、FK、完整 index_xinfo、索引 SQL／部分谓词，以及规范化的 CREATE TABLE 子句，28 表全部语义等价。材料表仅因去掉 batch 重建而有引号及约束排列差异。没有补入原库不存在的外键。

## 本机版本对齐

当前本机库没有学习内容，只有三项初始化设置。先在独立 SQLite 副本验证 `stamp(..., purge=True)` 与重复 upgrade，再持有应用相同的数据库进程锁；核对当前结构及现行编译包格式，制作含 WAL 已提交数据的一致性备份，并保留配套凭据目录。

随后仅显式对齐版本标签到 `0001_schema_baseline`，执行 upgrade head。全部 28 张应用表的数据逐行摘要不变，完整性与外键检查通过。备份位于私有 `.snapshots/migration-baseline-20261025-*/`；原始 EPUB 和旧历史备份未改动。该操作没有加入应用启动流程或通用旧库转换工具。

## 工程验收

`just lint`、`just test`（后端 733 项、前端 602 项）、`just build`、`just gen-api`、`just check-docs` 与 `git diff --check` 均通过。OpenAPI 与前端生成类型无变化，构建保留既有大 chunk 提示。

通过 `just start` 实际执行新基线的重复迁移、构建及启动，浏览器素材库显示“这里，留给下一本好书。”、导入 EPUB 入口与“共 0 项”；静态资源、来源和材料接口返回 200。验证后停止本轮服务，数据库为 `0001_schema_baseline`，完整性及外键检查通过。
