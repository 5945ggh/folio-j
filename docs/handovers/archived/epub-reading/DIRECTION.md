# EPUB 原生阅读与学习衔接方向讨论稿

> 2026-10-31 归档。材料对话、讲解形成与阅读辅助的未决问题已承接到[活动阶段安排](../../epub-reading/README.md#下一阶段接力顺序)及[按需评估事项](../../epub-reading/README.md#按需评估的阅读能力)；下文保留原讨论及当时的状态和用语。

> 整理于 2026-10-03。本文保留本阶段的产品动机、已对齐方向、初步建议和待讨论问题；不是已经实现的功能说明。主要方案见[材料与定位基线](MATERIAL_BASELINE.md)，开发顺序和准备条件见[阶段入口](../../epub-reading/README.md)。

下一阶段优先讨论素材接入、材料与 EPUB 原生阅读，将随手提问和深入学习接到已有的 Segment、Analysis 与工作台能力上。Occurrence 和 KnowledgePoint 暂缓深化，等待更具体的跨片段查找或学习活动提出需要。

当前 Source、Segment、讨论、Analysis 和 Section 编辑的基础能力已符合用户预期。按钮布局、审核呈现、修改提示与局部回退等仍需打磨，但不构成下一阶段方向讨论的阻塞。现有实现与验收依据继续见 [MVP 实施基线](../../MVP_IMPLEMENTATION_BASELINE.md)。

## 1 为什么调整阶段重心

**已对齐方向。** 过去网页 AI 解析难以找回，一个具体原因是原句、出处与聊天缺少稳定关联。原生阅读器若能将材料中的位置关联到 Segment 和 Analysis，就能支持回到原处发现讲解，以及从讲解返回原处。这项需求不以 Occurrence 为前提。

Occurrence 仍可能独立服务于跨作品查找、比较某个表达的不同用法，但这不是当前最紧迫的需求。复习、主动学习与 ITS 留到独立阶段展开；既有条目实验和概念讨论保留，不因暂缓而否定其价值，也不为尚未确定的活动提前设计完整知识模型。

已有讲解能力使原生阅读接入具备了实际落点。用户计划在后续实现时安排迁移此前的 EPUB 阅读器实现与经验；LearningJ 调查表明其定位基础有参考价值，但阅读恢复与标注尚未形成完整闭环，不能将旧项目整体视为可直接迁移的成熟阅读器。

**规范衔接。** 切片 0 已将阶段安排同步到 [PRD 4.7](../../../PRD.md#47-当前-epub-阶段安排)：EPUB 优先，Occurrence 与积累库暂缓。本文继续保留讨论背景，不将初步交互建议自动提升为实施契约。

## 2 真实阅读中的三类需要

| 阅读行为 | 用户需要 | 方向与尚未决定的部分 |
| --- | --- | --- |
| 即时查词 | 快速找到词条，必要时判断哪种切分、原形或义项适合当前语境 | 优先考虑与 Yomitan 配合；自建查词及语境辅助的范围待定。如提供内置查词，应可关闭以避免冲突 |
| 随手问 AI | 询问某处如何理解、为什么这样表达，减少复制原文与补充语境的操作 | 许多问题一次答复即可解决，也应能继续追问和找回历史；不要求每个问题都形成 Analysis |
| 主动划选 | 留下高亮、批注或书签，或者选出值得深入学习的片段 | 阅读标注与学习意图分别表达；划选可成为建立 Segment 并使用工作台的入口 |

这些行为来自用户自己的工作流，不构成按水平划分所有学习者的结论。某类问题很快解决，不等于其历史应立即丢弃；保存问答也不等于必须整理为独立讲解。

侧栏可承担原文与回答对照的需要。产品价值还包括自动带入原文及适当语境、保留位置关联、发现已有成果，以及将有价值的讨论接入现有学习能力；仅增加一个需要手动搬运内容的聊天区域不足以解决这些问题。

## 3 素材与材料

**已对齐含义。** 素材是用户提供的原始输入，本身保持不可变。材料是素材经过应用处理后，可由应用利用的形态。保存副本或仅引用外部位置原先都作为候选；当前采用首轮托管 EPUB 副本的设计方向，具体见[材料与定位基线](MATERIAL_BASELINE.md)，不表示已经实现。正式术语见 [GLOSSARY 第 2 节](../../../GLOSSARY.md#2-素材与材料)。

材料可以沿用素材的内容与呈现资源，例如 EPUB 的 CSS 和适用的分页呈现；处理不意味着统一改写成纯文本或重新排版。哪些资源保留、哪些结构需要派生，随后续阅读器迁移与定位需求确定。

**已明确不要求可逆映射。** 后续保证以应用实际需要为准：保留确定的原始输入，形成可利用的材料，并让受支持的引用能够从保存范围定位回阅读视图。不要求由处理结果逆向还原原始 EPUB 或 XHTML，也不以此为理由迁移旧项目全部规范化与恢复机制。

LearningJ 的多语言生成数据用于字素簇边界，NFC 已使用标准运行时能力。主要方案保留必要的 NFC、码点和 DOM 位置转换，不整套迁移其字素簇属性表及双端算法。分词可作为后补的派生数据，具体边界见基线第 8 节。

## 4 对象职责与阅读位置关联

以下是已对齐的职责方向，不直接规定数据库表、英文类名或外键。

| 对象 | 负责什么 | 边界 |
| --- | --- | --- |
| Source | 用户声明的作品、出处或来源范围 | 不等同于素材文件；首轮关联方案见材料基线 |
| 材料 | 应用能够利用的内容及其与原始素材的关系 | 为阅读、提取目标文本、取得语境和位置引用提供依据 |
| 原文引用 | 表达某条消息引用了材料的哪一处内容 | 与 Segment 分开考虑；一次引用不自动确立一个正式学习目标 |
| 对话与消息 | 保存讨论过程，并允许直接打开某条消息 | 阅读对话可随阅读转移焦点，不要求整条线程绑定一个选区 |
| Segment | 确定一个学习目标，并承载其讨论与讲解 | 继续支持手动输入；从材料建立时增加可靠的出处关联 |
| Analysis | 保存围绕 Segment 形成的自足讲解 | 沿用现有修订与块身份，不因阅读器入口另造一套讲解 |

**已对齐方向。** 阅读中的原文引用不适合直接等同于 Segment。材料范围内的阅读对话与已有片段对话需要不同的目标与上下文组织，但可以复用聊天基础能力。当前实现仍只有围绕 Segment 的讨论；扩展范围时须重新明确读取与写入边界。

箭头、侧边书签式标记等讨论提示由原文引用与消息关系派生。点击提示后展开讨论区域，进入对应线程并定位到对应问题。纯阅读书签、高亮与批注是否需要自己的持久对象，另按其职责设计。

**初步建议。** 单纯选择文字保持临时状态，加入输入框后属于草稿引用，发送时再成为消息的正式引用。引用需能保留当时的文字及可靠的位置依据；具体字段和请求契约在对应切片中确定。

手动粘贴的内容可以用于提问。没有可靠位置依据时，不生成声称精确对应原处的标记。后续可讨论携带出处的复制方式或手动重新关联，不把相同文字的搜索命中直接当作唯一位置。

## 5 从阅读发展为持久讲解

**已对齐方向。** 支持从原文和从讨论两个入口建立学习目标、形成讲解，不要求先走完查词或轻问答流程。

### 从原文进入

用户选定内容并明确保存学习片段，系统从材料取得目标原文、出处与适当语境，建立或选用 Segment 后留在原文，由用户明确打开片段或按需发起讲解请求。创建片段与请求生成仍是可分别表达的动作；C2 建立片段的可编辑语境预装已由 [PRD 4.7](../../../PRD.md#47-当前-epub-阶段安排)确认，后续材料问答的语境选择另行设计。

### 从讨论进入

例如，用户围绕某处表达完成问答后要求“把这个解释整理下来”。系统沿用相关原文引用和讨论，确定目标 Segment，再将理解整理成可独立阅读的 Analysis。问题焦点、理解所需的语境和最终 Segment 范围可能不同，不能仅凭最初选中的词机械确定讲解范围。

**初步建议。** 原来的阅读对话继续保留在材料下，通过来源关系关联生成的成果；不将含有其他位置问题的整条对话迁移为一个 Segment 的对话。原对话给出成果入口，阅读器原处也可以发现对应讲解。具体如何选取相关问答、记录整理依据，以及建立新片段还是复用已有片段，仍待细化。

两个入口可通过按钮或阅读 Agent 工具实现，共用已有成果能力。打开工作台不是内容保存的唯一入口；关闭侧栏或返回阅读，也不改变已保存成果的归属。

## 6 阅读辅助与页面职责

**方向已对齐，能力范围待定。** 阅读辅助可以按需查看指定范围的语境、读取已有讲解，并帮助建立学习目标或整理成果。是否需要单独的阅读 Agent、具体工具集合、权限和执行方式尚未决定；若“指定应用”还涉及外部应用，其接入范围应另行说明。

用户已明确关心 BYOK 成本与响应体验。**初步建议：** 系统能够确定的选区、出处和已有内容查询由应用直接处理；普通短问答尽量以合适材料直接回答，需要额外查阅或写入成果时再执行工具。侧栏呈现连续历史，不意味着每轮都必须发送全部历史。自动语境窗口、引用旧问题的方式、未读内容与剧透边界、调用预算均待讨论，不预先承诺固定调用次数或费用。

浏览归档、内容阅读和围绕内容工作仍可作为职责划分，见 [产品方向](../../../PRODUCT_DIRECTION.md)。阅读器既可呈现材料，也可产生引用和讨论；工作台可新建或修改成果。职责区分不要求独立页面，也不要求用户逐层进入。

未来可研究 asbplayer 的视频与字幕接入，以及通过 MCP 让外部 AI 使用应用资料和成果工具。这些是候选方向，不是本阶段依赖或已确认的兼容承诺。参考 [asbplayer 接口](https://docs.asbplayer.dev/docs/reference/external-api/)、[MCP 架构](https://modelcontextprotocol.io/docs/learn/architecture)与 [Yomitan API](https://github.com/yomidevs/yomitan-api)；具体接入能力与成本需在选定任务时核实。

## 7 后续讨论与收口顺序

讨论先明确材料身份与定位，再明确引用与消息、讲解形成与归属，以及具体阅读交互。实施切片可优先从原文接通已有工作台，再扩展材料对话，见[阶段入口](../../epub-reading/README.md)。

| 主题 | 需要覆盖的具体情形 |
| --- | --- |
| 材料身份与定位 | 托管副本、内容版本、呈现变化、移除内容后的引用 |
| 原文引用与消息 | 未展开侧栏、没有活跃线程、多线程选择、草稿未发送、手动粘贴、重合选区、一条问题引用多处 |
| 讲解形成与归属 | 新建或复用 Segment、范围调整、选取相关讨论、语境快照、部分失败、已有讲解发现与返回阅读 |
| 阅读交互与 Agent | 划线和高亮是否区分意图、标记聚合、侧栏尺寸与恢复、查词冲突、语境读取范围、权限及调用成本 |

用具体 EPUB 的阅读过程检验这些关系，再结合旧阅读器实现确定技术契约。不必在开始样书验证前穷尽所有例外情形；依赖未定行为的生产切片则先补齐契约。

确认的产品行为和不变式应同步到负责的长期规范，阶段任务与证据保留在本目录。本文不新增或关闭 PRD 的 TBD，也不代替 Occurrence 的类型、anchor、执行与审核契约讨论。
