## 已确定的输入

沿用 [PRD 4.7](../../../PRD.md#47-当前-epub-阶段安排)与[材料基线](MATERIAL_BASELINE.md)：Source 下的材料、不可变托管 EPUB、不可变处理版本、原始 spine 资源、码点定位。相同 Source + 完全相同输入字节复用材料；不同 Source 保留独立身份。更换字号／排版或重跑未来分词不改变版本。当前不做重新处理／版本切换 UI。

切片 0 的离线 JSON 与隔离页面只证明编译和定位；不能直接作为未清洗的上传接口、生产数据库格式或完整阅读器兼容承诺。

## 拟采用的数据关系

材料与不可变处理版本为逻辑职责，不要求每层各建一表。当前采用 Material 的不可变托管包加独立 ReadingPosition；schema 由后端统一生成客户端，前端不手写接口类型。

| 对象 | 最小数据 | 约束 |
| --- | --- | --- |
| Material | id、source_id、title、source_sha256、version_id、product_sha256、contract_version、原 EPUB BLOB、压缩编译产物 BLOB、created_at | 同 Source 按源摘要判重；标题或文件名不判重；所有读取校验所属 Source 仍存活 |
| 材料版本（包内） | 独立 version_id、contract_version、product_sha256 及包内资源 | 发布后正文、结构与资源不可变；同文件跨 Source 的版本身份独立，产物摘要可相同 |
| 版本内资源（包内） | id、manifest 身份、href、title、text、text_sha256、受控 HTML／CSS／属性 | 资源身份不由目录显示名称决定；spine 出现位置保存在有序章节 parts 上 |
| 阅读章节组织 | version_id、chapter_key、原目录标题、目录层级、按 spine 排序的资源范围 | 可跨多个资源，也须表达同一资源中的 fragment 边界；属于呈现索引，不改写资源正文或引用身份 |
| ReadingPosition | material_id、version_id、chapter_key、资源出现位置、resource_id、正文 offset 或图片定位、updated_at | 校验版本／资源；章内百分比由内容位置派生，不作为唯一恢复依据；具体字段在 schema 定稿时固定 |

图片采用受控 data 资源、包内 CSS 导入有界展开；不将 ZIP 内路径拼接磁盘路径或开放任意文件读取。当前原始字节及编译包都归 SQLite 事务管理，不额外维护资源文件目录。未来 Segment 出处和消息引用在各自切片增加，切片 1 不预建聊天外键、tokens 或 Lexeme。

## 拟采用的 API 边界

| 操作 | 草图 | 说明 |
| --- | --- | --- |
| 导入 | `POST /sources/{source_id}/materials` | 单 EPUB 上传；返回既有或新建材料的事实及警告，区分无效文件／不支持与重复导入 |
| 来源材料列表 | `GET /sources/{source_id}/materials` | 排除不可用或删除对象，不把构建中半成品当成可读材料 |
| 打开材料 | `GET /materials/{id}` | 返回确定版本、章节顺序与当前可恢复位置 |
| 章节读取 | `GET /materials/{id}/chapters/{chapter_id}` | 校验完整归属链，返回本章 parts 与所需资源正文／渲染信息，不在打开材料时发送全书 |
| 保存位置 | `PUT /materials/{id}/reading-position` | expected_revision 条件更新；校验版本、章、part、资源及文字／图片位置，陈旧写 409，不静默覆盖 |

所有业务逻辑进入 `services/`，API schema 从 Pydantic 导出并运行 `just gen-api`。UI 服务端状态经 TanStack Query。原型选择 JSON 的入口不会成为正式导入体验。

## 导入原子性与文件生命周期

采用原始 EPUB 请求体（`application/epub+zip`），受限流式读入内存，默认原文件上限 32 MiB；不引入 multipart 依赖。计算源摘要、受限编译后，在短数据库写事务内核对 Source 存活、判重并同时保存原字节、编译产物和材料身份。编译移出事件循环，展开及产物大小有上限。失败／取消没有发布事实，并发重复导入只保留一个对象。

工程取舍：首轮将托管副本和压缩编译产物存为 SQLite BLOB，使发布只有一个事务边界，避免 staging 文件与 SQLite 的双提交、进程中断后的无主文件及误清理。Source 在编译期间被删除时，发布事务拒绝迟到结果；崩溃由 SQLite 回滚未提交写入。代价是数据库包含书籍内容、体积增加；备份仍遵循现有 WAL 一致性规则。将来确需外置资源时另设计可恢复发布协议，不能以清理文件改变用户内容保留语义。

按材料独立托管，不预建跨 Source 物理去重和引用计数。数据库采用增量迁移，保留现有 Source／Segment／Analysis 数据，不因本阶段重建用户日常库；从空库迁移与现有库升级都要验证。

## 已确认的产品边界

1. **入口与导入反馈：** 来源详情放“导入 EPUB”及材料列表，成功后直接打开，重复导入定位已有书；错误说明不支持原因。本切片不默默创建来源。
2. **基础恢复方向已确认：** 用户认可横竖排，授权工程判断分页与恢复；先做滚动，以拼好的章节组织进度，保存视口附近正文位置，重新打开和换字号／行距后尽力回到附近。百分比辅助显示，不单独承担定位；不承诺相同显示页码。阅读设置可随材料恢复，作者 CSS 仍受已声明的兼容范围约束。
3. **独立材料移除：** 首轮暂不提供该入口，不混合“移除可读原书”和“删除学习成果”。
4. **Source 删除：** 延续既有来源删除确认，新增列出材料数量和原书不可再打开的影响；材料随来源不可见，托管字节暂不物理清理。来源所属片段／讲解仍按现行规则处理。材料对话尚未存在，未来切片须再补其删除影响。

章节名采用原书目录章名，不增加手动命名或自动翻译。用户明确实验室 UI／UX 仅供试验；正式界面沿用应用现有风格，集中于目录、正文、阅读设置及进度，不暴露调试 JSON 或自检操作。浏览器验收在独立测试数据库进行，不写入用户日常学习库。

## 章节、注音与恢复的实现边界

章节组织在切片 1 作为基础阅读的必需项，不能把切片 0 按 spine 逐个打开的试验 UI 直接当作交付。优先利用 EPUB nav 目录，兼容 EPUB 2 NCX；目录提供标题与入口，spine 提供内容次序。以有效目录入口界定连续阅读范围，把中间未单列目录的正文与插图一起呈现。保留目录层级，不把嵌套父子项都当作重复正文；同资源 fragment、前置内容、缺失／无效目录、重复或逆序目标要有针对性测试和显式回退。已有[样书与旧实现调查](CHAPTER_RESEARCH.md)；旧实现只合并图片和随后的一份正文，不能直接照搬为完整目录分章算法。

拼章是显示组织，不能把合并后字符串的全章偏移当作原文引用身份。一个章可含多个有序资源范围；章名改变不使引用失效。跨资源划选未来表示为有序的资源局部范围，不伪造全书坐标。多资源连续渲染也须处理样式作用域与重复 HTML id，不能直接字符串拼接各章 HTML 后声称隔离或定位仍然成立。

阅读恢复与精确引用采用不同容错：引用必须严格核对快照；阅读位置允许回到同版本、同章的附近可见位置并明确降级，不得把这种容错用于消息引用。插图处无正文时保留资源／图片的稳定位置与局部比例；文字百分比不应让纯图片章节除零、丢失位置或虚构“已读”。同一资源多次出现时，阅读进度还需识别其在当前章中的出现位置。

字号／行距／横竖排切换前记录最近的正文或图片锚点，布局及图片尺寸稳定后恢复；页面观察不会因为程序恢复滚动而立即用中间位置覆盖保存值。切片 1 按材料保存最后位置并携带逻辑章；2026-10-11 章节记忆扩展为同时保留各章最后位置，当前产品规则见 [PRD 4.7](../../../PRD.md#47-当前-epub-阶段安排)。章内百分比是辅助指标，不预建每章读完状态、阅读时长或统计系统。

后续振假名保留原书优先。自动注音数据附着于版本／资源范围，渲染层与原书注音分别标识；与原书 ruby 重叠的候选不覆盖、不叠加。接入时扩展当前 DOM 适配边界，覆盖自动注音开关、局部 token 包装、跨节点及原书 ruby 重叠的往返测试；现在不安装分词器或建立词汇体系。
