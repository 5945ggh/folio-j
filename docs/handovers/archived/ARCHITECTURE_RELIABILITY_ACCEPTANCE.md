# 事务、后台执行与阅读会话可靠性验收

日期：2026-10-28。实施起点：本地 `main` 的 `9b475f8`，包含整站主题与 Agent 上下文整合。模型设置分支未纳入本轮。范围为架构审查第 1、2、3 项；第 4–6 项继续后置，未修改 TBD、数据库模型或依赖。

## 实现

- 书名／封面保存把全书解码移到写事务外，锁内重验来源、材料身份与 metadata revision；原子保存并在提交前构造响应。
- 统一监护聊天、翻译、验证的进程内任务。扫描失败退避恢复，意外任务退出补齐本地终态；补偿失败只重试状态写入，已保存成果保留。健康接口报告当前状态和脱敏故障历史，关闭时等待任务释放。
- App 和阅读会话宿主共用 Router 路径分类，片段尾斜杠往返保留 iframe、Document、阅读位置及搜索草稿。

实现规则见[架构](../../ARCHITECTURE.md#46-job-与-workerjobs)。健康响应变更已通过 `just gen-api` 同步 OpenAPI 和前端生成类型。

## 回归与修复前反证

| 范围 | 新增验证 | 旧行为反证 |
| --- | --- | --- |
| 元数据事务 | 在工作线程暂停 bundle 解码，无关来源更新可完成；返回当前来源／使用状态；同目标 CAS、来源／材料删除及五项不可变身份变化仍拒绝陈旧保存 | 子进程加载 `9b475f8` 的 metadata 实现，同一回归在无关来源更新的 `BEGIN IMMEDIATE` 超时 |
| 后台扫描 | 真实离线 API 在聊天／翻译扫描首轮故障后仍自动完成；连续失败指数退避封顶、唤醒不绕过退避、恢复后重置间隔；翻译积压连续处理，仅空闲时等待扫描间隔 | 加载旧聊天 runtime 后任务一直 queued，5 秒等待超时，并出现未观察的任务异常日志；移除队列继续唤醒后，新增积压测试第二项超时 |

## 工程与浏览器验证

- `just gen-api` 通过，健康响应契约与前端生成类型一致。
- `just lint`、`just test` 最终收口通过：后端 825 项通过、1 项未分发的私有样书测试跳过，前端 636 项通过。
- `just build` 通过；`just check-docs` 检查 97 份文档、1070 个本地链接，全部有效。隔离 worktree 只读链接主工作区被 Git 忽略的历史验收附件，未复制用户数据库。
- `just test-browser` 完整 85 个 Chrome 配置通过，包含桌面、窄屏、横竖排、主题与减少动态效果配置。新增尾斜杠往返随真实 App 路由回归执行，核对隐藏期间与返回后的 iframe／Document 身份、滚动位置及搜索输入草稿。
- 额外生成阅读页预览；目视检查 390px 横排与 1280px 竖排：深色正文、原书注音、目标段落标记及顶部／底部工具栏正常，精确返回仍定位到第 350 段附近。
- `git diff --check` 通过。

## 独立复审

元数据与路由复审未发现阻断性回归。后台复审发现取消异常补偿后的健康状态残留问题，修复后通过补偿等待／退避期间停止的两项真实 API 回归；复审独立运行 supervision 与 health 共 14 项通过，确认无遗留阻断。后续补充的翻译积压回归通过，并确认撤去唤醒时会失败。

## 验证边界

所有测试使用临时数据库、合成材料或离线 API／模型 adapter，未访问用户数据库或真实模型。元数据仍需解码全书取得原书信息；本次验证其不占用写锁，未测量真实大书的性能收益。后台诊断不持久化到数据库，进程重启后重新统计。浏览器验证范围为本机隔离 Chrome，其他浏览器与实体触屏未验证。
