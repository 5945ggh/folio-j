# 后端细粒度读取性能验收

日期：2026-10-28。实施基准：本地 `main@7747434`，已包含前三项可靠性修复。本轮覆盖位置保存、章节注音和单图内容读取；未修改数据库格式、API 响应结构、依赖或 TBD。Reader 协调与翻译缓存归属继续后置。

## 实现与取舍

重复读取的主要成本来自完整 EPUB／NLP 解码，以及按图片 ordinal 从头扫描 HTML。位置写事务少读一次 BLOB 能减少 SQL，但短样本未显示稳定延迟或峰值收益。最终采用应用实例持有的 `ReaderViews`，保留校验后的私有编译视图、紧凑不可变 token 和惰性图片索引；三条生产服务必须显式接收该 module，旧流程只留在测量脚本的冻结对照中。

缓存命中仍核验来源、材料和确切代次，慢计算后复查，位置写事务重验身份及 CAS。默认保留预算为 128 MiB／8 条目，另有 8 个待处理缓存键、2 项并发计算和 32 个完整请求上限。章节返回独立模型；同身份加载合并，取消撤回排队投影，关闭等待已运行线程后再释放数据库。规则见[架构](../../ARCHITECTURE.md#313-全量注音与分词资产)。

收益集中于重复读取和并发请求。建立缓存会增加部分首次请求的 CPU 成本，并保留进程内存。超预算视图不驻留；搜索、图库列表、正文打开及其他资料路径未在本轮迁入。

## 方法与样本

真实服务运行在临时 SQLite WAL 中，未访问用户数据库或模型。确定性合成书包含完整非空 token 覆盖与不同的随机 PNG，另测本机只读 EPUB。报告只含规模、摘要和指标，不含正文或图片。运行入口见[开发指南](../../DEVELOPMENT.md#后端细粒度读取测量)。

| 样本 | 正文码点 | token | 图片出现项 |
| --- | ---: | ---: | ---: |
| 小 | 4,000 | 2,000 | 2 |
| 中 | 48,000 | 24,000 | 8 |
| 大 | 180,000 | 90,000 | 16 |
| 真实样书 | 88,779 | 60,000 | 17 |

主对照顺序运行冻结流程与最终实现；每个操作 1 次冷请求、3 次暖请求，另测 4 请求同身份并发。每组有独立 runtime。冷指该 runtime 无缓存，OS／SQLite 页缓存仍可能热。注音目标为首个含正文的章，最长章另测；图片首／中／末均测，表中列末图。两组源码摘要及全部 fixture 摘要一致。测量后的代码格式整理不改变执行流程。

latency 不含 HTTP 序列化、浏览器或 fixture 构造。tracemalloc 独立执行：冷峰值包含建立缓存和响应；冷后存活量在释放响应并 GC 后记录，含 runtime 及其他存活基础设施，不是精确缓存账面值；暖峰值只计本次新增分配，不能当总内存。RSS 是含构造及此前操作的进程高水位，不用于声称请求内存收益。

### 最长正文章补测

真实样书最长章 `chapter-2` 有 43,967 码点、29,647 个返回 token。每次冷／暖／内存／并发响应均核对完整 token 数，两组源码与 fixture 摘要一致；优化暖请求仍无 BLOB SELECT／解码。独立报告未覆盖主对照。

## 发现与回归

- 首版缓存直接保留 Pydantic token 树，大样本的 book／asset 在 128 MiB 下互相淘汰，暖注音约 351 → 790ms且每次解码。改为紧凑不可变 tuple，保持原预算，最终暖请求不再解码。
- 独立复审复现热缓存投影不受 pending key 上限控制，20 个已取消调用仍排队执行。增加完整请求准入、撤回排队投影、等待运行中线程；超额 503、取消释放名额及只执行已开始投影均有回归。
- 独立测试发现关闭遗漏缓存命中后的投影线程，补齐完整 operation 生命周期后，关闭等待实际线程结束。
- 新回归覆盖 SQL／解码计数、跨章并发、返回值隔离、代次切换、热缓存与解码期间删除、版本及写锁竞争、CAS、Unicode／图片进度、容量、失败、取消和关闭。恢复旧门禁／Pydantic 缓存的子进程反证均失败，新实现通过。
