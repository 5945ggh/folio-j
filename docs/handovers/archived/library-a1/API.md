## 候选顺序与安全边界

`COVER_RULE_VERSION = 2`。先尝试 EPUB3 `cover-image`／EPUB2 `meta name=cover` 的有效明确声明，再依 spine 阅读顺序遍历 XHTML 中的 `img`／SVG `image` 包内图片引用，最后补充 manifest 中图像资源的稳定顺序。引用顺序按文档遍历，重复候选只尝试一次；声明、引用或首图无效时跳过该候选，继续尝试后续可用图片。

“第一张”指上述候选顺序中的首张可用图，不依赖 ZIP 成员的物理排列。沿用包内路径、字节、展开比例、静态 PNG／JPEG、4 MiB 与 1600 万像素限制；不请求远程图片，不增加格式支持或图像解码依赖。归档全局安全检查失败时整体拒绝，不通过候选回退绕过限制。提取诊断保留失败原因，不只归为无封面。

图片引用必须指向 manifest 声明的包内资源；SVG `image` 支持 `href`／`xlink:href` 引用静态图片，不接入 SVG 封面。成功诊断记录候选来源 `declared`／`spine`／`manifest`，有跳过候选时附加去重后的 `skipped` 原因；全部失败区分 `no_images`、格式／资源／路径／结构问题、`unsafe_archive` 与 `invalid_package`。

JPEG 使用有界 marker／SOS 扫描，校验帧尺寸、非零且有效的组件声明、扫描组件归属与非空熵数据，要求 EOI；允许 EOI 后最多 1024 字节的尾随内容。两本本机样书分别有 8／1 字节尾随内容，旧版以文件末尾必须为 EOI 判断而误拒。当前检查仍为标准库结构校验，不宣称完整像素解码；浏览器加载失败继续占位并可重试。

## 缓存与目录

`MaterialCover` 增加 `rule_version` 与 `diagnostic_reason`，迁移 `0009_cover_rules` 接续 `0008_material_usage`，只增加列；既有缓存标记规则版本 `1` 与诊断 `legacy_cache`。旧成功和失败缓存都在下次请求时按版本 `2` 懒重建，不改原始 EPUB、Material 身份、不可变编译产物或阅读位置。

目录封面 URL 使用 `/api/materials/{id}/cover?v=2`。仅已确认的当前规则版本失败缓存将 `cover_url` 置为 `null`；旧版本缓存应仍提供当前版本 URL，使已有书籍能重新提取。版本参数用于资源缓存更新，服务端以自身当前规则校验缓存，不接受客户端任意改变提取规则。

前端封面失败状态绑定具体材料和资源 URL，URL 更新后允许重试；加载失败显示简洁占位，三点菜单提供“重试封面”并附带重试参数请求资源。无需删除书籍重导或清空用户库。服务端封面与缓存访问保持完整 Source 可见性检查，提取后写入前重新检查可见性与当前缓存版本。

## 验证要求

合成 EPUB 覆盖明确声明、缺失／坏声明、spine 首图、坏首图继续回退、manifest 补充、无图、全局安全拒绝，以及旧成功／失败缓存和当前失败目录 URL。新列从空库与旧 schema 均可迁移，生成客户端同步；两本真实样书的浏览器封面与旧缓存恢复单独验证，留用户本机。
