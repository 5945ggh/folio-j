## 1. 范围与已认可方向

已认可的方向：

- 翻译是一项独立能力，首个实现复用现有 LLM，后续可以接专用翻译模型或服务。
- 成功译文在本地保留，关闭或刷新后能够找回；取得译文不自动创建 Segment；成功译文的正文标记与本章记录按 PRD 4.8 的后续扩展显示。
- 用户可将对应原文保存为 Segment，并采用已有译文；原文、出处和本次结果保持关联。
- 朗读优先照顾片段学习，同时保留未保存选区的直接朗读。浏览器方式先独立可用，远端 TTS 由用户继续调研。
- 配置区分接入信息、能力配置和功能默认值。浏览器声音属于设备能力，不要求配置 Provider。

本轮实施范围：

| 路径 | 首轮范围 |
| --- | --- |
| 新翻译 | EPUB 中有可靠出处的选区；沿用同章连续目标及当前原生选区能力 |
| 找回译文 | 原处再次选择、材料内“最近翻译”、确切结果读取 |
| 转为学习片段 | 新建带出处的 Segment，或选用同一确切出处的已有 Segment；显式采用译文 |
| 设备朗读 | 当前阅读选区、译文对应原文及已有 Segment 原文；播放、停止、重播、语速和试听 |
| 接入设置 | 复用已有文本 Provider／模型，增加翻译方案与独立偏好；本机保存声音选择 |

Segment 页面直接生成新译文、无材料出处的任意文本翻译、批量翻译、整章翻译、材料对话、远端 TTS、端侧模型安装管理和音频文件保存留到后续切片。首轮采用译文适用于已有 Segment，设备朗读也适用于手动 Segment；这两项不要求增加第二种翻译任务目标。

## 3. 翻译目标、任务与成功结果

### 3.1 目标是值，不先建立学习对象

翻译目标包含 Source、Material、不可变材料版本、有序资源出现位置与码点范围、组装规则及 NFC 原文快照。复用出处验证和值结构，关系分别表达；不复用近似阅读位置，不让 SegmentProvenance 的归属要求泄漏到翻译入口。

服务端受理时核对来源和材料存活、目标范围及原文一致性。相同文字出现在不同位置、不同材料或重复 spine 中，仍是不同目标；显示章名、书名、屏幕位置和注音代次不参与身份。

### 3.2 三类信息分别保存

以下名称是方案工作名，正式命名在规范同步时确定，不是已存在的 ORM 或公开类型。

| 信息 | 主要内容 | 生命周期 |
| --- | --- | --- |
| TranslationTask／翻译任务 | 请求身份、目标、语境与配置快照、状态、执行身份、关联 Run、错误及时间 | 受理即持久化；承担重连、停止与幂等核实 |
| TranslationResult／成功译文 | 独立结果身份、目标快照、完整译文、目标语言、实际语境、实际方案／模型／参数／模板版本、调用来源及生成时间 | 完整成功后生成；正文及输入快照保持不变 |
| 采用记录 | 结果身份、Segment 身份、动作、实际采用的译文及可选语境、请求依据和操作时间 | 记录用户把哪份结果用于哪个片段；与写入原子提交 |

目标直接作为任务和结果中的版本化值保存，首轮不增加通用引用注册表。Run 记录调用；成功结果提供用户可找回的内容；采用记录连接学习资料。结果不能只存在 Run.output_text 或浏览器 Query 缓存里。

结果与 Segment 的关联按身份对去重，同一关联可以有多次独立的采用操作凭据。关联用于找回结果，操作凭据记录每次明确提交的内容，不能用更新关联的方式覆盖旧凭据。

采用前允许用户修改译文草稿。保存记录同时保留原结果身份和实际采用内容，不能把改写后的文字冒充模型当时的原始输出。再次翻译产生新结果，不改写旧成功结果、采用记录中的提交快照或 Segment 当前译文字段；首轮不提供原地编辑成功结果的入口。

采用后的日常编辑继续修改 Segment 当前字段，本轮不增加完整的用户编辑历史。采用凭据保留当次写入，之后重新翻译不覆盖片段当前内容。

### 3.3 LLM 首个 adapter

翻译 module 的 interface 接收目标文本、目标语言、必要语境和所选方案，返回译文或明确失败。LLM adapter 负责提示词、协议和参数映射；页面不知道 Chat Completions／Responses 的消息结构。未来专用服务接入同一翻译 interface，不要求它拥有聊天历史、prompt 或可选模型。

首轮沿用现有 llm 调用入口，每次实际模型调用产生 Run。翻译使用独立版本化模板，要求只翻译目标、参考语境、保留人称和语气、不补写情节、不附加教学分析；原文中的命令只是待译内容。无需工具调用或强制 JSON，应用负责组装结果元数据。

请求不自动携带其他线程历史、讲解风格、学习者画像或全书内容。译文以普通文本呈现，不执行 HTML；空输出、截断、拒绝或不完整响应不发布为成功结果。允许流式观察，部分文本标明未完成，不能用于“采用译文”。

未来 adapter 应明确是否支持独立语境。选中的方案不能满足当前请求时，在发送前提示调整；不把语境拼成额外待译文本，也不静默丢弃用户提供的语境。术语表、专有词翻译和更多参数在对应接入出现时扩展。

### 3.4 语境建议默认值

建议翻译拥有独立偏好：默认日译简体中文，自动摘录前文最多 3 句且不超过 200 个 Unicode 码点，后文默认 0。两侧均可手动扩展、编辑或清空；取文沿用 C2 的近端优先、句界和文本整理规则，具体参数不与 Segment 保存偏好绑定。

目标始终是所选原文。选到半句话时可以提供“补全句子后翻译”，用户选择后才建立新目标；辅助语境不扩大译文范围。定位用 prefix／suffix 不自动发送，自动语境也不以已滚过某处推断已读。有限输入只能控制应用发送范围，不能保证模型完全不使用自身已有的作品知识。

提交时冻结实际输入；之后改变全局偏好或继续阅读，不修改进行中的任务。已有结果保留当时的语境。用户手动更改语境后，可明确重新翻译；旧结果仍可读，但要标明其使用的是原语境。

## 4. 留存、复用与任务恢复

### 4.1 找回成功结果

建议成功译文不设自动过期时间，随本地数据备份。它们不计入学习片段数量；成功且可定位的结果按确切出处显示翻译标记，具体行为见 PRD 4.8。

- 原处再次选择并点击“翻译”时，先读取该确切目标的已有结果；有结果就展示，并提供“重新翻译”。查询失败时显示查询失败和重试，不直接转成一次新的付费调用。
- 材料内提供有界分页的“最近翻译”，展示原文摘要、译文、生成时间及实际方案，可打开结果、返回原处、保存为学习片段。
- 同一目标多次翻译形成结果列表，默认打开最近一次成功结果；允许选择历史结果。不同语言或语境有明确说明，不把旧译文冒充本次新配置下的输出。
- 关闭卡片、刷新或改换当前选区只改变呈现；重新打开能找到已成功结果及进行中任务。迟到响应不得替换用户后来选中的目标。

改变默认模型、翻译语言或语境设置不会自动重新生成。用户查看历史结果无需原 Provider 继续可用；生成新结果才要求有效接入。

### 4.2 区分三种重复

| 情况 | 处理 |
| --- | --- |
| 同一提交的响应丢失或双击 | 同 request_id 与相同请求返回同一任务／结果；同键异文冲突，不再次调用模型 |
| 再次回看同一出处 | 读取已存结果，不产生新 Run；历史结果按实际输入展示 |
| 用户主动重新翻译 | 新 request_id，固定新输入并允许产生新结果，即使输入与历史相同也不被缓存拦截 |

首轮不做跨材料或跨位置的内容级缓存合并。若后续引入推理缓存，其身份至少包含目标文本、实际语境、语言、接入／模型配置、参数和模板版本；缓存复用不能合并用户的出处记录。

### 4.3 受理、停止与提交

建议增加专用的持久翻译任务，采用 SQLite 和进程内 worker，复用可独立使用的预算、进程锁和调度基础。不上通用任务平台，不创建隐藏 ChatThread；Run 的翻译任务关联与既有 chat job 关联明确区分。

状态按 queued、running、stopping 及 succeeded／failed／cancelled／interrupted 表达。建议首轮每任务最多一次实际模型请求；应用和 SDK 均不自动重发生成。响应不确定时先核实本地任务，不承诺外部请求恰好执行一次或取消后一定不计费。

- 受理：检查可见性、目标与预算，固定输入及配置，以 request_id 幂等创建任务。
- 执行：检查任务仍有效，实际调用前创建 Run；网络等待不持有数据库写锁，翻译和讨论的模型调用共用总并发预算。
- 成功：在短事务中复查执行身份、Source／Material 存活，保存完整结果并完成任务。结果发布和任务成功共同提交，重试不重复发布。
- 关闭：不等于停止。后台继续处理，结果可从最近翻译恢复；界面提供明确停止动作。
- 停止：先撤销持久执行身份，再尽力取消底层调用。停止提交后到达的响应不得发布结果；若成功已先提交，则返回已成功状态和结果。
- 重启：未完成任务标为 interrupted，不自动重新调用。用户可明确重试，创建关联原任务的新请求；旧失败／中断记录保留。

超长目标、调用时限、输出预算和待处理数量必须有界校验，不静默裁剪目标。第 11 节的候选初值集中配置并用于离线边界验证，真实模型实测后可调整；不能照搬出处能保存 100000 码点这一存储上限。

## 5. 从成功译文建立或选用 Segment

### 5.1 新建：一次明确保存

用户在一份成功结果上点击“保存为学习片段”：

1. 固定 result_id，按其确切出处查询已有 Segment；不用此刻可能已经改变的 DOM 选区。
2. 展示轻量保存表单：原文和出处只读，译文预填当前结果；本次实际语境预填到对应字段，用户可修改或清空。备注可选，不要求模型设置。
3. 有候选时提供“选用已有片段”与“另存新片段”，不自动合并。默认采用当前所见结果，不再次运行语境预装覆盖它。
4. 保存时同时创建 Segment、精确出处和采用记录，固定原文；失败全部回滚，原译文与草稿仍可找回。
5. 成功后留在原文，提供“打开片段”；重复点击显示已经保存的去向，用户明确另存时才发起新的创建。

草稿改写只作用于采用副本。用户若要改变目标原文，应重新选择目标；不能沿用旧译文来源，把另一段原文挂在同一精确出处上。

创建接口继续具有 C1 的请求幂等能力，但需要在同一事务内保存采用关系。不能先创建 Segment，再另发一个无法原子核实的绑定请求。服务器验证结果、Source、材料与目标一致，不只信任前端携带的文本或 result_id。

### 5.2 选用已有：关联与覆盖分开

候选只来自同 Source 下确切出处相同的活跃 Segment。同文不同位置、无精确出处的手动片段和近似范围不进入自动候选。

选择候选本身只确定保存目标，不写入字段。已有译文为空时，表单可预选“采用这份译文”；非空时默认仅关联并保留当前译文，替换前展示新旧内容。语境始终默认保留，包括用户可能主动清空的字段；采用本次语境需单独选择。关联、采用译文及可选语境在同一次明确保存中完成，无需先关联再去另一页修改，未选择的字段和备注保持原值。

关联的结果从 Segment 中可找回，Segment.translation 表达当前采用／编辑后的译文，两者分别维护。一份片段可以关联多次翻译；选择不同结果阅读，不自动改写当前译文字段。

### 5.3 并发与幂等

修改已有片段的采用请求携带 request_id、result_id、segment_id、预期原文摘要、expected_revision、明确要写入的字段及内容。事务内核对目标身份、祖先存活和版本，按提交字段写入并保存采用凭据；未提交的字段保持原值。

所有会修改该片段译文或语境的编辑入口共同使用版本条件，不能只给“采用译文”单独加检查，仍让旧编辑页覆盖新结果。任何并发修改导致版本陈旧时返回冲突，保留草稿并展示当前内容，由用户核对后重新提交；不自动重放覆盖。

同一请求的成功凭据核实先于“新请求”的陈旧版本检查；重放须仍满足 Source／Segment 可见性。相同 request_id 改变结果、目标或采用内容返回冲突。采用记录与字段更新原子提交；失败不留下伪关联，重复核实不重复创建片段或推进 revision。

只关联结果而不修改字段的操作仍需验证目标和可见性，但不伪造内容修订。再次关联同一结果与片段返回已有关系；后续显式改用译文是独立的有版本条件的动作。

## 6. 删除与保留

删除影响预览须说明未保留译文的影响。只关联而未采用为当前译文，也算用户明确保留；已关联结果从活跃片段中可读。首轮不提供独立的批量译文清理；以后添加清理时，必须说明与采用记录的关系。

| 操作 | 成功译文与关联 | 运行中任务 |
| --- | --- | --- |
| 删除材料 | 未关联活跃 Segment 的结果逻辑删除、日常入口不可见；已关联结果保留快照，从仍可见的 Segment 读取，返回原文显示材料已删除 | 阻止新任务，撤销未完成任务，迟到结果不得发布 |
| 删除 Segment | 该 Segment 的关联不可见；若材料仍活跃，结果继续可从最近翻译读取；其他活跃 Segment 的关联保留 | 独立材料翻译不因单个 Segment 删除而取消 |
| 删除 Source | 该来源的结果、采用入口及关联调用详情均不可见，不因其他入口恢复 | 阻止新任务并撤销未完成任务 |
| 删除／停用 Provider 或模型 | 保留成功译文、采用副本和历史非敏感配置；新生成按配置有效性检查 | 沿用已受理快照；删除与凭据清理必须检查活动翻译任务 |

材料删除后，只能通过同 Source 下仍活跃的采用关系读取保留结果。若最后一个活跃 Segment 也被删除，则结果不再具有可见入口。直接按 result_id、task_id 或 run_id 请求，同样经过这些归属门禁；不能只保护列表。

对已经成功转为 Segment 的请求，材料删除后仍可按成功凭据核实保留的 Segment；新建或新关联请求继续要求材料可校验且活跃。删除后重导产生的新材料，不接回旧翻译记录。逻辑删除不承诺立即从磁盘或备份抹除内容。

## 7. Provider 与设置的增量调整

### 7.1 三层职责

| 层次 | 负责内容 | 首轮承载方式 |
| --- | --- | --- |
| 接入配置 | 名称、接入类型、地址、凭据、启用状态及配置版本 | 现有 Provider 保留 ID 与凭据引用，作为已支持的文本接入 |
| 能力配置 | 通过该接入执行某能力所需的参数与限制 | 新增翻译方案：首种 adapter 为 llm，引用已登记模型；设备朗读由浏览器提供 |
| 功能默认值 | 点击翻译、朗读、讲解、讨论时选择什么 | 增加默认翻译方案和翻译偏好；设备声音与语速在本机保存；已有三种模型用途保留 |

“翻译方案”拥有独立身份、名称、adapter 类型和 revision，首版围绕一个默认配置组织，不建设复杂多方案管理。首轮只开放 LLM 类型，引用现有 ProviderModel，不复制 endpoint 或凭据。若增加翻译专属参数，保存在方案中，不反写其他功能共用的模型参数。未来专用服务可增加不同的类型化配置，不要求填 model_id。

类型与能力的变化放在 adapter seam 上：未来协议、模型发现或声音发现属于对应 adapter。首轮复用现有文本协议字段与模型发现；不把 Provider 表一次性改造成任意 JSON 配置仓库，不为尚未选定的服务添加空表单。

同一供应商以后可提供文本和语音能力，但是否共享账号、端点或凭据由具体接入决定，不能仅因品牌相同自动合并。浏览器朗读不进入 Provider 列表，不创建模型登记或远端调用 Run。

### 7.2 设置页面职责

本节规定设置内容和保存行为，具体布局由前端施工协调，不要求重画现有页面。

| 设置区域 | 用户可操作内容 | 保存位置与行为 |
| --- | --- | --- |
| 服务接入 | 现有文本 Provider、模型登记、普通／流式能力验证 | 继续由后端保存；显示具体能力，不用一个“连接成功”代表翻译或语音均可用 |
| 翻译 | 单个默认方案、目标语言、前后文默认预算；模型可明确选用当前讨论模型 | 后端持久化；与讲解风格、讨论模型及 Segment 语境偏好分开 |
| 朗读 | 设备方式、日语声音、语速、试听、声音来源 | 当前浏览器保存；重新检测声音后解析偏好，不承诺跨设备复现 |

初始未选翻译方案时提供“用当前讨论模型建立翻译方案”的明确动作。操作创建引用该具体模型的方案，之后改讨论默认值不跟随改变翻译方案；没有可用模型则引导配置。翻译默认值独立于现有 analysis／chat／extraction 默认值。

语境建议默认见第 3.4 节；目标语言的初始值建议为简体中文，独立于讲解语言。修改偏好不发起模型调用，也不覆盖当前翻译或片段保存草稿。每个设置分组独立保存、检测陈旧版本，冲突保留本地草稿；浏览器声音不可同步成所有设备的可用声音。

翻译可用性先通过现有文本验证与真实选区路径检查。独立“示例翻译”不是本轮必要入口；后续提供时，只在用户点击后调用模型并产生 Run，不混入最近翻译，也不宣称一次生成证明翻译质量或其他能力。

### 7.3 迁移与失效

- 保留现有 Provider、ProviderModel、用途默认值和历史 Run 身份，不通过删除重建实现页面重组。
- 新增翻译配置采用增量迁移；旧库迁移不自动创建新的模型调用，不自动开启翻译，也不改变已有讨论／讲解选择。
- 任务受理时解析方案并固定实际 Provider、模型、协议、参数、模板与凭据内部引用。执行时不重新读取变化后的默认值。
- 配置失效保留旧选择并提示修复，不悄悄换模型、换协议或换 Provider。Provider／模型删除检查同时覆盖验证、聊天与翻译，避免存在活动翻译时删除所需凭据。
- LLM 翻译继续复用 Run；未来非 LLM 翻译需要有真实调用记录，但不伪造 prompt、模型名或 token 用量。具体记录形态随第二种 adapter 落实，不提前重写全部 Run schema。

## 8. 浏览器朗读的本轮契约

设备朗读是独立能力，翻译卡可调用它朗读目标原文；无需先翻译、保存或配置模型。朗读 module 的 interface 对页面提供目标固定、播放状态、停止和重播，adapter 内部区分设备合成与未来可持久音频，不能统一假定每次都有音频文件。

- 通过 SpeechSynthesis 的声音列表及变化事件检测可用声音，优先提供本地日语声音；声音缺失明确提示，不自动选择其他语言。
- 记住用户选中的声音、语言及语速，运行时重新核对。原声音不可用时提示重选，不把旧设备偏好当作当前能力证明。
- 一个应用页面内只有一个当前朗读目标；新播放停止旧播放，旧事件按播放代次隔离。切换选区不改变正在朗读的原文，停止后迟到事件不能恢复播放；离开阅读／片段页面停止。首轮不保证多个浏览器标签页之间的播放互斥。
- 从用户点击发起播放，以实际开始、结束和错误事件更新状态。关闭译文卡可继续播放，但仍保留可找到的紧凑控制；直接朗读也有控制入口。
- 首轮朗读基字原文，排除 rt／rp 和界面附加文字；不把原文整体替换成自动注音。原书 ruby 指定读法的可靠应用单独验证，当前不承诺读音正确。
- 暂不保存音频。保存 Segment 时保存原文和可追溯结果；设备声音属于偏好，不能显示成“已保存音频”。未来用户明确保留的远端音频应免受普通缓存清理影响，具体存储待选型。

未来接入远端 TTS 后，可提供显式启用的“失败时尝试设备朗读”；未启用时只提供切换入口。本轮没有远端主方式，因此界面称“设备朗读”，不增加尚不可执行的自动 fallback 开关。

证据：[Web Speech API 规范草案 §4.2](https://webaudio.github.io/web-speech-api/#tts-section)定义播放控制、声音和事件，没有直接返回音频字节的接口；[MDN SpeechSynthesis](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis)说明声音列表与变化事件；[localService](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice/localService)区分本地和远端合成服务。2026-10-23 核对；规范为社区组草案。日语声音、质量、网络依赖及设备差异仍需真实浏览器试听，不能以 API 存在推断离线可用。

## 9. 用例验收矩阵

此表是后续验收要求，本轮未实现或运行这些用例。

| 场景 | 应观察到的结果 |
| --- | --- |
| 初次翻译、关闭、刷新再打开 | 同一成功译文可恢复，不重复调用；未创建 Segment，同处历史共用翻译标记 |
| 同文不同位置、重复 spine、跨节点与 ruby | 出处分别校验；原文不混入注音，同文不自动合并 |
| 改模型／语言／语境后回看 | 历史结果标明原配置；只有明确重新翻译才创建新任务 |
| 受理响应丢失、重复提交 | 同请求只对应一个任务；同键异文冲突；不因核实失败盲目重发生成 |
| 截断、空输出、超限、取消与重启 | 不发布伪成功结果，不自动重试付费调用；错误及中断可找回 |
| 连续翻译 A、B，A 后返回 | B 的当前内容不被 A 覆盖，A 的成功结果仍可从历史找回 |
| 新建 Segment 后保存响应丢失 | 同请求找回同一个 Segment；出处、采用关系和正文共同成功或失败 |
| 选用已有 Segment | 空译文可预选采用，非空默认仅关联；语境始终默认保留，同次明确保存提交选定动作 |
| 两个页面同时编辑或采用 | 陈旧写入被拒绝且保留草稿；双向覆盖保护有效 |
| 用户修改采用副本后再次翻译 | 原成功结果、新成功结果和 Segment 当前编辑内容分别保留；不承诺每次手工编辑的历史版本 |
| 材料删除、Source 删除、Segment 删除 | 按第 6 节核验列表、详情、调用日志、成功核实和迟到结果；重导不换绑 |
| Provider 改动／删除与任务并发 | 已受理快照稳定，活动任务受保护；历史译文无 Provider 仍可读取 |
| 设备无日语声线、列表迟到、声音失效 | 可等待或重试检测，给出准确原因，不误报播放成功 |
| 播放、停止、新目标、离页 | 控制始终可达，旧事件不复活音频；没有生成音频文件的虚假提示 |
| 现有讨论、人工资料和设置 | 原权限、幂等、Run 查询、模型验证及默认值不回归 |

自动测试禁止真实网络和模型；适配器、持久化、幂等、删除和声音事件以离线数据验证。真实翻译质量和用户设备声线另行记录人工验收，需要模型录制时遵循仓库 RECORD=1 的人工执行规则。
