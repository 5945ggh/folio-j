## 1. 产品背景与问题

### 1.1 背景

Folio-J 源于开发者使用日语原版小说、动画等内容进行自学的个人实践。

这类学习以真实日语内容为主要输入。用户选择自己真正感兴趣的原版素材，在阅读或观看过程中尝试理解其内容；遇到超出当前能力的词汇或语法表达时，再借助词典、LLM 等工具获得必要帮助，并继续原本的内容消费。

在开发者的个人实践中，结合上下文、学习者水平和个人偏好，LLM 已能对明显超出当前水平的内容给出有助于理解的讲解。在传统的阅读辅助手段（如 yomitan）之上引入 LLM，可以使原版素材的可学习性与学习者当前语言水平进一步解耦，从而允许学习者更多地依据兴趣选择内容。

Folio-J 希望围绕这种以原版内容为中心的学习方式，形成一套覆盖理解辅助、主动学习、知识积累与后续适应性教学的个人日语学习系统。

### 1.2 理想中的学习流程

学习过程中，用户阅读、观看和理解自己选择的原版内容。当理解过程顺利时，不需要额外学习操作；当遇到障碍时，用户根据需要获得不同程度的辅助。例如：

- 查询单词或表达的含义；
- 获取一句话的简要解释；
- 针对复杂句子的结构、语法、语用、文化背景等获得详细解析；

这些辅助的首要目的是恢复对原文的理解，使用户能够继续沉浸于素材本身。并非每一次辅助都应转化为需要保存和复习的学习内容。当用户认为某个片段值得进一步掌握时，可以将其转化为更显式的学习活动，例如深入讨论、形成独立讲解、收录为积累条目供后续学习。

因此，原版内容既是用户最终希望理解的对象，也是语言学习发生的主要环境；LLM、词典和结构化学习材料作为支架，帮助用户处理当前尚不能独立理解的部分。

### 1.3 现有流程中的问题

目前这种学习方式往往需要在阅读器、播放器、词典、LLM 对话和复习工具之间频繁切换。随着学习持续，主要困难不仅是「如何获得一次好的讲解」，还包括：

- 为了获取高质量的 AI 解析，原文前后文、学习者水平、解析偏好和作品背景等信息需要重复交代；
- 临时解释、深入讲解和真正值得长期学习的内容混杂在聊天记录中，难以复用；
- 原文、讨论、讲解和后续学习记录之间缺少稳定联系；
- 不同工具之间切换存在一定人工衔接成本。

Folio-J 希望减少这些重复劳动，降低用户围绕原版素材持续学习的成本与消耗，并让有价值的理解过程和学习记录能够按需沉淀、关联和复用。

长期演进的动机与假设见 [PRODUCT_DIRECTION 第 2 节](PRODUCT_DIRECTION.md#2-产品重心围绕原文形成可持续使用的学习成果)。

## 2. 产品定位与长期方向

Folio-J（Lingua Portfolio - Japanese）是一个以用户感兴趣的日语原版内容为中心、利用 LLM 提供理解支架与学习支持的个人日语学习系统。首要目标是帮助学习者维持对超出当前独立理解能力的内容的理解，并逐渐减少对辅助的依赖。

首轮建立围绕「原文—讨论—讲解—学习条目」的基础能力：用户可以直接讨论片段，按需保存自足讲解、留下有出处的学习点，并在之后找回原句与解释。保存讲解可以止于讲解，创建条目的前置关系见第 4.3 节，不要求固定的「完整解析 → AI 提取 → 结算」流程。

本轮范围与入口由第 4 节和 F1–F9 定义。当前优先推进第 4.7 节的 EPUB 原生阅读阶段，Occurrence 与积累库暂缓；媒体播放、课程推荐或主动复习仍不在本阶段范围。ITS、个性化预学习与适应性教学的长期理由和设想归入 [PRODUCT_DIRECTION 第 2 节](PRODUCT_DIRECTION.md#2-产品重心围绕原文形成可持续使用的学习成果)，不作为首轮交付承诺。

## 3. 目标用户与使用场景

Folio-J 面向希望通过兴趣导向而不是难度导向选择日语原版内容作为主要语言输入来源的学习者。

用户可能已经能够通过外部工具获取素材和选择学习片段，也使用过其他第三方学习工具。

产品按单用户、本地运行设计。当前接入普通可重排 EPUB 阅读；媒体播放或主动复习流程仍留待后续独立阶段。

## 4. 当前版本目标与范围

### 4.1 当前目标

用户能够围绕自己选择的日语片段阅读、提问和讨论，按需要留下符合个人需求的独立讲解与学习条目，并在之后方便地找回、阅读和再理解。

当前版本应支持持续使用的学习流程，包括必要的追问、状态反馈和数据保存。

### 4.2 首轮目标能力与边界

下表定义片段学习的目标能力；实现差额见 [MVP 实施基线](handovers/MVP_IMPLEMENTATION_BASELINE.md)。材料阅读与学习衔接范围见第 4.7 节，后续顺序由[阶段入口](handovers/README.md)维护。「创建 AI 讲解」快捷入口纳入普通讨论能力，其余快捷按钮与组合工具可在闭环后按高频用法增加。

| 能力 | 用户能够完成的事情 | 首轮边界 |
|---|---|---|
| 来源与片段管理 | 登记用户声明的来源，添加目标文本、备注和必要语境，再次打开已有片段 | 手动录入；不要求导入或保存素材 |
| 学习背景与讲解偏好 | 保存学习背景和讲解要求，解析时自动带入 | 用户维护；不自动推断能力或掌握程度，不先建设完整学习档案系统 |
| 讲解形成与保存 | 直接保存手写或外部 Markdown、人工编辑全文；也可生成系统性或专题讲解，修改讲解块 | 人工入口无需模型；修改已有 Analysis 产生新修订，旧修订只读；Agent 继续按块编辑，整份删除由用户确认 |
| 学习条目创建与整理 | 将值得积累的学习点关联到原文与持久讲解，查看出处并整理 | Agent 查询条目、创建一个或多个待整理候选、修改待整理候选；用户直接整理状态，暂缓手动创建条目，不提供自动收录 |
| 查找与再阅读 | 从来源、片段或学习积累库找到已有内容，直接阅读原句和相关讲解，并围绕问题追问 | 原 Section Markdown 为阅读基线；支持基础独立对话，不做自动聚类 |
| Agent 协作与工具审核 | 在短问答或持续讨论中形成、修改讲解并整理条目；审核具体操作或使用 Full access，可停止本轮 | 首轮只读取当前片段资料；线程执行或待审核时不接收新轮，初始默认审核模式，空闲时可切换权限 |
| 运行与数据保障 | 配置模型、区分解析和提取等环节的状态，查看有用的失败信息并采取重试等操作，关闭后仍能找回数据 | 保存必要的调用与产物记录供排查；不要求先建设完整开发者调试平台 |

### 4.2.1 本轮材料目录与阅读管理

素材库提供跨 Source 的 EPUB 书籍目录，支持材料标题／Source 标题文字搜索、Source 与阅读状态筛选、排序和分页。漫画、有声书、视频仅为禁用占位；根入口进入素材库，Source 与设置独立可达，不新增 Home 或无对象工作台。不设独立继续区域，以最近打开排序配合已有位置恢复。

**导入与目录。** 导入明确选择已有或新建 Source，不静默决定归属；创建来源后保留已选文件，失败导入不撤销已创建的来源。完整编译和全量注音成功后才发布正式材料；等待、失败与正式书籍可区分，准备中不能进入阅读。受理导入后可继续浏览，成功刷新列表并提供入口，不自动跳转；当前条件未显示新书时仍提供可达入口。失败可重试同一文件或移除失败提示。同一标签页内导航承接导入状态，刷新或关闭页面后的进度恢复不作承诺。

加载、失败、真实空库和筛选零结果分别表达，不用首个 API 页或预览长度冒充完整数量。来源空间提供概览、材料、片段与讲解四种视图；概览按最近更新／添加的内容预览，完整来源及材料始终可达。讲解聚合直达所属 Segment 的确切修订，手动片段无需虚构书籍。显式 URL、历史导航和阅读返回优先于本地偏好；显式失效来源显示不可用，不静默切换到其他来源。

**书籍信息。** 详情显示真实的书名、封面、所属来源、导入时间、阅读状态、最近打开和章节数量，不用整个 Source 的学习内容推算本书成果。可修改应用内书名、上传自定义封面或恢复原书封面；书名与封面同次原子保存，失败或并发冲突保留草稿，放弃未保存修改须确认。封面限静态 PNG／JPEG、4 MiB、1600 万像素；自定义封面优先且不受自动封面缓存重建影响。编辑不替换 EPUB、不修改 Source，也不改变原书、编译版本、原文定位、阅读状态／位置及注音结果；查看详情与编辑不记为阅读打开。

自动封面优先使用有效的明确声明，否则按稳定顺序回退首张可用包内图片，无可用图片才占位。保留有界图片与包内路径安全限制；旧失败缓存可失效重提，新结果解除旧加载失败状态，无需删除重导，不改变材料身份、原始字节或阅读位置。

**删除与移动。** 独立材料删除采用 [F2](#f2-source-与片段)的保留范围。移动与“一并删除关联学习积累”继续后置，本轮不提供操作；后续移动须携带明确关联的片段及讲解，一并删除须展示实际影响，并验证历史引用、讨论和进行中任务。无材料出处的手动 Segment 不能按同来源、书名或出处文字推测其属于某本书。

**阅读管理。** 材料三态为未开始／进行中／已完成，完成由用户明确标记，不从章内百分比推断。新进入阅读并成功呈现目标章后记录最近打开，未开始转进行中；预取、后台刷新、换章与设置变化不计新打开，重读已完成保留完成。手动状态不清空位置或真实打开时间，不调用模型；状态与最近打开服务端持久化，独立于不可变材料及位置版本，重复动作与迟到打开不覆盖较新手工状态。未知历史打开时间留空。

材料目录不扩展新学习模型、通用事件／预处理框架、播放器、扫描或 MCP。全书进度、新书架及未接入学习能力继续后置。页面布局、菜单、焦点、列表恢复和具体展示参数见[素材库与来源空间](INFORMATION_ARCHITECTURE.md#素材库与来源空间)，技术机制见[架构](ARCHITECTURE.md#311-目录与材料使用状态)。目录与书籍管理的取舍分别保留在[前端调整计划](handovers/archived/frontend-refresh/PLAN.md)、[书籍管理计划](handovers/archived/book-management/PLAN.md)；独立删除与导入反馈的依据见[材料删除验收](handovers/archived/MATERIAL_DELETION_ACCEPTANCE.md)、[导入反馈验收](handovers/archived/EPUB_IMPORT_FEEDBACK_ACCEPTANCE.md)。

**书籍文本统计。** 详情独立加载当前材料版本的统计和高频词覆盖曲线；不挂载阅读器，不向前端发送全书 token。范围是全部可提取正文，包括目录和后记；重复 spine 按资源身份只计一次，不同资源的相同文字分别计入。

| 指标 | 初版口径 |
|---|---|
| 词次 N | 按固定分词配置统计有效词次：有非空白表层及正长度原文范围，排除空白、记号和补助记号；保留助词、助动词、数字和未登录词 |
| 词种 V | 按词典形归并；词典形缺失、空白或为明确占位值时回退表层，不按读音归并 |
| 单次词种 H | 只出现一次的词种数；单次词种比例为 H/V |
| 覆盖曲线 | 本材料频次最高的前 k 种词累计词次除以 N；80%／90%／95% 阈值取达到覆盖率的最小整数 k，同频按归并键稳定排序 |
| 字符数 | NFC 定位正文的 Unicode 码点数，包含空白和标点；ruby 的 rt／rp 不在定位正文中 |
| 汉字 | 按记录的 Unicode 版本统计名称属于 CJK UNIFIED IDEOGRAPH 或 CJK COMPATIBILITY IDEOGRAPH 的字符，提供不同汉字数和只出现一次的汉字数；不作 NFKC 折叠，不将々、〇及兼容符号展开算入 |
| 空输入 | 数量为 0；分母为 0 的比例和覆盖阈值显示“—”，曲线为空 |

统计注明范围、分词粒度及规则版本；词次覆盖率不表示理解率、掌握率或难度，未登录词不等于用户不会的词。本轮不统计平均自然句长、逐汉字读音或卷数。覆盖阈值由完整频次计算，有界曲线保留首尾及阈值点；具体采样上限见[统计实现](ARCHITECTURE.md#314-文本分析与统计契约)。

正文统计不依赖分词就绪；无代次时仍显示字符／汉字，词法部分标明尚未准备。读取不隐式补算、不调用模型，不改变最近打开、阅读状态或位置；失败不阻止详情及阅读。结果绑定材料版本、分词代次和规则版本，旧响应不冒充新结果，Source 删除后缓存也不能暴露内容。指标显示见[书籍详情统计](INFORMATION_ARCHITECTURE.md#书籍详情统计)，决定依据见[文本处理计划](handovers/archived/text-study/PLAN.md)及[B2 验收](handovers/archived/text-study/B2_ACCEPTANCE.md)。

详情统计自动检查当前分析代次，重新进入及窗口重新获得焦点时更新；不提供常驻刷新按钮，失败仍可重试。准备或发布新的分词代次后，已显示的统计按新身份更新。

**材料词汇。** 书籍详情提供独立词汇页，按上述有效词次和词典形回退口径查看本材料的词汇、词频与原文出现位置。支持一级词性筛选、词频升降序和词形／读音文字搜索，列表与出现位置分别分页；服务端计算并分页，不向前端发送全书 token。

词性先筛选词次，再按词典形归并并计算频次；相同归并键保留实际出现的多种词性、读音与表层词形。搜索匹配该组的词典形、任一表层或读音，平假名／片假名及宽度差异等价，不支持罗马音；命中后仍展示该词在当前词性筛选下的完整频次。例如搜索「食べた」命中「食べる」时，出现列表包含同组的其他词形。搜索比较不改写原文、token 或归并键。词汇出现位置按资源身份去重，与统计一致；重复 spine 选择第一个可完整定位的呈现位置，没有合法呈现时保留词次并说明无法定位。

从出现位置明确前往原文后，按材料版本、资源摘要、范围和原文快照核验，成功才定位并临时高亮；返回词汇页保留筛选、排序、页码与所选词。词汇页只读，不创建永久词条、学习片段或 Occurrence，不改变阅读打开或位置；明确进入阅读器后沿用阅读行为。无分析代次、分析后无有效词次、筛选无结果及失败分别呈现。本轮不接入词典释义。页面与返回规则见[材料词汇页](INFORMATION_ARCHITECTURE.md#材料词汇页)，实现与验收范围见[本轮记录](handovers/archived/reading-practice/VOCABULARY_ACCEPTANCE.md)。

### 4.3 语境与学习条目边界

用户决定是否提供前后文，并可修改或清空。手动录入继续由用户提供语境；从 EPUB 选区建立学习片段时，按第 4.7 节的 C2 规则自动预装可编辑语境。目标文本与语境明确区分，补齐语境不扩大目标或本次解析范围；模型按语义寻找远处语境留待后续。

保存讲解不要求同时创建 Occurrence；用户可以只留下某一个学习点，不要求完整提取整份报告。AI 批量提取是可选的整理能力，不是所有条目都必须经过的独立模型阶段。

创建 Occurrence 时，条目需有明确的原文定位和持久讲解出处。来自讨论的新理解，应先整理为能够脱离对话阅读的讲解，再建立条目关联；不以直接引用聊天消息替代讲解。两项动作可以由一次明确请求发起，不要求用户分别操作两个页面。部分失败保留已经独立保存的成果，处理规则见 F8，具体执行与恢复契约待架构细化。

用户明确触发保存或收录，不要求先完成一个正式的解析定稿流程。普通问答或解析完成不自动触发成果整理、条目创建或结算；首轮不提供解析完成后自动提取的开关。

### 4.4 功能区域

| 区域 | 职责 |
|---|---|
| 来源目录 | 找到来源记录，浏览其片段并添加新片段 |
| 片段阅读与讨论 | 找到原文、已有讲解与讨论，按需展开工作台形成或修改成果，查看、创建与整理学习条目 |
| 学习积累库 | 跨片段查找学习条目，直接阅读原句和相关讲解 |

这些区域表达功能职责，不规定必须有三个独立页面或导航入口；设置提供可访问的入口。普通打开片段先呈现阅读内容，指定讲解或讨论入口直达对应对象；讲解阅读可同时参照原文，返回来处与查看所属来源分别表达。

普通回看和人工编辑不启动工作台，也不查询讨论、任务或模型设置。显式展开讨论、未显式收起的线程直达或「创建 AI 讲解」才启动；启动后在当前 Segment 页面内收起保活，保留草稿、待核实提交及审核补充要求。离页后的草稿保存范围沿用既有规则，不承诺恢复人工编辑草稿。具体路由优先级、专注布局和窄屏切换见[讲解浏览与按需讨论](INFORMATION_ARCHITECTURE.md#讲解浏览人工保存与按需讨论)，依据见[A1 独立回看验收](handovers/archived/text-study/A1_ACCEPTANCE.md)及[专注布局计划](handovers/archived/segment-layout/PLAN.md)。

工作台组织学习活动，不拥有学习内容。Analysis 与 Occurrence 关联到 Source 下的 Segment，Occurrence 还关联具体讲解版本与块；关闭工作台、结束讨论或切换页面不改变其归属与存在。

### 4.5 讨论、共享资料与成果保存

讨论以 Segment 为共同起点，可直接提问，也可围绕已有讲解或条目展开。独立线程保留各自过程，持久讲解可在同片段共享；资料范围、目标判定与写入意图集中见 [F7](#f7-片段讨论与成果整理)。

值得长期使用的解释保存为自足 Analysis，补齐必要背景、限定条件与不确定性，使用户无需重读聊天即可理解。人工入口与工作台可以新建文档或形成已有文档的新修订，身份及保存规则见 [F3](#f3-解析)。

保存讲解、生成待整理候选与用户收录分别表达；候选与整理见 [F5](#f5-学习条目创建与整理)，部分成功与恢复见 [F8](#f8-状态与诊断)，审核模式及 Full access 的工具范围见 [F9](#f9-agent-工具权限与审核)。普通问答不默认写入成果。

JSON 文档树及教学 payload 的生产用途留待主动学习交互确定，不作为首轮阅读功能的前提。

### 4.7 当前 EPUB 阶段安排

本阶段接通“导入 EPUB → 阅读原文 → 按需学习／讨论与形成讲解 → 返回原处”，沿用 Source、Segment、Analysis 与编辑审核能力，保留手动片段入口。F5／F6 的 Occurrence 与积累库继续作为后续目标；SRS／ITS、视频／asbplayer 和 MCP 不作为本阶段交付条件。阶段取舍见[原生阅读方向](handovers/archived/epub-reading/DIRECTION.md)，后续顺序及材料对话的准备条件见[阶段入口](handovers/epub-reading/README.md)。

#### 材料、位置与阅读

- 原 EPUB 托管副本与处理版本保持不可变。材料归属、同字节复用及删除后重导遵循 [F2](#f2-source-与片段)。
- 原文位置绑定材料版本、原始 spine 资源及确切出现位置，采用 Unicode 码点半开范围与原文快照。显示章节、字号、横竖排、窗口尺寸和分词不改变引用身份；失配时明确无法定位，不搜索同文后静默改挂。
- 阅读章节按有效目录组织，可连接被插图分开的多个 spine 资源；保留 spine 顺序及底层资源身份，优先采用原目录章名，异常目录明确回退，不把重复文档书名冒充章名。
- 横竖排均采用按章连续滚动，保持原生划选，避免跨页选择问题。阅读恢复按原文位置回到原附近，不承诺相同像素或页码；百分比只辅助表达当前位置，排版留白不计入正文长度，不表示累计已读、学习完成或材料完成。
- 成功呈现的稳定位置按章保存，普通打开整本书恢复全书最后位置；预取、失败跳转及恢复过程的临时位置不写入。章内恢复、搜索、图库、相邻切章和临时返回点分别保持其意图；连续查阅保留首次原点，继续主动阅读后的下一次跳转更新原点，只有实际返回成功才消费返回点。
- 阅读设置变化保留当前原文上下文，不先闪现章首。偏好区分当前浏览器跨书与逐材料版本作用域，主题不反色图片；合法既有设置不因展示范围裁减。具体控件、作用域和保存位置见[阅读外观与工具显隐](INFORMATION_ARCHITECTURE.md#阅读外观与工具显隐)，导航判定见[跳转链与返回点](INFORMATION_ARCHITECTURE.md#跳转链与返回点)。
- 同标签页片段往返可短期复用最近一本书的阅读会话。返回先核验材料可用性、内容版本及阅读状态，再刷新学习资料；带片段出处的返回仍精确定位。暂离时停止输入、采样及延迟保存，完成已有位置写入；材料失效或版本不一致时不展示旧正文。释放条件及租期见[阅读会话往返](INFORMATION_ARCHITECTURE.md#阅读会话往返)，不改变持久位置、引用或删除规则。
- 书内搜索仅匹配规范正文，去首尾空白并 NFC，排除 ruby 读音；支持重复／重叠命中及同资源连续 part，不跨不同资源或章边界拼接。图库保留每次图片出现的身份；正文与图库共用独立图片查看器，关闭返回各自来处，支持缩放、复制图片、下载原图及在图库中查看当前出现项。查询、浏览、放大、复制和下载不写 Run、最近打开或阅读位置，明确前往书中位置才进入正常定位链路；具体入口与关闭行为见[书内搜索与图库](INFORMATION_ARCHITECTURE.md#书内搜索与图库)。

#### EPUB 即时查词

读者可以导入自己的本地明镜词典，在 EPUB 正文和词卡日文中查词。查词使用当前来处的文字、点击位置或明确选区，可结合分词与读音。较长的原文匹配优先，同一原文范围的不同词条和读音在一页内分列。切换到其他匹配范围时，原文强调同步变化。

默认由读者开启点击查词。开启后点击正文基字查词，点击已有记录的划线时可从词卡进入该处记录。鼠标也可选择按住 Shift 指向查词，普通鼠标点击仍打开划线记录。父子卡可同时阅读，返回父卡恢复原先所读位置，关闭整组回到书中。查词属于临时阅读操作，词典释义与查询记录不自动成为学习资料。

#### 选区与持久学习资料

- 消息原文引用与 Segment 分开。普通划选只产生临时选择，不创建内容或调用模型；显式点击“保存为学习片段”后捕获目标快照并准备草稿，最终提交成功才创建片段和固定原文。
- Segment 创建时可保存同一活跃 Source 下的材料出处。出处包含材料、不可变版本、有序资源局部范围和逐段快照，重复 spine 的出现分别校验；同一逻辑章只界定首版支持范围，不承担身份。
- 一份出处表达同章连续目标，可在资源／part 边界拆分；拒绝空范围、逆序、重叠、跨章及跳过中间文字的拼凑，只合并同一资源出现内相邻范围，不靠重排修复顺序。按校验后各段原文依次拼接并整体 NFC 形成 Segment.text，不补虚构间隙。
- 精确出处与目标原文同时固定；首版不事后换绑或解除出处后编辑目标，需要不同目标时新建片段。界面仅支持单个 chapter part iframe 内跨 DOM 节点的原生选择，不支持跨 iframe 拖选、跨章或追加不连续选区；底层出处和回读支持同章多资源范围，不截断不支持的选择后冒充完整目标。
- 已有片段只按同材料版本、规范范围和确切出现位置提供有界候选，复用由用户显式选择，提交时复核可见性与出处。相同文字不自动合并；候选失效不静默新建替代，选用不覆盖已有资料。
- 创建或选用成功后留在阅读器，由用户明确打开片段才进入资料页。原处预览只读取已有原文、译文和讲解，不调用模型、启动讨论或创建内容；所选讲解及确切修订在打开完整片段与返回原文时保留。
- 正文标记与页边入口可独立隐藏，默认开启，当前浏览器内跨书及跨标签页同步，兼容旧偏好；隐藏不改变资料或精确定位，本章记录始终可用。标记只作用于基字，保留原生选择、扩选与复制，不与工具栏或按需注音重复消费同一次操作。
- 精确出处的只读展示来自核验结果，改名只更新显示，不改变身份；不可定位时保留状态及可靠名称，缺失部分省略，不补造 0%。自由文本 source_ref 独立保留。
- 返回原文先验证同章全部范围，再定位第一段；任一范围无法投影时明确定位不完整。等待注音或准备失败时保留定位意图并允许重试，不保存未呈现位置、不提前消费返回点。版本或快照失配保留可见资料的历史文字，Source／Segment 删除仍受不可见门禁约束。
- 阅读器正文复制保留所选基字原文及换行／空白，排除原书和自动注音，不改变选区或注音显示。段尾译文只属显示内容，不进入原文定位或保存；译文可独立复制，混合选择只提取原文。

原处预览、段尾译文、浮窗停驻、信息顺序、精确出处文案和临时高亮的表现规则集中见[选区与资料往返](INFORMATION_ARCHITECTURE.md#选区与资料往返)。C1／C2 的范围与取舍依据保留在[文本资料计划](handovers/archived/text-study/PLAN.md)、[精确样例](handovers/text-study/C2_EXACT_CASES.md)及[原处预览验收](handovers/archived/text-study/INLINE_PREVIEW_ACCEPTANCE.md)。

**C2 相邻语境预装。** 此处集中维护默认值与用户行为，句界细则见[架构](ARCHITECTURE.md#资料写入与材料出处契约)，原始安排与样例见[实施计划](handovers/archived/text-study/PLAN.md#10-c2-阅读选区与资料往返)。自动取文在本地完成，不调用模型；字符预算约束预装长度，不表示 token 或费用预算。

| 配置 | 初始默认 | 行为 |
| --- | --- | --- |
| 自动预装语境 | 开启 | 可关闭，关闭后仍可手动填写 |
| 前文／后文句数上限 | 各 3 句 | 两侧独立配置非负整数 |
| 前文／后文字符上限 | 各 200 个 Unicode 码点 | 两侧独立配置非负整数，可调整为 100 等值 |

- 从最靠近目标的正文向两侧分别扩展，保持原文顺序。选区所在句的未选残部计该侧一句，优先于更远句；目标本身不计入语境预算，目标内的文字不重复放入前后文。任一侧的句数或字符预算为零时，该侧为空。
- 在不可变原文上确定目标、两侧范围及原句界，再整理前后文副本：按 Unicode White_Space 去除两端空白，CRLF 转 LF，清空纯空白行内容并将内部连续空行折叠为一行。句内普通／全角空格、标点、组合字符、变体选择符与零宽字符保留，标题按正文处理；整理不改变目标、exact、摘要或 spine 出现位置。
- 句数与字符数均为上限，不强制填满，不跨侧借用剩余预算。字符预算按合并整理后整体 NFC 的 Unicode 码点计，内部空格、LF 与标点计入，排除注音 rt／rp 和应用附加文字。优先近端完整句，超限时取贴近目标的部分，再去除裁切边缘空白；只有切开含正文的句／残部才标记截断，预算停在句间空白、恰好完整候选或纯空白侧不标截断。
- 自动取文限于同一逻辑章，可跨该章相邻 part，不因 iframe 尚未挂载而少取，也不因资源全文已加载而越过章界。目标选区的单 iframe 限制保持原位。支持只取前文，不依据阅读进度猜测用户已读范围或扩大后文。
- 学习偏好维护跨材料的默认值；本次草稿可临时调整预算，临时调整不自动改写默认值。设置变化只影响之后的预装，不重算已有资料或自动覆盖当前草稿。目标原文保持确切选区，语境预装不将其扩成整句。
- 新建草稿显示目标与简短语境预览，完整前后文可展开修改或清空。首次预填结果只填入未被用户修改的对应字段；清空也算修改。重新按预算取文是明确动作，在有修改时先保留原草稿供用户选择替换；切换目标后旧结果失效。重开已有片段、切换设置或选用已有片段均不覆盖已保存资料。
- 预装失败保留目标与草稿，允许重试、手动填写或仅保存目标；目标出处校验失败仍拒绝保存。用户手动补充的语境沿用输入限制，不受自动预装预算裁剪。来源标识须区分自动摘录与用户已编辑内容，不将改写文字标为经过精确校验的原书引用。
- 保存本身不启动模型调用。显式发起讨论或生成时使用实际已保存语境并固定本轮输入快照；后续修改不回写历史任务或 Run。定位用 prefix／suffix 仍独立于模型语境。


#### 注音与后续边界

全量注音来自本地分词，不调用模型。新书完整生成并持久保存全书分词与读音后才可读，准备失败可重试；已有书籍可补算，无需重导，重建失败保留旧结果，完整校验成功才切换。分词重算不改变正文、材料版本、原文引用或阅读位置。

保留原书 ruby，只补充未覆盖且有可靠读音的含汉字范围，纯假名不重复注音；词首／词尾假名可可靠分离时仅标剩余含汉字部分，否则保留边缘或回退整词，词内假名不拆分，重叠或不能安全包装的候选跳过。注音可按原书／全量范围及显示方式选择，首次默认原书与展示，记住用户选择，隐藏／按需查看保留排版空间并提供触屏及键盘入口。分词单位不成为学习实体，人工读音纠错后置；具体显示与控件见[阅读器交互](INFORMATION_ARCHITECTURE.md#阅读器-r11)，依据见[全量注音计划](handovers/archived/full-ruby/PLAN.md)。

本阶段不扩大现有片段 Agent 的读取范围。材料对话的上下文、历史、未读内容、权限及调用成本须在切片 3 收口，拥有全文不等于允许发送全文；切片 4 再确定从讨论选取目标、相关问答及部分成功反馈。跨章／不连续目标、额外章名编辑或章名翻译继续后置，不由工程试验、API 草图或占位关闭未决项。

滚动阅读与恢复取舍见[切片 1 验收](handovers/archived/epub-reading/SLICE_1_ACCEPTANCE.md)；章节记忆和跳转链的依据见[章节位置验收](handovers/archived/epub-reading/CHAPTER_MEMORY_ACCEPTANCE.md)及[阅读交互记录](handovers/archived/reader-r1/INTERACTION_POLISH.md)。当前交付与验证限制统一见[实施基线](handovers/MVP_IMPLEMENTATION_BASELINE.md)。

### 4.8 阅读翻译与设备朗读

翻译与设备朗读辅助当前阅读，不要求先创建学习片段或获得完整解析。范围与取舍依据见[阅读辅助原方案](handovers/archived/text-study/TRANSLATION_AND_SPEECH_PLAN.md)，后续入口调整见[验收记录](handovers/archived/text-study/TRANSLATION_AND_SPEECH_ACCEPTANCE.md)；交付状态由实施基线维护，待验证与后续接入见[阅读辅助后续安排](handovers/epub-reading/README.md#阅读辅助后续安排)。

- 首轮翻译仅作用于 EPUB 中有确切出处的同章连续选区，沿用第 4.7 节的支持范围。显式触发后固定原文、出处、语境和实际配置；先采用 LLM adapter，允许以后接入专用服务。Segment 直接生成译文、批量／整章翻译及材料对话后置。
- 默认日译简体中文，前文最多 3 句／200 个 Unicode 码点，后文为 0，偏好独立于 Segment 语境及讲解语言。本次语境可检查、编辑、清空或扩大，只翻译目标；补全句子须用户选择，不自动扩大目标或发送全书／其他讨论历史。
- 完整成功译文在本地持久保存，不自动过期，原输入、配置和结果保持不变；部分输出、拒绝和截断不发布为成功。关闭、刷新和回到同出处可找回，失败查询不转为新调用；显式重译创建新结果，旧结果与 Segment 当前译文保留，失败或停止后仍可读旧文，历史回看不调用模型。
- 翻译不创建 Segment 或 Analysis。同一确切出处的成功结果可聚合呈现，保留各自身份及历史；同文异址、材料版本或 spine 出现不合并，进行中／失败／取消不绘制成功标记。片段与译文重叠仅合并显示入口，不建立采用关系；后台完成仍刷新记录及标记。
- Reader 新建片段统一从正文划选的“保存为学习片段”进入，翻译详情和本章记录保留已关联片段的打开入口；不提供独立采用表单，来源等手动入口保持独立。
- 保存草稿仅匹配同材料、版本、resource／spine 出现及摘要的成功译文；裁掉完整目标两端 Unicode White_Space 后核对坐标和原文，仅允许整体边缘空白不同，内部空白、标点与同文异址不忽略，不改写原选区出处。优先采用本 Reader 会话最近显式选中的有效匹配结果，否则取最新匹配成功结果，历史选择不写偏好。
- 完整译文仅预填一次，用户修改、清空或开始提交后，迟到结果不覆盖。片段语境沿用第 4.7 节，不套用翻译历史语境；选用已有片段不覆盖其译文或语境。新建在同一事务保存片段、原出处及采用凭据，记录实际提交内容；不确定响应核实首次冻结请求，不重复生成。
- 关联结果、采用快照与当前可编辑译文分别维护，普通编辑不承诺完整版本历史，编辑仍检查版本，冲突保留草稿。只关联也表达保留意图，不要求覆盖当前译文字段。
- 关闭卡片不取消已受理翻译，停止须明确触发。首轮每任务至多一次模型调用，响应不确定先核实本地状态；重启中断任务不自动重放，停止后的迟到结果不得发布，成功结果不因晚到停止撤销。集中可配置资源上限仍为待真实模型实测的候选，不作质量或性能承诺。
- 删除材料后，未关联活跃片段的译文不可见；明确关联的结果可从活跃 Segment 读取并说明原材料已删。删除确认说明未保留译文的影响；Source 删除后关联内容不可见，迟到结果和重导不恢复或换绑。停用／删除 Provider 不抹去已保存译文。
- 阅读器允许确认删除某一确切出处的全部已有阅读翻译历史及正文划线，同时停止该处进行中的重译；旧结果和迟到任务不得使记录再次出现。同文异址的记录不受影响，之后明确发起的新翻译可重新留下记录。已另存的 Segment、其当前译文、讲解和关联译文快照保留；删除不建立新的采用关系。已发送但响应尚未核实的翻译先核实原提交，再删除该处记录。
- 翻译设置独立维护一个默认方案，复用 Provider、模型及凭据身份。明确采用当前讨论模型后绑定具体模型，后续讨论默认值变化不改翻译选择；配置修改不改已受理快照。设备声音与语速保存在当前浏览器，不需要 Provider。
- 设备朗读支持阅读选区、译文对应原文及 Segment 原文，无需先翻译或保存。一个页面一个播放目标，新播放停止旧目标，选区变化不替换正在朗读的文本；关闭译文卡保留可达播放控制，关闭播放条或离开阅读／片段页停止并清理目标。
- 设备支持时可暂停／继续，不支持暂停时保留停止；结束或停止后可重播，设备暂停若实际结束朗读则按真实终态提供重播。偏好在下次播放或重播生效，继续不重建当前播放；设置提供日语试听，无声线及设备错误准确反馈。
- 朗读只使用基字原文，排除 rt／rp，不承诺特殊 ruby 发音正确或离线可用。浏览器方式不提供可保存音频，不显示“已保存音频”；外部 TTS 留待片段学习、制卡等音频保存与复用场景评估，接入后再提供可选择的备用策略，本轮不展示无效 fallback。

具体呈现分别见[翻译卡片与历史回看](INFORMATION_ARCHITECTURE.md#翻译卡片与历史回看)、[本章记录与翻译标记](INFORMATION_ARCHITECTURE.md#本章记录与翻译标记)及[朗读条与声音浮层](INFORMATION_ARCHITECTURE.md#朗读条与声音浮层)。

### 4.9 阅读摘录、书签与记录检索

持续使用阶段按“带上下文复制 → 位置书签与备注 → 扩展书内搜索”实施，安排见[实际阅读评测计划](handovers/reading-practice/PLAN.md)，可用状态见实施基线。

**带上下文复制。** 阅读选区提供独立操作，将目标原文、相邻语境及可选出处组合为供外部 AI 提问使用的文本。目标保持确切选区，语境沿用第 4.7 节的句界、同章范围、整理和双预算规则。默认前文最多 3 句／200 个 Unicode 码点，后文 0 句／200 个码点；附带出处默认开启。两侧句数和字符上限独立可调，任一预算为零时该侧为空。复制偏好作为个人默认值保存在数据库，适用于连接同一后端的各浏览器和全部材料，与翻译及片段语境偏好独立。旧浏览器配置直接忽略。

修改先保留为草稿，显式保存成功后供复制使用；保存失败或并发冲突保留草稿，不静默覆盖较新的设置。关闭设置、切换工具、收起分组或切章均保留同次阅读草稿。离开当前 Reader 路由或换书时，有草稿提供保存后离开、放弃并离开、继续编辑；正文会话保活不绕过保护。保存中离开先等待已提交请求的结论，失败保留当前页面与草稿。刷新或关页使用浏览器原生提醒，不承诺离页后恢复。

恢复复制默认值只修改草稿，保存后生效；排版、注音与阅读界面分别恢复自身字段。设置未成功读取时，阅读和普通复制仍可用，带上下文复制明确提示并允许重试。

输出按出处、目标原文、前文、后文分别标明；空侧省略，字符裁切在标签注明。出处使用当前书名和章名，缺失部分省略。设置提供随偏好变化的固定样例预览。一次点击直接复制，不附加讲解要求、学习背景或私人资料，不创建 Segment、不调用模型。剪贴板失败保留完整文本供手动复制，选择改变或离开阅读后不恢复旧反馈。普通复制继续保留第 4.7 节的纯原文行为。任意模板与多预设后续按使用需要决定。

**位置书签与备注。** 阅读工具栏可一键保存点击时已呈现的当前位置，成功后以单行摘要轻提示并提供添加备注入口；备注可留空、随后修改或清空。附近已有书签时先不创建，提示“附近已有书签”，可查看已有书签或选择“仍然添加”；继续添加仍保存首次点击的位置，关闭提示则放弃本次添加，不改动已有书签。附近判定使用原文位置的小范围容差，不按摘要相似度合并，也不清理历史重复记录。

列表按书中位置排列，卡片提供章节、章内大致进度和限行的摘要、备注。点击卡片查看详情，另有直接跳转入口；详情展示完整摘要与备注，并提供跳转、编辑和删除。删除使用应用内确认框。摘要从规范正文按固定内部预算摘取，优先保留当前位置所在句或短段落，过长时选择逗号等边界，必要时截断并标示省略；不开放设置，不调用模型。图片位置保留图片身份和局部进度；无附近文字时使用有效原图说明或显示图片位置，不编造原文。

书签独立于学习片段和自动记录的最后阅读位置，继续阅读不覆盖书签。跳转采用当前排版并沿用临时返回点，定位失败保留返回机会；添加、查看和编辑书签本身不改变自动阅读位置。首版通过工具栏和左侧列表访问，不增加常驻原文高亮或页边书签。

创建重试沿用首次位置和请求身份，不重复创建；备注保存检查版本，冲突保留草稿。独立删除书签后不再展示。删除书籍时保留书签、摘要和备注，随书籍隐藏；删除来源后同样不可见。重新导入不将旧书签关联到新材料。本阶段不提供脱离书籍的归档查看或恢复入口。

**扩展书内搜索。** 保持本书范围，支持按内容类型筛选：原文；明确关联本书的片段原文、当前译文及备注；各确切出处最新成功阅读译文；书签备注与原文摘要。结果说明命中字段，并能定位原文及打开命中的资料。同位置结果可归组呈现，各对象身份保留。译文历史和讲解全文检索后续评估；无材料关联的手动片段不按来源名推断属于本书。

## 5. 设计原则

| 原则 | 含义 |
|---|---|
| 讲解质量优先 | 持久讲解允许自由写作，只施加软格式约束（二级标题 = 一个学习对象）；不为了索引字段压缩必要解释，也不要求每次问答生成完整报告。 |
| 活动与成果分开 | 工作台承载学习活动，原文、讲解与条目持续保存；保存讲解与收录学习点分别表达，不强制走完整流水线。 |
| 可复原 | 规范化只切分和编号，**绝不改写**解析内容。切分结果拼接后与输入字符串逐字符一致，包括换行；精确规则见 [ARCHITECTURE 4.3](ARCHITECTURE.md#43-规范化器servicesnormalizerpy)。 |
| 不做破坏性合并 | 知识点的"同一性"取决于标准，因此不在写入时合并。Occurrence 保留具体语境、提取判断与出处；MVP 暂缓跨片段的 KnowledgePoint 归属管理，不预先规定知识点的实现形态。anchor 是召回键，不是裁决者。 |
| 全链路可追溯 | 模型生成产物可追溯到相关 Run、prompt 版本、模型和原始输出；手动创建内容记录其来源与操作，不伪造模型调用。条目始终保留原文与具体讲解出处。 |
| BYOK、本地优先 | 用户自带 API Key；数据存在本地单文件数据库中。 |

## 6. 核心学习活动与可选路径

以下活动可以按需要组合，不表示必须依次完成的工序。例如，用户可以「保存片段 → 直接讨论 → 整理专题讲解 → 收录一个学习点」，也可以「保存片段 → 生成系统性解析 → 阅读」，或从已有讲解发起批量提取。这些路径表达产品方向，具体首轮入口见第 4.2、4.5 节及待定事项。

### 6.1 准备共用的学习背景

用户维护可反复使用的学习背景、讲解预设和模型配置，在聊天中表达本次要求；输入范围、优先关系和任务快照见 [F1](#f1-设置)。

### 6.2 登记来源并保存片段

选择或创建 Source，手动输入目标文本，或从第 4.7 节的阅读选区保存学习片段。保存与解析相互独立，可先保存后讨论；字段、原文固定及删除规则见 [F2](#f2-source-与片段)。

### 6.3 形成并阅读讲解

用户可直接编写／粘贴 Markdown，或明确请求 AI 生成完整或专题讲解；保存后可独立阅读和再次找回，不要求继续提取。新建文档、重新解析和修改已有文档的身份与保护规则集中见 [F3](#f3-解析)，规范化见 [F4](#f4-规范化与展示)。

### 6.4 围绕片段讨论，按需留下成果

从原文、已有讲解或条目开始讨论；需要时明确要求保存自足讲解，再生成待整理候选，例如“把刚才的解释整理下来，并生成这个用法的候选条目”。讨论与写入目标见 [F7](#f7-片段讨论与成果整理)，工具权限见 [F9](#f9-agent-工具权限与审核)，部分成功见 [F8](#f8-状态与诊断)。

### 6.5 整理条目并再次阅读

用户按需要分次整理候选，继续保留、收录、设为仅参考或删除，不要求清空候选后才能阅读。状态与再次整理见 [F5](#f5-学习条目创建与整理)，原句及确切讲解回看见 [F6](#f6-知识库)。

### 6.6 异步操作与离开页面

AI 操作由后台执行，用户可离开后返回查看；审核等待、服务中断、同线程发送及主动停止的完整规则集中见 [F8 的后台执行契约](#后台执行审核等待与停止)。人工保存不作为模型任务。

### 6.7 生命周期与状态表达

片段持续保存，任务状态、已有内容与条目整理进度可以并存，不要求开始或结束总体学习 Session。状态含义与反馈规则集中见 [F8](#执行状态已有内容与整理进度)。

## 7. 功能需求

优先级：P0 = MVP 必须；P1 = MVP 期间尽量完成；P2 = 预留。

首轮基本能力以第 4.2 节及下列功能要求为准，「创建 AI 讲解」快捷入口纳入普通讨论，其余高频组合工具不作为首轮闭环的前提。交付顺序与全篇优先级在实施计划中统一，不恢复旧的独立两阶段流水线。

### F1 设置

#### 页面组织与保存

设置分别维护学习偏好、模型与服务、外观、对话权限、翻译与设备朗读；页面组织、入口和反馈呈现见[设置交互](INFORMATION_ARCHITECTURE.md#设置顶部分类)。

服务端设置每组明确保存，修改只作用于提交的字段；某个未修改的默认模型失效，不阻止其他组保存。学习背景与默认预设同次保存要么全部成功，要么保留原值。服务、模型与预设的新增／编辑在弹窗内独立保存。未保存修改受到离页保护，保存失败保留输入，继续编辑后不再显示“已保存”。

学习偏好提供独立保存的“学习片段语境”配置，维护自动预装开关及两侧句数、字符上限；行为与默认值见第 4.7 节。该配置不混入讲解风格或模型参数，保存不改写已有片段及当前草稿。

#### 阅读设置

阅读器内保留一处完整入口，按排版、注音、阅读界面、带上下文复制组织。常用项（包括注音范围）直接可调，其余选项与说明按需展开；专注阅读沿用工具栏的独立入口，不在设置面板重复展示。复制摘要使用已保存配置，未保存、保存中、失败和冲突在收起后仍可发现。排版、注音与阅读界面沿用即时呈现及各自保存范围，复制显式保存；不提供跨组总恢复。每组标题旁的“重置”只影响自身设置，不改学习资料或阅读进度；阅读界面重置保留工具栏上的专注选择，复制重置仅改草稿。具体分组、存储作用域和会话 UI 见[阅读设置](INFORMATION_ARCHITECTURE.md#阅读设置分组与会话)。

#### 应用外观

外观提供浅色、深色与跟随系统，默认跟随系统，选择后立即生效并保存在当前浏览器；跟随系统时响应系统颜色模式变化，同一浏览器的标签页同步选择。浏览器无法保存时仍应用当前选择，并提示保存失败。外观选择独立于服务端设置和模型接入，设置读取失败不阻止调整外观。

素材库、来源、详情、设置、学习片段与讨论共用应用颜色模式，保留现有浅色视觉、布局和阅读层次。EPUB 阅读器继续独立选择白／黑／跟随系统纸面，应用外观不改写阅读纸面偏好，图片保留原始颜色。视觉基线和样式使用规则见[设计系统](DESIGN_SYSTEM.md)。用户自定义 CSS 与其他阅读器重构留待后续。

#### Agent 权限默认值

产品初始默认审核模式，用户可修改新对话默认值，已有线程不自动更改。每个对话显示自身模式，空闲切换、运行／待审核限制及 Full access 边界由 [F9](#f9-agent-工具权限与审核)统一维护。

#### 学习背景

| 信息 | 首轮行为 | 用途 |
|---|---|---|
| 母语 | 用户可填写 | 为必要的语言对比提供背景 |
| 解释语言 | 单独设置，可以与母语不同 | 决定讲解主要使用的语言 |
| 学习情况自述 | 可选自由文本 | 描述已有基础、学习目标及当前困难 |

- 自述是讲解参考，不是经过验证的能力或掌握度判断。不要求填写 JLPT 等级，也不从自述等级自动推断已掌握哪些知识。
- 不能仅因用户填写「初级／中级」就省略理解当前原文所必需的解释。背景信息对解析质量的实际影响需通过使用反馈检验。
- 首轮由用户主动维护，不自动推断或更新画像。后续如引入学习表现反馈，应区分系统观察与用户自述，不静默覆盖用户填写的信息。

#### 讲解偏好预设

- 提供一份基于现有 v0.1 参考模板整理的默认讲解预设；用户可编辑，并按需保存其他命名预设、设置默认值。
- 讨论与讲解生成采用设置中的默认预设，讨论输入区不提供临时预设覆盖。首轮采用可编辑文本，不建设要素库、多预设叠加、权重调节或复杂继承机制。
- 预设内容按下列维度组织，但不要求每项都有内容，也不把这些维度强制转换为解析的固定教学栏目。

| 维度 | 含义 | 示例 |
|---|---|---|
| 讲解组织与细度 | 如何逐步帮助理解 | 先整体后局部、逐块细讲、保留必要推导 |
| 重点关注 | 哪些内容值得展开 | 活用变化链、表达对比、语用与语气 |
| 辅助信息取舍 | 哪些辅助说明需要或可省略 | 注音、常规词典释义、例句数量 |
| 表达方式 | 如何呈现讲解 | 术语配简释、尽量紧凑但不省略关键关系 |

- 偏好表达重点与取舍，不要求模型为填满栏目而添加无依据的解释。例如，关注语用和文化语境不意味着每句话都必须产生文化解读。
- 省略要求应明确边界。例如，不主动逐词注音或列出常规词典释义，但读音、词义选择或搭配直接影响当前理解时，仍保留必要说明。使用词典工具不等于已经掌握相关知识。

#### 本次要求与使用边界

- 用户在聊天消息中直接表达本次要求，例如重点解释某组表达的差别，或简略处理已理解的部分；不另设“本轮要求”按钮或输入框。
- 本次明确要求可调整所选预设中的讲解取舍，不自动修改长期预设，也不改变目标文本与语境的区分、格式契约、解释与推测的区分等产品基础要求。
- 普通提问只提交一份消息正文，本次要求统一写在正文中。旧任务与消息保留；恢复旧任务时，将原问题和原独立补充要求完整合入可编辑正文。工具审核中的反馈说明继续独立提供。
- 系统接受任务时确定本次实际使用的学习背景、预设和用户消息全文并保留记录；排队期间或任务完成后的设置变化不改写该次输入与已有结果。

| AI 操作 | 使用方式 |
|---|---|
| 讲解生成 | 使用学习背景、所选讲解预设、本次补充要求及目标材料；专题讲解按其范围组织 |
| 独立追问 | 使用解释语言和相关偏好，围绕当前问题回答，不每次重新生成整份解析 |
| 讨论成果整理 | 将相关讨论形成可独立阅读的讲解，保留必要背景、限定条件与不确定性；具体入口待定 |
| AI 条目整理／提取 | 遵循条目契约，使用解释语言等必要信息；讲解偏好不改变字段结构，也不允许补讲或偏离所引用的讲解 |

#### 模型配置

用户通过设置界面维护 Provider、可选模型和按用途划分的默认模型，不要求日常操作通过手动编辑配置文件完成。底层存储方式由架构决定，界面与文件不能形成两套独立配置真相。

**Provider 接入**

| 配置项 | 含义 |
|---|---|
| 名称 | 用户自定义的显示名称，用于区分服务、账号或不同接入配置 |
| API 地址 | 服务的 base_url |
| 鉴权信息 | API Key 等；允许本地服务采用无鉴权配置 |
| 默认调用协议 | Chat Completions 或 Responses；个别模型可在高级设置中覆盖 |
| 模型列表 | 从 Provider 获取的模型，以及用户手动添加的模型 |

首轮支持 OpenAI 兼容的 Chat Completions 与 Responses 两种文本调用协议。调用协议与解析、追问、提取等用途分别表达，不因支持某种协议而承诺支持其全部工具或多模态能力。

**模型发现与验证**

- 配置 Provider 后尝试获取模型列表，并提供手动刷新。显示获取状态与最后更新时间；失败时保留已有列表。
- 始终允许手动填写模型 ID。刷新后某模型不再出现，不自动删除既有配置或替换默认模型，而是提示检查。
- 模型选项同时显示 Provider 名称与模型 ID。模型出现在列表中不代表已验证其调用协议、流式能力或结构化输出能力。
- 分别反馈模型列表获取、指定模型调用和所需输出能力的验证情况，不用一个笼统的「连接正常」代表全部可用。生成与能力验证由用户按需触发，不自动遍历测试全部模型。
- 发现列表可登记模型，已登记项不重复添加，保留手动登记与失败时缓存。验证状态基于当前配置，未验证、进行中、成功、失败或中断须可区分，可查看原因、刷新页面及回看记录；控件组织见设置交互。
- 当前仅开放普通文本与流式文本验证，可分别或组合触发；组合操作说明调用次数，每项分别产生 Run，已接受的一项不因另一项失败撤销。结构化输出标明尚未开放验证，不以两项文本通过宣称全部能力已验证。
- 提取优先采用已支持的原生结构化输出；不支持时可采用明确的提示词约束与严格校验兼容方式。兼容方式不标为原生能力已验证，不因能正常聊天就认定适合提取。

**用途默认值与操作时选择**

| 用途 | 系统默认模型的作用 |
|---|---|
| 解析生成 | 保留既有配置；普通讲解入口不再使用，也不产生独立生成调用 |
| 独立追问 | 新开启的对话 |
| 条目提取 | 用户单独发起的 AI 条目提取 |

三项可以采用同一模型，也可以来自不同 Provider，不预设某一用途必须使用低价或小模型。实际选择包含 Provider、模型 ID、调用协议和适用参数；参数按支持情况提供，未指定时尽量使用服务默认值，不向所有模型强行传递同一组参数。

这些用途默认值不规定必须发生三类调用，也不要求每个 Occurrence 都调用提取模型。讲解与保存共用本轮普通对话的 Provider、模型、协议和参数；保存工具自身不调用模型。「创建 AI 讲解」以当前明确选择的模型新建普通线程，缺省采用追问模型；未配置可用追问模型时先选择模型，不回退到旧解析默认值。条目创建的调用方式随其工具契约确定；上下文复用和缓存机制见 [ARCHITECTURE 4.1](ARCHITECTURE.md#41-上下文管理器servicescontextpy)。

| 操作位置 | 选择行为 |
|---|---|
| 保存片段 | 可预选之后用于解析生成的模型，也可保持「使用系统默认」；此要求与普通新对话模型机制的关系待收口 |
| 创建 AI 讲解 | 采用当前明确选择的模型，或新对话默认模型；每次新建普通对话 |
| 新建对话 | 默认采用追问模型，允许改选 |
| 继续追问 | 默认沿用该线程当前选定模型，发送前可更换；改选后的模型用于本轮及后续回复 |
| 触发提取 | 默认采用提取模型，允许为本次操作更换 |

- 普通讲解按新对话模型选择规则运行，不另外启动解析模型；保留既有用途默认配置，不据此安排多阶段调用。片段不另建三个用途的完整默认配置。
- 「使用系统默认」在操作提交时解析为当时的默认值；明确选定的模型保持该指定。单次改选不自动修改全局默认值。
- 保存时预选模型不发起解析，也不锁定目标原文。
- 在对话中切换模型不改写历史消息；系统为新模型提供该线程所需的历史、原文与相关资料，不自动混入其他线程历史，也不要求必须存在解析。Folio-J 本地保管完整对话与出处，不仅依赖某个 Provider 的远端会话 ID。

**待收口：片段保存时的模型预选。** 上表保留既有预选要求；其保存位置、与新对话模型选择的优先关系及是否继续保留该入口尚待确认。当前片段保存未提供模型预选，普通 AI 讲解使用前述新对话／追问模型机制；实现差额见[实施基线的未落实契约](handovers/MVP_IMPLEMENTATION_BASELINE.md#2-尚未落实的契约与目标差额)。本项不改变已确认的普通讲解机制，也不自行取消原预选要求。

**配置变化、失败与记录**

- 系统接受任务时固定实际使用的 Provider、模型、协议和参数。之后修改默认值不影响已排队任务，不改写历史结果。
- 指定配置不可用时明确报告，不悄悄切换 Provider、模型或采用新的默认值；用户可以改选后重试。
- 每次生成及模型调用验证记录实际调用信息。密钥由本地后端管理，不进入普通模型信息响应、提示词或调用日志。

### F2 Source 与片段

#### 来源管理

- 用户能够创建、浏览 Source，并维护其标题、备注和出处描述等信息，不要求上传素材文件。
- Source 表达用户声明的来源范围，不与单个文件一一对应；同一来源可容纳多份 EPUB，其他媒体按第 4.6 节保留为后续范围。具体片段仍保留各自的出处信息，不因同属一个 Source 而被视为连续原文。
- 手动录入继续支持，不要求创建虚拟 TXT 素材；用户疑问、听写等附带信息也不因此成为素材。当前 EPUB 阶段允许在来源详情导入一份或多份 EPUB，成功后从书卡进入阅读；不因导入自动创建学习片段或发起模型调用。
- 同一来源重复导入相同字节返回已有活跃材料；不同来源保留独立材料身份。删除后重新导入相同字节创建新材料及版本，不恢复旧材料、阅读位置或自动换绑历史出处。原书托管副本和已发布处理版本保持不变，内容不同的 EPUB 作为新材料处理。书籍详情、信息编辑和删除入口见第 4.2.1 节；移动继续禁用。
- 从系统保存的 EPUB 中选取目标文本，与手动录入汇合到 Segment 学习流程，沿用 Source／Segment 归属及下述原文固定规则。已确认的同章范围、可编辑语境预装和显式复用边界见第 4.7 节，按 C1／C2 实施。
- 修改当前来源信息不反写历史调用实际使用的输入。

#### 片段保存与编辑

- 每个 Segment 归属于一个 Source。目标日文必填，其他附带信息按需提供；支持先保存、后提问；「创建 AI 讲解」快捷入口新建普通对话并提交明确请求创建、保存独立讲解的预定问题。
- 片段提供明确的复制分享入口，可复制原文及出处、仅原文或仅出处；保留已保存语境和原有文字／换行，区分目标与语境，不带译文、听写、讲解或个人管理备注，不自动发送到外部服务。结果明确反馈，失败可手动复制；预览、出处排序及控件见[片段阅读交互](INFORMATION_ARCHITECTURE.md#讲解浏览人工保存与按需讨论)。
- 已保存且尚未触发原文固定的目标文本允许修改，仍为同一个 Segment。
- 原文有三种固定触发：首次以该原文为输入的 AI 任务被系统接受、首次成功保存持久讲解、首次建立精确材料出处，任一成功即固定目标原文。AI 触发不等待模型返回；打开编辑器、取消或失败保存不固定。任务失败／中断、删除讲解均不解除固定，需要不同目标文本时创建新片段。
- 人工保存必须核对用户编辑时看到的原文摘要；期间目标原文已改变时拒绝提交，保留草稿且不固定原文、不保存讲解。原文固定与成果保存同时成功或失败；备注等附带信息变化不作为原文变化。
- 当前聊天受理与持久讲解保存共同固定原文；精确出处创建也触发原文固定。已有历史讲解却未锁定的片段（含仅剩软删讲解）须保守固定当前原文，记录保护生效时间；不伪造历史受理时间或旧讲解当时的原文快照，不改写历史修订。
- 该规则是目标文本的编辑边界，不构成整个片段的线性生命周期，也不要求用户手动执行锁定操作。
- 来源与管理信息可以维护；新一次解析可以采用不同语境和要求，但历史调用使用过的内容保持原样。个人管理备注与提供给模型的输入需明确区分，具体输入形式在交互设计中确定。

#### 删除与清理

首轮按对象提供明确范围的删除，不提供归档。普通筛选用于选择当前展示内容，不额外引入长期隐藏状态。

| 删除对象 | 删除范围 |
|---|---|
| Source | 下属 EPUB 材料、Segment，以及这些片段的解析、修订、讲解块、对话和 Occurrence 等关联学习内容 |
| 单份 Material | 清理该材料托管副本与派生阅读数据，保留材料身份及历史出处所需信息；保留所属 Source、全部 Segment 及其讲解、讨论和学习条目，以及同来源其他材料 |
| Segment | 该片段及其解析、修订、讲解块、对话和 Occurrence 等关联学习内容 |
| 单份 Analysis | 该解析及其全部修订、讲解块和引用它的 Occurrence；保留 Segment、其他 Analysis 及属于 Segment 的对话线程 |
| 单条 Occurrence | 仅该条学习记录，不删除其原文和解析 |

- 删除表达用户不再需要保留这条记录，例如错误、重复或试验产物；已删除内容不进入日常浏览。它是独立操作，不是待整理、已收录、仅参考之间的状态切换；首轮不提供恢复入口。
- 级联范围包含已收录、仅参考及其他整理状态的 Occurrence。收录不意味着创建了独立于来源的内容副本。
- 删除单份 Analysis 前展示其关联内容及条目数量，由用户确认；提供删除业务接口，但首轮不向 Agent 开放整份 Analysis 删除工具。对话内容保留，其中指向已删除讲解的入口显示已删除，不改指其他讲解。
- 用户通过管理界面删除时，先展示影响范围，包括相关片段、解析和已收录条目数量，由用户确认；不能将其描述成仅从目录移除入口。若向 Agent 开放删除工具，审核模式下将具体对象与影响范围纳入工具审批，Full access 下不再逐次审批，但仍展示执行结果与实际影响。权限模式不自动授予尚未开放的 Source／Segment 删除工具。
- 删除覆盖与所选对象确有归属关系的内容，不因标题或 anchor 相同而影响其他来源。
- 独立材料删除清理托管 EPUB、编译包、分词、封面及阅读状态／位置，保留身份、书名、版本和删除记录等历史出处所需信息；用户选择的本地原文件不受影响。确认明确所删书籍、清理不可撤销及学习积累保留，提交中防重复，失败可重试；成功刷新目录与计数、回到有效页并隔离旧缓存。
- 单份材料删除保留学习内容的原文、语境和出处信息，不解除片段原文固定。材料删除须保留精确历史出处与文字快照，返回原文明确提示材料已删除，不搜索同文或因重导而自动换绑。材料对话尚未实现，其删除与保留范围在对应切片明确。
- 来源删除确认须列出 EPUB 材料数量；删除后这些材料不可再读，原始托管字节暂不物理清理。材料随来源的不可见性不能被迟到导入或位置保存恢复；物理存储策略不扩大既有学习内容删除范围。
- 后台任务及迟到结果不能重新生成或恢复已删除的可见内容。关联调用记录的处置与运行中任务的处理方式，在架构设计中统一。
- 此处定义产品上的删除范围，不直接规定数据库硬删除。逻辑删除、物理清理及保留策略由架构落实，并与 Occurrence 的软删除约束保持一致；首轮不因此增加回收站或恢复界面。

### F5 学习条目创建与整理
- P0：Occurrence 表达一个可独立作出收录决定的学习点，关联目标原文与持久讲解。相同原文位置不足以判重，不同讲解的条目分别保留来源；条目数量不直接代表原文出现次数或掌握程度。
- P0：提供 Agent 查询已有条目及其状态、原文位置和讲解出处，创建一个或多个待整理候选，以及修改已有待整理候选的基本能力。首轮暂缓手动创建条目；批量提取不是必经阶段，也不要求设置独立批量提取按钮。后续按真实高频组合增加 Shortcut tool，复用同一套定位、引用与权限规则。
- P0：条目创建只组织已有讲解支持的学习内容，不在短字段中补充新的教学分析。讨论中的补充理解需先成为自足讲解，条目再引用该讲解；不直接以聊天消息作为阅读出处。
- P0：解释语言等必要设置可用于 AI 整理；讲解偏好不改变字段契约，不授权增加来源讲解未支持的内容。
- P0：条目契约明确且带版本；AI 标签只能从预定义词表中多选或不选，禁止自造标签。当前四类类型与五个标签见 GLOSSARY 第 4.1 节；具体 schema 和 anchor 规则仍待细化，手动输入形式留到相应能力阶段。
- P0：无论创建入口如何，保存的条目必须通过原文定位与讲解引用校验，引用应属于明确的来源修订。校验通过不等于已证明教学解释正确或提取完整。
- 候选创建／修改按独立结果反馈；已经通过校验并成功保存的部分保留，失败部分回传 Agent 修复，不将整批重跑作为默认恢复手段。自动修复与临时故障重试受统一的有限执行预算约束，见 F8；具体参数由执行策略确定，不沿用可与 Agent 循环叠加的独立「再重试 2 次」占位。
- P0：系统记录条目的片段、具体修订／讲解块、Source 与创建来源；模型参与时关联相关 Run，手动操作不伪造 Run。

- 首轮移除独立的「忽略」状态，不再使用 `dismissed` 同时表达忽略与删除。删除是独立产品操作，保留 Occurrence 以状态变更软删除的技术约束；内部删除状态编码由架构落实，不因此增加归档、回收站或恢复入口。

- 首轮不提供解析完成后自动提取的开关。

#### 再次整理已有讲解

- Agent 再次整理前先读取相关已有条目，以补充遗漏的待整理候选、明确修改已有待整理候选为主。修改仍遵循 F9，不因称为「重新提取」而绕过审核。
- 已收录、仅参考条目只作为参考，Agent 不修改其内容、出处或状态。已有待整理候选不会因新一次调用自动失效；不整批替换、自动合并或迁移用户的整理决定。
- 不确定是否重复时，可以说明疑似重复或不同之处，但不能仅凭相同 anchor 或原文位置合并记录。不承诺 Agent 每次都能准确识别语义重复或完全消除重复候选。
- 讲解产生新修订后，旧条目继续引用原修订。待整理候选若需要更新内容和出处，应一起提出具体修改；已收录、仅参考条目不会自动跟随。Agent 可在讨论中指出新讲解对旧解释的纠正和受影响条目，用户若希望由 Agent 修改，需自行将目标退回待整理。
- 用户明确需要彻底重做时，可清理选定候选后再生成；清理范围与删除按已有规则处理，不隐含在普通再次整理中。
- 结果展示本次新增、提出修改和实际保存的内容，各次调用保留来源；不要求用户先管理「第一批、第二批」提取结果才能使用。一次再次整理没有发现新学习点也可以正常完成，不为凑数量生成候选。

### F8 状态与诊断

用户能查看任务进度、有用的失败信息及已保存成果，并采取重试等操作；系统保留必要的调用与产物记录，供排查使用。首轮不要求完整开发者调试平台，诊断入口与展示粒度由交互设计确定。

#### 后台执行、审核等待与停止

生成讲解、获得 AI 回复、AI 整理讨论成果或提取条目等涉及 AI 的操作，均采用后台异步执行的产品行为。系统接受任务后，用户可离开当前片段、切换页面或关闭浏览器，无须等待完整回复；离开页面不构成取消任务，离开和返回也不自动重复发起模型调用。该要求适用于最终纳入首轮的 AI 入口，不将普通手动保存也规定为模型任务。

重新进入时，用户能查看已提交任务的当前状态，并读取已完成结果；结果不依赖原页面持续打开才能保存。流式显示是观察任务的方式，不是任务执行的前提。普通提问和快捷生成讲解均展示当前可确认的活动和受理后的已用时间。撰写、保存和已保存各以实际事件为准；没有中间输出时保留等待状态。

本地后台服务停止与离开界面是不同事件。服务停止或故障导致任务中断时，应明确呈现中断／失败及可采取的重试操作，不把残缺结果冒充成功产物，也不承诺服务未运行时任务仍能继续。

工具等待审核时，展示待审核状态并保存具体方案；离开页面不代表同意或拒绝，返回后仍能处理。依赖该写入的动作等待审核与实际保存完成，不将尚未保存的讲解当作正式 Occurrence 出处。后台重启不得使待审核方案被自动执行；执行中断与审核等待需分别表达。

同一线程执行本轮或等待审核时，可继续输入草稿，但不能发送新一轮讨论，不做消息排队。待审核期间通过同意、拒绝及可选附加指令，或停止本轮来推进；审核反馈不视为另发一轮消息。其他独立线程不因某线程待审核而被一并阻塞，后台仍可按资源调度。

用户可以主动停止本轮，停止后不再启动其后续生成、自动修复或工具操作，尚未执行的待审核方案取消。停止不是撤销，已保存成果保留；恰在提交的操作按实际保存结果反馈。未完成回复可明确标为中断内容，不作为成功讲解。停止处理完成、线程回到空闲后可以继续发送；已停止的旧任务与方案不能因迟到结果继续写入。

#### 执行状态、已有内容与整理进度

片段及其解析作为持续保存、可再次访问的学习内容，不要求完成提取或结算后才能离开，也不因结算完成而关闭。系统分别呈现 AI 任务的执行状态、已有内容和条目的整理进度，不以单一状态表示整个片段的生命周期。

| 关注点 | 表达范围 | 示例 |
|---|---|---|
| 执行状态 | 某次解析、AI 回复、提取任务及相关工具操作 | 排队中、执行中、等待审核、成功、部分完成、失败或中断；拒绝某次工具操作需可辨认 |
| 已有内容 | 片段已有的解析，以及选定解析的提取情况 | 已有 2 份解析；选定解析尚未提取 |
| 整理进度 | 一批提取结果或明确范围内条目的处理情况 | 3 条待整理；本批条目已整理 |

这些信息可以并存，例如「已有 2 份解析 · 1 个任务进行中 · 3 条待整理」。聚合展示应明确其统计范围，不将某次任务的状态或某批条目的整理结果冒充整个片段的唯一状态。

使用「尚未提取」描述未执行提取的事实，不使用「待提取」暗示必须完成后续工序。没有提取结果不代表片段使用未完成；已整理条目也不妨碍继续阅读、追问或生成另一份解析。

首轮不引入必须开始、结束的总体解析 Session，也不要求用户执行「结束学习」来关闭片段。离开界面、一次任务完成与一批条目整理完成分别表达，不互相触发。

工具待审核、被拒绝、执行成功和执行失败分别可辨认；批准不等于保存成功。拒绝不作为模型错误自动重试同一操作，用户的新指令可形成新方案。

#### 成功、失败与等待的判定

操作成功表示适用的字段、类型、原文定位、讲解引用、权限和当前目标状态校验通过，且结果已经实际保存；不表示教学解释已被证明正确，也不表示学习点已提取完整。引用存在不能单独证明提取判断正确。没有发现新学习点是正常结果，不作为失败或要求继续凑数的理由。

| 情况 | 保存与反馈 | Agent 后续行为 |
|---|---|---|
| 字段不合法、原文定位失败、讲解引用无效 | 不保存无效结果，返回具体错误及相关条目／操作 | 在执行预算内按反馈修正后重新提交 |
| 目标内容、状态或存在性已变化 | 不应用旧方案，说明当前情况 | 重新读取，遵守当前可操作范围；不能把已收录条目改回待整理后修复 |
| 临时调用或存储错误 | 保留已有成果，报告原因与写入情况；保存结果不确定时明确标出 | 先核实实际保存情况，再有限重试，避免重复创建或应用 |
| 正在等待用户审核 | 保存待审核方案，显示等待，不算失败 | 等待决定，不当作错误重试 |
| 用户拒绝或操作权限不允许 | 不执行该操作，反馈原因及用户附加指令 | 不反复提交同一方案；有新指令时据此调整，仍不得越过工具范围 |

#### 保留成功部分与反馈修复

- 以实际成功保存的独立条目或修改为单位保留成果。一次尝试创建 10 条候选，8 条通过校验并保存、2 条定位失败时，8 条可立即查看，2 条只保留必要失败诊断，不作为正常 Occurrence 入库。已有条目的修改失败时，原内容保留。
- 只有能够独立识别、校验并保存的结果才计为成功。整个输出无法解析时，不凭猜测宣称其中一部分成功；不将残缺内容冒充完整讲解或条目。
- 讲解已独立保存后，后续候选失败不撤销讲解。任务中断、后续修复失败或耗尽预算，也不回滚已经成功保存的成果。
- 工具反馈给 Agent 时分别说明哪些已保存、哪些未保存、哪些保存结果需要核实，附成功记录的明确标识与具体失败原因。Agent 修复失败部分，不重新提交已成功的创建或修改。
- 未成功创建的候选在修正后仍走创建流程；修改已经保存的候选继续走修改流程和相应审核。修复不授权改变用户整理状态，也不豁免校验或审批；需要更新获批内容时仍按 F9 处理。
- 对可修复错误，执行流程允许 Agent 根据反馈继续尝试；临时故障允许有限重试。设置有限的修复次数、时间或调用预算，具体参数及底层重试与 Agent 循环的协调方式在执行策略中确定，不能多层叠加而无界运行。
- 达到预算后停止本次自动修复，保留成果，展示尚未完成的项目、原因和后续可采取的操作，允许用户之后继续。待审核、用户拒绝或权限不允许不按技术失败自动重试。
- 用户能看到实际进展，例如「已新增 8 条候选，2 条因原文定位失败尚未完成」；之后修复成功则更新结果。不能静默丢弃错误并将部分完成描述为全部成功，也不能把可验证的条目计数当作整份讲解的知识覆盖率。

### F9 Agent 工具权限与审核

任务意图与执行许可分别表达。Agent 先确定本次要对哪个对象做什么，再按线程权限模式执行。已开放的写入工具必须遵循本节；具体工具名称与粒度由架构设计，不依赖提示词单独保证。

| 模式 | 行为 |
|---|---|
| 审核模式 | 可直接执行的操作按下表运行；需审核的写入先准备具体方案，用户同意后执行 |
| Full access | 对已开放且符合任务意图的工具操作，省去逐次审批；仍展示结果、校验数据并保留历史出处 |

每个对话清楚显示自身模式，仅在本轮结束或停止完成、线程空闲时允许切换；运行和待审核期间不切换，不通过切换 Full access 放行挂起方案。产品初始默认审核模式，新对话可采用用户更改后的默认值。共享片段资料不意味着共享或继承其他线程的权限。Full access 不扩大工具集合，也不将普通问答自动转换为修改任务。

**审核模式下的操作分类：**

| 操作 | 行为 |
|---|---|
| 读取原文、检索讲解与条目 | 直接执行 |
| 用户明确要求保存为独立讲解 | Agent提供完整正文后直接保存，不要求为同一新建动作额外审批；普通解释不默认授予保存意图 |
| 修改已有讲解 | 审核确定目标、基础版本与具体修改后执行 |
| 修改已有待整理候选内容 | 默认审核具体目标与内容差异后执行；保存后仍为待整理，批准修改不代表收录 |
| 删除指定 Section | 作为修改已有讲解审核，成功后形成新修订；不删除历史修订与引用 |
| 删除整份 Analysis | 首轮不向 Agent 开放；由用户经关联范围确认后操作，见 F2 |
| 仅创建待整理候选 | 默认直接执行，不因写入候选或批量创建本身额外要求审核；仍校验原文与讲解出处 |
| 创建非待整理条目，或改变整理状态 | 首轮不提供给 Agent；收录、设为仅参考、退回待整理由用户界面操作，Full access 也不开放 |

分类依据是工具的实际效果，不仅是工具名称或「新建／修改」。混合操作若同时生成候选并修改已有讲解或候选，不能因含有候选生成而绕过修改审核。Full access 省去上述逐次审批，但不能通过组合工具或先创建再修改状态的方式完成自动收录。组合工具的审批展示与恢复实现仍待细化，部分完成时遵循 F8 保留已保存成果的规则。

**具体方案与用户反馈：**

- 修改审批应展示目标讲解／Section 或待整理候选、修改目的及原内容和拟保存内容，或可理解的差异。先准备可判断的结果，不让用户批准模糊的「允许修改」后再任意生成内容。
- 用户可以同意或拒绝，并可在任一选择中附带新指令。同意只批准已展示的方案；同意并附带指令时先应用该方案，成功后再执行后续任务，失败则明确报告。拒绝不应用该方案，附带指令可用于重新准备。
- 补充指令不得静默改变刚批准的内容。后续若形成新的、需要审核的修改，应再次按当前权限模式处理。
- 方案待审核期间不修改正式讲解或条目；离开页面不会替用户决定。依赖该写入的动作必须等待实际保存成功，待审核方案不能冒充正式成果。
- 审批绑定确定对象、基础版本与具体变更。其他对话已修改目标时，旧审批不能覆盖新版本；应基于最新内容重新准备，并在审核模式下重新展示。Full access 同样不能盲目覆盖过时目标，须重新核对，但不额外引入逐次审批。
- Full access 不绕过原文定位、引用校验、不可变修订、删除范围和历史出处规则。执行结果均需可见、可检查。

混合效果工具的审批展示仍见 `[TBD-17]`。初始默认审核模式、只在空闲线程切换、停止时取消未执行方案，以及候选创建免审／修改需审／不开放自动收录的边界已确认。

## 8. 成功标准

本节按已确认的基本能力整理为验收草案，具体案例继续审订。「创建 AI 讲解」验证每次新建普通对话、预定问题明确请求创建保存、Agent正文原样落库、真实身份返回及主页面可读；普通提问验证默认只回复；其余快捷按钮和高频组合工具可在闭环后打磨。

- 用户可围绕已保存片段直接讨论，不被要求先生成完整报告；保存与阅读讲解不以提取和结算为前提。
- 发起解析或讨论时，适用的学习背景与偏好自动带入，无需重复粘贴。
- C2 中从“保存为学习片段”入口预装有界语境；本次流程内收起再展开保留草稿，修改、清空、配置变化及迟到结果不导致预填覆盖用户内容，重开已存片段保留其语境。目标与出处保持稳定，保存不隐式调用模型。预算与失败样例见[验收矩阵](handovers/text-study/TEST_MATRIX.md)。
- 原文、讲解与条目持久保存；离开工作台或重新进入后仍能找回。对于纳入首轮的讨论整理入口，成果脱离聊天历史仍可理解。
- 阅读 Occurrence 时，在当前页面读到原句与确切来源版本的原 Section，并能回到完整讲解；不以点击次数替代已有阅读基线。
- 已保存条目的定位与引用必须通过校验；模型输出失败和未完成结果可识别，不把这一要求描述成模型每次提取均正确、完整或稳定。
- AI 任务离开页面后仍由后台执行，返回可查看状态和结果；后台停止导致的中断可识别，刷新不重复发起调用。
- 对纳入首轮的 Agent 写入工具，审核模式能查看具体方案、同意或拒绝并附加指令；拒绝不落地修改，待审核可返回处理，批准不重复应用，过时版本不覆盖新内容。Full access 可直接执行同类已开放操作，仍满足引用与修订规则。
- Agent 创建条目一律为待整理且默认免审；修改待整理候选在审核模式下默认需审核，保存后仍为待整理。用户在审核期间改变目标整理状态后，旧修改不能继续应用。两种权限模式均不提供自动收录或整理状态工具，批量与混合工具也不能绕过。
- 待整理、已收录和仅参考可相互调整；仅参考保留查找与阅读，默认不参与后续学习活动。删除条目不删除原文和讲解，删除后不进入日常浏览；首轮无独立忽略状态、归档或恢复入口。
- 再次整理先参考已有记录，不自动清空候选、替换旧条目、迁移状态或漂移出处；无需为使用这一能力先管理提取批次。
- 部分失败时已独立保存的讲解、候选与修改保留，无效结果不作为正常条目入库；反馈区分已保存、未保存和需核实，继续执行不重复创建成功部分。没有新学习点可正常完成。
- 自动修复有有限预算，耗尽后保留成果并说明未完成内容；用户拒绝、权限不允许和等待审核不会引发错误重试循环，修复也不绕过已有审核规则。
- 多份讲解并存时，Section 操作核对明确的 Analysis、基础修订和块归属；更新、插入、删除产生新修订，旧引用保留。删除整份 Analysis 须经用户关联范围确认，不删除 Segment 的对话线程。
- Agent 不能读取其他片段资料或检索其他线程聊天历史；当前片段下已保存讲解可共享。初始默认审核模式，运行／待审时不能切换模式；同线程不能继续发送或排队，其他线程不随审核等待被锁住。停止后不再启动本轮后续操作，未执行方案取消，已保存成果可找回。
- 实际试用观察用户是否愿意持续使用、整理是否打断学习、旧讲解是否容易找回。「一周内不再打开网页 AI」可作为个人观察，不作为硬性验收条件；学习条目数量不代表掌握度。
