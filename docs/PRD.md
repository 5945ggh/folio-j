## 1. 产品背景与问题

### 1.1 背景

Folio-J 源于开发者使用日语原版小说、动画等内容进行自学的个人实践。

这类学习以真实日语内容为主要输入。用户选择自己真正感兴趣的原版素材，在阅读或观看过程中尝试理解其内容；遇到超出当前能力的词汇或语法表达时，再借助词典、LLM 等工具获得必要帮助，并继续原本的内容消费。

在开发者的个人实践中，结合上下文、学习者水平和个人偏好，LLM 已能对明显超出当前水平的内容给出有助于理解的讲解。在传统的阅读辅助手段（如 yomitan）之上引入 LLM，可以使原版素材的可学习性与学习者当前语言水平进一步解耦，从而允许学习者更多地依据兴趣选择内容。

Folio-J 希望围绕这种以原版内容为中心的学习方式，形成一套覆盖理解辅助、主动学习、知识积累与后续适应性教学的个人日语学习系统。

### 1.2 理想中的学习流程

学习过程中，用户阅读、观看和理解自己选择的原版内容。当理解过程顺利时，不需要额外学习操作；当遇到障碍时，用户根据需要获得不同程度的辅助。例如：

- 查询单词或表达的含义；
- 获取一句话的简要解释；
- 针对复杂句子的结构、语法、语用、文化背景等获得详细解析；

这些辅助的首要目的是恢复对原文的理解，使用户能够继续沉浸于素材本身。并非每一次辅助都应转化为需要保存和复习的学习内容。当用户认为某个片段值得进一步掌握时，可以将其转化为更显式的学习活动，例如深入讨论、形成独立讲解、收录为积累条目供后续学习。

因此，原版内容既是用户最终希望理解的对象，也是语言学习发生的主要环境；LLM、词典和结构化学习材料作为支架，帮助用户处理当前尚不能独立理解的部分。

### 1.3 现有流程中的问题

目前这种学习方式往往需要在阅读器、播放器、词典、LLM 对话和复习工具之间频繁切换。随着学习持续，主要困难不仅是「如何获得一次好的讲解」，还包括：

- 为了获取高质量的 AI 解析，原文前后文、学习者水平、解析偏好和作品背景等信息需要重复交代；
- 临时解释、深入讲解和真正值得长期学习的内容混杂在聊天记录中，难以复用；
- 原文、讨论、讲解和后续学习记录之间缺少稳定联系；
- 不同工具之间切换存在一定人工衔接成本。

Folio-J 希望减少这些重复劳动，降低用户围绕原版素材持续学习的成本与消耗，并让有价值的理解过程和学习记录能够按需沉淀、关联和复用。

长期演进的动机与假设见 [PRODUCT_DIRECTION 第 2 节](PRODUCT_DIRECTION.md#2-产品重心围绕原文形成可持续使用的学习成果)。

## 2. 产品定位与长期方向

Folio-J（Lingua Portfolio - Japanese）是一个以用户感兴趣的日语原版内容为中心、利用 LLM 提供理解支架与学习支持的个人日语学习系统。首要目标是帮助学习者维持对超出当前独立理解能力的内容的理解，并逐渐减少对辅助的依赖。

首轮建立围绕「原文—讨论—讲解—学习条目」的基础能力：用户可以直接讨论片段，按需保存自足讲解、留下有出处的学习点，并在之后找回原句与解释。保存讲解可以止于讲解，创建条目的前置关系见第 4.3 节，不要求固定的「完整解析 → AI 提取 → 结算」流程。

本轮范围与入口由第 4 节和 F1–F9 定义。当前优先推进第 4.7 节的 EPUB 原生阅读阶段，Occurrence 与积累库暂缓；媒体播放、课程推荐或主动复习仍不在本阶段范围。ITS、个性化预学习与适应性教学的长期理由和设想归入 [PRODUCT_DIRECTION 第 2 节](PRODUCT_DIRECTION.md#2-产品重心围绕原文形成可持续使用的学习成果)，不作为首轮交付承诺。

## 3. 目标用户与使用场景

Folio-J 面向希望通过兴趣导向而不是难度导向选择日语原版内容作为主要语言输入来源的学习者。

用户可能已经能够通过外部工具获取素材和选择学习片段，也使用过其他第三方学习工具。

产品按单用户、本地运行设计。当前接入普通可重排 EPUB 阅读；媒体播放或主动复习流程仍留待后续独立阶段。

## 4. 当前版本目标与范围

### 4.1 当前目标

用户能够围绕自己选择的日语片段阅读、提问和讨论，按需要留下符合个人需求的独立讲解与学习条目，并在之后方便地找回、阅读和再理解。

当前版本应支持持续使用的学习流程，包括必要的追问、状态反馈和数据保存。

### 4.2 首轮目标能力与边界

下表定义片段学习的目标能力；实现差额见 [MVP 实施基线](handovers/MVP_IMPLEMENTATION_BASELINE.md)。材料阅读与学习衔接范围见第 4.7 节，后续顺序由[阶段入口](handovers/README.md)维护。总体讲解快捷入口纳入 Analysis 能力，其余快捷按钮与组合工具可在闭环后按高频用法增加。

| 能力 | 用户能够完成的事情 | 首轮边界 |
|---|---|---|
| 来源与片段管理 | 登记用户声明的来源，添加目标文本、备注和必要语境，再次打开已有片段 | 手动录入；不要求导入或保存素材 |
| 学习背景与讲解偏好 | 保存学习背景和讲解要求，解析时自动带入 | 用户维护；不自动推断能力或掌握程度，不先建设完整学习档案系统 |
| 讲解形成与保存 | 直接保存手写或外部 Markdown、人工编辑全文；也可生成系统性或专题讲解，修改讲解块 | 人工入口无需模型；修改已有 Analysis 产生新修订，旧修订只读；Agent 继续按块编辑，整份删除由用户确认 |
| 学习条目创建与整理 | 将值得积累的学习点关联到原文与持久讲解，查看出处并整理 | Agent 查询条目、创建一个或多个待整理候选、修改待整理候选；用户直接整理状态，暂缓手动创建条目，不提供自动收录 |
| 查找与再阅读 | 从来源、片段或学习积累库找到已有内容，直接阅读原句和相关讲解，并围绕问题追问 | 原 Section Markdown 为阅读基线；支持基础独立对话，不做自动聚类 |
| Agent 协作与工具审核 | 在短问答或持续讨论中形成、修改讲解并整理条目；审核具体操作或使用 Full access，可停止本轮 | 首轮只读取当前片段资料；线程执行或待审核时不接收新轮，初始默认审核模式，空闲时可切换权限 |
| 运行与数据保障 | 配置模型、区分解析和提取等环节的状态，查看有用的失败信息并采取重试等操作，关闭后仍能找回数据 | 保存必要的调用与产物记录供排查；不要求先建设完整开发者调试平台 |

### 4.2.1 本轮材料目录与阅读管理

本节定义素材库与来源空间的产品行为，当前交付状态及验收入口见 [MVP 实施基线](handovers/MVP_IMPLEMENTATION_BASELINE.md)。

一级空间为素材库与 Source，设置稳定可达；根入口替换式跳转素材库，不新增 Home 或无对象工作台。素材库目前只接 EPUB 书籍；顶部同时展示漫画、有声书、视频的禁用占位选项，鼠标与键盘均不能切换。跨 Source 组合材料标题／Source 标题文字搜索、Source 与阅读状态筛选、排序分页。不设独立继续区域，以最近打开排序配合已有位置恢复。

素材库采用 A（轻原生）：主导航与内容两栏，顶部一排左侧类型切换、右侧工具，不另叠大页头。搜索与筛选由命名明确的图标入口展开，生效条件可见且可清除；排序依据与方向合为一个入口，保留卡片大小调整。书卡以真实封面为主体，下方书名，底部右侧三点菜单提供书籍详情、编辑书籍信息、移动到其他来源、阅读状态和底部删除书籍。菜单使用紧凑行距；阅读状态作为二级入口，在子菜单中选择未开始／进行中／已完成。移动显示“暂未开放”并禁用，鼠标与键盘均不执行。删除书籍打开范围确认，规则见下文。封面／书名进入阅读，菜单不触发阅读，不常驻状态下拉框，也不重复同名来源。素材库与来源空间的同一书籍使用相同菜单。单页不显示整套分页控件，多页保留真实分页。

只有已确认的真实空库才显示整个可点击的低对比虚线导入区，区内无独立按钮，顶部重复加号与相邻分隔线隐藏；有书后恢复加号。入口支持 Tab、Enter／Space，取消导入回到入口，导入完成后回到仍存在的有效入口。搜索／筛选无结果显示调整或清空条件的提示；加载和失败不冒充空库。导入仍明确选择已有／新 Source，不静默决定归属。未实现拖拽时不显示拖入文件文案。

导入中的“新建来源”进入专门的表单视图，只呈现来源信息与创建／返回操作。创建成功后回到添加书籍，自动选中新来源并保留已选文件；返回未完成的创建也保留文件和原有来源选择。每个视图只显示一组操作，正常创建后通过来源选择表达结果，导入等待和失败反馈按实际状态出现。

全局导航显示“来源目录”；折叠可用品牌旁侧栏图标，不使用底部常驻“收窄导航”文字菜单。公共样式和控件可复用，不要求每个路由共用固定两栏外壳；来源空间、Reader 与 Segment 按各自页面职责组织。全书进度、新书架、播放器与未接入学习能力继续延期。

书籍详情显示书名、封面、所属来源、导入时间、阅读状态、最近打开及章节数量等真实信息，不用整个 Source 的学习内容推算本书成果。详情和卡片菜单共用书籍信息编辑表单，可修改应用内书名、上传自定义封面或恢复原书封面；编辑不包含替换 EPUB，不修改 Source 信息。书名与封面同次原子保存，保存失败保留草稿，并发编辑冲突提示重新读取；放弃未保存修改须确认。封面沿用静态 PNG／JPEG、4 MiB、1600 万像素限制。自定义封面优先且不受自动封面缓存重建影响。信息编辑不改变原 EPUB、不可变编译版本、原文定位、阅读状态、位置或注音结果；查看详情和编辑不记录一次阅读打开。

2026-10-22 确认提前开放独立材料删除，本轮只提供“删除材料，保留学习积累”。删除同时清理应用托管的 EPUB 副本、编译包、分词、封面及阅读状态／位置数据，只保留材料身份、书名、版本与删除记录等历史出处所需信息；用户选择的本地原文件不受影响。确认框指明所删书籍、清理不可撤销，以及 Source、Segment、讲解、讨论等学习内容和同来源其他材料均保留。取消不执行删除，提交中防止重复操作，失败保留确认框并允许重试；成功后刷新目录与计数，末页失效时回到有效页，不再显示旧材料缓存。

移动与“一并删除关联学习积累”继续后置，本轮不展示一并删除选项。后续移动携带明确关联的片段及其讲解；一并删除须展示实际影响，并验证历史引用、讨论和进行中任务。没有材料出处的手动 Segment 只有 Source 归属与自由文本出处，不能按同来源、书名或出处文字猜测其属于某本书。

封面优先使用有效的明确声明，声明缺失或不可用时按稳定、可测试的顺序回退首张可用包内图片，确实无可用图片才占位。保留有界静态图片与包内路径安全限制，失败图片不显示破损图标。旧失败缓存可失效并重新提取，前端新封面结果应解除旧加载失败状态；不要求删除重导，不改材料身份、原始字节、不可变编译包或阅读位置。

Source 使用主导航／来源列表／来源内容三栏，来源列表全高独立滚动，搜索／排序／新建位于栏头；超出一次 API 返回上限时仍可访问全部来源。右侧为紧凑名称、可选说明与来源菜单，以及概览／素材／片段／讲解四视图。来源信息、编辑、删除集中于来源菜单；导入位于素材区域并固定当前来源，添加片段位于片段区域。

来源概览以最近更新的讲解和最近添加的片段为主，所属素材与已有备注为辅助。当前有界预览为讲解 2 条（updated_at 降序）、片段 3 条（created_at 降序）、素材 3 份；备注约 4 行并可在来源信息查看完整内容。条数是展示参数，不是领域不变式；总数取真实目录统计，不取预览长度。无讲解但有片段、只有书籍、全空来源、零来源分别如实呈现；失败与加载不冒充空态。概览查询独立于完整列表旧检索条件，不推导学习状态或活动流。

普通主导航进入来源目录时记住上次有效来源身份，否则选当前排序首项，打开概览；主动选择来源也打开概览。明确 URL、同路径刷新、浏览器前进后退与阅读返回优先恢复精确视图、条件、窗口及可恢复列表位置；旧 expanded=book 未带 view 的链接仍按素材窗口处理。显式失效来源显示不可用，不能静默换源；检索把当前来源滤出、或来源不在首批，也不等于失效。

素材视图保留已有真实类型预览和同类全部材料的应用内模态窗口，支持刷新直达及阅读后返回原窗口；概览素材的“查看全部”进入当前来源素材视图。讲解仍属于 Segment，聚合列表直达所展示的确切修订；手动片段不要求虚构书籍。

材料三态为未开始／进行中／已完成，完成由用户明确标记，不从章内百分比推断。新的阅读进入成功呈现目标章后显式记录一次最近打开，未开始转进行中；预取、后台刷新、换章与设置变化不计新打开。重读已完成保留完成。手动状态不清空位置或真实打开时间，不调用模型。状态与最近打开服务端持久化，独立于不可变材料及位置版本；重复动作与迟到打开不覆盖较新手工状态。未知历史打开时间留空，不推断完成。

侧栏宽屏可收窄并保存偏好，窄屏临时抽屉；返回来处与所属 Source 分开，保留筛选、排序、页码、列表位置与展开状态。保留原文锁定、不可变修订、讨论草稿现有边界、审核／停止、迟到成果保护、阅读恢复与 Source 删除门禁。

材料目录允许必要聚合查询、索引、有界可重建封面缓存与轻量状态写入；不引入新学习模型、通用事件系统、视频音频播放器、扫描、MCP 或通用预处理框架。注音与选区学习边界见第 4.7 节。导航见[信息架构](INFORMATION_ARCHITECTURE.md)，技术边界见[架构](ARCHITECTURE.md)。

**书籍文本统计。** 书籍详情独立加载当前材料版本的统计和高频词覆盖曲线；不挂载阅读器，也不向前端发送全书 token。统计覆盖全部可提取正文，包括目录、后记等，不标作“小说正文”。同一资源重复出现在 spine 时只计一次；不同资源即使文字相同也分别计入。

| 指标 | 初版口径 |
|---|---|
| 词次 N | 按固定分词配置统计有效词次：有非空白表层及正长度原文范围，排除空白、记号和补助记号；保留助词、助动词、数字和未登录词 |
| 词种 V | 按词典形归并；词典形缺失、空白或为明确占位值时回退表层，不按读音归并 |
| 单次词种 H | 只出现一次的词种数；单次词种比例为 H/V |
| 覆盖曲线 | 本材料频次最高的前 k 种词累计词次除以 N；80%／90%／95% 阈值取达到覆盖率的最小整数 k，同频按归并键稳定排序 |
| 字符数 | NFC 定位正文的 Unicode 码点数，包含空白和标点；ruby 的 rt／rp 不在定位正文中 |
| 汉字 | 按记录的 Unicode 版本统计名称属于 CJK UNIFIED IDEOGRAPH 或 CJK COMPATIBILITY IDEOGRAPH 的字符，提供不同汉字数和只出现一次的汉字数；不作 NFKC 折叠，不将々、〇及兼容符号展开算入 |
| 空输入 | 数量为 0；分母为 0 的比例和覆盖阈值显示“—”，曲线为空 |

界面使用“词次（按词典形统计）”“词种”和“词次覆盖率”，说明统计范围、分词粒度和规则版本。覆盖率不表示理解率、掌握率或难度；未登录词不等于用户不会的词。本轮不统计平均自然句长、逐汉字读音或卷数。曲线最多返回 512 点，保留首尾及阈值点，阈值由完整频次计算。

正文统计不依赖分词就绪；无可用分词代次时仍显示字符／汉字，词法部分显示尚未准备。统计读取不隐式补算、不调用模型，不改变最近打开、阅读状态和位置；失败不阻止详情或阅读，允许重试。结果标明材料版本、采用的分词代次和规则版本，旧响应不冒充新代次；Source 删除后缓存也不能继续暴露内容。当前交付状态见[实施基线](handovers/MVP_IMPLEMENTATION_BASELINE.md)，规则及验收安排见[文本处理计划](handovers/text-study/PLAN.md)。

### 4.3 语境与学习条目边界

用户决定是否提供前后文，并可修改或清空。手动录入继续由用户提供语境；从 EPUB 选区建立学习片段时，按第 4.7 节的 C2 规则自动预装可编辑语境。目标文本与语境明确区分，补齐语境不扩大目标或本次解析范围；模型按语义寻找远处语境留待后续。

保存讲解不要求同时创建 Occurrence；用户可以只留下某一个学习点，不要求完整提取整份报告。AI 批量提取是可选的整理能力，不是所有条目都必须经过的独立模型阶段。

创建 Occurrence 时，条目需有明确的原文定位和持久讲解出处。来自讨论的新理解，应先整理为能够脱离对话阅读的讲解，再建立条目关联；不以直接引用聊天消息替代讲解。两项动作可以由一次明确请求发起，不要求用户分别操作两个页面。部分失败保留已经独立保存的成果，处理规则见 F8，具体执行与恢复契约待架构细化。

用户明确触发保存或收录，不要求先完成一个正式的解析定稿流程。普通问答或解析完成不自动触发成果整理、条目创建或结算；首轮不提供解析完成后自动提取的开关。

### 4.4 功能区域

| 区域 | 职责 |
|---|---|
| 来源目录 | 找到来源记录，浏览其片段并添加新片段 |
| 片段阅读与讨论 | 找到原文、已有讲解与讨论，按需展开工作台形成或修改成果，查看、创建与整理学习条目 |
| 学习积累库 | 跨片段查找学习条目，直接阅读原句和相关讲解 |

这些区域表达功能职责，不规定必须有三个独立页面或导航入口。设置提供可访问的入口，不作为与三者并列的主要学习区域。布局与导航在后续交互设计中确定。

根入口替换式跳转素材库，来源目录保持独立入口。普通打开片段先呈现阅读内容，指定讲解或讨论入口直接定位对应对象；讲解阅读可同时参照原文，讨论按需展开。返回来处与查看所属来源分别表达。当前导航与定位约定见[阅读与导航](INFORMATION_ARCHITECTURE.md)。

2026-10-20 已确认回看与讨论生命周期：普通回看和人工编辑不启动工作台，也不查询讨论、任务或模型设置。显式展开讨论、未显式收起的线程直达或快捷生成才启动；URL 中 chat=0 优先于 thread，首次进入保持纯回看；启动后在当前 Segment 页面内收起保活，保留草稿、待核实提交及审核补充要求。离页后的草稿保存范围沿用既有规则，不承诺恢复人工编辑草稿。当前实现差额见[实施基线](handovers/MVP_IMPLEMENTATION_BASELINE.md)。

片段阅读页进入专注布局，隐藏全局主导航，使用左侧窄工具栏、中央原文与讲解、右侧按需讨论。返回、讨论显隐和片段管理归属工具栏；讲解集合管理新建，单篇管理编辑、版本与删除。窄屏将工具栏收为顶部操作栏，讨论与阅读切换保持会话和阅读位置。具体导航与操作规则见[信息架构](INFORMATION_ARCHITECTURE.md#讲解浏览人工保存与按需讨论)。

工作台是组织学习活动的界面，不是学习内容的归属实体。Analysis 与 Occurrence 关联到 Source 下的 Segment；Occurrence 还关联具体讲解版本与块。关闭工作台、结束一次讨论或切换页面，不改变这些内容的持久归属与存在。

### 4.5 讨论、共享资料与成果保存

用户可以直接围绕 Segment 开始讨论，也可以围绕某份解析、某个讲解块或某条 Occurrence 提问。多条独立对话均可持续追问、保存和再次查看，不要求先有完整解析或主对话，也不将工作台绑定到唯一一份解析。

首轮 Agent 按需读取当前 Segment 的原文、用户提供的语境、该片段下的讲解／修订／Section／Occurrence，以及必要的 Source 信息、本线程历史和适用的学习背景与偏好。不跨片段检索，也不主动检索其他线程的聊天历史；其他线程已整理为当前片段持久讲解的内容可共享读取。不要求每轮将全部资料放入上下文。该边界针对 Agent，不限制用户在积累库跨片段查找。实际读取来源可追溯，资料更新不反写历史回答和成果；持久内容与任务／审核状态以保存的数据为准，不仅依赖聊天记忆。

对话保留讨论过程；值得长期使用的解释应整理成自足讲解，补齐必要背景、保留限定条件与不确定性，不要求用户重读低信息密度的对话来理解成果。新建 Analysis 与修改已有文档可由人工资料入口或工作台发起：明确修改已有文档时形成其新修订；新建讲解时创建独立 Analysis。人工操作不要求先建立对话，具体行为见 F3。

对话可以是针对一个问题的一次性问答，也可以从快捷生成完整解析开始，持续按反馈打磨讲解、整理条目。用户无须因动作变化而切换线程；线程也不永久绑定唯一一份文档。参考对象与修改目标分别表达，目标确定规则见 F7。

「回答问题」「保存讲解」「生成候选」「用户收录」是不同动作。首轮 Agent 只创建和修改待整理候选，不代用户收录、设为仅参考或退回待整理。自然语言指令表达任务意图，权限模式决定已开放工具是否需审核；明确要求修改不等于在审核模式下跳过审批，也不开放首轮未提供的收录能力。执行结果应可见、可检查，普通问答不默认触发写入。具体入口、工具粒度、校验和恢复实现仍待细化，部分成功与自动修复行为遵循 F8。

提供审核模式与 Full access，规则见 F9。首轮不建设任意自定义工具权限策略、任意消息处分叉或对话树合并，不因此预设通用工具平台或某种 Agent 循环实现。

### 4.7 当前 EPUB 阶段安排

2026-10-03 确认优先接通“导入 EPUB → 阅读原文 → 按需讨论／形成讲解 → 返回原处”。沿用已有 Source、Segment、Analysis 与编辑审核能力，保留手动片段入口。F5／F6 的 Occurrence 与积累库规则继续作为后续目标，本阶段不实现；SRS／ITS、视频／asbplayer 和 MCP 同样不作为交付条件。

已确定的边界：

- 原 EPUB 以不可变托管副本保存；材料属于一个 Source，处理产物有不可变版本。相同 Source 下完全相同字节优先返回已有材料，不同 Source 不合并领域身份；内容不同的文件作为新材料。
- 原文位置绑定材料版本及原始 spine 资源，采用 Unicode 码点半开范围和原文快照。字号、横竖排、窗口尺寸、显示章节分组与分词结果不改变引用身份；不能校验时明确无法定位，不在同文搜索后静默改挂。
- 阅读章节按书内有效目录组织，允许把被插图分开的多个 spine 资源拼成连续章节；spine 顺序和底层资源身份仍保留。显示优先采用原书目录章名，缺失或异常目录有明确回退，不把重复的文档书名当成真实章名。
- 保留原书 ruby；分词生成的振假名只能补充未被原书注音覆盖的范围，不能覆盖或叠加已有注音。自动注音属于可重建显示层，不改变正文、材料版本、原文引用或阅读位置。
- 横竖排阅读方向已获认可；采用横竖排滚动，以拼好的章节组织进度，保存正文位置作为恢复依据，百分比用于辅助显示。字号、行距或布局变化后尽力回到原附近，不要求相同页码或像素。2026-10-04 用户实测后认可当前不做分页，避免引入跨页划选问题。
- 消息原文引用与 Segment 分开；普通划选不创建学习片段、不发起模型调用。Analysis 继续归属 Segment，支持从原文和从讨论进入持久讲解。
- 本阶段不扩展现有片段 Agent 的读取权限。材料对话须在切片 3 单独确定上下文、历史、未读内容、权限及调用成本；阅读器拥有全文不等于允许向模型发送全文。

2026-10-20 已确认 C1／C2 的阅读出处范围，2026-10-22 补充学习片段入口与语境预装；本轮按 C1 → C2 启动实施，交付状态见实施基线：

- Segment 可在创建时保存精确材料出处，材料与片段属于同一活跃 Source。出处绑定材料、不可变版本与有序的资源局部码点范围，每段保存原文快照；重复 spine 的出现位置分别校验与保留。显示章节只界定首版支持范围，不承担引用身份。
- 一份出处表达同一逻辑章内的一个连续目标，可在资源／part 边界拆成多段；拒绝空范围、逆序、重叠、跨章和跳过中间文本的拼凑。同一次资源出现内的相邻范围合并，不通过重排输入修复顺序。跨章及不连续目标留待后续。
- 创建时由校验后的各段原文按序直接拼接并整体 NFC，作为 Segment.text，不补虚构间隙。精确出处一经建立即固定目标；首版不事后换绑或解除出处后编辑原文，需要不同目标时重新选取并创建片段。
- 首版界面使用单个 chapter part 的 iframe 内原生选择，支持跨 DOM 节点；不支持跨 iframe 拖选、跨章选择或追加不连续选区。底层出处及回读仍支持同章多资源范围，不支持的选择不截断后冒充完整目标。
- 选区完成后在浮动工具栏提供“保存为学习片段”。普通划选只保留临时状态；点击入口后捕获此次选区快照并准备草稿，最终提交成功才创建片段及固定原文。只按同材料版本、规范范围与确切出现位置有界查询已有 Segment，由用户显式选用；不按相同文字自动合并。选用时复核仍可见且出处相同，候选失效不静默新建替代。
- 新建或选用成功后留在原文，顶部显示可关闭的轻量提示，由用户明确选择“打开片段”后进入资料页。提示不抢焦点，悬停或获得焦点期间暂停自动关闭。
- 已保存学习片段以低强调细下划线表示，竖排使用旁线，注音不加线。普通轻点可见标记的基字打开已有资料，单片段直接预览，多个确切命中先选择；修饰键操作、拖动、长按划选、键盘扩选及复制保留。标记轻点不同时切换阅读工具栏或按需注音；双击不增加等待优化，首击可能先显示预览，形成选区后以选择为先。临时定位高亮独立于永久学习／翻译标记。
- 页边使用扁平小符号或聚合数字，至少 44px 命中区域只放在正文外真实留白；竖排优先底部，无空间时使用本章列表，不挤压正文。页边入口固定在对应片段首处原文的位置，随正文一起滚动；排版变化时重新定位，滚动不切换锚点或临时合并入口。页边单片段同样直接预览，再次点击同一入口收起预览，点击其他入口切换目标；聚合候选和完整本章片段列表显示原文摘要与精确到分钟的保存时间，不显示身份后缀或额外选择提示；完整 ID 收入保存信息。全部分页读取完成后才开放完整列表和标记。
- 预览默认紧凑、横排，类型标签下的操作行左侧提供列表返回（由列表进入时），右侧提供“打开片段”；随后是浅底色与细竖线区分的原文引用，长原文可展开；有已存译文时优先显示译文，随后显示已有讲解，没有译文则直接读讲解。没有译文或讲解时显示已保存原文。多份讲解默认最近更新的一份，显示篇名并允许切换和加载更多；正文摘录不冒充译文。“本章记录”中的讲解直接完整展示，内容区支持独立滚动；“此处记录”未展开时标为“讲解预览”，仅在实际截断时显示底部渐隐，展开后显示完整讲解。个人备注低强调呈现；信息顺序为操作、原文引用、译文、讲解、备注、保存信息，保存信息在底部默认折叠，底部不另加分隔线。读取不调用模型、不启动讨论、不创建新资料。
- 横排正文中仅对应单一翻译目标、且不含学习片段的划线，普通轻点在完整原段之后展开最新成功译文；段内短选区不拆原段，跨段目标在最后一段之后显示。一次只展开一处，再点同一处收起，点击另一处切换，正文滚动保留；淡入淡出尊重减少动态偏好，开合时保持当前原文位置。译文字号略小、低强调，不附记录工具栏。页边入口继续打开完整记录浮窗；竖排、重叠多目标或无法安全插入的作者版式保留浮卡。译文为显示内容，不加入原文定位或保存；译文可独立复制，混合复制只提取原文。
- 正文划线预览贴近实际点击的行或列，横排优先下方、上方回退，竖排优先侧方；页边预览以被点击的按钮为锚点，左右页边优先向外侧留白展开、空间不足再向正文侧展开，竖排底部入口优先向上展开。窄屏统一使用底部浮卡，以原文强调表示对应目标。
- 正文空白与两侧页边采用同一退出规则：普通轻点清除已有原生选区及选区工具栏，并收起未手动停驻的紧凑预览；这次点击不再切换阅读工具栏显隐。新划选、拖动、长按、修饰键和控件操作保持原有行为，固定本章列表与展开侧栏保持打开。

- 同时保留一个预览，点击另一标记切换目标；当前选中片段持续强调全部出处范围。未手动停驻的紧凑浮卡在卡外普通轻点、原文划选或正文滚动时收起，固定本章列表保持；卡内滚动独立。“本章记录”标题栏仅保留关闭按钮，不提供展开或收起操作；“此处记录”与学习片段预览的相关按钮统一使用“展开／收起”文案。“展开”进入右侧覆盖式完整阅读侧栏，正文不重排，目标不随滚动变化；“收起”恢复紧凑预览，保留当前目标、类型标签、所选片段／讲解及本次手动位置，叉号完全关闭。侧栏与目录共存，同侧设置或图库替换它；窄屏按前侧显示。明确“打开片段”才离开阅读器，携带所选讲解及确切修订并保留返回原文入口。切章、失效或删除清理旧目标，重排重新计算标记和入口，草稿切换沿用保护规则。
- 阅读设置的“正文标记”分别提供阅读记录下划线、页边入口两项全局偏好，统一控制学习片段与第 4.8 节的翻译标记，默认开启，当前浏览器内跨书及跨标签页同步。两项可独立关闭，本章记录始终可用，已有资料不变。旧版偏好继续兼容；其他类型的标记按后续切片确定。
- 新建片段时按下述规则预装前后文，用户可修改或清空；选用已有片段保留其已保存语境。从原文进入讲解后仍使用既有 Segment／Analysis，不增加材料对话或扩大 Agent 权限。
- 精确出处以只读文字显示“材料名 · 章名 · 章内约 N%”，采用当前材料名与校验后的逻辑章位置；改名不改变出处身份。材料已删、版本不可用或快照失配时只显示可靠材料名并保留状态，无法取得可靠名称则省略，不补造 0%。自由文本 source_ref 独立保留，有精确出处时称“出处补充”，否则称“出处说明”。
- 返回原文先验证全部出处范围，再定位第一段起点；与书内搜索共用临时定位高亮，在精确目标稳定呈现约 2.5 秒后，用约 260ms 淡出并清理；背景与文字颜色同步恢复。正文主动输入、轻点或划选提前开始淡出，新导航、切章及离页立即清理；减少动态效果时直接消失。重排不续期、不重新变亮，也不恢复已清理的高亮。永久学习／翻译标记保持原有显示规则，关闭展示仍能定位。任一段无法投影时明确定位不完整。等待注音准备或准备失败时保留定位意图，允许重试。版本不可用或快照失配时保留可见资料的历史文字并说明无法定位，不搜索同文换绑；Source／Segment 删除后继续遵守不可见门禁。

| --- | --- | --- |
| 自动预装语境 | 开启 | 可关闭，关闭后仍可手动填写 |

- 从最靠近目标的正文向两侧分别扩展，保持原文顺序。选区所在句的未选残部计该侧一句，优先于更远句；目标本身不计入语境预算，目标内的文字不重复放入前后文。任一侧的句数或字符预算为零时，该侧为空。
- 在不可变原文上确定目标、两侧范围及原句界，再整理前后文副本：按 Unicode White_Space 去除两端空白，CRLF 转 LF，清空纯空白行内容并将内部连续空行折叠为一行。句内普通／全角空格、标点、组合字符、变体选择符与零宽字符保留，标题按正文处理；整理不改变目标、exact、摘要或 spine 出现位置。
- 句数与字符数均为上限，不强制填满，不跨侧借用剩余预算。字符预算按合并整理后整体 NFC 的 Unicode 码点计，内部空格、LF 与标点计入，排除注音 rt／rp 和应用附加文字。优先近端完整句，超限时取贴近目标的部分，再去除裁切边缘空白；只有切开含正文的句／残部才标记截断，预算停在句间空白、恰好完整候选或纯空白侧不标截断。
- 自动取文限于同一逻辑章，可跨该章相邻 part，不因 iframe 尚未挂载而少取，也不因资源全文已加载而越过章界。目标选区的单 iframe 限制保持原位。支持只取前文，不依据阅读进度猜测用户已读范围或扩大后文。

- 新建草稿显示目标与简短语境预览，完整前后文可展开修改或清空。首次预填结果只填入未被用户修改的对应字段；清空也算修改。重新按预算取文是明确动作，在有修改时先保留原草稿供用户选择替换；切换目标后旧结果失效。重开已有片段、切换设置或选用已有片段均不覆盖已保存资料。
- 预装失败保留目标与草稿，允许重试、手动填写或仅保存目标；目标出处校验失败仍拒绝保存。用户手动补充的语境沿用输入限制，不受自动预装预算裁剪。来源标识须区分自动摘录与用户已编辑内容，不将改写文字标为经过精确校验的原书引用。

2026-10-16 已确认跳转链随继续阅读结束：A→B→C 的连续查阅仍返回 A；在 B 持续主动推进正文后，原返回入口继续保留，下一次从 B′ 跳到 C 时将返回点更新为 B′。首轮以页面前台且有焦点时、主动净前进至少一个阅读视口且首末移动相隔至少 5 秒作为继续阅读信号；单纯停留、短时查阅、工具面板滚动及排版恢复不触发更新。后台或重排中断尚未确认的信号，已确认信号保留到下一次实际跳转。该判断只管理临时返回点，不标记已读或学习完成，章节位置保存规则保持独立。

### 4.8 阅读翻译与设备朗读

2026-10-23 已确认并授权实施，切片与验收样例见[阅读辅助方案](handovers/text-study/TRANSLATION_AND_SPEECH_PLAN.md)。本节维护产品行为，工程交付见实施基线。

- 首轮从 EPUB 有确切出处的选区发起翻译，沿用同章连续目标和当前选区支持范围。普通划选不调用模型；点击后固定原文、出处、语境和实际配置。翻译能力允许不同 adapter，先复用 LLM；Segment 直接生成译文、批量／整章翻译、远端 TTS 及材料对话分别后续接入。
- 翻译默认日译简体中文，前文最多 3 句且不超过 200 个 Unicode 码点，后文默认 0，偏好独立于 Segment 语境预装和讲解语言。可检查、编辑、清空及扩大本次语境；只翻译目标。补全句子须用户选择，不静默扩大目标，不自动发送全书或其他讨论历史。
- 完整成功的译文在本地持久保存，不自动过期；原输入、实际配置和结果保持不变。关闭、刷新、回到相同出处时可找回，成功结果从正文标记和本章记录读取，同一出处的历史在详情中展开；失败查询不自动转为新调用。重新翻译由用户明确触发，产生新结果，不覆盖旧结果或 Segment 当前译文。部分输出、拒绝和截断不发布为成功。
- 选区译文卡的标题栏提供重译、停止与收起图标，进度在同一行显示；语境与设置保持折叠。重译期间保留当前译文，取得完整新结果后再替换展示，失败或停止后仍可读旧译文。“上一版／返回新版”只切换查看一对已保存结果；其他历史仍从完整列表读取。宽屏支持拖动标题栏及键盘移动，窄屏保持底部停靠。
- 取得译文不创建 Segment 或 Analysis；成功且可精确定位的译文会形成可隐藏的正文翻译标记。Reader 创建片段统一从正文划选的“保存为学习片段”进入；本章记录和划选翻译详情不提供“保存为学习片段”或“另存新片段”，保留已关联片段的打开入口。来源等其他手动创建入口不变。
- 正文划选保存草稿提供可编辑、可清空的译文。仅匹配同材料、版本、resource／spine 出现及摘要，并在裁掉完整目标两端 Unicode White_Space 后核对坐标和原文；只允许整体边缘空白不同，内部空白、标点与同文异址均不忽略。匹配不修改本次原选区或出处。优先预填本 Reader 会话内最近在翻译详情中选中的匹配成功结果，没有有效选择时使用最新匹配成功结果；历史选择不写入偏好。
- 完整译文只预填一次；用户修改、清空或已开始提交后，迟到结果不再覆盖。片段语境沿用第 4.7 节的独立草稿，不套用翻译历史语境。带入结果的新建在一次事务中保存片段、原选区出处和采用凭据，记录实际提交的译文与片段语境；重试核实首次冻结的请求，不重复生成。材料原文固定沿用精确出处规则。
- 阅读器右上入口为“本章记录”，内含“学习片段｜翻译”两个标签页。翻译按正文位置排列，同一确切出处多次成功结果共用一项和一个标记，列表只显示原文与最新成功译文，不显示语言、已留存或译文份数，历史仍可回看；同文不同位置、材料版本或 spine 出现分别保留。失败、取消及进行中任务不绘制翻译标记。关闭卡片或切换选区后，已受理任务完成仍更新本章记录和标记。
- 学习片段沿用红色细实线，翻译采用同色系低强调虚线；竖排沿文字旁侧绘制，注音不加线。覆盖片段的部分只画实线，点击相互重叠的连续记录共用“此处记录”入口，两类内容通过标签切换；归并仅作用于呈现，不合并底层片段或译文身份。独立翻译直接显示最新结果，历史回看不触发新调用；底部工具栏不再提供“最近翻译”入口。
- 单条翻译从正文或页边直接打开详情，不显示返回列表。由列表进入详情时，返回箭头与记录标题同排；返回或 Escape 回到列表并恢复原入口焦点，直达详情的 Escape 关闭浮卡。译文原文右上角使用朗读图标，悬停及辅助名称说明“朗读原文”；播放时切换停止图标，声音不可用及错误保留可见反馈。类型标签采用紧凑行高，详情不另设返回与朗读工具行。同一出处的历史列表只显示生成时间、语言和译文，原句集中在顶部详情展示。
- 正文划选保存流程仍可显式选用同一确切出处的活跃 Segment；候选点击不写入，选用不覆盖已有译文或语境。产品不提供独立采用表单。关联结果、采用快照和当前可编辑译文分别维护，不承诺每次普通编辑的历史版本；相关编辑入口继续检查版本，冲突保留草稿。
- 关闭卡片不停止已受理翻译，停止有明确入口；首轮每任务最多一次模型调用，响应不确定先核实本地状态。重启中断任务不自动重放，停止后的迟到结果不能发布。已成功结果不会因晚到停止而撤销。资源上限采用方案中的集中可配置候选，待真实模型实测，不作为质量或性能承诺。
- 删除材料时，未关联活跃片段的译文不可见；明确关联过的结果保留，从活跃 Segment 读取并说明原材料已删除。只关联也算明确保留，不要求覆盖当前译文字段。删除确认说明受影响的未保留译文；删除 Source 后关联内容全部不可见，迟到结果不得恢复。重导不换绑旧结果，停用／删除 Provider 不抹去已保存译文。
- 设置保留原 Provider、模型和凭据身份，新增独立翻译方案，首版围绕一个默认配置组织。明确采用当前讨论模型后绑定具体模型，后续讨论默认值变化不改翻译选择；配置修改不影响已受理快照。设备朗读不需要 Provider，声音和语速保存在当前浏览器。
- 设备朗读适用于阅读选区、译文原文和 Segment 原文，无须先翻译或保存。一个页面只有一个当前播放目标，开始新播放停止旧播放，选区改变不替换正在朗读的文本；关闭译文卡仍保留可达的播放控制，离开阅读／片段页停止并清理当前目标。播放条使用图标操作、原文摘要及语速／声音设置入口；设备支持时朗读中可暂停、暂停后继续，未开始或不支持暂停时保留停止。结束或停止后提供重播，整体不自动收缩；关闭入口明确同时停止朗读。声音浮层突出原生声音选择与 0.5–1.5 倍速滑块（0.1 步进）、常用预设及恢复默认，重新检测放在“更多选项”；支持外部点击、Escape 和再次点击入口关闭。偏好更改后短暂提示，下次播放或重播生效，继续不重建当前朗读；设置页提供日语试听，无可用声音或错误准确反馈。设备暂停若实际结束朗读，按真实终态提供重播。
- 设备朗读使用基字原文，不重复读 rt／rp，不承诺原书特殊 ruby 发音正确或离线可用；浏览器方式不提供可保存音频，不能显示“已保存音频”。外部 TTS 暂缓，后续围绕片段学习、制卡等音频保存与复用场景评估；接入后再提供用户可选择的备用策略，本轮不展示无效 fallback 开关。

## 5. 设计原则

| 原则 | 含义 |
|---|---|
| 讲解质量优先 | 持久讲解允许自由写作，只施加软格式约束（二级标题 = 一个学习对象）；不为了索引字段压缩必要解释，也不要求每次问答生成完整报告。 |
| 活动与成果分开 | 工作台承载学习活动，原文、讲解与条目持续保存；保存讲解与收录学习点分别表达，不强制走完整流水线。 |
| 可复原 | 规范化只切分和编号，**绝不改写**解析内容。切分结果拼接后与输入字符串逐字符一致，包括换行；精确规则见 [ARCHITECTURE 4.3](ARCHITECTURE.md#43-规范化器servicesnormalizerpy)。 |
| 不做破坏性合并 | 知识点的"同一性"取决于标准，因此不在写入时合并。Occurrence 保留具体语境、提取判断与出处；MVP 暂缓跨片段的 KnowledgePoint 归属管理，不预先规定知识点的实现形态。anchor 是召回键，不是裁决者。 |
| 全链路可追溯 | 模型生成产物可追溯到相关 Run、prompt 版本、模型和原始输出；手动创建内容记录其来源与操作，不伪造模型调用。条目始终保留原文与具体讲解出处。 |
| BYOK、本地优先 | 用户自带 API Key；数据存在本地单文件数据库中。 |

## 6. 核心学习活动与可选路径

以下活动可以按需要组合，不表示必须依次完成的工序。例如，用户可以「保存片段 → 直接讨论 → 整理专题讲解 → 收录一个学习点」，也可以「保存片段 → 生成系统性解析 → 阅读」，或从已有讲解发起批量提取。这些路径表达产品方向，具体首轮入口见第 4.2、4.5 节及待定事项。

### 6.1 准备共用的学习背景

用户维护学习背景、讲解偏好和模型配置，并在后续学习中反复使用。不要求每次添加片段都重新填写。

学习背景表达关于学习者的信息，讲解预设表达通常希望如何讲解，本次要求表达这一次需要特别关注或调整的内容。学习背景与默认预设在设置中维护，本次要求直接写在聊天消息中，不提供独立补充框，也不自动改变长期设置。

### 6.2 登记来源并保存片段

用户选择或创建 Source，输入目标日文，并按需要附带译文、疑问、前后文等信息。

保存片段与发起解析是两个独立动作。用户可以先保存、以后再解析；也可以通过「保存并解析」快捷入口连续完成两个动作。不调用模型不影响片段的保存和再次打开。

### 6.3 形成并阅读讲解

2026-10-20 已确认独立人工资料入口：用户在 Segment 下输入或粘贴 Markdown 保存 Analysis，不要求区分自己编写或粘贴已有内容，无需模型配置、对话线程或 AI 调用。保存后打开刚保存的确切修订，并可从来源重新找回。首版不做批量文件导入、URL 抓取或富文本编辑；交付证据见[实施基线](handovers/MVP_IMPLEMENTATION_BASELINE.md)。

用户发起解析，系统带入适用的学习背景、讲解偏好及本次输入，显示生成过程并保存完整结果。用户可以阅读整份解析或定位到其中的讲解块。

提供「生成总体讲解」快捷入口，意图包含生成并保存一份 Analysis。对话中的总体／专题讲解或讨论整理请求复用同一能力，利用适用的片段资料、讨论、背景、偏好与本次要求；没有既有讨论时使用片段材料与本次要求。后续可在同一对话继续讨论和编辑。模型选择见 F1，内部上下文与生成契约见 [ARCHITECTURE 4.1](ARCHITECTURE.md#41-上下文管理器servicescontextpy)。

Analysis 可以是完整片段的系统性解析，也可以是针对一个疑问的专题讲解，或由讨论整理出的自足讲解。讲解应表达自身范围，不强制专题内容扩写为覆盖整个片段的报告；这些范围不预设不同实体。

需要重新解析时，生成另一份独立文档，原有解析仍可找回。只保存和阅读解析也是完整、正常的使用方式，不要求每份解析都必须提取。

用户也可全文编辑已有 Analysis 的当前修订；提交明确基础修订，冲突或失败保留草稿，旧修订只读。人工操作不伪造 Run，不启动讨论；新建与全文修改的来源分别留存。提交前告知首次保存讲解会固定目标原文，取消或失败不固定；未保存修改的取消遵循草稿确认规则，不承诺关闭页面后的草稿恢复。

### 6.4 围绕片段讨论，按需留下成果

用户可从目标原文直接开始讨论，也可选择已有讲解或条目继续提问。普通问答留下可继续和回看的对话，不自动创建讲解文档或 Occurrence。

用户认为某段理解值得保存时，可以明确要求整理为独立讲解；需要积累学习点时，再让 Agent 关联原文与该讲解生成待整理候选。例如「把刚才的解释整理下来，并生成这个用法的候选条目」。用户查看后自行收录或设为仅参考，Agent 不通过组合操作替用户完成整理决定。若讲解已保存而候选创建失败，讲解仍然保留；失败反馈与后续修复见 F8，具体首轮交互和执行契约仍待细化。

对于已有持久讲解，Agent 可按要求整理一个或多个候选，再由用户在界面收录或设为仅参考；首轮不提供手动创建条目的表单。条目来源需清楚，不将聊天消息直接充当学习条目的阅读内容。

### 6.5 整理条目并再次阅读

用户查看候选后，可继续保留为待整理、收录供后续学习、设为仅参考，或删除不需要的记录。整理可分次完成，不阻止继续阅读或添加片段，也不要求清空候选；原文与讲解的保存不依赖条目是否被收录。

整理决定由用户作出，不表示掌握。界面使用「整理」「收录」「仅参考」等具体动作，不要求完成不可逆的「结算」阶段。三种状态的含义、转换及候选修改规则见 [F5](#f5-学习条目创建与整理)，删除见 [F2](#f2-source-与片段)，工具审批见 [F9](#f9-agent-工具权限与审核)。

之后用户可以从来源、片段或学习积累库找回内容；阅读条目时直接看到原句和来源 Section，并能回到完整解析或继续追问，详见 [F6](#f6-知识库)。

### 6.6 异步操作与离开页面

生成讲解、获得 AI 回复、AI 整理讨论成果或提取条目等涉及 AI 的操作，均采用后台异步执行的产品行为。系统接受任务后，用户可离开当前片段、切换页面或关闭浏览器，无须等待完整回复；离开页面不构成取消任务。该要求适用于最终纳入首轮的 AI 入口，不将普通手动保存也规定为模型任务。

重新进入时，用户能查看已提交任务的当前状态，并读取已完成结果；结果不依赖原页面持续打开才能保存。流式显示是观察任务的方式，不是任务执行的前提。

本地后台服务停止与离开界面是不同事件。服务停止或故障导致任务中断时，应明确呈现中断／失败及可采取的重试操作，不把残缺结果冒充成功产物，也不承诺服务未运行时任务仍能继续。

工具等待审核时，展示待审核状态并保存具体方案；离开页面不代表同意或拒绝，返回后仍能处理。依赖该写入的动作等待审核与实际保存完成，不将尚未保存的讲解当作正式 Occurrence 出处。后台重启不得使待审核方案被自动执行；执行中断与审核等待需分别表达。

同一线程执行本轮或等待审核时，可继续输入草稿，但不能发送新一轮讨论，不做消息排队。待审核期间通过同意、拒绝及可选附加指令，或停止本轮来推进；审核反馈不视为另发一轮消息。其他独立线程不因某线程待审核而被一并阻塞，后台仍可按资源调度。

用户可以主动停止本轮，停止后不再启动其后续生成、自动修复或工具操作，尚未执行的待审核方案取消。停止不是撤销，已保存成果保留；恰在提交的操作按实际保存结果反馈。未完成回复可明确标为中断内容，不作为成功讲解。停止处理完成、线程回到空闲后可以继续发送；已停止的旧任务与方案不能因迟到结果继续写入。

### 6.7 生命周期与状态表达

片段及其解析作为持续保存、可再次访问的学习内容，不要求完成提取或结算后才能离开，也不因结算完成而关闭。系统分别呈现 AI 任务的执行状态、已有内容和条目的整理进度，不以单一状态表示整个片段的生命周期。

| 关注点 | 表达范围 | 示例 |
|---|---|---|
| 执行状态 | 某次解析、AI 回复、提取任务及相关工具操作 | 排队中、执行中、等待审核、成功、部分完成、失败或中断；拒绝某次工具操作需可辨认 |
| 已有内容 | 片段已有的解析，以及选定解析的提取情况 | 已有 2 份解析；选定解析尚未提取 |
| 整理进度 | 一批提取结果或明确范围内条目的处理情况 | 3 条待整理；本批条目已整理 |

这些信息可以并存，例如「已有 2 份解析 · 1 个任务进行中 · 3 条待整理」。聚合展示应明确其统计范围，不将某次任务的状态或某批条目的整理结果冒充整个片段的唯一状态。

使用「尚未提取」描述未执行提取的事实，不使用「待提取」暗示必须完成后续工序。没有提取结果不代表片段使用未完成；已整理条目也不妨碍继续阅读、追问或生成另一份解析。

首轮不引入必须开始、结束的总体解析 Session，也不要求用户执行「结束学习」来关闭片段。离开界面、一次任务完成与一批条目整理完成分别表达，不互相触发。

## 7. 功能需求

优先级：P0 = MVP 必须；P1 = MVP 期间尽量完成；P2 = 预留。

首轮基本能力以第 4.2 节及下列功能要求为准，总体讲解快捷入口纳入Analysis切片，其余高频组合工具不作为首轮闭环的前提。交付顺序与全篇优先级在实施计划中统一，不恢复旧的独立两阶段流水线。

### F1 设置

#### 页面组织与保存

设置采用学习偏好、模型与服务、对话与权限三个顶部分类，视觉沿用素材库的公共导航与控件。学习背景与默认讲解预设一起维护，讲解／讨论默认模型靠近服务配置；验证记录为模型页的次级入口。页面及导航规则见[阅读与导航](INFORMATION_ARCHITECTURE.md#设置顶部分类)。

每组明确保存，修改只作用于提交的字段；某个未修改的默认模型失效，不阻止其他组保存。学习背景与默认预设同次保存要么全部成功，要么保留原值。服务、模型与预设的新增／编辑在弹窗内独立保存。未保存修改受到离页保护，保存失败保留输入，继续编辑后不再显示“已保存”。

C2 在学习偏好提供独立保存的“学习片段语境”配置，维护自动预装开关及两侧句数、字符上限；行为与默认值见第 4.7 节。该配置不混入讲解风格或模型参数，保存不改写已有片段及当前草稿。

#### Agent 权限默认值

- 产品初始默认使用审核模式；用户可设置新对话采用审核模式或 Full access。每个对话显示自身模式，规则见 F9。
- 修改新对话默认值不自动更改已有线程。线程仅在空闲时可切换模式；本轮运行或等待审核期间不切换，需等本轮结束或停止完成，不因切换 Full access 自动放行挂起方案。

#### 学习背景

| 信息 | 首轮行为 | 用途 |
|---|---|---|
| 母语 | 用户可填写 | 为必要的语言对比提供背景 |
| 解释语言 | 单独设置，可以与母语不同 | 决定讲解主要使用的语言 |
| 学习情况自述 | 可选自由文本 | 描述已有基础、学习目标及当前困难 |

- 自述是讲解参考，不是经过验证的能力或掌握度判断。不要求填写 JLPT 等级，也不从自述等级自动推断已掌握哪些知识。
- 不能仅因用户填写「初级／中级」就省略理解当前原文所必需的解释。背景信息对解析质量的实际影响需通过使用反馈检验。
- 首轮由用户主动维护，不自动推断或更新画像。后续如引入学习表现反馈，应区分系统观察与用户自述，不静默覆盖用户填写的信息。

#### 讲解偏好预设

- 提供一份基于现有 v0.1 参考模板整理的默认讲解预设；用户可编辑，并按需保存其他命名预设、设置默认值。
- 讨论与讲解生成采用设置中的默认预设，讨论输入区不提供临时预设覆盖。首轮采用可编辑文本，不建设要素库、多预设叠加、权重调节或复杂继承机制。
- 预设内容按下列维度组织，但不要求每项都有内容，也不把这些维度强制转换为解析的固定教学栏目。

| 维度 | 含义 | 示例 |
|---|---|---|
| 讲解组织与细度 | 如何逐步帮助理解 | 先整体后局部、逐块细讲、保留必要推导 |
| 重点关注 | 哪些内容值得展开 | 活用变化链、表达对比、语用与语气 |
| 辅助信息取舍 | 哪些辅助说明需要或可省略 | 注音、常规词典释义、例句数量 |
| 表达方式 | 如何呈现讲解 | 术语配简释、尽量紧凑但不省略关键关系 |

- 偏好表达重点与取舍，不要求模型为填满栏目而添加无依据的解释。例如，关注语用和文化语境不意味着每句话都必须产生文化解读。
- 省略要求应明确边界。例如，不主动逐词注音或列出常规词典释义，但读音、词义选择或搭配直接影响当前理解时，仍保留必要说明。使用词典工具不等于已经掌握相关知识。

#### 本次要求与使用边界

- 用户在聊天消息中直接表达本次要求，例如重点解释某组表达的差别，或简略处理已理解的部分；不另设“本轮要求”按钮或输入框。
- 本次明确要求可调整所选预设中的讲解取舍，不自动修改长期预设，也不改变目标文本与语境的区分、格式契约、解释与推测的区分等产品基础要求。
- 系统接受任务时确定本次实际使用的学习背景、预设和补充要求并保留记录；排队期间或任务完成后的设置变化不改写该次输入与已有结果。

| AI 操作 | 使用方式 |
|---|---|
| 讲解生成 | 使用学习背景、所选讲解预设、本次补充要求及目标材料；专题讲解按其范围组织 |
| 独立追问 | 使用解释语言和相关偏好，围绕当前问题回答，不每次重新生成整份解析 |
| 讨论成果整理 | 将相关讨论形成可独立阅读的讲解，保留必要背景、限定条件与不确定性；具体入口待定 |
| AI 条目整理／提取 | 遵循条目契约，使用解释语言等必要信息；讲解偏好不改变字段结构，也不允许补讲或偏离所引用的讲解 |

#### 模型配置

用户通过设置界面维护 Provider、可选模型和按用途划分的默认模型，不要求日常操作通过手动编辑配置文件完成。底层存储方式由架构决定，界面与文件不能形成两套独立配置真相。

**Provider 接入**

| 配置项 | 含义 |
|---|---|
| 名称 | 用户自定义的显示名称，用于区分服务、账号或不同接入配置 |
| API 地址 | 服务的 base_url |
| 鉴权信息 | API Key 等；允许本地服务采用无鉴权配置 |
| 默认调用协议 | Chat Completions 或 Responses；个别模型可在高级设置中覆盖 |
| 模型列表 | 从 Provider 获取的模型，以及用户手动添加的模型 |

首轮支持 OpenAI 兼容的 Chat Completions 与 Responses 两种文本调用协议。调用协议与解析、追问、提取等用途分别表达，不因支持某种协议而承诺支持其全部工具或多模态能力。

**模型发现与验证**

- 配置 Provider 后尝试获取模型列表，并提供手动刷新。显示获取状态与最后更新时间；失败时保留已有列表。
- 始终允许手动填写模型 ID。刷新后某模型不再出现，不自动删除既有配置或替换默认模型，而是提示检查。
- 模型选项同时显示 Provider 名称与模型 ID。模型出现在列表中不代表已验证其调用协议、流式能力或结构化输出能力。
- 分别反馈模型列表获取、指定模型调用和所需输出能力的验证情况，不用一个笼统的「连接正常」代表全部可用。生成与能力验证由用户按需触发，不自动遍历测试全部模型。
- 模型接入界面按 Provider、已登记模型和能力验证组织。发现列表可选择登记，已登记项不重复添加，手动登记仍可用；列表获取失败保留缓存。模型行以图标和文字显示未验证、验证中、可用、验证失败或中断，并可查看对应原因与记录。验证状态基于当前配置，运行中可刷新页面继续查看。
- 当前仅开放普通文本与流式文本验证。模型行通过“可用性验证”菜单提供普通文本、流式文本和两项重新验证；组合入口说明调用次数，每项分别产生 Run，已接受的一项不因另一项请求失败撤销。结构化输出标明尚未开放验证；不以“两项文本通过”宣称全部能力已验证。
- 提取优先采用已支持的原生结构化输出；不支持时可采用明确的提示词约束与严格校验兼容方式。兼容方式不标为原生能力已验证，不因能正常聊天就认定适合提取。

**用途默认值与操作时选择**

| 用途 | 系统默认模型的作用 |
|---|---|
| 解析生成 | 用户单独发起的讲解生成 |
| 独立追问 | 新开启的对话 |
| 条目提取 | 用户单独发起的 AI 条目提取 |

三项可以采用同一模型，也可以来自不同 Provider，不预设某一用途必须使用低价或小模型。实际选择包含 Provider、模型 ID、调用协议和适用参数；参数按支持情况提供，未指定时尽量使用服务默认值，不向所有模型强行传递同一组参数。

这些用途默认值不规定必须发生三类调用，也不要求每个 Occurrence 都调用提取模型。对话内生成 Analysis 沿用本轮已选的 Provider、模型、协议和参数。无线程的独立入口显示解析默认模型并允许本次改选，再以该模型建立线程。条目创建的调用方式随其工具契约确定；上下文复用和缓存机制见 [ARCHITECTURE 4.1](ARCHITECTURE.md#41-上下文管理器servicescontextpy)。

| 操作位置 | 选择行为 |
|---|---|
| 保存片段 | 可预选之后用于解析生成的模型，也可保持「使用系统默认」 |
| 生成或重新生成解析 | 显示本次实际模型，允许修改后提交 |
| 新建对话 | 默认采用追问模型，允许改选 |
| 继续追问 | 默认沿用该线程当前选定模型，发送前可更换；改选后的模型用于本轮及后续回复 |
| 触发提取 | 默认采用提取模型，允许为本次操作更换 |

- 解析生成按「本次明确选择 → 片段保存的解析模型预选 → 系统解析默认模型」确定实际选择。片段不另建三个用途的完整默认配置。
- 「使用系统默认」在操作提交时解析为当时的默认值；明确选定的模型保持该指定。单次改选不自动修改全局默认值。
- 保存时预选模型不发起解析，也不锁定目标原文。
- 在对话中切换模型不改写历史消息；系统为新模型提供该线程所需的历史、原文与相关资料，不自动混入其他线程历史，也不要求必须存在解析。Folio-J 本地保管完整对话与出处，不仅依赖某个 Provider 的远端会话 ID。

**配置变化、失败与记录**

- 系统接受任务时固定实际使用的 Provider、模型、协议和参数。之后修改默认值不影响已排队任务，不改写历史结果。
- 指定配置不可用时明确报告，不悄悄切换 Provider、模型或采用新的默认值；用户可以改选后重试。
- 每次生成及模型调用验证记录实际调用信息。密钥由本地后端管理，不进入普通模型信息响应、提示词或调用日志。

### F2 Source 与片段

#### 来源管理

- 用户能够创建、浏览 Source，并维护其标题、备注和出处描述等信息，不要求上传素材文件。
- Source 表达用户声明的来源范围，不与单个文件一一对应；未来接入素材后，同一来源可容纳多份、不同形式的输入，例如同一作品的不同卷。具体片段仍保留各自的出处信息，不因同属一个 Source 而被视为连续原文。
- 手动录入继续支持，不要求创建虚拟 TXT 素材；用户疑问、听写等附带信息也不因此成为素材。当前 EPUB 阶段允许在来源详情导入一份或多份 EPUB，成功后进入阅读；不因导入自动创建学习片段或发起模型调用。
- 同一来源重复导入相同字节返回已有活跃材料；不同来源保留独立材料身份。删除后重新导入相同字节创建新材料及版本，不恢复旧材料、阅读位置或自动换绑历史出处。原书托管副本和已发布处理版本保持不变，内容不同的 EPUB 作为新材料处理。书籍详情、信息编辑和删除入口见第 4.2.1 节；移动继续禁用。
- 从系统保存的 EPUB 中选取目标文本，与手动录入汇合到 Segment 学习流程，沿用 Source／Segment 归属及下述原文固定规则。已确认的同章范围、可编辑语境预装和显式复用边界见第 4.7 节，按 C1／C2 实施。
- 修改当前来源信息不反写历史调用实际使用的输入。

#### 片段保存与编辑

- 每个 Segment 归属于一个 Source。目标日文必填，其他附带信息按需提供；支持先保存、后解析，以及「保存并解析」快捷入口。
- 片段原文卡提供独立的“复制分享”入口，居中模态浮层展示只读预览，底部主复制按钮旁的下拉切换“原文与出处／仅原文／仅出处”，切换只更新预览。默认先呈现已保存前文、目标原文和后文，再附自然出处；有语境时用引用块区分目标，保留原有文字与换行。出处优先采用可靠材料名、核对后的章名和手填出处，无材料名时回退来源名，省去字段标签及章内百分比。空字段省略，不带译文、听写、讲解和个人管理备注。复制成功或失败有明确反馈，失败可从预览手动复制；不自动发送到外部服务。
- 已保存且尚未触发原文固定的目标文本允许修改，仍为同一个 Segment。
- 2026-10-20 已确认三种原文固定触发：首次以该原文为输入的 AI 任务被系统接受、首次成功保存持久讲解、首次建立精确材料出处，任一成功即固定目标原文。AI 触发不等待模型返回；打开编辑器、取消或失败保存不固定。任务失败／中断、删除讲解均不解除固定，需要不同目标文本时创建新片段。
- 人工保存必须核对用户编辑时看到的原文摘要；期间目标原文已改变时拒绝提交，保留草稿且不固定原文、不保存讲解。原文固定与成果保存同时成功或失败；备注等附带信息变化不作为原文变化。
- 当前聊天受理与持久讲解保存共同固定原文；精确出处创建也触发原文固定。已有历史讲解却未锁定的片段（含仅剩软删讲解）须保守固定当前原文，记录保护生效时间；不伪造历史受理时间或旧讲解当时的原文快照，不改写历史修订。
- 该规则是目标文本的编辑边界，不构成整个片段的线性生命周期，也不要求用户手动执行锁定操作。
- 来源与管理信息可以维护；新一次解析可以采用不同语境和要求，但历史调用使用过的内容保持原样。个人管理备注与提供给模型的输入需明确区分，具体输入形式在交互设计中确定。

#### 删除与清理

首轮按对象提供明确范围的删除，不提供归档。普通筛选用于选择当前展示内容，不额外引入长期隐藏状态。

| 删除对象 | 删除范围 |
|---|---|
| Source | 下属 EPUB 材料、Segment，以及这些片段的解析、修订、讲解块、对话和 Occurrence 等关联学习内容 |
| 单份 Material | 清理该材料托管副本与派生阅读数据，保留材料身份及历史出处所需信息；保留所属 Source、全部 Segment 及其讲解、讨论和学习条目，以及同来源其他材料 |
| Segment | 该片段及其解析、修订、讲解块、对话和 Occurrence 等关联学习内容 |
| 单份 Analysis | 该解析及其全部修订、讲解块和引用它的 Occurrence；保留 Segment、其他 Analysis 及属于 Segment 的对话线程 |
| 单条 Occurrence | 仅该条学习记录，不删除其原文和解析 |

- 删除表达用户不再需要保留这条记录，例如错误、重复或试验产物；已删除内容不进入日常浏览。它是独立操作，不是待整理、已收录、仅参考之间的状态切换；首轮不提供恢复入口。
- 级联范围包含已收录、仅参考及其他整理状态的 Occurrence。收录不意味着创建了独立于来源的内容副本。
- 删除单份 Analysis 前展示其关联内容及条目数量，由用户确认；提供删除业务接口，但首轮不向 Agent 开放整份 Analysis 删除工具。对话内容保留，其中指向已删除讲解的入口显示已删除，不改指其他讲解。
- 用户通过管理界面删除时，先展示影响范围，包括相关片段、解析和已收录条目数量，由用户确认；不能将其描述成仅从目录移除入口。若向 Agent 开放删除工具，审核模式下将具体对象与影响范围纳入工具审批，Full access 下不再逐次审批，但仍展示执行结果与实际影响。权限模式不自动授予尚未开放的 Source／Segment 删除工具。
- 删除覆盖与所选对象确有归属关系的内容，不因标题或 anchor 相同而影响其他来源。
- 单份材料删除保留学习内容的原文、语境和出处信息，不解除片段原文固定。精确材料出处接入后，材料删除须保留历史出处与文字快照，返回原文明确提示材料已删除，不搜索同文或因重导而自动换绑。材料对话尚未实现，其删除与保留范围在对应切片明确。
- EPUB 切片 1 的来源删除确认须列出材料数量；删除后这些材料不可再读，原始托管字节暂不物理清理。材料随来源的不可见性不能被迟到导入或位置保存恢复；物理存储策略不扩大既有学习内容删除范围。
- 后台任务及迟到结果不能重新生成或恢复已删除的可见内容。关联调用记录的处置与运行中任务的处理方式，在架构设计中统一。
- 此处定义产品上的删除范围，不直接规定数据库硬删除。逻辑删除、物理清理及保留策略由架构落实，并与 Occurrence 的软删除约束保持一致；首轮不因此增加回收站或恢复界面。

### F3 解析
- P0：解析采用产品基础要求、学习背景、所选讲解预设、本次补充要求，以及 Source 信息、目标原文和用户手动提供的语境等附带信息；遵循 F1 的作用范围与优先关系。

- P0：每次调用记录一条 Run，包含渲染后的完整消息、模型与参数、原始输出、token 用量和耗时。
- P0：可对同一片段重新解析，生成另一份独立 Analysis 及其初始修订版，保留原有解析文档；修改已有 Analysis 才生成该文档的新修订版。
- P0：Analysis 可承载系统性解析、专题讲解和讨论整理后的自足讲解，短讲解不强制扩写为完整报告。提供创建和用户删除接口，Agent 可创建但不能删除整份 Analysis；删除边界见 F2。
- P0：用户可在 Segment 下新建手写讲解或粘贴导入外部 Markdown，统一记录为用户保存，不要求声明原创或外部导入；人工全文修订记录用户修改来源，不关联虚构 Run。无需模型配置或聊天；首版不做批量文件导入、URL 抓取和富文本编辑。
- P0：用户可重命名已有 Analysis，名称去除首尾空白并做 NFC 规范化，保存后为 1–200 个字符。名称属于讲解本身，当前与历史版本均显示现名称；重命名不产生正文修订，不改变原始 Markdown、Section 或引用。并发改名冲突保留草稿，重新读取并核对当前名称后可再保存。
- P0：人工全文编辑作用于当前修订，明确 Analysis 和基础修订；旧修订只读。新请求没有正文变化时不产生空修订；正文为空白、超限、版本冲突或保存失败均保留草稿。缺少二级标题沿用 F4 的宽容规范化规则。
- P0：全文替换未提供显式块映射时，为新块分配新身份，不按标题或位置延续旧身份；旧 Revision／Section 及其引用保留。该人工能力不扩大 Agent 当前按块编辑的工具范围。
- P0：人工创建／修订提交有稳定操作身份；同请求同内容返回原保存结果，同身份不同内容明确冲突。已成功保存后的重复提交优先核实原结果，不因随后修订而重复创建或误报首次失败；核实与重放不绕过删除门禁。响应不确定时保留原请求用于核实，不用新身份盲目重建。
- P0：已有讲解支持修改指定 Section 的标题和／或正文、在指定位置插入一个或多个 Section、删除指定 Section。省略的字段保持原样，单块全文替换沿用块更新操作；支持在正文开头插入。编辑前置总述时可修改或清空内容，不强制普通二级标题。
- P0：每次实际应用的文档变更形成新修订；删除 Section 仅在新修订中移除，旧修订及引用不变。操作明确指定 Analysis 和作为依据的修订；块操作还指定目标 Section，执行时检查相应归属和当前版本，不依赖线程中的隐式「当前文档」。参数与变更提交契约在架构中细化。

### F4 规范化与展示
- P0：按照架构文档中的规范化规格切分（二级标题为学习对象，前置内容为 preamble），生成展示编号和稳定 ID。

### F5 学习条目创建与整理
- P0：Occurrence 表达一个可独立作出收录决定的学习点，关联目标原文与持久讲解。相同原文位置不足以判重，不同讲解的条目分别保留来源；条目数量不直接代表原文出现次数或掌握程度。
- P0：提供 Agent 查询已有条目及其状态、原文位置和讲解出处，创建一个或多个待整理候选，以及修改已有待整理候选的基本能力。首轮暂缓手动创建条目；批量提取不是必经阶段，也不要求设置独立批量提取按钮。后续按真实高频组合增加 Shortcut tool，复用同一套定位、引用与权限规则。
- P0：条目创建只组织已有讲解支持的学习内容，不在短字段中补充新的教学分析。讨论中的补充理解需先成为自足讲解，条目再引用该讲解；不直接以聊天消息作为阅读出处。
- P0：解释语言等必要设置可用于 AI 整理；讲解偏好不改变字段契约，不授权增加来源讲解未支持的内容。
- P0：条目契约明确且带版本；AI 标签只能从预定义词表中多选或不选，禁止自造标签。当前四类类型与五个标签见 GLOSSARY 第 4.1 节；具体 schema 和 anchor 规则仍待细化，手动输入形式留到相应能力阶段。
- P0：无论创建入口如何，保存的条目必须通过原文定位与讲解引用校验，引用应属于明确的来源修订。校验通过不等于已证明教学解释正确或提取完整。
- 候选创建／修改按独立结果反馈；已经通过校验并成功保存的部分保留，失败部分回传 Agent 修复，不将整批重跑作为默认恢复手段。自动修复与临时故障重试受统一的有限执行预算约束，见 F8；具体参数由执行策略确定，不沿用可与 Agent 循环叠加的独立「再重试 2 次」占位。
- P0：系统记录条目的片段、具体修订／讲解块、Source 与创建来源；模型参与时关联相关 Run，手动操作不伪造 Run。
- 整理状态为 `pending`（待整理）、`learning`（已收录）、`reference`（仅参考），用户可在三者之间调整。Agent 创建的条目一律为 `pending`；用户从界面收录后为 `learning`，不重复结算。`reference` 保留主动查找与阅读能力，默认不参与后续学习活动；`learning` 不代表掌握，也不自动启动 SRS。
- 首轮移除独立的「忽略」状态，不再使用 `dismissed` 同时表达忽略与删除。删除是独立产品操作，保留 Occurrence 以状态变更软删除的技术约束；内部删除状态编码由架构落实，不因此增加归档、回收站或恢复入口。
- 用户直接操作界面即可收录、设为仅参考或退回待整理，无需再经过 Agent 审批；首轮不提供 Agent 整理状态工具。删除是独立操作，不被解释为对某个知识点作出永久拒绝建议的决定；再次整理不能恢复已删除记录，也不据此自动建立永久拒绝建议规则。
- Agent 创建待整理候选默认无需审核；修改已有待整理候选内容，在审核模式下默认需审核，批准并保存后仍为 `pending`。单条和批量遵循同一边界；Full access 只省去已有工具的审批，不允许创建非待整理条目或改变整理状态。
- 条目内容编辑工具只作用于当前仍为待整理的记录。若待审核期间用户已经收录、设为仅参考或删除目标，旧方案不能继续应用，也不能自动退回待整理后再修改；执行时须重新核对目标状态及内容。修改已有讲解仍按 F9 处理，并保持旧条目引用不漂移。
- 首轮不提供解析完成后自动提取的开关。

#### 再次整理已有讲解

- Agent 再次整理前先读取相关已有条目，以补充遗漏的待整理候选、明确修改已有待整理候选为主。修改仍遵循 F9，不因称为「重新提取」而绕过审核。
- 已收录、仅参考条目只作为参考，Agent 不修改其内容、出处或状态。已有待整理候选不会因新一次调用自动失效；不整批替换、自动合并或迁移用户的整理决定。
- 不确定是否重复时，可以说明疑似重复或不同之处，但不能仅凭相同 anchor 或原文位置合并记录。不承诺 Agent 每次都能准确识别语义重复或完全消除重复候选。
- 讲解产生新修订后，旧条目继续引用原修订。待整理候选若需要更新内容和出处，应一起提出具体修改；已收录、仅参考条目不会自动跟随。Agent 可在讨论中指出新讲解对旧解释的纠正和受影响条目，用户若希望由 Agent 修改，需自行将目标退回待整理。
- 用户明确需要彻底重做时，可清理选定候选后再生成；清理范围与删除按已有规则处理，不隐含在普通再次整理中。
- 结果展示本次新增、提出修改和实际保存的内容，各次调用保留来源；不要求用户先管理「第一批、第二批」提取结果才能使用。一次再次整理没有发现新学习点也可以正常完成，不为凑数量生成候选。

#### 成功、失败与等待的判定

操作成功表示适用的字段、类型、原文定位、讲解引用、权限和当前目标状态校验通过，且结果已经实际保存；不表示教学解释已被证明正确，也不表示学习点已提取完整。引用存在不能单独证明提取判断正确。没有发现新学习点是正常结果，不作为失败或要求继续凑数的理由。

| 情况 | 保存与反馈 | Agent 后续行为 |
|---|---|---|
| 字段不合法、原文定位失败、讲解引用无效 | 不保存无效结果，返回具体错误及相关条目／操作 | 在执行预算内按反馈修正后重新提交 |
| 目标内容、状态或存在性已变化 | 不应用旧方案，说明当前情况 | 重新读取，遵守当前可操作范围；不能把已收录条目改回待整理后修复 |
| 临时调用或存储错误 | 保留已有成果，报告原因与写入情况；保存结果不确定时明确标出 | 先核实实际保存情况，再有限重试，避免重复创建或应用 |
| 正在等待用户审核 | 保存待审核方案，显示等待，不算失败 | 等待决定，不当作错误重试 |
| 用户拒绝或操作权限不允许 | 不执行该操作，反馈原因及用户附加指令 | 不反复提交同一方案；有新指令时据此调整，仍不得越过工具范围 |

#### 保留成功部分与反馈修复

- 以实际成功保存的独立条目或修改为单位保留成果。一次尝试创建 10 条候选，8 条通过校验并保存、2 条定位失败时，8 条可立即查看，2 条只保留必要失败诊断，不作为正常 Occurrence 入库。已有条目的修改失败时，原内容保留。
- 只有能够独立识别、校验并保存的结果才计为成功。整个输出无法解析时，不凭猜测宣称其中一部分成功；不将残缺内容冒充完整讲解或条目。
- 讲解已独立保存后，后续候选失败不撤销讲解。任务中断、后续修复失败或耗尽预算，也不回滚已经成功保存的成果。
- 工具反馈给 Agent 时分别说明哪些已保存、哪些未保存、哪些保存结果需要核实，附成功记录的明确标识与具体失败原因。Agent 修复失败部分，不重新提交已成功的创建或修改。
- 未成功创建的候选在修正后仍走创建流程；修改已经保存的候选继续走修改流程和相应审核。修复不授权改变用户整理状态，也不豁免校验或审批；需要更新获批内容时仍按 F9 处理。
- 对可修复错误，执行流程允许 Agent 根据反馈继续尝试；临时故障允许有限重试。设置有限的修复次数、时间或调用预算，具体参数及底层重试与 Agent 循环的协调方式在执行策略中确定，不能多层叠加而无界运行。
- 达到预算后停止本次自动修复，保留成果，展示尚未完成的项目、原因和后续可采取的操作，允许用户之后继续。待审核、用户拒绝或权限不允许不按技术失败自动重试。
- 用户能看到实际进展，例如「已新增 8 条候选，2 条因原文定位失败尚未完成」；之后修复成功则更新结果。不能静默丢弃错误并将部分完成描述为全部成功，也不能把可验证的条目计数当作整份讲解的知识覆盖率。

### F9 Agent 工具权限与审核

任务意图与执行许可分别表达。Agent 先确定本次要对哪个对象做什么，再按线程权限模式执行。已开放的写入工具必须遵循本节；具体工具名称与粒度由架构设计，不依赖提示词单独保证。

| 模式 | 行为 |
|---|---|
| 审核模式 | 可直接执行的操作按下表运行；需审核的写入先准备具体方案，用户同意后执行 |
| Full access | 对已开放且符合任务意图的工具操作，省去逐次审批；仍展示结果、校验数据并保留历史出处 |

每个对话清楚显示自身模式，仅在本轮结束或停止完成、线程空闲时允许切换；运行和待审核期间不切换。产品初始默认审核模式，新对话可采用用户更改后的默认值。共享片段资料不意味着共享或继承其他线程的权限。Full access 不扩大工具集合，也不将普通问答自动转换为修改任务。

**审核模式下的操作分类：**

| 操作 | 行为 |
|---|---|
| 读取原文、检索讲解与条目 | 直接执行 |
| 用户明确要求新建讲解 | 可以直接生成并保存，不要求为同一新建动作额外审批 |
| 修改已有讲解 | 审核确定目标、基础版本与具体修改后执行 |
| 修改已有待整理候选内容 | 默认审核具体目标与内容差异后执行；保存后仍为待整理，批准修改不代表收录 |
| 删除指定 Section | 作为修改已有讲解审核，成功后形成新修订；不删除历史修订与引用 |
| 删除整份 Analysis | 首轮不向 Agent 开放；由用户经关联范围确认后操作，见 F2 |
| 仅创建待整理候选 | 默认直接执行，不因写入候选或批量创建本身额外要求审核；仍校验原文与讲解出处 |
| 创建非待整理条目，或改变整理状态 | 首轮不提供给 Agent；收录、设为仅参考、退回待整理由用户界面操作，Full access 也不开放 |

分类依据是工具的实际效果，不仅是工具名称或「新建／修改」。混合操作若同时生成候选并修改已有讲解或候选，不能因含有候选生成而绕过修改审核。Full access 省去上述逐次审批，但不能通过组合工具或先创建再修改状态的方式完成自动收录。组合工具的审批展示与恢复实现仍待细化，部分完成时遵循 F8 保留已保存成果的规则。

**具体方案与用户反馈：**

- 修改审批应展示目标讲解／Section 或待整理候选、修改目的及原内容和拟保存内容，或可理解的差异。先准备可判断的结果，不让用户批准模糊的「允许修改」后再任意生成内容。
- 用户可以同意或拒绝，并可在任一选择中附带新指令。同意只批准已展示的方案；同意并附带指令时先应用该方案，成功后再执行后续任务，失败则明确报告。拒绝不应用该方案，附带指令可用于重新准备。
- 补充指令不得静默改变刚批准的内容。后续若形成新的、需要审核的修改，应再次按当前权限模式处理。
- 方案待审核期间不修改正式讲解或条目；离开页面不会替用户决定。依赖该写入的动作必须等待实际保存成功，待审核方案不能冒充正式成果。
- 审批绑定确定对象、基础版本与具体变更。其他对话已修改目标时，旧审批不能覆盖新版本；应基于最新内容重新准备，并在审核模式下重新展示。Full access 同样不能盲目覆盖过时目标，须重新核对，但不额外引入逐次审批。
- Full access 不绕过原文定位、引用校验、不可变修订、删除范围和历史出处规则。执行结果均需可见、可检查。

混合效果工具的审批展示仍见 `[TBD-17]`。初始默认审核模式、只在空闲线程切换、停止时取消未执行方案，以及候选创建免审／修改需审／不开放自动收录的边界已确认。

## 8. 成功标准

本节按已确认的基本能力整理为验收草案，具体案例继续审订。总体讲解快捷入口与对话内生成均验证Analysis自动保存；其余快捷按钮和高频组合工具可在闭环后打磨。

- 用户可围绕已保存片段直接讨论，不被要求先生成完整报告；保存与阅读讲解不以提取和结算为前提。
- 发起解析或讨论时，适用的学习背景与偏好自动带入，无需重复粘贴。
- C2 中从“保存为学习片段”入口预装有界语境；本次流程内收起再展开保留草稿，修改、清空、配置变化及迟到结果不导致预填覆盖用户内容，重开已存片段保留其语境。目标与出处保持稳定，保存不隐式调用模型。预算与失败样例见[验收矩阵](handovers/text-study/TEST_MATRIX.md)。
- 原文、讲解与条目持久保存；离开工作台或重新进入后仍能找回。对于纳入首轮的讨论整理入口，成果脱离聊天历史仍可理解。
- 阅读 Occurrence 时，在当前页面读到原句与确切来源版本的原 Section，并能回到完整讲解；不以点击次数替代已有阅读基线。
- 已保存条目的定位与引用必须通过校验；模型输出失败和未完成结果可识别，不把这一要求描述成模型每次提取均正确、完整或稳定。
- AI 任务离开页面后仍由后台执行，返回可查看状态和结果；后台停止导致的中断可识别，刷新不重复发起调用。
- 对纳入首轮的 Agent 写入工具，审核模式能查看具体方案、同意或拒绝并附加指令；拒绝不落地修改，待审核可返回处理，批准不重复应用，过时版本不覆盖新内容。Full access 可直接执行同类已开放操作，仍满足引用与修订规则。
- Agent 创建条目一律为待整理且默认免审；修改待整理候选在审核模式下默认需审核，保存后仍为待整理。用户在审核期间改变目标整理状态后，旧修改不能继续应用。两种权限模式均不提供自动收录或整理状态工具，批量与混合工具也不能绕过。
- 待整理、已收录和仅参考可相互调整；仅参考保留查找与阅读，默认不参与后续学习活动。删除条目不删除原文和讲解，删除后不进入日常浏览；首轮无独立忽略状态、归档或恢复入口。
- 再次整理先参考已有记录，不自动清空候选、替换旧条目、迁移状态或漂移出处；无需为使用这一能力先管理提取批次。
- 部分失败时已独立保存的讲解、候选与修改保留，无效结果不作为正常条目入库；反馈区分已保存、未保存和需核实，继续执行不重复创建成功部分。没有新学习点可正常完成。
- 自动修复有有限预算，耗尽后保留成果并说明未完成内容；用户拒绝、权限不允许和等待审核不会引发错误重试循环，修复也不绕过已有审核规则。
- 多份讲解并存时，Section 操作核对明确的 Analysis、基础修订和块归属；更新、插入、删除产生新修订，旧引用保留。删除整份 Analysis 须经用户关联范围确认，不删除 Segment 的对话线程。
- Agent 不能读取其他片段资料或检索其他线程聊天历史；当前片段下已保存讲解可共享。初始默认审核模式，运行／待审时不能切换模式；同线程不能继续发送或排队，其他线程不随审核等待被锁住。停止后不再启动本轮后续操作，未执行方案取消，已保存成果可找回。
- 实际试用观察用户是否愿意持续使用、整理是否打断学习、旧讲解是否容易找回。「一周内不再打开网页 AI」可作为个人观察，不作为硬性验收条件；学习条目数量不代表掌握度。
