# 升级与备份

已有学习数据时，请在更新代码和启动前先做备份。`just start` 和 `just migrate` 都会执行数据库迁移。首次从空库启动见[项目首页](../README.md#快速开始)。

## 数据与凭据

新安装默认数据库为 `~/Folio-J-Data/app.db`。用户配置 `~/Folio-J-Data/app.toml` 中的 `[database].path` 可固定其他绝对路径（支持 `~/`）；程序目录 `config/app.toml` 中明确填写的字段覆盖用户配置，`FOLIO_J_DATABASE_PATH` 环境变量优先于 TOML。未显式指定数据库且当前程序目录有旧 `data/app.db` 时，继续使用该旧库，不搬迁文件。迁移和应用读取同一路径并在终端显示，完整优先顺序见[应用配置](USAGE.md#应用配置)。

**旧安装换到新程序目录前，先固定数据路径。** 停止服务并完成下面的一致性备份后，在 `~/Folio-J-Data/app.toml` 将 `[database].path` 设为旧数据库的绝对路径；如文件已有配置，只编辑所需字段。检查新程序目录的 `config/app.toml` 与环境变量没有指向其他库，再启动新程序。若继续使用原处的数据库，须一直保留旧目录中的数据库及配套文件。也可按下文将整组数据恢复到独立路径，再将用户配置指向恢复后的数据库。用户配置的创建与编辑步骤见[使用指南](USAGE.md#首次启动前选择数据位置)。

模型密钥保存在数据库旁的 `<数据库文件名>.secrets/` 私有目录，新安装默认对应 `~/Folio-J-Data/app.db.secrets/`。目录权限为 `0700`，文件权限为 `0600`；这是文件权限保护，尚未加密。旧凭据暂保留以支撑已接受请求的固定引用，不应仅按当前设置页清理该目录。

升级前停止使用目标库的服务，制作 SQLite 一致性备份，并同时备份对应凭据目录。数据库使用 WAL 模式，不要在服务仍写入时只复制主数据库文件。恢复时保持数据库与凭据目录配套；改名或换路径时，凭据目录也须对应新的数据库文件名。

已安装的查词词典及当前选择保存在数据库旁的 `<数据库文件名>.dictionary.sqlite3.library/`。旧版单词典索引 `<数据库文件名>.dictionary.sqlite3` 仍在原位使用。要保留全部词典与当前选择，请在服务停止时同时备份、恢复该目录和存在的旧索引；若更改数据库文件名，两处也需对应改名。保留原始 ZIP 时，也可从「设置 → 词典」重新导入并选择。 在设置中删除词典会移除本机安装项与对应索引；删除当前词典时一并确认替代项，最后一本删除后当前选择为空。目录事务提交前失败会保留原状态；提交后若文件清理失败，可能留下无目录引用的暂存文件，已删除词典不会重新出现在列表。无法识别身份的旧损坏索引不会被当作有效词典删除。

### 制作备份

在应用终端按 Ctrl-C 停止服务。在平时启动应用的程序目录运行 `just data-path` 核对源库。如平时用 `FOLIO_J_DATABASE_PATH` 指定数据库，备份时也要传入同一值。

选择一个私下保管的位置，父目录须已存在。下面的命令会创建新目录 `folio-backup-01`。再次备份时另取新名字。

```sh
just backup "$HOME/folio-backup-01"
```

没有安装 `just` 时，使用 `uv run --project backend --no-dev python -m app.backup create "$HOME/folio-backup-01"`。

**备份可能含未加密的模型密钥、私人书籍和词典，请私下保管整个目录。** 命令通过 SQLite 备份接口生成完整主库副本，并收集配套凭据、已安装的词典和当前词典选择。原 EPUB、编译后的书籍、阅读位置、书签、片段、讲解修订、讨论和已保存译文随主库保留。`manifest.json` 记录版本、有哪些配套内容以及文件大小与 SHA-256。看到命令成功结束后，再复制或移动整个备份目录。恢复会核对清单，复制时请保持目录内容完整。

用户的 `app.toml` 另行保存，换机器时先核对端口和绝对路径。阅读配色、部分界面设置和设备朗读偏好保存在原浏览器中，在新设备上可重新选择。

### 恢复到独立路径

停止目标服务。选择一个**尚不存在**的目录，恢复成功后数据库位于其中的 `app.db`，凭据和词典与它相邻。

```sh
just restore "$HOME/folio-backup-01" "$HOME/folio-restored-01"
```

没有安装 `just` 时，使用 `uv run --project backend --no-dev python -m app.backup restore "$HOME/folio-backup-01" "$HOME/folio-restored-01"`。

恢复会检查备份格式、文件清单、内容校验值、数据库及支持的数据版本。检查失败请根据报错核对原备份，成功后再用恢复库启动。

```sh
FOLIO_J_DATABASE_PATH="$HOME/folio-restored-01/app.db" just start
```

打开一本已读过的书，从书签跳转，再从已保存讲解定位原文。如原来安装了词典，也在书中查一次词。确认后，在 `~/Folio-J-Data/app.toml` 中把 `[database].path` 指向恢复库的绝对路径。原数据仍在原处，可以保留到核对完成。历史未完成的模型任务按正常重启规则标记为中断。

## 当前迁移基线

原生备份格式为 v1，首个支持的数据库版本是 `0004_translation_reader_removal`，书籍采用 `FJEPUB` v2。应用版本、备份格式和数据库迁移版本分别记录。更新应用前先用手头的版本备份。在新版目录运行 `just data-path`，确认指向原库或有意恢复的副本，再执行 `just start`。启动会先运行正常的增量迁移。

## EPUB 存储格式与开发库重建

备份保存原 EPUB 和已编译的书籍。书签与片段使用原材料及版本的身份定位，重新导入原 EPUB 会创建新的身份。要保留原文关联，请使用整库恢复。

## 旧开发数据库与备份

早期手工备份含 `backup-info.txt`，需要用记录的代码版本和当时的《升级与备份》恢复。旧开发库在升级前也应先用匹配版本制作完整备份。当前迁移链从 `0001_schema_baseline` 到 `0004_translation_reader_removal`。更早的 `0001_initial` 至 `0006_translations` 以及旧编译包需要匹配的历史代码，修改版本标签不能转换书籍或修复定位。
