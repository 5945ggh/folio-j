## 2. 产品重心：围绕原文形成可持续使用的学习成果

**已有共识。** Folio-J的核心体验是：用户拿到一段原文后，可以围绕它理解、讨论，按需留下讲解，并在之后找回、重读和复用自己的学习成果。

现有片段学习以Segment为共同起点。用户可以直接提问，也可以先获得总体讲解；可以围绕一个专题深入讨论，也可以修改已有讲解。保存讲解、积累学习点和参与学习活动各有用途，不要求每次使用都走完固定流程。新增的阅读对话方向见[原生阅读方向讨论稿](handovers/epub-reading/DIRECTION.md)，不将每次原文引用自动等同于 Segment。

此前以素材库和精美阅读器为主体的探索，花费了较多精力处理素材浏览，却迟迟没有完成核心学习体验。本次开发先建立Source、Segment、讨论和讲解能力，是为了先验证真正帮助学习的部分。

这一取舍并不否定原生阅读器的价值。未来在应用内阅读、划选并创建片段，可以减少内容在工具间搬运的成本；它应当接入已有学习能力，而不是要求重新围绕某一种素材格式组织整个产品。

**对近期开发的影响：** 优先打磨已有内容的查找、阅读、讨论与成果保存体验。素材导入、媒体播放和学习活动的范围，在各自成为明确任务时再决定；不为了展示完整产品轮廓而提前建设它们。

### 2.1 理解辅助与长期教学方向

以下内容承接既有 PRD 的长期方向，用于保留动机与设想，不新增首轮要求或交付顺序。

**已有共识。** 兴趣导向的原版内容是学习输入，辅助首先帮助用户恢复理解、继续阅读或观看，并逐渐减少对辅助的依赖。即时解释、保存讲解和后续学习各有用途，不是每次辅助都要转化为长期积累。

| 活动 | 主要关注的问题 |
| --- | --- |
| 沉浸理解 | 如何更好地理解当前内容 |
| 主动学习 | 值得停下来进一步掌握的内容，以何种形式展开学习与讲解 |
| 知识积累 | 如何保存、关联和再次利用已有理解与学习记录 |
| 适应性教学 | 下一步学习或复习什么，需要多少辅助，以及如何逐渐减少辅助 |

**长期方向与设想。** Folio-J 希望向智能教学系统（ITS）演进：结合学习者目标、已有知识、素材特征和实际学习表现，提供适合不同内容的学习形式和原生交互组件，调整辅助深度并推荐学习内容。卡片式间隔复习只是可能的主动学习形式之一，不作为全部学习内容的统一模型；可定制的学习形式也应容纳不适合卡片的内容。

长期来看，系统还可以利用素材本身及学习者的历史状态，主动寻找高学习价值的词汇、句子和片段，进而帮助学习者从该作品中选择具有高覆盖率和高迁移价值的内容进行短期预学习，从而降低初始沉浸的理解成本，提高冷启动效率。

例如，对一部感兴趣但明显超出当前水平的轻小说，系统未来可以分析整部作品的词汇、表达和句子分布，形成与作品绑定的个性化启动学习，并为阅读中积累的知识安排复习。这些设想以及学习者模型、冷启动推荐和适应性机制仍需通过真实使用验证；不要求首轮提前建立通用教学引擎或对应字段。

## 3. 需要保持清楚的概念边界

### 3.1 来源、素材、材料与片段

**已有共识：** Source表达用户声明的来源范围，不与单个文件一一对应；Segment表达这次实际拿出来学习的目标文本。手动输入是完整、合法的入口，不以系统持有原始素材为前提。

**2026-10-03 已对齐含义：** 素材是用户提供且保持不可变的原始输入；材料是素材经过应用处理后，可由应用利用的形态，并可保留原有内容和呈现资源。可逆映射不作为要求。具体定义见 [GLOSSARY 第 2 节](GLOSSARY.md#2-素材与材料)；首轮托管 EPUB 副本、按材料版本定位的[主要设计方案](handovers/epub-reading/MATERIAL_BASELINE.md)已获认可，实施契约按阶段收口。此前的 `Material／素材` 暂称不继续作为正式英文命名依据。

| 概念 | 主要回答的问题 | 应保留的边界 |
| --- | --- | --- |
| Source／来源 | 这段内容属于用户声明的哪个作品、出处或内容范围？ | 不要求有对应文件，不自动核实或归并作品关系 |
| 素材 | 用户提供的原始输入是什么，如何保留或引用它？ | 原始输入保持不可变；保存方式、文件与素材的粒度仍待定 |
| 材料 | 应用如何利用处理后的内容，并追溯原始素材及位置？ | 保留内容与呈现资源的具体范围、处理与定位契约待定 |
| Segment／片段 | 本次学习、讲解和讨论的目标文本是什么？ | 可以从材料中选取，也可以直接手动输入；阅读中的原文引用不自动等同于 Segment |

例如，用户可以用一个Source组织某部作品，并将多个卷的EPUB与其关联；其中有些Segment来自EPUB划选，有些来自手动录入。这是可能的组织方式，不规定作品、卷、动画改编和单集必须归入同一来源。

希望保留的方向是：一个Source可关联多份素材及其材料，Segment未来可带有可选的材料位置与素材出处。具体关联、定位、版本和删除关系尚未定案，不能从这个方向直接推导数据库外键或文件层级。当前自由文本`source_ref`也不等同于这些未来关系。

**对后续设计的影响：** 保持手动片段入口独立可用。原生阅读先按具体 EPUB 场景明确材料、引用、对话及讲解形成的关系，再确定模型与迁移范围；不从术语定义直接推出通用媒体层或处理流水线。

### 3.2 讨论过程与持久讲解

**已有共识。** ChatThread保留讨论过程，Analysis保存可以脱离聊天独立理解的讲解。同一片段可以留下多条讨论和多份讲解，线程不永久绑定一份文档。

值得再次阅读的讲解，应当容易被找到和打开。用户回看它时，无须先重读聊天，也无须先处理模型、权限和任务控件。阅读中产生新问题时，又应当能够轻便地进入讨论。

**对近期开发的影响：** 让内容身份与具体入口保持一致，并提供顺畅的原文参照。讲解的独立性首先体现在可查找、可定位和可阅读，不以立即增加一个独立页面为前提。

### 3.3 知识积累与学习活动

**已有共识。** Occurrence表达学习点在具体片段中的出现与出处；它不等同于复习卡片。知识记录可以成为学习活动的输入，但不应提前按某一种练习形式塑造全部积累内容。

**方向性设想：** 跨来源查找和重读积累，与主动练习、回忆和复习，可以有各自的活动空间。未来活动可能包括回忆式问答、听力辨析、翻译、跟读或其他教学交互，具体形式由学习需要验证。

**对近期开发的影响：** 不把远期活动设想写成当前卡片字段、通用教学引擎或活动调度要求。本次截至2C的回看不敲定Occurrence、anchor或KnowledgePoint的后续契约。

## 4. 长期功能空间的职责草案

**方向性设想。** 以下区分用户想完成的事情，帮助判断未来功能放在哪里。它们不是已经定案的一级导航，也不要求各自拥有独立页面。

| 空间（暂称） | 用户主要想回答的问题 | 可能的职责与尚未确定之处 |
| --- | --- | --- |
| Home | 我回到应用后，接下来去哪里？ | 从其他空间呈现值得继续的内容；具体内容依赖使用反馈，不预设统计仪表盘 |
| 素材库 | 我有哪些可以直接读、看、听的原始内容？ | 找到并打开素材，进入阅读或播放；内部分类及支持格式待定 |
| 按来源组织的学习档案 | 围绕这个来源，我讨论过什么、留下过什么？ | 从当前来源目录逐步支持学习历史回顾；是否直接聚合讲解、条目和活动待定 |
| 知识库／学习积累库 | 我从不同来源积累了什么，如何再次理解它？ | 查找、筛选、重读和发现联系；具体组织方式仍需随积累功能设计 |
| 学习中心 | 我现在要练习或复习什么？ | 承载主动学习活动；活动形式与推荐方式待定 |
| 设置 | 我要如何配置学习偏好和应用能力？ | 提供跨区域的配置入口，沿用已有模型、背景和偏好设置能力 |

素材库、来源档案和知识库具有不同的观察角度。例如，对同一部作品，用户可以分别关心“有哪些原始内容”“我围绕它学过什么”和“哪些知识能与其他来源联系”。这些视角可以共享内容、相互链接，不需要复制出三套数据；也不因共享对象就必须合并成一个页面。

来源目录当前作为进入片段的入口已经有用。“按来源回顾学习”的长期价值值得保留，但不要求现在将来源详情做成汇总全部内容的大页面。

Home可以理解为其他空间的投影视图：它提供继续入口，不拥有新的学习内容。最近片段、未完成讨论或最近阅读素材都只是候选内容。等实际使用表明某种恢复入口有帮助时，再让它进入首页。

**对近期开发的影响：** 来源目录拥有独立位置，根入口可以暂时跳转至它。近期导航只呈现已有功能；不为凑齐上述空间增加空入口或中转页。最终中文名称、一级导航数量及侧栏形态均继续开放。

## 5. 阅读与工作台的演进原则

### 5.1 区分职责，保持切换轻便

**已有共识。** 浏览归档帮助用户找到内容；阅读视图呈现具体对象；工作台支持围绕对象展开活动。这些职责可以作为设计分析的工具，但不要求用户逐层经过“归档 → 概览 → 阅读 → 工作台”。阅读中顺手提问，是应当自然衔接的连续行为。

Segment需要让人了解“这里已经有什么”，但这可以通过同页的原文、讲解和讨论入口表达。是否需要独立Segment概览，应当由内容规模与回顾需求决定。Analysis是否需要独立页面、抽屉或其他阅读形态，也继续由实际场景决定。

本轮采用同一个片段页面承载阅读和按需展开的讨论，是当前选择；它不预先排除未来的其他呈现方式。

### 5.2 入口表达意图，目标保持稳定

**已有共识。** 点开片段应首先看到该片段的内容，点开讲解应直接读到那份讲解，点开讨论应打开对应线程。工作台允许多个入口，Source目录无须垄断进入路径。

未来从Reader选取文本、从知识条目回看出处、从Home继续活动，都可以汇合到相同的片段及其成果。工作台是针对具体内容展开活动的环境，不需要因为它重要，就把一个没有对象的“工作台”设为一级入口；Reader也可以从具体素材进入。

“返回来处”与“查看所属来源”分别表达导航历史和内容归属。从不同入口打开同一对象时，来处可以不同，归属保持一致。具体修订与出处的定位也应当稳定，不因换了入口而静默指向另一份内容。

### 5.3 原文参照与阅读主体共同可用

**已有共识。** 日语讲解常需要反复参照原句，原文与讲解不适合被长期限定为互斥标签。呈现方式应当兼顾短片段、长原文、长讲解及不同屏幕，让参照易于到达，也让正文保有足够阅读空间。

本轮桌面参照区、展开收起和窄屏滚动的具体实现，是可继续打磨的方案。后续按实际阅读体验调整，不将某个固定栏宽、吸顶行为或分屏比例提升为长期产品原则。

### 5.4 导航提供方向感，控件服务当前动作

**已有共识。** 保留安静、阅读友好的视觉气质，减少无关控件争夺注意力。全局导航说明所在功能区域，内容导航说明当前对象有哪些可读内容和可做的动作。

**方向性设想。** 若功能空间增多，可以考虑克制的侧栏、可折叠导航或混合布局。是否采用这些形态，取决于实际入口数量、切换频率和可用阅读空间，目前不定案。

## 6. 下一步何时需要做哪些决定

| 待讨论的问题 | 适合进一步决定的时机或证据 |
| --- | --- |
| Home具体呈现什么？ | 回访使用暴露了明确的“继续学习”需求，能够说明新首页比当前直接进入内容更方便时 |
| 来源目录是否更名，来源详情如何组织学习历史？ | 用已有来源、片段、讲解和讨论回看真实积累，发现当前查找方式的具体不足时 |
| 是否需要独立Segment概览或Analysis阅读页面？ | 同页内容导航难以表达积累，或独立阅读、直接访问的场景需要额外形态时 |
| 一级空间和导航最终怎样排列？ | 明确各区域的实际职责与常用切换路径之后，用页面验证空间和操作成本 |
| 素材与材料如何命名、关联、定位和保存？ | 按原生阅读方向，以具体 EPUB 内容明确粒度、定位与生命周期，再同步技术契约 |
| 素材库按什么分类？ | 已有明确的素材类型和查找任务时，不提前固定“文字／影音”二分 |
| Occurrence、anchor与跨来源积累如何组织？ | 对应切片开始前按PRD未决项和具体例子收口；本次界面方向不代替这些决定 |
| 学习中心、KnowledgePoint或聚类是否需要独立模型？ | 有明确的学习活动或跨来源组织需求之后，避免仅为远期完整性预建实体 |

这些是讨论触发条件，不是开发排期。近期可以继续从已有页面和真实学习过程出发，发现一个具体问题，讨论并验证一个适度调整。
