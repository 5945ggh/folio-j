# 设计系统

本规范维护现有视觉基线、颜色作用域与样式使用规则。产品行为由 [PRD F1](PRD.md#f1-设置)维护，页面职责和交互参数由[阅读与导航](INFORMATION_ARCHITECTURE.md)维护，运行机制见[前端架构](ARCHITECTURE.md#6-前端结构)。实际色值以 CSS 为准，交付状态与验收入口见[实施基线](handovers/MVP_IMPLEMENTATION_BASELINE.md)。

## 视觉基线

延续现有浅色视觉：公共页面以白色内容面、低对比灰色导航和克制的操作色组织信息；片段阅读保留黑白灰层次，让日文原文成为阅读主体。已有字体、留白、尺寸、布局、信息密度与控件位置保持各自职责，不因支持深色而统一成另一套页面样式。

深色沿用相同的信息层级和交互结构，分别适配背景、正文、辅助文字、边框、焦点、选中和状态反馈。删除、错误、警告、成功等状态保留明确语义，不能只靠背景亮度表达。封面、正文图片、品牌图案与 SVG 插画保留原始配色，不使用整页反色滤镜。

## 颜色作用域

| 作用域 | 颜色来源 | 使用边界 |
|---|---|---|
| 公共应用 | `frontend/src/theme/tokens.css` | 素材库、来源、详情、设置、片段、讨论、公共加载与错误页 |
| 页面与组件 | 公共语义变量及区域别名 | 保留局部阅读层次、悬停、按钮和内容组合；不建立另一套应用主题 |
| EPUB Reader | `frontend/src/materials/reader-r1.css` 的阅读变量 | 独立白／黑纸面、阅读工具、预览与局部对话框 |
| EPUB iframe | `reader-palette.ts` 显式桥接的阅读变量 | 独立文档内的正文、选区和标记；不复制一份配色常量 |

应用根节点的 `data-theme` 确定公共颜色模式。Reader 在自己的作用域设置 `color-scheme`，独立解析白／黑纸面；应用浅色配黑纸面、应用深色配白纸面都属于正常组合。两处的系统模式各自读取系统颜色偏好，不互相改写存储值。应用颜色选择不影响材料版本、内容身份与阅读位置。

## 语义变量使用规则

- 按用途选择变量：内容面、正文、辅助文字、边框、强调、危险状态、遮罩与阴影分别维护。变量名表达用途，避免按十六进制值命名或为每页复制主题表。
- 文字强调使用 `--color-accent`，实心操作按钮使用 `--color-accent-solid`，按钮前景使用 `--color-text-on-accent`。兼容别名 `--accent` 与 `--accent-solid` 同样分开，局部黑色操作风格可各自定义浅色分支。
- 公共变量用 `light-dark()` 配合当前作用域的 `color-scheme` 解析。原生输入和对话框继承所在作用域；Reader 的独立纸面可以显式选择 light／dark。
- 保留已有浅色差异时，可使用 `light-dark(原浅色值, var(--color-相应用途))`。重复值应收拢到组件或区域的语义变量，避免在文件末尾追加成片暗色选择器覆盖。
- 明确区分纯配色与几何变化。背景、文字、阴影等配色更新原地应用；字体、字号、宽度、注音范围和横竖排继续使用阅读布局恢复链路。纯配色不重建 iframe、不重新绑定 ruby 事件、不触发位置写入。
- Markdown、表格、图表、工具提示和浮层使用其所在作用域的颜色。新增状态同时核对正常、悬停、焦点、选中、禁用和错误表现。

## 维护与后续范围

修改颜色时检查浅色基线、深色、系统模式变化、公共页面与 Reader 的独立组合，以及文字／图标与表面的对比。涉及阅读布局时继续验证原文位置、选区、注音与图片表现。检查结论记录在对应验收资料，长期规范只维护规则。

当前提供内置浅色、深色与系统模式。用户自定义 CSS 的入口、作用范围和存储契约，以及其他 Reader 重构，留待后续单独设计。
