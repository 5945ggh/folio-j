# Occurrence 与 anchor 小样本试提取报告（batch-01）

## 范围与结果

本轮按 `pilot-brief-v0.1`、A0 基线处理指定 `cases/01`–`06` 六份既有 Markdown 解析。先试 01–03（22 条），再用 04–06 补看会话省略、工具 `で`、句尾形式和停顿（13 条）；A0 没在批次中途改动。每组的原始绝对路径、快照、目标原文、语境、选择理由和 Section 行号在 `manifest.json`，快照在 `snapshots/`。实际提示词版本未随指定的 `cases` 提供，逐样本记为未知；不能仅凭目录研究名称宣称是已确认的 v0.1 prompt。

研究触及 PRD 的 `TBD-03`（anchor 书写）与 `TBD-08`（按 anchor 分组）的待定边界；本文的候选改法不修改或批准这些产品决定。

共形成 **35 条**记录：grammar 22、lexis 10、expression 3；没有强行产出 other。`validate.py` 对实际文件复跑后，`validation.json` 为 **6 份样本、35 条通过、0 条机械失败**。这只证明 JSON 契约、引用、anchor 可机械格式及目标文本精确定位等事项；语义忠实度、收录粒度和日语分析正误仍需人审。首批 22/22 也曾通过同一校验。无外部模型 API、网络检索、新依赖或第一阶段重写。

实验执行当时的仓库未提供 `justfile`，当时环境中 `just` 命令不可用；尝试 `just lint` 和 `just test` 均返回 `command not found`。这只是该轮验证记录，不描述当前仓库命令状态。本轮没有产品代码改动，以可复跑的标准库校验脚本作为本任务的验证依据。

样本是人为挑选、且六句相邻，不能把条数或类型比例推断为总体率。已覆盖：活用（sample01-o08/o09）、多表记（sample01-o11）、助词和接续（sample01-o01/o12）、整体表达（sample03-o05）、同一 Surface 不同学习点（sample01-o08/o09）、不连续 Surface（sample02-o03、sample06-o03）、对比讲解（多条）。**未充分覆盖：** 单个目标中同一完整 Surface 多次重复的位置序号；本批虽有多个 `で`，本轮合理 Surface 都更长，正式记录的 `match_index` 均为 1。省略现象见样本 04/05，但其若作为独立学习点无法满意地写成 A0 anchor，故只留审查候选。不存在足够材料检验跨作品、跨模型或重复抽取稳定性。

## Anchor 召回行为

- **信息损失：** `V-て + くる`（sample04-o03）不携带过去形及「此前准备的结果来到现在」这一语境视角；`V-辞 + こと`（sample03-o06）不携带内部的 `行動を共にする`。因此 anchor 必须与 gloss、Surface、解析出处一起看。
- **形式漂移：** `ことが多くなる`（sample03-o07）由实例 `ことが多くなった` 还原，有解析支撑，却是固定词串而非一般形容词变形规则；`V-た + N`（sample04-o04）用过去形代表解析所讲的更宽「普通形小句＋名词」。这两种方向都会改变召回范围。
- **过宽召回：** 按 `kind + NFKC(anchor).strip()`，`grammar / N + で` 把 sample01-o02（漫画媒介）、sample01-o07 与 sample03-o02（地点）、sample04-o02（网络媒介）和 sample05-o03（工具）分在同一组。它仍适合找「で」的相关实例，但组内需保留各自 gloss 和出处，不能推断五条是同一知识点。`lexis / サボる` 同样召回 sample01-o08 与 sample02-o01，两份解析来源分别保留；虽然都在翘课语境，也不跨文档合并。
- **多 anchor 的边界：** sample01-o11 的两表记是同一对象的明示检索形式。sample03-o05 若额外加入 `N + を共にする`，会从「一起行动」扩为更一般的表达族；本轮不把这种上位句型作为同一对象的第二 anchor。相同 anchor 不证明同一知识点，不同 anchor 也不证明完全无关。

## 最小修改建议（仅建议，未改 A0）

以下 after 只是针对已提取案例的**推演**，不覆盖 `occurrences.jsonl`，也不是独立复测。每项均需在更多材料上检查回归风险。

| 建议及证据 | A0 当前结果 | 候选 after 与改善 | 代价 |
| --- | --- | --- | --- |
| 增加 `V-ます幹` 槽位；sample02-o02 | `サボりがち` fallback。 | `V-ます幹 + がち` 可表达解析 02:L82–98 明说的接续，减少由实例词干造成的漏召回。 | 新槽位定义、动词形态判断与校验用例；不能凭原文自动推导所有词干。 |
| 增加 `A-語幹` 槽位；sample03-o07 | `ことが多くなる` fallback。 | 可在另一个明确讲「多い → 多くなる」的记录中用 `A-語幹 + くなる`；不会误把包含 `い` 的 `A-い` 直接接 `くなる`。当前 o07 是否还需 `ことが` 前缀仍待粒度判断。 | 又添一种形态槽位，且可能拆分当前「情况变多」整体点；需人工审核泛化范围。 |
| 明确连体小句槽位与名词短语范围；sample01-o04、sample04-o04、sample02-o03 | `S + N`、`V-た + N`、`N + と + N + は`。 | 定义 `S-連体`（小句在名词前作修饰）及 N 是否包含带修饰语的名词短语；o04 候选 `S-連体 + N` 会比现有 `S + N` 明确。 | 新槽位和名词短语定义可能扩大或重排检索组；需要明确嵌套边界，不能只凭字符串校验。 |
| 明写多 anchor 仅限同一对象的表记/已讲形式；sample01-o11、sample03-o05 | o11 两表记并列，o05 仅固定整体。 | 把这对正反例写入未来规则，避免自动把对比例或上位句型加入 anchors。 | 规则文字增多，表达族与同一对象的界线仍可能需要个案复核。 |
| 明确无法合理 anchor 时保留 review 候选及输入差异；sample02-r01、sample04-r01、sample05-r01、sample06-r01 | 本轮只在 `review.md` 留候选。 | 将「目标与讲解不一致」「没有可定位 Surface」「只有标点/节奏」「anchor 不足以表示学习点」列为明确待审原因；人工确认后才决定如何表示。 | 多一条复核路径，减少正式候选数量；不能由机械校验代替判断。 |

本轮**不建议**给 `N + で` 直接附加未经批准的中文义项或人物语境来强行拆组：A0 已把它定义为检索表示，而本批显示宽组在浏览相关实例时仍有用。若未来发现检索噪声高，再用独立样本评估用法筛选，并保留来源隔离。
