# 阅读呈现实验：观察与验证

## 比较对象与方法

从 batch-01 保留的 Occurrence 中只选 `sample01-o11`（見かける）、`sample04-o03`（調べてきた）、`sample05-o05`（んだけどね）和双 Section 的 `sample04-o04`。三个视图共用同一目标原文及 Surface 位置：①原有标题与 gloss；②原 Section Markdown 的页面内展开；③由确定性 Markdown 树和前端组件呈现的同一内容。没有重提取 Occurrence、补写教学内容、设计复习题或调整 anchor。

| 案例 | 基线缺少的已有讲解 | 原 Section / JSON 树中已恢复的内容 |
| --- | --- | --- |
| `sample01-o11` | gloss 只说「与見る比较」，没交代结论。 | 来源 `sample01-s05`（296–345 行）的词义差别、车站例句、漫画语境延伸，以及原句没有「よく」的限定。 |
| `sample04-o03` | gloss 只给「此前查过、成果来到现在」的结论。 | `sample04-s04`（110–172 行）的 `調べる → 調べて → 調べてくる → 調べてきた`、时间线、`調べた` 与 `調べてきた` 的对比、勿只按物理「来」理解的提醒。 |
| `sample05-o05` | gloss 只概括随意的解释或补充。 | `sample05-s06`（250–349 行）的 `んだ／けど／ね` 分步说明、逐步对比，以及「言外内容没有唯一答案」的限定。 |
| `sample04-o04` | gloss 只概括名词修饰结论。 | 按原顺序展示 `sample04-s05`（173–211 行）与 `sample04-s06`（212–245 行）：普通形小句修饰名词及「サーブ」前为何没有「を」。两块各有标题、行号和独立展开控件，没有重复展示。 |

**可观察的主要改善来自完整内容的恢复。** 现有 gloss 适合作索引提示，直接展开讲解后，不离开当前页面就能重读推导、对比、例子和保留条件。JSON 树本身没有产生新知识；它与原 Section 显示相同的讲解。树视图额外提供只由 Markdown 标题生成的段内导航，以及略紧的排版；在 `んだけどね` 中可跳到原文的「んだ」「けど」「ね」三级标题。这是可比较的交互差异，**本轮不能据此断言它提高了学习效果**。若用户认为直接展开的原 Section 已足够，下一步完全可以保持轻量实现。

## 转换与保真边界

- `build.mjs` 读取 batch-01 的 `manifest.json`、`occurrences.jsonl` 和解析快照，用本目录固定版本的 Marked 17.0.5 建立 `data.json`。4 个案例合计引用 5 个 Section。每个 Section 保留完整 `raw_markdown`、原 `section_ref` 和 1-based 行范围；顶层树节点的 `raw` 串接必须逐字还原该 Section，构建时断言，不满足就失败。
- 树节点保留标题、段落、引用、强调、代码、列表等 Markdown 结构和原有顺序。没有识别「例句」「对比」「推导」等语义类别；暂不支持的 token 以原文 fallback 显示，不静默丢弃。
- Marked 不提供原生源码位置。Section 行范围来自 manifest 且精确；内部节点的行号通过在原片段内匹配 token 的 `raw` 推算。容器标记被剥离或相同文字重复时，**嵌套节点行号可能较粗**，不应被当作精确列级映射。原 Markdown 和 Section 行号仍可回溯。
- 原 Section 视图使用本地 Marked 渲染，并将结果转成受限 DOM；JSON 视图递归创建组件。链接只接受受限协议，图片以替代文本表示；本轮五个 Section 没有图片。两种视图都不载入远程资产。

## 尚需判断

这不是用户学习效果测量。若要把树节点进一步归类为「推导」「例句」「对比」，必须另设语义判断和保真复核，不能把 Markdown 的引用或列表形状自动等同于这些教学角色。

## 用户验收补充

用户亲自体验后确认：直接渲染并展示原 Section 的 Markdown，对「阅读与再理解」已可作为基线，主要体验问题是内容略长。JSON 树在当前阅读场景尚未显示出必须采用的价值，但保留其作为后续主动学习研究材料的可能性。

无论主动学习内容将来由固定规则还是 LLM 提取，都要根据实际复习交互重新设计；本次验收不等于批准现有 JSON 树作为复习 schema，也未验证长期记忆效果。原构建、浏览器检查和截图交付情况按上文保留，用户验收不补记任何未完成的技术验证。
