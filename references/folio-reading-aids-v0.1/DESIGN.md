# Folio-J 阅读辅助、阅读记录与解析阅读：实施建议稿

版本：v0.1 · 2026-10-19

本文供产品审阅和本地 coding agent 接力。依据为本轮用户讨论及 `folio-j_仓库快照_20261019220331.xml`。本文未修改生产仓库。下列“已确认”来自用户；“推荐方案”是本轮供审阅的具体设计，不能表述成已经实施或验收的功能。

## 1. 本轮目标与已确认取舍

两个交付目标：

1. 得到可听、可理解的原文：阅读中以及书外回看时，可以取得、重用和修正译文，取得并重播音频。
2. 理解能够留下来，并在以后找回：可以人工创建、粘贴导入、编辑与独立阅读 Markdown 解析，并可靠返回原文。

已确认取舍：

- 原生 AI 问答和现有工作台 AI 的后续开发暂缓。保存、编辑和阅读资料不以模型调用为前提。
- 内容阅读视图与 Workbench 职责分开。是否复用组件按实现判断。
- Analysis 保留 Markdown；解除面向未来 Occurrence 提取的标题层级及学习对象格式要求。
- TTS 与翻译和解析管理同样重要。翻译可复用已有文本 LLM 接入；TTS 需要实际语音服务适配。
- Anki 导出、SRS、Occurrence/KnowledgePoint 的生产设计暂缓。
- 已保存原文、出处、讲解修订和用户修正需要保留；开始日常使用后维护增量迁移和可靠备份。

“书外”在本文指阅读器之外、Folio-J 应用之内的素材/来源页面。跨应用分享与导出不属于本轮交付。

## 2. 核心推荐：轻量阅读记录与明确的片段学习

### 2.1 三种状态足够表达本轮需求

| 状态 | 何时产生 | 保存什么 | 在哪里看到 |
| --- | --- | --- | --- |
| 临时选区 | 用户划选原文 | 页面内目标快照 | 原生选区和操作菜单 |
| 阅读记录 | 翻译或 TTS 成功保存，或首次解析成功保存 | 确定的原文范围及已有译文、音频或关联解析；允许只有解析 | 书内标记、书内列表、书外列表与详情 |
| 片段与解析 | 用户明确创建解析并首次保存 | Segment 及 Analysis/Revision | 片段资料页；阅读记录提供关联入口 |

本轮不另加“待整理、已掌握、已收录”等学习状态，也不设置“自动保存但未保留”的第二套内容保留状态。翻译和 TTS 成功都默认保存；标记显隐是显示偏好，关闭面板不删除内容。

这是有意选择的默认行为：用户已经明确触发了一个会产生可复用结果的动作，随后不必再点保存。若自用表明纯朗读历史产生过多噪声，再调整记录展示或增加显式收藏；不先把两套概念放进首轮界面。

### 2.2 ReadingRecord 的边界

`ReadingRecord` 为本稿暂定代码名，界面称“阅读记录”。它表示“这份材料中，这一处原文已有哪些阅读辅助结果”。它不是一次调用日志，也不承担学习目标、聊天线程、知识点归属和复习状态。

最少需要：

- 独立 ID、材料 ID、不可变材料版本 ID。
- 原始资源身份、半开码点范围 `[start, end)`、原文快照。
- 当前译文结果、当前音频产物的引用，以及必要的来源/版本信息。
- 创建和内容更新时间、编辑并发版本、可见性信息。
- 可由所关联 Segment 反查解析。Analysis 不再直接获得第二个父级。

章节名与当前排版的 part/屏幕位置用于展示和导航；范围身份以原始资源和不可变正文坐标为准。原文引用作为记录内的值即可，首轮不必另建通用 Anchor 表。

### 2.3 写解析时沿用 Segment/Analysis

“新建解析”直接打开编辑器，带入当前原句和出处。用户无需先填写 Segment 表单。

- 打开空编辑器、输入但取消：不创建空 Segment、Analysis 或只有空壳的阅读记录。
- 首次成功保存：在一个事务中校验原文引用、建立或取得 ReadingRecord、建立或取得关联 Segment、创建 Analysis 和初始 Revision。
- 联建服务拥有完整事务，复用无隐式提交的创建辅助函数；不能直接串调用内部会提交的现有 `create_segment()`。先核对请求幂等，任一环节失败均整体回滚。
- 从已有记录新建解析：复用同一 Segment，创建另一份独立 Analysis。
- 编辑已有解析：产生同一 Analysis 的新 Revision。
- 首轮同一 ReadingRecord 至多关联一个存活 Segment，重复点击与并发保存依靠针对未删除 Segment 的唯一约束和请求幂等处理。一个 Segment 仍可有多份 Analysis。
- 手动录入的 Segment 不要求有 ReadingRecord，原入口继续合法。

写解析本身已经表达了围绕原文留下学习成果的意图。这里的 Segment 创建应在保存动作的行为说明中透明表达，不引入另一个前置步骤，也不将每次翻译都建立为隐藏 Segment。

## 3. 阅读器交互

### 3.1 入口

普通划选只产生操作条：`翻译`、`朗读`、`新建解析`。系统复制与 Yomitan 的现有手势继续工作。选区出现不调用服务、不创建记录、不弹出大侧栏。

点击动作前捕获稳定选区快照，随后切换选区、翻页或关闭面板不改变已受理请求的目标。长按/键盘选择可通过同一动作入口使用，不把悬停设为唯一入口。

首轮范围限定为当前生产阅读器单个 part/iframe 文档内的连续选区。跨 part 的选区不能在界面上伪装成已支持；未来需要跨资源目标时单独扩展。

### 3.2 一个当前结果面板

动作执行后收起操作条，打开一份当前结果面板。面板包含：

- 原文摘要或明确的选区对应关系；离开原句较远时显示完整目标。
- 译文及生成中/失败/已保存状态；已有译文可人工编辑。
- 朗读生成或重播/停止控制。
- `新建解析`；已有解析时可打开具体解析或解析列表。
- 章节出处、关闭和“查看阅读记录”等次级入口。

原文、译文、音频和解析各自有明确动作；不要求先翻译才能朗读，也不要求已有译文/音频才能写解析。面板不显示模型调试字段，不承载聊天输入或 Agent 工具审核。

只同时打开一份当前面板。点击另一条记录替换当前内容；已有书内记录侧栏展开时更新该侧栏/详情，不另叠第二个竞争窗口。完整长解析进入较大的内容阅读视图，不在小面板里继续堆成长卡背。

### 3.3 已有结果的原文标记

推荐采用三层视觉：

1. 已有结果但未聚焦：低强调细线和页边短签。签上的文本/图标只表达含译文、音频或多条记录。
2. 正在查看：当前范围临时强调，页边签进入选中态。
3. 留白足够时：只为当前记录画一条短连接线，连接范围与展开面板。

不常驻展示所有连线，也不把颜色解释成学习进度或掌握程度。若同一视觉区域的多个签挤在一起，显示一个数量入口，展开候选后选择具体记录。显示聚合不合并数据。

打开/关闭结果、出现标记和短连线均不改变正文排版。标记层复用可靠的 DOM Range 坐标，复杂按钮与卡片放在父阅读器覆盖层，避免在原文文本节点里插入 UI。

细线是可替换的显示方式，不是记录身份。不能稳定绘制时优先保留页边入口与聚焦高亮；不要为装饰连线引入全新的排版引擎。

### 3.4 留白不足、竖排与窄屏

- 宽屏且有足够真实留白：边签展开为页边卡。
- 留白不足：使用现有工具层的覆盖式侧卡；不为腾位置自动修改用户正文宽度。
- 窄屏：底部卡片或覆盖式详情，保留明确的关闭和回到原文入口。
- 竖排：标记随原文书写方向定位，展开内容保持适合阅读译文/解析的普通横排；采用可用侧边/底边空间，不机械旋转横排连线。
- 滚动或重排后重测范围矩形。原句离开视口时关闭贴句面板，或在已固定的记录侧栏中继续显示；持久结果不受影响。

### 3.5 关闭与焦点

点击当前签可开/关；点击其他签切换；面板有显式关闭按钮。Escape 优先关闭当前应用层中最上层的弹出内容，并尊重事件是否已被处理。

使用 Yomitan、复制、拖选原文不应导致当前结果消失或误发请求。不要用覆盖整页的透明点击层截获扩展交互。第三方扩展浮窗的状态不能依赖未经验证的检测。

编辑中的未保存正文/译文需要明确的草稿处理；在同页切换面板时保留，离页/刷新前提供离开保护。明确取消才放弃草稿。

## 4. 书外回看与内容阅读

### 4.1 同一记录的不同入口

首轮从素材详情提供“阅读记录”列表，并在阅读器工具入口提供本书列表。来源页可增加聚合入口。暂不为少量内容新增全局一级导航或“知识库”页面。

列表显示原文摘要、已有译文摘要、章节和内容类型，支持只有解析的记录，支持本书范围内原文/译文的简单搜索。按内容更新时间排序；纯页面打开不制造新记录。

在书外点击记录，先打开记录详情。用户可以直接读译文、播放音频、修改译文、打开/新建解析；“回书中原文”是明确动作。无需为了找一句译文先加载整本书。

书内和书外编辑的是同一个 `record.id` 及其结果。没有导出副本，没有依赖前端复制的同步协议。深链接应支持打开确切记录；读取后端记录、验证材料版本、导航成功后再高亮，不仅拼一个查询参数。

### 4.2 Segment/Analysis 的阅读视图

`/segments/:id` 可沿用为片段资料入口；已有 Analysis/Revision 直达链接保持有效。默认显示原句、可参照的译文/音频、解析列表或具体正文。

主操作是 `新建解析`、`粘贴/导入`、`编辑`、`回原文`。阅读组件不要求 Job、onGenerate 或打开聊天；不在挂载时自动创建线程或发起模型任务。

Workbench 后续可以作为围绕这些对象展开活动的入口。旧线程和已有数据保留；本轮不扩大其能力。未来 Occurrence/KnowledgePoint 的阅读形态可借鉴内容参照方式，本轮不预建空页签或通用对象浏览器。

## 5. 自由 Markdown 与人工写入

编辑入口包含可选标题、Markdown 正文、预览、保存、取消。支持粘贴文本和导入单个 UTF-8 `.md` 文件；导入先进入可编辑草稿，用户保存后才产生正式修订。

正文可没有标题，也可自由使用标题、列表、引用等受支持 Markdown。使用现有安全渲染能力；自由写作不等于运行任意 HTML、远程脚本或新增附件系统。当前 HTML/图片渲染边界需要在实现说明中如实保留。

### 5.1 对当前 normalizer 的最小处理

当前 `normalize()` 对没有 H2、有 H1、重复标题等情形只给 warnings，并不拒绝；`create_analysis()` 接受非空 Markdown。实际强约束主要在旧 Agent 块编辑协议和阅读层的 LO/格式提醒展示。

推荐：

- 阅读视图直接对完整 `source_md` 渲染，不强制逐 Section 展示。
- 隐去与自由写作冲突的格式提醒和 LO 编号要求。历史 warnings 可以继续保留在数据中。
- 新增独立的全文修订写入服务；不把任意全文替换塞入不允许 H2 的 `update_preamble` 操作。
- 保留 normalizer v1 和历史 Section/Revision，不重切或覆盖历史。全文替换没有显式块映射时给新块分配新身份，旧引用继续指向旧版本。
- 旧 Agent 块编辑按其原契约继续可读/可执行，不通过删除局部校验来“放开 Markdown”。

因此，本轮不要求先建设新的文档树、编辑器框架或 normalizer v2。

### 5.2 写入事实与原文锁

人工创建/修订记录 `origin=user_import/user_edit` 等实际来源，`run_id=null`，不伪造 AI 调用。

首次持久解析保存时固定目标原文。材料派生原文已有不可变范围；手工 Segment 则沿用现有原文锁并把触发条件扩展到人工保存讲解。当前只在 AI Job 受理时加锁的规则需要同步修改。

标题目前位于 Analysis 文档级；首轮标题编辑明确影响文档显示名，历史正文仍按 Revision 读取，不声称旧标题已有完整版本历史。

## 6. 结果所有权与重复操作

### 6.1 一份结果，一个可写来源

ReadingRecord 唯一拥有材料范围上的译文和音频。材料派生 Segment 通过可空的 `reading_record_id` 关联它；唯一约束只覆盖未删除的 Segment。片段阅读 DTO 解析关联后返回当前译文/音频；写入也路由到同一个记录，不能同时维护两份可编辑译文。

旧手动 Segment 的 `translation`、原文和语境继续可用。对于有 ReadingRecord 的 Segment，旧字段只作为兼容/历史迁移需要的存量信息，不继续作为另一条写入路径。统一片段内容解析服务同时用于阅读 DTO 和新的输入快照；关联记录没有译文时返回空值，不回退到陈旧的 `Segment.translation`。

关联 Segment 的译文编辑必须携带 ReadingRecord 的基础版本，经记录服务写入；现有 Segment 更新入口不得直接修改其 `translation`。Segment 自身的管理字段和学习语境继续使用 Segment 版本校验。旧 AI 输入快照按受理时事实保留；新快照保存实际采用的译文文本及其结果 ID/记录版本，不在执行时重新读取当前结果，也不依赖 `Segment.revision` 表达共享结果版本。

原句可以为兼容保留不可变文本快照，但它不再是第二份自由编辑文本。学习语境允许表达用户另外补充的信息，与原文范围的身份分开。

### 6.2 去重与范围

首轮范围唯一键为 `(material_id, version_id, spine_index, resource_id, start, end)`。`spine_index` 表达不可变版本内资源的这一次出现，避免重复 spine 中相同资源和文字被错误合并；`part_index` 用于呈现和导航，不进入范围身份。

- 完全相同范围：打开/更新同一记录。
- 相同文字出现在不同位置：不同记录。
- 有重叠但范围不同：各自保留，显示时可聚合入口。
- 同一范围拥有译文与音频：一条记录、两个独立结果，不各建一条记录。
- 同范围重复保存解析：复用关联 Segment；每次明确新建解析产生独立 Analysis。
- 范围唯一性与请求幂等分别处理。重试同一请求不新增结果；明确重新生成可产生新版本。

### 6.3 重新生成和人工修正

点击“翻译”时已有结果优先打开；重新生成使用独立动作。重新翻译成功即自动持久保存为一个结果，刷新后仍可找回；采用该结果才切换当前译文。未采用结果不是未保存草稿，也不引入收藏或保留状态。此前版本和人工修正不被迟到结果覆盖。人工编辑保存带基础版本校验。

播放已有音频直接读取已保存字节。换声线或改变合成参数需要明确重新生成，成功的音频字节及生成事实自动保存；切换当前音频引用不覆盖旧产物。全局默认声线变化不改掉历史音频。单纯调整播放速度不自动等同于重新合成。

关闭面板、隐藏标记和删除记录是不同动作。首轮可提供带撤销的记录移除；若已关联 Segment/Analysis，不允许悄悄级联删除学习成果。可暂时限制删除关联记录，并提供进入片段管理的入口，不需要先建立复杂删除策略。

删除 Segment 及其解析不删除共享 ReadingRecord、译文或音频。删除后的 Segment 继续保留历史关联，但不占用存活关联的唯一名额；用户之后明确新建解析时可以建立新的 Segment，不复用已删除对象或自动恢复旧成果。

## 7. 翻译与 TTS 的服务边界

### 7.1 翻译

业务输入：确定的目标原文、实际采用的有限上下文、目标语言、所选服务/模型配置。输出：译文文本及实际调用来源。

默认只带有限前文，用户可展开查看/调整；后文或全章不自动进入模型输入。具体字符上限放在一处配置，并在接入模型时按真实延迟/上下文限制确认。每次调用保存实际上下文快照，不能用当前页面上后来变化的内容重建旧调用。

LLM 适配复用已有 Provider、凭据管理、`CallSnapshot` 和 `generate_text()`；翻译使用自己的用途默认值和版本化 prompt，不带聊天历史、讲解风格或 Agent 工具。

已有 Run 允许 `job_id=null`，可以记录无线程的单次翻译。新增 `purpose=translation` 时，同时更新类型、状态查询、来源可见性、重启中断恢复与并发预算；不要只新增一个调用路由而漏掉这些边界。

未来专职翻译 API 实现同一个业务接口。不同服务配置和能力按实际协议表达，不要求所有翻译供应商伪装成 Chat Completions。

### 7.2 TTS

最少区分三件事：

| 对象 | 需要表达的内容 |
| --- | --- |
| 服务配置 | 适配器类型、endpoint/本地引擎定位、凭据引用、模型配置及配置版本 |
| 声线选择 | 服务内 voice ID、展示名、语言及服务实际支持的选项；首轮可存配置内，不强制独立建表 |
| 一次合成及音频产物 | 实际输入、服务/模型/声线/参数快照、调用状态、音频字节和媒体类型、可选时长、内容摘要 |

业务操作为短选区合成，返回可保存的音频字节；应用负责持久托管和播放。调用不能只返回并长期依赖一个会过期的供应商 URL。

推荐首轮将已成功生成的短音频作为持久结果保留，随资料备份。数据库 BLOB 可延续现有项目的原子托管方案；流式读取、字节上限和清理规则按真实产物规模落实。缓存可用于避免重复合成，但不能静默回收仍被阅读记录引用的唯一音频。

重用键至少包含实际朗读文本、服务/模型、声线和影响合成的参数；正文与必要的读音覆盖分开保存，读音修正不改写书籍原文。

现有文本 LLM Provider 只支持两种文本协议，不能假定配置同一个 base URL 就支持语音。TTS 适配与文本调用共享凭据、配置快照、错误处理等基础能力，音频协议保持明确。

仓库要求模型调用经过 `llm/` 并产生 Run。实现建议保留该要求，在 `llm/` 增加语音适配入口，为 Run 增加真实的语音用途和可区分的输入/输出快照，使用音频产物引用；不要填写假的文本协议或提示词来满足旧字段。若本地实施选择独立语音调用记录，应先明确修订这条规范并保留同等追溯，不能自行绕开。

具体 TTS 服务/声线仍需用用户真实小说句子试听后选定。本文确定业务边界和结果持久化，不宣称已选定、接通或验证音质。首个适配器只覆盖选定服务实际需要的参数。

### 7.3 状态和错误

- 翻译与音频独立执行、独立保存，一项失败不影响另一项及已有结果。
- 成功结果写入持久存储之后才显示“已保存”。取得内容但写入失败要显示“尚未保存”，允许复制/下载和重试保存。
- 初次失败/取消不留下可见空记录；已有记录上的失败不清除旧结果。
- 异步请求绑定请求开始时的原文范围，迟到结果只写其自己的记录。
- 成果发布前在最终写事务内重新核对 Source 存活、目标记录未被移除及请求仍有发布资格。移除记录或取消任务撤销相应请求的发布资格；迟到结果不得按原范围重新创建记录或恢复已删除内容。关闭面板不撤销正常请求的保存。
- 记录详情、译文结果、音频字节和新 Run 查询均检查完整来源可见性链，Source 删除后不能通过旧资源 URL 继续读取。
- 跨页或刷新后查询持久状态；重启后不自动重放未知结果的付费请求。中断显示可重试。
- 重复提交、用户修正和重新生成使用请求身份及内容版本，防止重复扣费和互相覆盖。

首轮可用受控单次任务实现，不需要 Agent 工具循环或通用工作流引擎。内部工作记录与用户可见阅读记录的生命周期分开。

## 9. 建议实施顺序与验收

### A. 原文范围与阅读记录

实现选区快照、范围校验、记录身份、书内/书外详情及确切回跳。用离线 fixture 填充译文/音频测试，不将 fixture 当真实模型验收。先接通整条用户路径，再加装饰连线。

验收：相同范围复用、不同位置同文区分、重叠记录可区分；字号/注音/横竖排变化后仍对应原文；书外阅读无需先加载书；Source 删除门禁生效。

### B. 翻译与短音频

用相同目标引用依次接入单次翻译和一个经试听选定的 TTS 服务；成功结果持久化、已有结果重用、人工译文编辑及独立失败恢复。

验收：刷新和重启后可找回；音频不依赖供应商临时 URL；选择改变不串结果；TTS 失败不清除译文；改过的译文不被迟到结果覆盖。真实音质和真实服务兼容性需要单独人工试用，不能用模拟响应通过替代。

### C. 人工解析与独立阅读

新建/粘贴/导入自由 Markdown、全文修订、片段联建和解析阅读。该切片可以提前在现有手动 Segment 上完成，与阅读辅助的服务接入独立推进。

验收：无 H2 的正文正常保存/阅读；不配置 AI 也能创建编辑；取消空编辑器不产生空片段；同范围多个解析复用 Segment；旧修订不变；内容页不挂载或依赖工作台 AI。

### D. 用真实内容收口显示细节

验收宽/窄屏、竖排、Yomitan、密集重叠标记、页边留白不足、打开/关闭/返回和草稿保护。边签、细线和连线可调整；数据身份和保存规则保持稳定。

### 工程约束

遵循当前 `AGENTS.md`：增量迁移、`just gen-api`、必要测试、`just lint`、浏览器检查和文档同步。网络/模型录制按仓库现行规则由人类执行。新增翻译/语音调用不能绕开调用记录。

合入时将已接受的行为写入 PRD/GLOSSARY，将职责写入 INFORMATION_ARCHITECTURE，将实际技术和调用记录写入 ARCHITECTURE/TECH_STACK；阶段安排更新对应 handover，实际验收单独记录。无需因本稿出现新建议就重写所有长期文档。

## 10. 本稿需要通过体验继续验证的取舍

- 自动保留所有成功 TTS 的历史量是否合适；本稿先选择低保存摩擦、完整结果可找回。
- 默认细线加边签是否过密；可改成仅边签或按书关闭标记，不影响持久内容。
- 最满意的 TTS 服务、声线以及可接受延迟；需要真实试听。
- 长解析更适合独立页还是宽侧栏；本稿优先独立内容阅读，保持原文参照和返回路径。

这些是可替换的体验选择，不作为重做知识体系的理由。交互样例用于检查这些选择；它不代表真实 EPUB 定位、服务调用或持久后端已经实现。
