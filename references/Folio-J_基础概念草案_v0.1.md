# Folio-J 基础概念草案 v0.1

> 日期：2026-10-17。状态：供讨论与案例验证的设计提案，不是已批准的生产契约或开发排期。
>
> 参考输入：本轮对话、用户提供的《learning-j 数据模型契约》（data-model.md），以及 Folio-J 2026-10-16 仓库快照。旧文档作为设计参考，不视为当前 Folio-J 的实现说明。文中的示例学习者、编号和过程均为概念验证用假设，不是对用户实际能力的诊断。

## 1. 总体立场

Folio-J 建立一份由学习者参与维护的开放学习档案。它连接学习者的目标、经历、语言材料、知识对象、实际表现和系统判断，服务于理解辅助与后续学习。

这份档案不是一张能力总评分表，也不是 Agent 上下文中不断改写的一段摘要。它需要同时回答五类问题：

| 部分 | 回答的问题 |
|---|---|
| 学习者的自述与选择 | 我怎样学习过，想达到什么目标，希望怎样获得帮助？ |
| 知识与能力地图 | 我们在谈哪种语言现象，希望学习者能够怎样处理它？ |
| 经历与观察记录 | 实际发生过什么，留下了哪些可追溯的信息？ |
| 解释与学情判断 | 这些记录支持什么结论，适用范围和未知部分是什么？ |
| 教学决定与交互 | 根据目标与当前判断，现在怎样帮助，或者选择不打扰？ |

这些是概念职责，不要求对应五个模块或五张数据库表。

本草案采用两个基本立场：知识身份可以在使用中维护和修正；学习者模型可以利用自述、自然阅读和主动学习等多种来源。与之配套的要求是，身份判定与学情判断都必须保留出处、作用范围和纠正路径。

## 2. 知识模型：把形式、意义范围和能力要求分开

### 2.1 KnowledgePoint 的建议定义

**KnowledgePoint（KP，知识点）是系统中一个可持续引用、具有明确范围的语言知识对象。它描述一种用法、形式与意义的联系、结构规律或相关语言机制。**

KP 的范围应足以支持讲解、关联例证和区分学习状态，但不声称是语言学或认知意义上的最小单位。

一个正式 KP 至少应能说明：

- 它讲什么，以及暂时不涵盖什么；
- 有哪些代表性例子或来源；
- 与邻近知识有什么区别；
- 定义来自哪里，哪些部分仍待核对。

以上是内容要求，不是要求每条记录都写成长报告。尚未厘清的问题可以先成为“待辨认的学习关注点”，保留原文和疑问，不为满足 KP 结构而编造通用规律。

KP 也不等于教材标题、词典条目、讲解小节、一次练习或者复习卡片。

知识地图采用公共参照与本地积累相结合的方式：词典、教材等提供外部参照，实际阅读中的问题按需要补充。不同来源的分类和定义可以并存并建立映射，不要求先裁定全世界唯一的日语知识体系。语言分析的正确性仍需独立核对，不能仅由学习者是否答对反向证明。

### 2.2 区分身份、显示名称、检索形式

本轮建议采用：

**稳定身份负责引用；名称负责展示；anchor 负责召回；范围说明负责解释对象的含义。**

同一 KP 可以有多个检索表示。相同 anchor 也可以召回多个不同 KP。即使使用确定性规则生成规范形式键，该键也只证明形式在所选规则下相同，不证明语义范围相同。

例如，“V＋ている”“V-て＋いる”“〜ている”可以作为相关检索入口，但具体能否视为同一种记法，需要核对槽位含义和接续约定。不能仅靠删除符号把它们自动合并。

对于一个形式具有多种用法的情况，可以保留一个浏览用的形式组，再关联具体 KP。例如：

    形式组：〜ている
      关联 KP A：动作进行、持续方面的某个明确用法
      关联 KP B：动作结果所处状态方面的某个明确用法
      其他用法按需要再补充

上述两类用法有 JF 教学资料支持，但这不是“〜ている”的完整分类。[W4]

形式组用于聚合和导航，不承载一个可以直接授予所有成员的“掌握度”。它可以先实现为查询分组，而不一定立即成为独立实体。

SKOS 将概念身份与标签、别名和范围说明分开；OntoLex-lemon 也区分词条、形式和义项。这些是可借鉴的表征思路，不要求 Folio-J 使用它们的完整技术栈。[W1][W2]

### 2.3 Lexeme 保留为算法索引，不提升为完整语义身份

旧文档将 Lexeme 与 KP 分开，并明确承认其形态三元组不能区分所有同形同音同词性的异义情况。[D1 §2.1]

本草案继承这一区分。Lexeme 服务分词聚合、词形关联和词汇候选召回；词典条目及义项保留各自来源与版本；KP 按实际学习所需的语义范围组织。

因此，分析器输出相同 Lexeme、词典中对应同一个条目、中文释义相近，都不能单独证明是同一个 KP。反过来，也不要求为每个 token 或每个词典义项预先创建 KP。

### 2.4 能力目标：对知识“能做什么”

另设一个概念上的 **Capability（能力目标）**，表达在特定条件下能够完成的语言活动。

一种便于理解的写法是：

    能力目标 = 处理对象 + 要完成的活动 + 适用条件 + 成功判据

例如：

- 在新出现的文字语境中，理解某种结果状态表达；
- 听到相关表达时，辨认其读音与意思；
- 能说明两种用法的区别；
- 能在需要的场景中恰当地使用该表达。

它们可以关联同一个 KP，但不是同一种能力。不需要为每个 KP 预建所有维度的组合，只有实际学习或判断需要时才建立具体目标。

能力目标也可以是综合性的，例如“在允许查词、不看整段译文的条件下理解一小段小说对话”。综合能力可以关联多个 KP，也允许暂时不能完整分解。

**Goal（个人学习目标）**则表达某个学习者现在是否愿意追求这些能力，以及优先级和约束。知识是什么、可以怎样处理它、用户想不想学，分别表达。

### 2.5 关系与粒度

关系至少要区分：同一对象的不同名称、语义范围较宽或较窄、值得对比、仅仅相关，以及教学上的建议先后顺序。

“先讲 A 有助于讲 B”不自动成为所有学习者都必须遵守的先修关系。语义相关也不等于同一对象。

拆分 KP 的实用判断是：是否存在稳定、重要的用法差异；是否需要不同解释或例证；是否影响我们对学习者表现的判断。不能只因用户一次答错就拆分，也不能因为两个表达意思相近就合并。

领域解释本身允许不确定。对于一句有歧义的原文，可以保留多个候选解释；不能将系统自己的语义分析不确定性，转写为用户能力不足。

## 3. Agent 如何参与知识身份维护

Agent 可以承担“查找已有对象、比较范围、提出新对象或关系”的工作。它不需要每次从零自由生成，也不应被要求只能选择预设列表中的一个条目。

建议流程为：

    从当前内容形成带出处的候选
      → 检索可能相关的 KP
      → 比较定义、用法条件和例证
      → 复用、建立关系、新建或保留未决
      → 对影响既有资料的操作作范围核对

比较结果不应只有“相同／不同”两种：

| 判断 | 对应处理 |
|---|---|
| 是同一语义范围的不同记法 | 复用身份，按需要补充名称或检索入口 |
| 相同形式，不同用法 | 分别保留 KP，共享形式检索入口 |
| 一个较宽，一个较窄 | 建立范围关系，不直接合并 |
| 值得对比或存在局部重叠 | 建立对应关系，保留差别 |
| 检索和语境不足以判定 | 保留候选及原始疑问，不强行归类 |

检索未命中不证明全库不存在同一对象；语义相似分数也不能直接承担身份裁决。SKOS 对 closeMatch 与 exactMatch 的区分说明了类似的建模需要，尤其不能把局部相似任意沿关系链传播。[W1]

本轮不把全部自动化都改成人工审批。可允许低影响、可撤销的自动关联与暂定判断；涉及合并大量已有资料、拆分知识范围或改变已有学习安排时，需要独立的影响核对和授权策略。

名称润色与语义范围变更也应区别处理。前者可以保持对象含义不变；后者应保留旧定义及适用关系，复核哪些历史判断仍然适用。

**合并与拆分规则：**原始例证、既有记录的身份和出处不改写；当前归属可以通过新决策调整；旧判断只在有依据的范围内重新求值。旧的“整体会了”不能平均分配或复制给拆出来的所有用法。合并知识也不自动合并复习排程、覆盖个人选择，或把重复记录当作新证据。

旧文档中可撤销的 canonical 合并、保留 Occurrence 原始 KP 引用、不迁移复习历史的原则值得继承，但语义拆分与学情影响需要另行扩展。[D1 §3.1]

## 4. 学习者模型：自述、选择、表现和判断共同组成画像

### 4.1 Biography 与当前画像

**Biography 是学习者参与维护的语言学习经历与反思。**它可以包含学习背景、动机、重要经历、自评、目标变化，以及对哪些帮助有用的反思。ELP 的 Biography 本身就包含目标设定、自评和持续反思，而不只是注册资料。[W3]

Biography 不直接等于所有行为日志，也不要求用户每天写学习日记。自然阅读和主动学习的记录可以成为它的参考来源，但系统生成的总结与用户自己的陈述需要区分。

**LearnerModel 是应用对学习者的结构化认识。**它包含用户声明、实际观察、系统推断及其相互关系。

**ProfileView 是针对当前用途形成的画像视图。**阅读辅助、预习筛选、独立学习和用户回顾可以读取不同的信息子集，但应来自同一组有出处的记录，不能各自维护一份互相漂移的“真相”。

### 4.2 画像的主要组成

| 组成 | 例子 | 信息边界 |
|---|---|---|
| 经历与背景 | 接触语言的渠道、学过的教材、用户报告的外部学习 | 学过、接触过不等于掌握 |
| 当前目标 | 想读的作品、希望减少哪类帮助 | 目标由学习者参与确定 |
| 偏好与限制 | 解释语言、阅读中不要自动出题、可接受的负担 | 喜欢某种形式不自动证明它最有效 |
| 具体学情 | 对一个能力目标的表现和当前判断 | 文字、听力、规则解释、产出可以不同 |
| 策略与困难假设 | 在某类情境下倾向先查词；可能混淆某类用法 | 系统推断标明依据与替代解释 |
| 当前情境 | 本次只想阅读、允许简短帮助 | 不自动变成长期标签 |

画像应表达长处、进步和可利用的已有经验，不只记录不足。与日语学习无关的人格诊断或敏感属性推断不属于这一模型的目标。

### 4.3 学情判断的最小表达

建议用 **LearnerClaim（学情判断）**表达一个有范围的判断。对于重要判断，应能回答：

| 信息 | 作用 |
|---|---|
| 判断对象 | 指向什么知识、能力、活动或暂未归类的困难 |
| 判断内容 | 本次表现、当前自评，或者跨次推断是什么 |
| 条件与时间 | 使用了哪些提示，在哪种模态与语境中，何时观察、何时解释 |
| 来源与依据 | 用户自述、实际表现、外部记录、规则或模型评价 |
| 未知与冲突 | 没有观察什么，有没有相反或范围不同的依据 |
| 适用状态 | 暂定、可使用、受争议、已被修正等，不等于掌握等级 |

具体示例：

> 对“在文字中辨认某类结果状态表达”的能力，已有少量独立处理新例子的记录。相关词义已提供，但没有给出目标语法提示。暂时支持在类似文字任务中减少基础提示；听力、主动表达和长期保持尚无记录。

这种判断可以指导动作，而不需要先显示一个精确百分比。未来使用概率时，必须明确概率对应的目标与条件；来源权重、模型把握、测量结果和用户决定优先级不共用一个 confidence 字段。

用户的“我觉得会了”以自评保存；系统对表现的判断单独保存。用户要求“不再推荐”，可以直接控制建议，不必强行把能力状态改成“已经掌握”。

## 5. 经历与证据：从实际痕迹到可解释判断

### 5.1 Experience：先记录实际发生的事

**Experience（经历／观察记录）**表示一次有学习相关意义的经历，或者系统实际捕获的行为与可见表达。来源可以是用户自述、自然阅读、讨论、练习或外部导入。

记录应保留足以理解其含义的信息：时间或时间范围、原始表述／作答／事件、相关材料或任务、实际可知的辅助条件、来源及观测限制。与 KP 的关系可以暂时未知；不要求先完成语义消解才能保存一次经历。

“用户说去年读过一本小说”意味着现在获得一条关于过去经历的自述，不意味着应用观测到了去年的阅读过程。报告时间与所述事件时间需要区分。

同样，应用观测到页面展示、用户选区、请求查词，与确认用户实际理解这些文字，是不同层面的信息。

### 5.2 Evidence 是记录与判断之间的关系

本草案不把所有信息都装进一个“证明已知”的证据桶。

一个记录是否能作为证据，要相对于某个具体判断说明。查词事件可以直接支持“发生过查词”，可以为“这类内容值得准备帮助”提供线索，却不足以单独证明“完全不会这个词”。

建议的链路是：

    原文、任务、用户表达与行为
      → 经历记录
      → 对内容和表现的解释
      → 有范围的学情判断
      → 当前画像视图
      → 教学决定

“系统解释一条记录”与“用户新增一次学习经历”分别记录。可以复用原有消息、批注、讲解和作答的引用，不要求复制出另一份完整档案。

e-ECD 研究把任务表现、支持材料使用、观察解释和能力推断分开，提示和支架还会改变表现的证据意义。这里借用的是这种区分，不预设 Folio-J 已有经过校准的测量算法。[W5]

### 5.3 阅读痕迹可以进入模型，但应保留其条件

| 观察 | 合理的直接表达 | 需要更多依据的进一步判断 |
|---|---|---|
| 多次查询相关内容 | 在这些已记录情境中多次求助 | 困难究竟是读音、词义、语法还是确认习惯 |
| 很少调用帮助 | 在已捕获的使用记录中辅助调用较少 | 是否真正独立理解；是否使用了应用外帮助 |
| 用户留下解释性批注 | 用户在当时写下了这种理解 | 该理解是否正确、是否由已有答案提示 |
| 提示后修正回答 | 在给定支持下完成了修正 | 以后能否独立完成 |
| 在新语境中自然解释正确 | 获得与相关能力有关的一次表现 | 更广范围的迁移与保持 |

自然行为既不应被一律排除，也不应被视作完全可靠的能力测量。建议让弱线索首先用于低影响、可拒绝的帮助排序；用于广泛隐藏辅助、停止复习等更强动作时，需要更充分的依据与可恢复入口。

“没有数据”不等于“用户没有学习”。没有捕获到求助，也不等于求助没有发生。

### 5.4 防止模型用自己的产物反复证明自己

同一次回答被多个模型评价，不构成多次独立表现；AI 生成讲解，再从讲解中提取条目，也没有证明用户掌握了这些条目。

新导入的资料如果只是本站旧记录的再次导出，不应增加独立证据数。知识合并、摘要更新和分析重跑也不得伪造新的学习进步。

因此需要保留实际观测来源和派生关系。系统可以重新解释旧依据，但必须知道自己是在改判断，而不是发现了新表现。

## 6. 初始化与持续变化

### 6.1 初始化：建立“可用但不完整”的起点

用户可以从一段自述开始：为何学习、过去怎样学、现在想理解什么、遇到什么困难、希望怎样获得帮助。

系统保留原始表述，并整理为经历、自评、目标与偏好。结构化整理不能扩大原话含义；由 AI 补充的原因解释作为推断，不混入用户自述。

已有教材学习记录、考试或复习记录可以导入，但保留原来的测量和任务范围。可选的小范围初始观察只帮助决定怎样开始，不冒充全面等级测验，不作为阅读门槛。

无需在首次使用时为所有 KP 填写状态。起点可以是：目标和偏好清楚；部分经历来自自述；相关能力有少量观察；其余未知。

### 6.2 变化的四种来源

画像更新需要区分：学习者实际变化；系统对学习者了解增加；知识范围被重新组织；用户目标或当前情境发生变化。

例如，原来粗略的一个 KP 被拆分后出现更多“未知”，不表示用户退步。用户在其他地方学习后回来，则可以新增外部学习自述或表现，不必假定本站记录覆盖其全部学习。

### 6.3 一条完整的假设案例

| 阶段 | 记录与解释 | 对画像的影响 |
|---|---|---|
| 初次自述 | “以前学过〜ている，但阅读时有些句子仍分不清。” | 有接触经历与自评，不直接登记掌握 |
| 自然阅读 | 在一处相关原文请求解释 | 记录求助情境；具体困难可能尚未确定 |
| 阅读讨论 | 用户明确把某个结果状态例子解释为正在发生的动作 | 若原文分析可靠，形成局部混淆假设，不推广到全部用法 |
| 接受帮助 | 看到解释后说“这下明白了” | 记录即时反馈，不自动证明迁移 |
| 后续自然表达或任务 | 在另一个语境中，无目标语法提示地正确解释 | 对相应文字理解能力增加证据 |
| 开放画像回顾 | 用户补充“刚才只是忘了读音，意思本来知道” | 补充自述并复核旧归因，保留原行为记录 |
| 目标变化 | 用户决定近期不安排此类复习 | 调整学习意愿，不改写已有能力依据 |

这条过程可以停在任一步。一次阅读不必产生 KP，一次提问不必形成练习，一份讲解也不必被收录。

## 7. 开放、持久性与边界

### 7.1 对学习者开放什么

开放学习者模型研究关注让学习者能够看到系统对自己的表示，并讨论开放程度与学习者控制。[W6]

Folio-J 的建议目标是让用户能够检查：系统怎样认识自己，依据是什么，哪些是自述、哪些是推断，哪些部分未知，以及这些信息怎样影响帮助。用户可以纠正、提出异议、补充外部经历，或要求某些信息不参与某种用途。

开放不等于公开。对用户可见、对外部 Agent 可读取、允许据此行动，是三种不同范围。

用户不需要检查每个中间步骤。界面可以默认给出简明解释，重要判断能够展开追溯；日常使用中只对有实际影响的变化提示。

### 7.2 长期档案与上下文摘要分开

旧文档的 LearnerProfileNote 具有条数与字数预算，并按 LRU 淘汰。[D1 §6.2]

这适合描述一组有限的上下文工作笔记，不宜作为长期 Biography 和证据的唯一存储方式。本草案建议：

长期经历、用户决定和已被使用的依据按明确规则保存；当前画像按需要更新；提供给 Agent 的摘要可以裁切、替换和重建。

不再注入上下文，不意味着删除历史；某条经历很久未被检索，不表示它失去价值。用户主动删除、撤回或限制使用时，相关判断和摘要也需要相应调整，不能通过旧摘要使被排除的信息重新生效。

这不是要求永久记录所有鼠标和滚动事件。观测按用途最小化，原始痕迹、摘要和正式判断分别规定保留粒度。已经丢弃的细节不能在以后假装能够精确重建。

## 8. 对旧设计的继承与明确调整

旧文档已具备不少可保留的原则：原文和来源版本稳定、事实与当前投影分离、合并不改写原始引用、复习记录不自动证明整词掌握、用户选择不会被抽取重跑覆盖。[D1 §§0.1、2.4、3.1]

本轮主要调整如下：

| 旧文档设计 | 本草案建议 |
|---|---|
| 同一形式的不同义项共享 KP，anchor 为唯一自然键 | anchor 保留形式召回价值；KP 按明确语义范围组织，允许同 anchor 多 KP |
| KnownEvidence 仅保存 Lexeme 的特定正向来源 | 可保留为特定来源的记录，不承担整个证据模型；学情依据扩展到经历、作答和有范围的自评 |
| LearnerProfileNote 是有预算、可淘汰的工作记忆 | 作为上下文摘要的一种实现候选，不作为长期档案唯一来源 |
| StudySession 采用讨论—提取—确认等固定阶段 | 保留为一种具体学习活动流程，不作为所有经历进入模型的前置条件 |
| Annotation 是独立叶子、不接知识关系 | 不强迫批注转成 KP；允许在授权范围内引用批注作为经历或理解依据，无须先完成解析 |
| 原文位置与材料通过 Sentence 契约组织 | 继承稳定位置与版本原则；不借本次概念设计把旧 Sentence 模型强加给当前 Folio-J |

当前 Folio-J 的 GLOSSARY 已把 anchor 定义为检索锚点，并说明相同 anchor 不证明知识点相同；这一点比旧 learning-j 的形式唯一键更接近本草案。[D2 docs/GLOSSARY.md §4]

当前 Segment、Analysis、Workbench 的职责继续成立。Occurrence 暂沿用现有“有原文与讲解出处的学习实例记录”含义；新增经历与证据关系不全部塞入 Occurrence。若以后扩展其定义，需要单独明确变化，不能让两套语义暗中共用同一名称。

## 9. 第一轮验证与暂不冻结的部分

先验证概念能否准确表达真实情况，再决定数据库和算法。

建议用一小组案例检查：同形异义、不同记法同一用法、宽窄概念、无法定位到连续文字的篇章困难、仅有阅读痕迹、应用外学习、AI 错判后纠正、知识合并／拆分、导入重复以及用户撤回记录。

对每个案例要求说清楚：保留了什么原始信息，形成了什么判断，有没有越过证据范围，用户能否理解和纠正，以及这些信息怎样改变下一次帮助。

尤其要检验两个现实风险：过细的 KP 是否增加组织负担却无教学收益；Agent 的身份归并与学情推断是否出现“看上去合理、实际错误”的结果。检索漏召回与语义判错应分开记录，不能只测 JSON 是否符合格式。

本轮暂不冻结完整日语知识分类、每类能力的概率模型、全局掌握阈值、所有行为信号权重、完整先修图、SRS 传播公式与 MCP 工具清单。

建议先稳定的，是以下边界：

1. KP 的稳定引用与 anchor 的检索表示分开。
2. 知识对象、能力目标和个人学习意愿分开。
3. 经历记录、对记录的解释和当前学情判断分开。
4. 自述、系统观察和推断均可进入画像，但保留各自来源和范围。
5. 知识可以合并拆分，画像可以修正，而历史表现不因此被改写或复制。
6. 长期学习档案不等于本轮 Agent 上下文；用户能够控制档案及其用途。

**这版草案的中心，是让系统持续回答：“关于这位学习者，我们依据什么，知道哪些事情，又有哪些事情还不知道？”Agent 帮助维护这一认识，而不替代它的概念边界。**
